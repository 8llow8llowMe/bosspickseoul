### 내린 결정

- **빈 상태와 장애를 가르는 기준은 「그 목록이 0건일 수 있는 목록인가」다(#376).** 고정
  목록(서울 자치구 25개)이 0건이거나 여러 지표가 **동시에** 0건이면 장애로 보고 재시도를
  연다. 상위 선택에 딸린 목록이나 단일 지표 0건은 정상이다. 200 이면 성공이라고 보고 빈
  상태를 그리면 장애가 조용히 넘어간다 — 2026-09-11 dev 에서 실제로 그랬다. 판정은 순수
  함수로 뺐다(`isStatusTopTenAllEmpty`·`isHomeRankingsAllEmpty`). 규칙 정본은
  `frontend/docs/engineering/data-fetching-rules.md`(이슈가 적은 `data-fetching.md` 는 오기).
- **홈 랭킹의 예시 폴백은 유지한다.** 라벨이 붙는 의도된 설계다. 다만 세 지표 동시 폴백만
  `console.warn` 으로 남긴다. Sentry 가 이 저장소에 없어 기존 관용구를 따랐다.
- **문서의 범위 표기 물결표는 `\~` 로 이스케이프한다(#351·#353).** GFM 취소선은 물결표
  하나로도 성립해서 `S0~S5`·`730~800KB` 가 **이미 GitHub 에서 취소선으로 렌더되고 있었다.**
  prettier 3.9 가 파서를 micromark v4 로 바꾸며 이를 `~~` 로 정규화해 적을 뿐이라, prettier
  가 깨뜨린 게 아니라 원래 깨져 있던 것이다. 렌더 확인은 `gh api -X POST /markdown`.
- **`next dev` 가 쓰는 `nextjs-agent-rules` 블록은 수용해 커밋한다(#372).** Next 가 블록
  본문에 적어 둔 방침이고, 내용도 유효하다. 끄려면 `next.config.ts` 의 `agentRules: false`.
  `next-env.d.ts` 는 Next 문서가 "should not be tracked" 라고 못박아 추적에서 뺐다.
- **배포 게이트 라벨은 「에이전트가 라벨을 붙이지 않는다」 규칙의 예외다(#344).** 두 정본
  문서가 정반대를 말하고 있었다. 스킬 쪽이 막으려는 것은 분류 라벨이고 `frontend-web` 은
  Jenkins 배포 게이트라, 「라벨」을 「분류 라벨」로 좁히고 예외를 명시했다.
- **검증할 수 없는 리팩토링은 하지 않는다(#374 → #375).** `recommend-map` 의 최신값 ref
  7곳을 `useEffectEvent` 로 옮기는 것이 정식 해소지만, 이 컴포넌트의 테스트는 순수 함수·
  SSR·소스 스캔뿐이고 검증 환경에서 카카오 SDK 가 로드되지 않는다. 파일 단위 예외를 줄
  단위로 좁히는 데까지만 하고 사유를 주석에 남겼다.
- **테스트를 쓰면 예전 구현에 대고 돌려 실패를 확인한다.** 이번에 두 번 구했다. #345 의
  첫 테스트는 `act()` 가 effect 를 흘려보내 예전 구현에서도 통과했고(렌더별 값 기록으로
  교체), #373·#374·#376 의 새 테스트는 전부 되돌리기 실험으로 회귀를 잡는 것을 확인했다.

### 주의사항

- **인계 문서는 저장소 `docs/handoffs/` 에 커밋한다.** `~/.claude/handoffs` 가 아니다.
  append-only — 기존 문서를 고치지 말고 새 문서로 낸다.
- **`git status` 가 깨끗해졌다.** `next-env.d.ts` 되돌리기와 `AGENTS.md` 자동 수정은
  더 이상 주의사항이 아니다(#372). dev 서버를 띄워도 워킹트리가 그대로다.
- **스택 PR 의 base 를 다른 브랜치로 두지 않는다.** #327 을 `--delete-branch` 로 머지하자
  그 위에 쌓인 #328 을 **GitHub 이 자동으로 닫았다.** base 브랜치를 일시 복원해야 다시
  열렸다. `frontend/CLAUDE.md` 에 적어 뒀다.
- **테스트가 `src/` 트리를 직접 훑는다.** `global-styles.test.ts` 의 규약 가드들이 그렇다.
  작업 중 임시 파일을 `src/` 아래 만들면 무관한 테스트가 빨개질 수 있다. scratchpad 나
  `os.tmpdir()` 를 쓴다. 인계 문서가 권하던 「`src/` 아래 `__scratch-*.test.ts`」는 이
  스캐너와 충돌한다.
- **vitest 목에서 거부 promise 를 테스트 본문에서 만들지 않는다.** `mockRejectedValue` 나
  본문 안의 `mockImplementation(() => Promise.reject(...))` 는 컴포넌트가 `.catch` 를 달기
  전에 promise 를 만들어 **미처리 거부로 엉뚱한 곳에서 테스트가 깨진다**(실측).
  `vi.hoisted` 상자를 만들어 팩토리 구현은 고정하고 안쪽 함수만 갈아끼운다. 예시는
  `src/components/recommend/recommend-map.retry.test.ts`.
- **브라우저 페인은 여전히 숨겨지면 하이드레이션되지 않는다.** 이번에도 두 번 겪었다.
  지도는 페인에서 카카오 SDK 자체가 로드되지 않는다. 로직 검증은 dev BFF 를 curl 로
  치거나(`curl localhost:5173/api/bff/...`) SSR 마크업을 grep 한다.
- **zsh 에서 `$VAR:refs/...` 를 쓰지 않는다.** `:r` 이 히스토리 수식어로 먹혀 refspec 이
  망가진다. git ref 조작은 `gh api` 쪽이 안전했다.
- **스크립트로 일괄 치환하면 커밋 전에 diff 를 본다.** 물결표 이스케이프 스크립트의 런
  길이 계산이 틀려 63개 파일을 망가뜨렸다. diff 를 보고 잡아 전부 되돌렸다.
- **`agentRules` 블록을 prettier 가 재포맷하면 `next dev` 가 매번 다시 쓴다.** 이번엔
  건드리지 않는 것을 확인했지만, 그 파일을 손볼 때는 `hasCurrentAgentRules` 로 서명이
  유지되는지 확인한다.
