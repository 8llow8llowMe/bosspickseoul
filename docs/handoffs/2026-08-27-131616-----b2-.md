### 내린 결정

**슬라이스 B1 설계 (머지됨, 재론하지 않는다)**

- **조건의 정본은 쿼리스트링이다.** 리포트는 `POST` 로 계산하지만 화면 입장에서는 "이 URL 이 가리키는
  결과"라는 읽기다. 그래서 `useMutation` 이 아니라 `useQuery`. 검증은 새로 짜지 않고 `conditions.ts` 의
  기존 판정을 재사용한다 — 화면과 URL 이 서로 다른 "유효한 조건"을 갖는 순간 사용자가 고르지도 않은
  조건으로 404 가 난다. 코덱은 `src/lib/simulation/report-route.ts` (접두사 `a.`/`b.` 지원 — B3 용)
- **입력 화면이 계산 성공 시 쿼리 캐시를 미리 채운다.** `simulationReportQueryKey`(`report-query.ts`)를
  단일 출처로 둬서 시딩 키와 조회 키가 구조적으로 갈라질 수 없다. **실측 확인**: 계산 → 상세 리포트
  이동에서 `POST /simulations/reports` 호출 수가 3 → 3 (재호출 0)
- **표시 로직은 순수 모듈**(`report-presentation.ts`). 이 화면의 오독 위험(만원 단위, `levy: 0` vs `null`,
  273억이 자기 매출이 아님)이 전부 문자열 만드는 지점에 있어서, 렌더 없이 값을 고정했다
- `ui/button.tsx` 에 **`ButtonLink`** 를 추가했다. `Button` 은 `forwardRef<HTMLButtonElement>` 라
  `as={Link}` 로는 타입·ref 가 깨진다. `Root` 의 공통 css 를 `buttonBase` 로 추출해 공유하며 `Button`
  기존 동작은 불변(`&:disabled` 포함, 리뷰에서 선언 단위 대조 확인)

**레거시 삭제 (#143)**

**단위·표기 함정 (슬라이스 B 전체)**

- **`formatLargeWon`(만원 입력) vs `status-formatters`(원 입력)** — 바꿔 쓰면 정확히 10,000배 틀린다
- **`topAgeGroups[].salesAmount` 는 자치구×업종 전체 분기 매출**이지 사용자 점포 예상이 아니다.
  범위 라벨과 억 단위 축약(`formatSalesAmountCompact`)이 둘 다 필요하다
- **`levy: 0` vs `levy: null`** — 0 은 "부담금 0원", null 은 "비프랜차이즈라 해당 없음". falsy 검사 금지
- **`lastId: 0` 은 "처음부터"가 아니라 "0번 다음부터"** — 첫 조회에 키를 싣지 마라
- **recharts 는 SSR 정적 렌더에서 차트 내부를 전혀 그리지 않는다.** 차트 값에 대한
  `renderToStaticMarkup` 단언은 **언제나 통과하는 공허한 단언**이 된다. 배선을 검증하려면
  엘리먼트 트리를 걸어 props 를 직접 단언해라(`simulation-customer-insight.test.ts` 가 그 예)
