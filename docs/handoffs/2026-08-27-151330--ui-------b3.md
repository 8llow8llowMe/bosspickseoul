### 내린 결정

**직전 세션에서 확정 — 재론하지 않는다**

- **아이디 타입은 방향에 따라 다르다.** 응답은 String(`"14954"`), 요청은 integer/int64.
  `franchiseeId` 계열 4개는 **API 클라이언트 경계에서 number 로 정규화**(`lib/api/simulation.ts`),
  `historyId` 는 **string 그대로**(요청에 싣는 곳이 없다 — 삭제·상세 API 없음).
- **조건 URL 코덱은 두 벌이다.** 요청 코덱 `toSimulationReportSearchParams` 는 `simulationReportQueryKey`
  가 캐시 키를 만드는 입력이라 **표시 전용 값(`brandName`)을 넣으면 안 된다.** 되돌아가기용
  조건 코덱 `toSimulationConditionSearchParams`/`parseSimulationConditionState` 가 따로 있다.
- **토스트**(`@/components/ui/toast` + 순수 로직 `@/lib/ui/toast-state`)가 이제 전역에 있다.
  `AppProviders` 안에 `ToastProvider` 가 들어가 있으니 어디서든 `useToast()` 로 쓴다.
  문서 흐름에 피드백을 넣지 않는다 — 레이아웃이 밀린다.
- **로그인 복귀 경로**는 `@/lib/auth/return-path` 한 벌(`safeReturnPath`/`buildLoginHref`/
  `currentBrowserPath`). 카카오는 `auth_return` 쿠키로 복귀한다.

### 남은 작업

#### 1. 시뮬레이션 **결과 화면** 폭 1320px → 800px

- 대상: `frontend/src/components/simulation/report/simulation-report-page.tsx:43`
  현재 `width: min(1320px, calc(100% - 40px))` → `min(800px, calc(100% - 40px))`
- **입력 화면(`simulation-builder-page.tsx`)은 건드리지 않는다.** 거기는
  `grid-template-columns: minmax(0,1fr) 380px` 2단 레이아웃이라 800px 로 줄이면 sticky 결과 패널이 깨진다.
  사용자가 말한 "결과화면"은 `/simulation/report` 다.
- 640px 이하 분기(`width: calc(100% - 32px)`)는 그대로 둔다.

#### 2. 비용 구성 **도넛 영역 400px**

- 대상: `frontend/src/components/simulation/report/simulation-cost-breakdown.tsx:33`
  `Layout` 이 `grid-template-columns: 220px minmax(0, 1fr)` → 220px 을 400px 로.
- **⚠️ 사용자 문구가 모호하다: "도넛 그래프 표시하는 것도 400px로 클리프? 수정하고싶어".**
  `클리프` 는 오타/음성인식 흔적으로 보인다. 착수 전 사용자에게 확인할 것:
  - (a) 도넛이 놓인 **컬럼 폭**을 400px 로 → `Layout` 첫 트랙만 수정. 가장 유력.
  - (b) 도넛 **자체 크기**(현재 `height={180}` 하드코딩)를 키우고 싶다.
- **(b)라면 주의**: `DonutChart`(`src/components/analysis/charts/donut-chart.tsx:120`)의
  `height={180}` 은 **공용 컴포넌트**다. 쓰는 곳이 4개 —
  `analysis-result-view.tsx` · `status-detail.tsx` · `simulation-cost-breakdown.tsx` ·
  `simulation-customer-insight.tsx`. 직접 고치면 분석·구별현황까지 바뀐다.
  → `height` 를 **옵셔널 prop 으로 추가**하고 시뮬레이션 호출부에서만 넘긴다(기본값 180 유지).
- **1번과 상호작용한다**: 컨테이너가 800px 인데 도넛 컬럼이 400px 이면 비용 표가 약 360px 로 좁아진다.
  `Layout` 의 767px 이하 1단 분기와 함께 실화면으로 확인할 것.

#### 3. 헤더에 `상권 시뮬레이션` 추가

- 대상: `frontend/src/components/layout/site-header.tsx:368` 의 `navigationItems`
  현재 `/status 구별현황` · `/analysis 상권분석` · `/recommend 상권추천` 3개.
  `{ href: '/simulation', label: '상권 시뮬레이션' }` 추가.
- **활성 판정 함정**: 같은 파일 396행이 `pathname === href || pathname.startsWith(`${href}/`)` 다.
  `/simulation` 항목은 `/simulation/report`·`/simulation/compare` 에서 활성이 되지만
  **`/analysis/simulation` 에서는 활성이 되지 않는다**(그쪽은 `/analysis` 가 활성).
  의도한 동작인지 확인하고, 필요하면 커뮤니티·채팅처럼 예외 분기를 추가한다(389·393행이 예시).
- **레이블 길이 주의**: 기존 3개는 4자인데 `상권 시뮬레이션` 은 8자다. 헤더가 최근 반응형 개편
  (햄버거 전용 + 플로팅 우측 패널, PR #114)을 거쳤으니 **태블릿/모바일에서 줄바꿈·넘침 확인 필수.**
  짧게 가려면 `시뮬레이션` 도 후보 — 사용자에게 확인할 것.
- `INNER_WIDTH` 매핑(41행)은 페이지별 헤더 콘텐츠 폭이다. `/simulation` 은 `default`(1120px)로
  두면 되는지, 1번에서 본문을 800px 로 줄인 것과 어울리는지 함께 볼 것.
