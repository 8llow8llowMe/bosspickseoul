### 2. 카피 진단은 컴포넌트에서 끝나지 않는다 (리뷰가 잡았다)

`chatting-unavailable-page.tsx` 본문에서 「V2 API」·「계약」을 걷어냈는데, **같은 두 라우트의
`metadata.description` 이 그 문구를 그대로 들고 있었다.** `index: false` 는 검색 노출만 막고
**공유 프리뷰(OG 카드)는 막지 않는다** — 링크를 붙이면 카드 본문으로 그대로 뜬다.

더 나쁜 것은 **새로 넣은 「백로그를 노출하지 않는다」 테스트가 그 자리를 못 덮었다**는 것이다.
컴포넌트 마크업만 봐서 초록인데 목표는 안 지켜지는 상태였다. 라우트 소스까지 단언 범위를
넓혀 해결했다(`app/**/page.tsx` 를 `node:fs` 로 읽어 단언 — 선례는
`analysis-map-shell.route.test.ts`. `generateMetadata` 가 async 라 import 해서 부르는 것보다 단순하다).

**함께 봐야 하는 자리**: `metadata.description` · `aria-label` · 테스트 픽스처.
그리고 **화면이 읽지 않는 데이터에도 카피가 산다** — `route-skeletons.ts` 가 sitemap 이 읽지도
않는 `title`·`description` 27개 엔트리에 낡은 내부 카피를 나르고 있었다(함께 제거).

### 3. 「없음」을 단언하는 테스트는 되돌려서 빨간불을 보고 넘어간다

### 4. 인덱스를 고칠 때 ⬜ → 🟩 로 뒤집으면 거짓을 거짓으로 바꾸는 것이었다

`docs/features/_index.md` 가 `status`·`community` 를 **⬜ 미착수**로 표기하고 있었다. 둘 다 이미
서비스되는 화면이다(status 컴포넌트 10개+테스트 3종, community 14개+테스트 4종). 그런데

「코드는 있는데 문서가 없는」 칸이 없었다 → **🟦 구현 완료·명세 미작성** 을 추가했다.

죽은 링크 3개도 걷어냈다(`status/status.md`·`community/community.md`·`recommend/recommend.md`
전부 없는 파일을 가리켰다). 죽은 링크는 「문서가 있다」는 인상을 준다.

## 남은 작업 — 그리고 다음에 무엇을 해야 한다고 보는가

### ⚠️ 「페이지별 UI 재검토」는 지금 수익률이 낮다

스윕 PR1~4 가 정확히 그 렌즈였다. DESIGN.md 정본과 전 화면을 대조해 토큰·웨이트·빈 상태·
접근성·카피를 갈았고 **회귀 grep 이 전부 0**이다(비표준 웨이트, vw 폰트, 네거티브 트래킹,
`Sparkles`, uppercase, `dashed`). 같은 렌즈를 세 번째로 대면 나오는 건 **미정의 토큰 1개,
죽은 코드 1개** 수준이다 — #172 가 그 실증이다.

그 렌즈에서 남은 진짜 문제는 하나뿐이고 **페이지별로 고칠 수 없다**(아래 ③).

### 한 번도 안 해본 렌즈: 과업 흐름

지금까지 검토는 전부 「이 화면이 규격에 맞나」였다. **「사용자가 목적을 달성하나」는 아무도
안 봤다.** 문제일 만한 근거 — **검증할 가설이지 확인된 결함이 아니다**:

- **입구가 4개인데 관계가 안 보인다.** 헤더에 구별현황/상권분석/상권추천/시뮬레이션이 나란히
  있는데, 「장사 시작하려는데 어디가 좋지?」를 든 사람이 어느 걸 눌러야 하는지 화면이 말하지 않는다.
- **`/analysis` 는 아무것도 보여주기 전에 4단계 선택을 요구한다**(자치구→행정동→상권→업종).
  어떤 상권을 고를지 모르는 사람은 여기서 막힌다.
- **`/recommend` 와 `/analysis` 가 개념적으로 겹친다.** 둘 다 「상권 고르기」인데 하나는 추천,
  하나는 검증이다. 그 구분이 화면에 없다.
- **화면 간에 「다음에 뭘 하지」가 이어지는지 미확인.**

**제안**: 과업 3개를 끝까지 걸어보고 막히는 지점을 기록한다. 화면 단위가 아니라 여정 단위.

1. 「강남에서 카페 하려는데 어디가 좋을까」 — 입구 선택부터 상권 결정까지
2. 「역삼역 앞 한식집, 되는 장사인가」 — 특정 후보 검증
3. 「얼마 드는지 보고 저장해두기」 — 시뮬레이션 → 저장 → 다시 찾기

산출물은 화면별 지적 목록이 아니라 **여정별 이탈 지점 + 우선순위**다.
※ 과업 3의 「다시 찾기」는 `/profile/bookmarks` 라 **로그인이 필요**하다.

## 다른 기기에서 이어받을 때 (집 컴퓨터)

- **`.env.local` 은 gitignore 다.** 직접 채워야 데이터가 뜬다 — `frontend/.env.local.example` 참고.
  Kakao 지도는 로컬 도메인 제한으로 타일이 안 뜰 수 있다(dev 키 필요).
- **`.claude/launch.json` 은 기기별로 다시 써야 한다**(추적 대상 아님).
- **워크트리 `/tmp/bosspick-url` 은 이 회사 기기 것이다.** 집에서는 새로 만든다.
- **이 기기에서만 해당하던 함정**: 저장소가 `~/Documents` 아래에 있으면 macOS TCC 때문에
  dev 서버가 `getcwd: Operation not permitted` → pnpm `EPERM: uv_cwd` 로 죽는다. 우회는
  **Documents 밖**(`/tmp` 등)에 워크트리를 만들어 거기서 띄우는 것. 집 기기에서 저장소 위치가
  다르면 이 문제 자체가 없다.

## 공통 주의사항

- **PR 에 `--label frontend-web` 필수.** 분류 꼬리표가 아니라 **fail-closed Jenkins 배포
  게이트**다. 빠지면 머지돼도 조용히 미배포된다.
- **branch protection 이 꺼져 있다.** develop 이 되돌려져 머지된 PR 3개가 도달 불가였던 사고
  전례가 있다(#148). 브랜치를 딸 때마다 `origin/develop` 해시를 먼저 확인한다.
- **`pnpm qa:verify` 는 `next-env.d.ts` 를 더럽힌다**(dev/prod import 경로가 뒤바뀜).
  커밋하지 말고 `git checkout --` 로 되돌린다.
- **`rm -rf .next` 는 dev 서버를 먼저 멈추고 한다.** 켠 채로 지우면 Internal Server Error.
- **브라우저 pane 이 숨겨져 있으면 하이드레이션이 진행되지 않는다.** 이펙트 결과(주소창·API
  호출)를 읽기 전에 화면을 한 번 그리게 하라. `tabs_context` 가 pane 표시 여부를 알려 준다.
- **prettier 가 마크다운 표를 재정렬하므로** 명세 문서 문자열 치환이 조용히 실패할 수 있다.
  치환 후 반드시 결과를 확인한다.
- `git rm` 으로 스테이징된 삭제는 **다음 커밋에 딸려 들어간다.** 커밋을 쪼갤 생각이면
  `git rm` 시점을 늦추거나 `git reset` 후 다시 나눈다(오늘 한 번 걸렸다).
