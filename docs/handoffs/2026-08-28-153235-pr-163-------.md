### ⚠️ D 항목의 함정 — 그대로 만들면 정반대로 읽힌다

API `scoreDescription` 이 지표마다 방향을 다르게 말한다.

| 지표 | 점수가 높으면 |
| --- | --- |
| 기회도 `OPPORTUNITY_SCORE` · 거주수요 `RESIDENT_POPULATION_SCORE` | **좋다** |
| 위험도 `RISK_SCORE` · 혼잡도 `CONGESTION_SCORE` | **나쁘다** |

점수를 그대로 초록↔빨강에 매핑하면 **「위험도 100(=매우 위험)」이 초록**이 된다.
**색은 점수가 아니라 「좋음/보통/나쁨」에 매핑**하고, 변환은 지표별 방향을 아는 함수가 맡는다.
다만 **호가 채우는 양은 점수 그대로** 둔다 — 호까지 뒤집으면 가운데 숫자와 그림이 어긋난다.

「비어 있는 업종」도 같다. `storeRate` 는 **낮을수록** 좋아서 막대를 그대로 그리면 「짧을수록
좋은 막대」가 되어 게이지와 충돌한다. `100 - storeRate` 를 그린다.

### 내린 결정 (되돌리지 말 것)

- **「목록이 정본, 지도는 가속기」** — 지도 영역 질의가 뷰포트 기반이라 첫 진입에서 자치구
  25개 중 21개만 뱃지가 뜬다(강동·관악·금천·도봉구 없음, 실측). 지도만으로 도달 못 하는
  선택지가 있어서 드롭다운을 지도로 대체하지 않고 조건 바 + 선택 뷰(완전 목록)로 갔다.
- **레이아웃이 아니라 부품을 통일한다** — `/analysis` 는 검증 과업이고 좌측 고정 패널이라
  지도를 안 가린다. `/recommend` 는 패널이 지도 위에 떠 있다. 분석 레이아웃은 그대로 두고
  `OptionPicker` 만 공유했다. **분석을 추천처럼 바꾸는 방향은 검토하고 탈락시켰다.**
- **선택 화면은 같은 패널의 세 번째 뷰**(`'criteria' | 'picker' | 'results'`) — 모바일에서
  이 패널이 곧 바텀시트라 시트 위에 시트를 겹치지 않기 위해서다.
- **행정동이 정해지면 업종 선택 뷰를 자동으로 연다** — 업종만 지도에 없기 때문이다.
  이미 고른 업종이 있으면 열지 않는다(지역만 바꿔 보는 동선을 방해하지 않으려고).
- **서버가 정하는 값은 조건 UI 에 올리지 않는다** — `preset`·`priorityMetric` 은 결과 헤더
  「이 순서를 정한 기준」으로만 노출한다. 사용자가 고른 조건 칩과 같은 모양으로 그리지 않는다.
- **점수 기반 fill 농도를 버리지 않았다** — `resolveAreaPolygonStyle` 의 `baseFillOpacity`
  오버라이드. 공용 레이어로 결과 단계를 통째 교체했다면 순위 정보가 지도에서 사라진다.

### 주의사항

**`.next` 를 지울 때는 서버를 먼저 내린다.** 순서는 **서버 정지 → `rm -rf frontend/.next`
→ 재시작**. 켜진 채로 지우면 Internal Server Error 가 나서 이번 세션에 한 번 당했다.

**`.next` 오염이 가짜 하이드레이션 오류를 만든다.** 같은 워크트리에서 `pnpm qa:verify`
(=`pnpm build`)를 돌리면 프로덕션 산출물이 `dev/` 와 섞이고, `next dev` 에서
**Hydration failed** 가 뜬다. styled-components 클래스 인덱스가 어긋난 것으로 보여 내 변경이
회귀를 냈다고 오독하기 딱 좋다. 위 순서로 지우면 사라진다.

**스타일을 고쳤는데 화면이 안 바뀌면 SSR 이 옛 클래스로 굳은 것이다.** HMR 이 새 스타일을
컴파일해도 SSR 이 이전 클래스명을 내보내면 하이드레이션에서 그대로 굳는다(계측하면 옛 값이
나온다). 서버 재시작이 답이다. **`createGlobalStyle` 은 아예 HMR 로 재주입되지 않는다.**

**DESIGN.md 에 적힌 토큰이 CSS 에 없을 수 있다.** `--color-primary-500` 이 그랬고
(한 곳에서만 쓰이며 늘 하드코딩 폴백으로 칠해지고 있었다), **`--score-high/mid/low` 도
마찬가지다**(D 항목의 첫 단계가 이 토큰 정의인 이유). 문서에 있다고 믿지 말고
`global-styles.ts` 에서 확인한다. 런타임 확인은
`getComputedStyle(document.documentElement).getPropertyValue('--이름')` — 빈 문자열이면 없다.

**`styled.button` 은 `border` 를 선언하지 않으면 UA 기본 `2px outset` 이 나온다.** 전역
리셋은 `font`·`color` 만 다룬다. 저장소의 styled.button 77개 중 76개가 border 를 선언하는
이유다 — `background: transparent` 만 쓰고 끝내면 검은 테두리가 딸려 온다.

**`getComputedStyle` 을 `.focus()` 와 같은 tick 에서 읽으면 거짓말한다.** 스타일 재계산 전
값이 나온다. 툴 호출을 나눠 다음 라운드트립에 다시 잰다. 짝으로, 브라우저 pane 이 숨겨지면
`document.hasFocus()` 가 false 라 `:focus` 자체가 매칭되지 않는다.

**호버로 지도 레이어를 다시 그리지 않는다.** `hoveredAreaCode` 를 레이어 이펙트 의존성에
되돌리면 안 된다. 지역 이름 뱃지가 `<button>` 이라 키보드로 탭해 들어간 순간 포커스가
preview 를 켜고 그 버튼이 파괴되며 **포커스를 잃는다.** 증분 갱신(`stageHighlightsRef`).

**Kakao SDK 계측이 유용하다.** 지도 폴리곤은 canvas 렌더라 DOM 으로 안 읽힌다.
`kakao.maps.Polygon` 생성자와 `prototype.setOptions` 를 감싸면 실제 적용값을 잡을 수 있다.
`kakao.maps.Map` 도 같은 방법으로 감싸 `getLevel()`·`getCenter()` 를 확인했다. 패치 후
클라이언트 라우팅(`<a href>` 클릭)으로 화면을 오가면 SDK 가 유지돼 두 지도를 비교할 수 있다.

**prettier 가 표를 정렬하므로 명세 문서를 문자열 치환으로 고치면 자주 실패한다.** 줄 단위로
편집하거나, 치환 후 반드시 결과를 확인한다. 이번 세션에 두 번 조용히 실패했다.

**알려진 접근성 격차(이 작업이 만든 것 아님)**: 포커스 색 `#0ea5e9` 가 흰 면 대비 2.74:1 로
비텍스트 3:1 미달. `TextField` 와 전역 `:focus-visible` 이 모두 같은 색이라 한 컴포넌트만
바꾸면 체계가 깨진다. DESIGN.md §Primary (Fill) 에 「알려진 격차」로 이미 있다.
