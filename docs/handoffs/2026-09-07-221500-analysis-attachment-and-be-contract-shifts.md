### 내린 결정

- **분석 첨부는 폼 값에 넣지 않는다.** 사용자가 고치는 값이 아니라 초안이 준 값을
  되돌려 보내는 것뿐이라, 페이지가 초안을 들고 있다가 저장 때 싣는다
  (`createCommunityEditorPayload` 셋째 인자). 폼에 넣으면 「편집 가능한 값」으로 읽힌다
- **`analysisType` 변환은 한 곳에만 둔다**(`toAnalysisAttachment`). 초안·상세 응답은
  메타데이터 **객체**인데 작성 요청은 **코드 문자열**이다. 호출부가 객체를 그대로 넘기면
  400 `COMMUNITY_015` 인데, 그 실패는 사용자가 글을 다 쓰고 **저장을 누른 가장 늦은
  순간**에 드러난다
- **수정 요청에는 첨부를 싣지 않는다.** BE 가 분석 컬럼을 부분 갱신에서 빼 두어 보내지
  않으면 보존된다 — **이미지(`imageKeys`)와 정반대 규칙**이다(그쪽은 빼면 파일까지
  지워진다). 타입·주석·테스트 세 곳에 적어 뒀다
- **상세에 링크를 걸지 않았다.** `analysisRefCode` 가 `좌:우:업종:분기` 이어붙인
  문자열인데 그 형식이 계약이 아니라 `@Schema` **예시로만** 적혀 있다. 잘못 갈라 링크를
  만들면 깨진 링크가 된다 — 형식이 계약에 오르면 그때 잇는다
- **배선은 흐름 테스트로 잠근다.** 조각별 단위 테스트로는 배선이 끊긴 것을 못 잡는다
  (실제로 끊겨 있었다). `analysis-attachment-flow.test.ts` 가 초안 → 저장 → 상세를 한
  흐름으로 통과시키고, **배선을 되돌리면 실패하는 것까지 확인**했다

### 주의사항

- **turbopack 스테일 캐시에 이번 세션에만 세 번 걸렸다.** 증상이 매번 다르다 —
  hydration 실패 · 「X is not defined」 · SSR 이 **옛 DOM 구조**를 내보냄.
  판별: `curl localhost:5173` 로 SSR HTML 을 직접 보고 내 변경이 들어 있는지 확인한다.
  해결은 서버 정지 → `.next` 삭제 → 재시작. **콘솔 버퍼도 이전 세션 오류를 계속 들고
  있으니** 판단은 반드시 **새 탭**에서 한다
- **`/analysis`·`/community/register` 는 pane 이 보여야 렌더된다.** 배경 탭에서는
  `body.innerText.length` 가 13~550 으로 SSR 마크업만 남는다. `tabs_create` 는 기본이
  배경이라 반드시 `tabs_select` 로 앞에 낸다. **그래도 도중에 다시 숨겨질 수 있다** —
  오늘 B5 측정이 그렇게 실패했다
- **`dev` 서버를 띄우면 `next-env.d.ts` 가 바뀌고**(`.next/dev/types` 경로)
  **`.claude/launch.json` 이 prettier 검사에 걸린다.** `qa:verify` 전에 둘 다 정리한다
- **PR 은 develop 에서 딴다.** 한 번 기능 브랜치 위에 쌓았다가 다시 잡았다
- **`qa:verify` 가 develop 에서 빨간불일 수 있다.** 오늘 `dabad336`(INFRA)이
  `HANDOFF.md` 표 정렬을 공백 1칸 어긋나게 남겨 게이트가 깨져 있었다. 내 변경이
  통과했다고 말하려면 그런 것도 함께 고쳐야 한다(#240 에 포함, 무관한 변경이라 PR 에 명시)
- **BE PR 리뷰는 읽기만 한다.** 오늘 #235 를 리뷰했는데(테스트도 로컬에서 돌렸다) 코드는
  건드리지 않았다. 제안 하나가 `2ae6a7f1` 로 반영됐다
