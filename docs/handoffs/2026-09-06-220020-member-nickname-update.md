## 다음에 할 일: 닉네임 수정 연결 (A6)

프로필 회원정보 화면이 **「닉네임 변경은 아직 준비 중이에요」**(`profile-edit-page.tsx:315`)를
안내하는데 **백엔드는 살아 있다.** A1(탈퇴)·A2(비밀번호)와 같은 종류 — 사용자가 「없는
기능」으로 겪고 있고 FE 작업만 남았다.

### 백엔드 계약 (실측, 2026-09-06)

```
PATCH /api/v1/members/me      인증 필수
body: { "nickname": "길동짱" }
→ 200 { dataBody: MemberMyInfoResponse }   // GET /members/me 와 같은 타입
```

| 항목          | 값                                                                        |
| ------------- | ------------------------------------------------------------------------- |
| 검증          | `@NotBlank` → `MEMBER_108` · `@Size(max = 10)` → `MEMBER_109`             |
| 응답          | 수정된 회원 정보 전체 — **스토어를 응답으로 바로 갱신할 수 있다**         |
| 프로필 이미지 | 이 API 로 다루지 않는다. 전용 업로드/삭제 API 가 따로 있다(이미 연결됨)   |
| 미확인        | **닉네임 중복 정책.** 회원가입 쪽에만 있는지, 수정에도 걸리는지 확인 필요 |

컨트롤러: `backend/service/auth-service/.../member/adapter/in/web/controller/MemberWebController.java:69`
요청 DTO: 같은 경로 `.../dto/request/MemberMyInfoUpdateRequest.java`

### 어디를 고치나

| 파일                                                         | 할 일                                                         |
| ------------------------------------------------------------ | ------------------------------------------------------------- |

| `src/components/profile/profile-edit-page.tsx`               | 315행의 「준비 중」 안내를 입력 폼으로 교체                   |
| `docs/features/profile/profile.md`                           | S4 표의 「닉네임 수정 — 남았다」 행과 TC P-008 을 완료로 갱신 |
| `docs/superpowers/specs/2026-09-02-be-endpoint-inventory.md` | A 묶음 정정 이력에 완료 기록                                  |

### 따라갈 선례

- **`member-password.ts` + `profile-change-password-page.tsx`(A2)** — 같은 화면군의 쓰기 흐름.
  뮤테이션 성공 시 `clearMemberInfoQuery(queryClient, memberId)` → `hydrate()` 로 회원 정보를
  다시 받아 화면을 다시 가른다. 닉네임은 응답에 새 정보가 실려 오므로 그 값으로 바로 갱신해도 된다
- **`member-profile-image.ts`(A3)** — 같은 화면 안의 쓰기라 피드백 위치·문구를 맞추면 된다
- 검증 문구는 **서버 메시지를 그대로** 쓴다(`getApiMessage`). 10자 제한을 FE 에도 두되
  **서버 규칙을 복제한 것임을 주석에 남긴다** — 규칙이 갈리면 서버만 고쳐도 FE 가 막는다

### 주의

- `/profile/**` 은 미들웨어 보호라 **자동화로 열 수 없다**(`middleware.ts:14`). 화면 실물
  확인은 로그인한 사람이 해야 한다 — 지금까지 A1·A2·A3·기기세션 모두 같은 이유로 사람 눈
  확인이 밀려 있다. 이번에도 PR 본문에 **미검증으로 명시**할 것
- 닉네임은 헤더·프로필 카드 등 **여러 곳에 표시**된다. 수정 후 그 자리들이 함께 바뀌는지
  본다(`useAuthStore` 의 `memberInfo` 를 갱신하면 따라온다)
