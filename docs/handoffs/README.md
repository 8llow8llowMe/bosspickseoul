# 인계 문서 (handoffs)

한 작업 세션의 맥락 — **무엇을 하고 있었나 / 내린 결정 / 남은 작업 / 주의사항** — 을
남겨 다음 세션이나 **다른 기기**에서 이어받기 위한 노트다.

`.claude/skills/` 의 두 스킬이 읽고 쓴다.

| 스킬               | 하는 일                                     |
| ------------------ | ------------------------------------------- |
| `/context-handoff` | 지금 상태를 이 폴더에 새 문서로 저장한다    |
| `/context-resume`  | 가장 최신 문서를 읽어 그 지점부터 이어간다  |

## 왜 `$HOME` 이 아니라 저장소인가

원래 이 문서들은 `~/.claude/handoffs/` 에 쌓였다. 두 가지가 문제였다.

1. **기기를 못 넘는다.** 회사에서 저장한 인계를 집 컴퓨터에서 볼 수 없었다.
2. **워크트리마다 흩어졌다.** 폴더 이름을 `basename $PWD` 로 정해서, 같은 프로젝트의
   인계가 실행한 워크트리에 따라 `nowdoboss`·`bosspick-polygon` 처럼 갈렸다.

저장소에 두면 git 이 둘 다 해결한다. 대신 **커밋해야 따라간다** — 문서만 쓰고 커밋하지
않으면 다른 기기에서 보이지 않는다.

## 규칙

- **커밋되는 문서다.** 자격증명·토큰·개인정보를 적지 않는다.
- **append-only.** 기존 문서를 고치거나 지우지 않는다. 새 상황은 새 문서로 남긴다.
- 파일명은 `{timestamp}-{slug}.md`. **제목은 파일명이 아니라 frontmatter 의 `title:`**
  에서 읽는다 — 한글 제목은 슬러그에서 대부분 지워지므로 파일명만 보면 알 수 없다.
- 문서는 **쓰인 시점의 사실**이다. 브랜치·경로가 그 뒤로 바뀌었을 수 있다. 특히 `/tmp`
  아래 워크트리 경로는 재부팅하면 사라진다.

## 오래된 문서

작업이 끝나 더 볼 일이 없어진 인계는 지워도 된다 — git 이력에 남는다. 다만 **한 세션
안에서는 지우지 않는다**(append-only 규칙).
