## 작업 주제: 상권추천 UX 후속 4건 — 결과 지도·모바일 시트·업종 선택·보고서 시각화

### 요약

`/recommend` 를 저장소 규격으로 통일하고 조건 선택 UX를 재설계하는 작업이 **PR #163 에
전부 올라가 있다(open, base develop)**. 마지막 리뷰에서 나온 7건 중 **5건은 고쳐서
커밋했고**, 나머지는 명세로 남겼다. 이 스레드는 그것들을 구현하는 것이 목적이다.

**정본 명세: `frontend/docs/features/recommend/ux-followups.md`** — 항목 A/B/C/D 로 나뉘고
각각 착수 전 결정할 것이 표로 정리돼 있다. **이 문서를 먼저 읽으면 아래는 요약이다.**

### 작업 환경

- 워크트리 **`/tmp/bosspick-polygon`**, 브랜치 `feature/fe/recommend-polygon-unify`
- dev 서버: `.claude/launch.json` 의 `polygon-5173` (`/bin/sh -c "cd … && exec ./node_modules/.bin/next dev -p 5173"`)
- PR: `gh pr view 163`

### 남은 작업 (우선순위)

1. **B. 결과 지도** — 셋 중 사용자 체감이 가장 크다. 결과 상권 폴리곤이 **하나도 안 그려진다**.
   B-1(경계 조인)이 선행이고, 그게 되면 B-2(결과 0건이면 카메라 유지)·B-3(항목 선택 시 그
   상권 표시)은 작다. 착수 전 **조인 방식 (a)/(b)/(c) 결정 필요** — 명세는 (b) 별도 질의·캐시를
   권장한다(패닝 시 폴리곤이 깜빡이지 않음).
2. **C. 모바일 바텀시트 통일** — `analysis-sheet-state.ts` 를 `lib/map/bottom-sheet-state.ts` 로
   승격하고 추천이 쓰게 한다. collapsed 를 44px → **72px**. 착수 전 **추천의 「최소 지도 높이
   보장」 로직을 살릴지 결정 필요**(분석에는 없는 로직인데 지도가 주인공이라 근거는 있다).
3. **A. 업종 선택 UX** — 착수 전 결정이 3개(인기 업종 출처·아이콘 범위·선택 어포던스)라
   사용자 확인이 가장 많이 필요하다. `ChevronRight` 제거만이라도 먼저 해도 된다.
   **주의: 리뷰의 「버튼 ui 이상해」는 업종 목록이 아니라 조건 바 조각의 테두리를 가리킨
   것이었고, 그건 `8fa971df` 에서 이미 고쳤다**(styled.button 이 border 를 선언하지 않아
   UA 기본 2px outset 이 새어 나왔다). A 에 남은 것은 「찾기 어렵다」와 `ChevronRight` 다.
4. **D. 추천 보고서 시각화** — 점수를 작은 도넛 게이지로, 「이 상권에 비어 있는 업종」을
   막대 + 업종 아이콘으로. **B 와 같은 화면이라 함께 하면 효율적이다.**
   **착수 전 반드시 D-1 을 읽을 것** — 지표마다 점수 방향이 반대라(위험도·혼잡도는 높을수록
   나쁘다) 점수를 그대로 초록↔빨강에 매핑하면 「위험도 100」이 초록이 된다. 그리고
   `--score-high/mid/low` 토큰이 DESIGN.md 에만 있고 CSS 에는 없다(D-2) — 정의가 먼저다.
5. 위 작업 후 `pnpm test` + `pnpm qa:verify` 통과시키고 PR #163 에 push. PR 본문의
   「후속」 섹션 갱신.

### 내린 결정 (이번 세션, 되돌리지 말 것)

- **「목록이 정본, 지도는 가속기」** — 지도 영역 질의가 뷰포트 기반이라 첫 진입에서 자치구
  25개 중 21개만 뱃지가 뜬다(강동·관악·금천·도봉구 없음, 실측). **지도만으로는 도달 못 하는
  선택지가 있어서** 드롭다운을 지도로 대체하지 않고 조건 바 + 선택 뷰(완전 목록)로 갔다.
- **레이아웃이 아니라 부품을 통일한다** — `/analysis` 는 검증 과업이라 조건이 늘 보여야 하고
  좌측 고정 패널이라 지도를 안 가린다. `/recommend` 는 패널이 지도 위에 떠 있다. 그래서
  분석의 레이아웃은 그대로 두고 `OptionPicker` 만 공유했다. **분석 레이아웃을 추천처럼
  바꾸자는 방향은 이미 검토하고 탈락시켰다.**
- **선택 화면은 같은 패널의 세 번째 뷰**(`RecommendationView = 'criteria' | 'picker' | 'results'`)
  — 모바일에서 이 패널이 곧 바텀시트라 시트 위에 시트를 겹치지 않기 위해서다.
- **추천 기준(preset·priorityMetric)은 서버가 정한다** — 사용자가 고르는 값이 아니므로 조건
  바에 올리지 않고 결과 헤더 「이 순서를 정한 기준」으로 노출했다. 조건 바는 3조각 한 줄 유지.
- **점수 기반 fill 농도를 버리지 않았다** — `resolveAreaPolygonStyle` 에 `baseFillOpacity`
  오버라이드를 냈다. 공용 레이어로 결과 단계를 통째 교체했다면 순위 정보가 지도에서 사라진다.

### 주의사항

**`.next` 오염이 가짜 하이드레이션 오류를 만든다.** 같은 워크트리에서 `pnpm qa:verify`
(=`pnpm build`)를 돌리면 `.next/` 에 프로덕션 산출물이 `dev/` 와 섞이고, 그 상태로
`next dev` 를 띄우면 `/recommend` 에서 **Hydration failed** 가 뜬다. styled-components 클래스
인덱스가 어긋난 것으로 보여 내 변경이 회귀를 냈다고 오독하기 딱 좋다. **`rm -rf frontend/.next`
후 dev 서버 재시작하면 사라진다.** 이번 세션에서 여기에 시간을 꽤 썼다.

**`getComputedStyle` 을 `.focus()` 와 같은 tick 에서 읽으면 거짓말한다.** 스타일 재계산 전
값이 나와서 `:focus` 규칙이 안 먹는 것처럼 보인다. 툴 호출을 나눠 다음 라운드트립에 다시 잰다.
짝으로, 브라우저 pane 이 숨겨지면 `document.hasFocus()` 가 false 라 `:focus` 자체가 매칭되지
않는다 — 계측 전에 확인하고, false 면 실제 클릭으로 창 포커스를 준다.

**`createGlobalStyle` 은 HMR 로 재주입되지 않는다.** `.area-map-label` 처럼 전역에 둔 규칙을
고치면 dev 서버를 재시작해야 반영된다.

**호버로 지도 레이어를 다시 그리지 않는다.** `hoveredAreaCode` 를 레이어 이펙트 의존성에
되돌리면 안 된다. 지역 이름 뱃지가 `<button>` 이라, 키보드로 탭해 들어간 순간 포커스가
preview 를 켜고 그 버튼이 파괴되며 **포커스를 잃는다.** 증분 갱신(`stageHighlightsRef`)으로
옮겨 뒀다.

**`styled.button` 은 `border` 를 선언하지 않으면 UA 기본 `2px outset` 이 나온다.** 전역
리셋(`global-styles.ts`)은 `font`·`color` 만 다룬다. 저장소의 styled.button 77개 중 76개가
border 를 선언하는 이유다 — 새 버튼을 만들 때 `background: transparent` 만 쓰고 끝내면
검은 테두리가 딸려 온다.

**Kakao SDK 계측이 유용하다.** 지도 폴리곤은 canvas 렌더라 DOM 으로 안 읽힌다.
`kakao.maps.Polygon` 생성자와 `prototype.setOptions` 를 감싸면 실제 적용값을 잡을 수 있다.
`kakao.maps.Map` 도 같은 방법으로 감싸 `getLevel()`·`getCenter()` 를 확인했다. 패치 후
클라이언트 라우팅(`<a href>` 클릭)으로 화면을 오가면 SDK 가 유지돼 두 지도를 비교할 수 있다.

**DESIGN.md 에 적힌 토큰이 CSS 에 없을 수 있다.** `--color-primary-500` 이 그랬고
(`recommend-map.tsx` 한 곳에서만 쓰이며 늘 하드코딩 폴백으로 칠해지고 있었다),
`--score-high/mid/low` 도 마찬가지다. **문서에 있다고 실재한다고 믿지 말고
`global-styles.ts` 에서 확인한다.** 런타임에서는
`getComputedStyle(document.documentElement).getPropertyValue('--이름')` 이 빈 문자열이면 없는 것이다.

**알려진 접근성 격차(이 작업이 만든 것 아님)**: 포커스 색 `#0ea5e9` 가 흰 면 대비 2.74:1 로
비텍스트 3:1 미달. `TextField` 와 전역 `:focus-visible` 이 모두 같은 색이라 한 컴포넌트만
바꾸면 체계가 깨진다. DESIGN.md §Primary (Fill) 에 「알려진 격차」로 이미 있다.

**더 큰 후속 2건**(이번 3건과 별개, condition-selector D8):
- `/recommend` URL 상태 없음 → 화면 보관함 미지원의 원인이자 딥링크의 선행 조건
- 분석 ↔ 추천 딥링크 — **주 동선은 추천→분석**이다. `/analysis` 가 이미 선택 전체를 URL 로
  읽으므로 그쪽이 링크 한 줄로 되고, 추천 결과를 본 사용자의 다음 질문이 "1위 이 상권 자세히"라
  깔때기 방향도 그쪽이다. B 작업과 URL 상태를 함께 하면 결과 화면이 새로고침·공유에서 복원된다.
