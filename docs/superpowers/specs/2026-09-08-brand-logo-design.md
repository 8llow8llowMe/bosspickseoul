# BossPickSeoul 브랜드 로고 설계

- 상태: 사용자 설계 확정
- 작성일: 2026-09-08
- 대상: BossPickSeoul 프론트엔드 브랜드 자산
- 기준 브랜치: `develop`

## 1. 배경

현재 저장소에는 로고 자산이 존재하지 않는다.

- 헤더는 `BossPickSeoul` 텍스트를 그대로 렌더링한다. `frontend/src/components/layout/site-header.tsx:502`, 스타일은 같은 파일 57행의 `Brand`(19px / 700 / `min-height: 40px` / `line-height: 28px`).
- 푸터도 동일하게 텍스트만 렌더링한다. `frontend/src/components/layout/site-footer.tsx:43`의 `Title`(15px / 600).
- `frontend/public/`에 `favicon`, `icon.svg`, `apple-icon` 이 모두 없다.
- `frontend/DESIGN.md`는 프론트맷터가 `brand: Toss`이며, "Brand (Logo/Marketing Only)" 섹션이 `#0064FF`(토스 공식 Pantone 2175 C)와 `#202632`(Pantone 433 C)를 브랜드 컬러로 서술한다.

이번 작업은 BossPickSeoul 자체 로고를 정의하고, DESIGN.md의 타사 브랜드 컬러 서술을 자체 값으로 교체한다.

### 작업 중 확인된 저장소 사실

설계 근거가 되므로 함께 기록한다.

- **DESIGN.md가 서술한 primary 서체는 실제로 로드되지 않는다.** `frontend/public/fonts/`에는 Pretendard 9종만 있고 Toss Product Sans 파일이 없다. `frontend/src/lib/fonts.ts`는 Pretendard를 `next/font/local`로 로드하고 Toss Product Sans는 `fallback` 배열에 이름만 나열한다. 따라서 **실제 렌더 서체는 Pretendard**이며, 워드마크는 Pretendard 기준으로 설계한다.
- 사용 가능한 Pretendard 무게는 400 / 500 / 600 / 700 이다.

## 4. 정체성 근거

| 재료 | 내용 |
| --- | --- |
| 이름 | **Boss**(사장) + **Pick**(고른다) + **Seoul**(서울) |
| 하는 일 | 서울 상권 데이터로 "어디서, 무슨 업종으로 창업할지" 판단을 돕는다 |
| 고유 구조 | 자치구 → 행정동 → 상권 → 업종 4단계 좁혀가기 |
| 핵심 동작 | 비교(A vs B), 복합 지표 히트맵, Top N 랭킹 |
| 톤 | 차분·낙관·절제. DESIGN.md 원칙 5 "절제가 신뢰를 전달한다" |

심볼은 **B 이니셜을 모듈 격자로 재구성**한다. 격자는 이 서비스의 실제 구조(히트맵, 격자형 지표, 4단계 좁혀가기)와 연결되는 유일한 형태이고, 격자 한 칸을 강조색으로 채워 **"여러 칸 중 하나를 골랐다"**는 Pick 의미를 형태에 담는다.

## 5. 마스터 심볼

### 5.1 기하

- 격자: **4열 × 7행**
- `viewBox="0 0 19 34"`
- 모듈 `4 × 4`, 갭 `1`, pitch `5` (갭 비율 20%)
- 모듈 모서리 **각짐(`rx=0`)**
- 비례 19:34 = 0.559

셀 좌표는 `x = 열 × 5`, `y = 행 × 5`.

### 5.2 셀 배정

```
열      0  1  2  3
행 0    ■  ■  ■  ·
행 1    ■  □  □  ■
행 2    ■  □  □  ■
행 3    ■  ■  ■  ·
행 4    ■  □  □  ■
행 5    ■  □  ●  ■
행 6    ■  ■  ■  ·

■ 본체 (17칸)   □ 고스트 (7칸)   ● 강조 (1칸)   · 반드시 비움 (3칸)
```

- **본체 17칸**: `(0,0) (5,0) (10,0) (0,5) (15,5) (0,10) (15,10) (0,15) (5,15) (10,15) (0,20) (15,20) (0,25) (15,25) (0,30) (5,30) (10,30)`
- **고스트 7칸**: `(5,5) (10,5) (5,10) (10,10) (5,20) (10,20) (5,25)`
- **강조 1칸**: `(10,25)` — 아래 카운터의 우하단
- **반드시 비우는 3칸**: `(15,0) (15,15) (15,30)` — 3열의 노치

### 5.3 고스트 칸 규칙 (중요)

고스트는 **카운터에만** 넣는다. 카운터는 위 4칸 + 아래 4칸 = 8칸이고, 그중 강조 1칸을 제외한 **7칸이 고스트**다. 3열의 노치 3칸(`(15,0) (15,15) (15,30)`)은 **반드시 투명하게 비운다.**

빈 칸 전부에 고스트를 채우면 실루엣이 4×7 사각형이 되어 B 판독성이 크게 떨어진다. B를 B로 만드는 것은 그 노치다. 브라우저 실측으로 확인해 기각한 구성이다.

### 5.4 강조 칸 위치 근거

아래 카운터 2×2의 네 칸 중 **우하단**을 쓴다.

- 좌측 두 칸은 스템에 접해 강조 칸이 글자 획의 일부로 오독된다.
- 우상단은 무게중심이 위로 떠 불안하다.
- 우하단은 무게가 아래로 앉고, "B의 아래 볼이 위 볼보다 무거워야 한다"는 활자 원칙과 맞는다.

카운터가 2×2 = 4칸인 것이 4×7 격자를 택한 핵심 이유다. 3×5(카운터 1칸)와 4×5(카운터 2칸)에서는 강조색이 "고른 칸"이 아니라 단순 장식으로 읽힌다.

## 6. 브랜드 컬러

| 역할 | 값 | 용도 |
| --- | --- | --- |
| Brand Ink | `#191F28` | 심볼 본체, 워드마크. `grey900`과 동일 값 |
| Brand Accent | `#00795C` | 강조 칸 전용 |
| Brand Ghost | `#EDF0F3` | 고스트 칸 전용 |
| 다크 배경용 본체 | `#FFFFFF` | 어두운 배경에서 본체와 워드마크 |

### 6.1 대비 근거

강조 칸은 이웃한 본체(`#191F28`)와 고스트(`#EDF0F3`) **양쪽 모두와** 구분되어야 한다. 어두우면 본체에 흡수되고 밝으면 고스트에 흡수된다.

| 후보 | 본체 대비 | 고스트 대비 | 판정 |
| --- | --- | --- | --- |
| 잉크 그린 `#00795C` | 3.07 | 4.72 | **채택** |
| 주홍 `#E8461E` | 4.20 | 3.45 | 차선 |
| 딥 코발트 `#1B3FD8` | 2.17 | 6.66 | 기각 |

파랑 계열은 구조적으로 부적합하다. 본체 대비를 확보할 만큼 밝히면(`#2E5BFF` 수준, 대비 3.20) 토스 파랑 `#0064FF`와 색상값이 거의 같아지고, 어둡게 두면 본체에 흡수된다.

### 6.2 사용 규약

- **`#00795C`는 로고 전용이다. UI 어디에도 사용하지 않는다.** `green500`(`#03b26c`)과 계열이 같아, UI에 풀면 성공/상승 시맨틱과 혼동된다. 명도가 크게 달라 로고 안에서는 구분되지만 이 분리는 규약으로만 유지된다.
- DESIGN.md 원칙 4("파랑은 인터랙션이지 장식이 아니다")를 보존하기 위해 로고는 `blue500`을 쓰지 않는다.
- 타사 브랜드 컬러(`#0064FF`, `#202632`)는 DESIGN.md에서 제거한다.

## 7. 크기별 변형

브라우저 1배율(DPR 1) 실측으로 임계점을 확인했다.

| 변형 | 사용 크기 | 구성 | viewBox |
| --- | --- | --- | --- |
| **Primary** | 48px 이상 | 격자 + 고스트 7칸 | `0 0 19 34` |
| **Grid** | 34 ~ 47px | 격자, 고스트 제거 | `0 0 19 34` |
| **Solid** | 33px 이하 | 갭 제거, 모듈 `4×4` 인접 | `0 0 16 28` |

### 7.1 임계점 근거

- **34px**: 갭이 1px로 렌더되어 또렷하다. 격자 사용 하한.
- **27px**: 갭 0.79px. 읽히지만 흐리다.
- **20px**: 갭 0.59px. B가 부슬부슬 깨진다. 격자 사용 불가.

### 7.2 Solid 변형 셀 배정

`viewBox="0 0 16 28"`, `x = 열 × 4`, `y = 행 × 4`, 모듈 `4 × 4`, 갭 없음. 카운터와 노치는 투명하게 비운다(고스트 없음).

- 본체 17칸: `(0,0) (4,0) (8,0) (0,4) (12,4) (0,8) (12,8) (0,12) (4,12) (8,12) (0,16) (12,16) (0,20) (12,20) (0,24) (4,24) (8,24)`
- 강조 1칸: `(8,20)`

Solid 변형의 비례는 16:28 = 0.571로, 격자 변형(0.559)과 미세하게 다르다. 두 변형이 같은 화면에 동시에 놓이는 경우는 없으므로 이 차이는 허용한다.

**알려진 한계**: 16px에서 강조 칸은 약 2.3px로 렌더된다. DPR 1에서는 미세한 점으로 보이고, DPR 2에서는 약 4.6px로 충분하다. 16px·DPR 1 환경에서 강조색이 사실상 보이지 않는 것을 수용한다.

## 8. 컨테이너 (앱아이콘 · 헤더 락업)

4×7 격자는 비례가 0.559라 텍스트 높이에 맞추면 폭 15px의 조각이 되고, 넓은 워드마크 옆에서 장식 불릿처럼 보인다. 브라우저 실측으로 확인했다. 정사각 컨테이너가 이 문제를 해결한다.

- 형태: 정사각, `border-radius = 변 길이 × 0.25`
- 배경: Brand Ink `#191F28`
- 내부 심볼: 흰색(`#FFFFFF`), 강조 칸은 `#00795C` 유지
- 심볼 높이 = `변 길이 × 0.625`
- 심볼 폭은 높이에서 파생한다. 격자 변형은 `높이 × 19 / 34`, Solid 변형은 `높이 × 16 / 28`

| 컨테이너 | radius | 심볼 높이 | 심볼 변형 |
| --- | --- | --- | --- |
| 32px (헤더) | 8 | 20 | **Solid** |
| 64px | 16 | 40 | Grid |
| 180px (apple-icon) | 45 | 112 | Primary |

180px의 심볼 높이는 `180 × 0.625 = 112.5`이며 정수로 내려 112를 쓴다.

헤더 컨테이너가 Solid를 쓰는 이유: 32px 컨테이너의 심볼 높이는 20px이고, 그 크기에서 격자 갭은 0.59px로 무너진다(7.1). 격자를 살리려면 심볼이 34px 이상이어야 하고 컨테이너가 46px가 되는데, 헤더 `min-height: 40px`에 들어가지 않는다.

컨테이너 반전 변형: 어두운 배경에서는 배경 `#FFFFFF` + 심볼 `#191F28`로 반전한다.

## 9. 워드마크

- 서체: **Pretendard** (실제 로드 서체, 1절 참조)
- 조판: `BossPick` **700** + `Seoul` **400** — 한 덩어리
- 크기: 19px / `line-height: 28px` / `letter-spacing: -0.01em`
- 색: `#191F28` (어두운 배경에서 `#FFFFFF`)

무게 분리 근거: 13자를 전부 700으로 두면 헤더에서 한 덩어리로 뭉쳐 읽기 어렵다. 무게 분리는 이름의 의미 구조(브랜드 + 지역)와도 일치한다. 브라우저 실측으로 전체 700 대비 우월함을 확인했다.

`Seoul`을 `grey700`으로 낮추는 변형도 검토했으나, 색 분리와 무게 분리를 겹치면 과하다. **무게 분리만 사용한다.**

## 10. 락업

### 10.1 가로형 (기본)

```
[컨테이너 32] ─8px─ BossPickSeoul
```

- 컨테이너 32px + 간격 8px + 워드마크 19px
- 수직 중앙 정렬
- 간격 = 컨테이너 변 길이 × 0.25

### 10.2 세로형

- 컨테이너 또는 Primary 심볼 위, 워드마크 아래
- 간격 = 심볼 높이 × 0.25
- 수평 중앙 정렬

### 10.3 최소 여백

락업 사방으로 **컨테이너 변 길이의 25%** 이상(32px 컨테이너 기준 8px)을 비운다.

### 10.4 심볼 단독 사용

컨테이너 없이 심볼만 쓰는 경우는 34px 이상에서만 허용한다. 그 이하에서는 컨테이너 + Solid를 쓴다.

## 12. 검증 기준

- Primary / Grid / Solid 세 변형이 각각의 사용 크기에서 B로 읽힌다.

- 헤더 락업이 `min-height: 40px` 안에 들어가고 내비게이션과 충돌하지 않는다.

- 어두운 배경에서 반전 변형이 정상 동작한다.
- 강조색 `#00795C`가 UI 코드 어디에도 등장하지 않는다.
- DESIGN.md에 `#0064FF`와 `#202632`가 남아 있지 않다.

| 각진 모듈과 UI 톤 | UI는 라운드 계열, 로고는 각짐 | 컨테이너 radius 25%가 완충 역할을 한다 |

## 14. 결정 기록

| 결정 | 대안 | 근거 |
| --- | --- | --- |
| B 이니셜 모듈 격자 | 원+수직선 / 직선+45도 / 핀+격자 / 한강 곡선 | 사용자 선택. 격자가 서비스 구조와 연결되는 유일한 형태 |
| 4열 7행 | 3×5 / 4×5 / 5×7 | 카운터가 2×2 = 4칸이라 "여러 칸 중 하나" 의미가 성립. 비례 0.559로 B에 정확 |
| 각진 모듈 | `rx=2` 라운드 / 원형 | 헤더 크기에서 `rx=2`는 0.7px로 사라져 큰 크기에서만 보이는 장식이 된다. 원형은 대각선 간격이 열려 B가 무너진다 |
| 고스트는 카운터만 | 빈 칸 전부 | 노치를 메우면 실루엣이 사각형이 되어 B가 약해진다. 실측 확인 |
| 강조 칸 우하단 | 좌상 / 우상 / 좌하 | 좌측은 스템에 붙어 획으로 오독. 우하단이 무게중심이 안정적 |
| 잉크 그린 `#00795C` | 주홍 `#E8461E` / 딥 코발트 `#1B3FD8` | 사용자 선택. 파랑은 대비-유사성 딜레마로 구조적 탈락 |
| 정사각 컨테이너 | 심볼 단독 | 심볼 비례 0.559가 락업에서 얇은 조각으로 보인다. 실측 확인 |
