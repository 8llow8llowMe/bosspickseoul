사용자 수와 신뢰에 가장 크게 걸리는 순서입니다. 오른쪽 수치는 코드·실화면에서 잰 값이고, 결과 지표 추정은 결과 지표 가설에 따로 적었습니다.

요약 「월 매출」을 업종 전체 합계로 밝히고, 점포당 월 매출을 첫 숫자로 올린다

홍대 걷고싶은 거리 커피-음료가 「월 매출 26억 3527만원」으로 보입니다. 이 값은 점포 59곳의 합계이고, 한 곳당으로는 약 4,467만원입니다. 사장님이 한 가게 매출로 읽으면 서비스 전체를 믿지 못하게 됩니다.

오독 위험 숫자 1 → 0

상권분석에 「상권·역·동 이름 검색」을 넣는다

지금은 자치구→행정동→상권→업종 네 단계를 지도에서 차례로 눌러야 합니다. 「망원시장」처럼 이름만 아는 사용자가 가장 많습니다.

탭 6 → 3

「어디가 좋을지 모르겠다면」 추천에서 행정동 필수를 푼다

홈의 약속과 달리 추천은 자치구와 행정동까지 골라야 열립니다. 업종만 정한 사용자가 서울 전체나 자치구 단위로 추천을 받을 수 있어야 합니다(BE 협의 필요).

필수 입력 3 → 1

분석 → 추천 → 시뮬레이션을 링크로 잇는다

추천 카드에서 「창업 비용 계산」으로 바로 가고, 시뮬레이션 비교의 B는 A를 복사해 시작합니다.

탭 8 → 4 · 12 → 3

404·오류 화면을 만든다

dev에서 없는 주소로 들어가면 영문 「404: This page could not be found.」만 뜨고 헤더도 홈 링크도 없습니다.

탈출 경로 0 → 2

시뮬레이션 결과 카드에 「권리금은 포함하지 않았어요」를 적는다

대부분은 카드에서 멈추고 상세 리포트까지 가지 않습니다. 수천만 원이 빠진 금액을 실제 필요 자금으로 받아들입니다.

로그인·가입에서 카카오를 맨 위에, 카카오 규격 노란 버튼으로 둔다

지금은 흰 버튼이 이메일 폼 아래에 있어 375px 화면에서 스크롤해야 보입니다.

진단 방법

진단 방법과 제외 범위

실화면 점검. dev 사이트에서 홈 → 상권분석(마포구 → 서교동 → 홍대 걷고싶은 거리 → 커피-음료) → 결과, 상권추천, 시뮬레이션, 구별현황, 커뮤니티, 로그인을 800px와 375px에서 직접 따라갔습니다. 비로그인 상태입니다.

데스크톱 실측. 같은 경로를 헤드리스 Chromium 1440×900으로 다시 돌고, 색·크기를 브라우저 계산값으로 읽었습니다. 결과는 데스크톱 점검에 따로 모았습니다.

코드 리뷰. 홈·셸·인증, 상권분석·구별현황, 추천·시뮬레이션, 커뮤니티·프로필·공용 UI 네 영역을 나눠 읽었습니다. 모든 발견 사항에 파일과 줄 번호를 붙였고, 핵심 주장(월 매출 라벨, 시트 기본 접힘, 비교 B 빈 편집기, 북마크 코드 노출, 404 기본 화면, 비활성 안내 문구)은 다시 코드로 대조했습니다.

수치의 종류. 표마다 근거를 세 가지로 구분합니다. 실측은 dev 화면이나 HTTP 응답에서 확인한 값, 코드 계산은 CSS·로직에서 계산한 값, 추정은 공개 연구를 근거로 한 기대 범위입니다. 추정치는 계측과 A/B로 확인하기 전까지 목표값으로만 씁니다.
