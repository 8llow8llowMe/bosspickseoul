# Frontend Design Guide

## 1. 디자인 방향

NowDoBoss 프론트엔드는 다음 인상을 유지해야 한다.

- 신뢰감 있는 상권/데이터 제품
- 과도하게 장식적이지 않은 블루 중심 UI
- 정보량이 많아도 구조가 명확한 카드형 레이아웃
- 모바일에서도 흐름이 끊기지 않는 실용성

핵심 키워드:

- `Trustworthy`
- `Data-first`
- `Clear hierarchy`
- `Calm blue accents`

## 2. 브랜드 톤

- 기본 배경은 화이트 기반으로 간다.
- 강조 색은 네이비와 블루를 사용한다.
- 서브 배경은 매우 옅은 블루 톤을 사용한다.
- 경고나 에러를 제외하고 채도가 높은 색을 남발하지 않는다.
- 퍼플 계열, 네온 계열, 과한 글래스모피즘은 사용하지 않는다.

## 3. 기본 토큰

초기 기준 토큰은 아래 값을 우선 사용한다.

```css
:root {
  --color-primary-700: #1549b5;
  --color-primary-600: #336dd3;
  --color-primary-100: #f0f5ff;
  --color-text-900: #191f28;
  --color-text-700: #333333;
  --color-text-500: #606d85;
  --color-border-300: #c4c4c4;
  --color-border-200: #dde3ea;
  --color-surface: #ffffff;
  --color-surface-muted: #f8fafc;
  --color-success: #1f9d55;
  --color-warning: #d9822b;
  --color-danger: #d14343;
}
```

레거시에서 확인된 대표 색상은 `#1549B5`, `#336DD3`, `#191F28`, `#606D85`, `#F0F5FF`, `#C4C4C4`다. 새 작업은 이 계열에서 파생한다.

## 4. 타이포그래피

- 기본 폰트는 `Pretendard`로 통일한다.
- Next.js에서는 `next/font/local`을 사용해 로컬 폰트를 주입한다.
- 제목은 강한 계층을 주되, 과도한 폰트 혼합은 금지한다.

권장 계층:

- Display: `40/48`, `700`
- H1: `32/42`, `700`
- H2: `28/38`, `700`
- H3: `24/34`, `700`
- Body Large: `18/30`, `600`
- Body: `16/26`, `400` 또는 `500`
- Caption: `14/22`, `400` 또는 `500`

규칙:

- 한 화면에서 제목 크기 체계는 3단계 이내로 제한한다.
- 본문 색은 기본적으로 `--color-text-500` 또는 `--color-text-900`만 사용한다.

## 5. 레이아웃

- 데스크톱 기본 콘텐츠 폭은 `1200px` 또는 `1280px` 기준으로 잡는다.
- 전체 페이지 좌우 여백은 `24px` 이상을 유지한다.
- 카드/섹션 사이 간격은 `24px`, `32px`, `40px` 스케일 안에서 정리한다.
- 헤더는 고정형을 유지하되, 레이아웃별 높이와 배경 전환 규칙을 일관되게 관리한다.

권장 간격 스케일:

- `4, 8, 12, 16, 20, 24, 32, 40, 48, 64`

## 6. 반응형 기준

새 코드의 기준 breakpoint는 아래를 우선 사용한다.

- `640px`
- `768px`
- `1024px`
- `1280px`

예외 규칙:

- 레거시 레이아웃을 그대로 맞춰야 하는 구간은 임시로 기존 breakpoint를 허용한다.
- 단, 같은 화면 안에서 breakpoint 숫자를 무분별하게 늘리지 않는다.

## 7. 표면과 카드

- 카드 기본 배경은 흰색
- 카드 radius는 `16px` 또는 `20px`
- 카드 shadow는 부드럽고 얕게 유지
- 정보 묶음이 많을 때는 border + 약한 shadow 조합을 우선 사용

권장 shadow:

- 기본 카드: `0 10px 30px rgba(21, 73, 181, 0.08)`
- hover 카드: `0 14px 36px rgba(21, 73, 181, 0.12)`

## 8. 버튼

버튼은 3종으로 제한한다.

### Primary

- 배경: `--color-primary-700`
- 텍스트: white
- 용도: 저장, 실행, 다음 단계, 로그인

### Secondary

- 배경: white
- 테두리: `--color-primary-700`
- 텍스트: `--color-primary-700`
- 용도: 보조 액션, 비교, 상세보기

### Ghost/Text

- 배경 없음
- 텍스트: `--color-text-700` 또는 `--color-primary-700`
- 용도: 필터, 닫기, 서브 내비게이션

버튼 규칙:

- radius는 `12px` 또는 `14px`
- 높이는 `40`, `44`, `48` 중 하나로 통일
- 아이콘 간격은 `8px`

## 9. 입력 컴포넌트

- 입력 높이는 `44px` 또는 `48px`
- 기본 border는 `--color-border-200`
- focus 시 `--color-primary-600`으로 강조
- placeholder는 지나치게 밝지 않게 설정
- 에러 상태는 빨간색 border + 하단 메시지 조합으로 통일

## 10. 탭, 사이드바, 네비게이션

- 활성 상태는 블루 underline 또는 블루 텍스트로 표현한다.
- 활성/비활성 차이를 색상과 두께로 동시에 준다.
- 모바일에서는 가로 탭이 길어질 경우 스크롤 가능한 탭 바를 허용한다.

## 11. 차트와 데이터 표현

- 차트는 장식보다 해석 가능성을 우선한다.
- 한 차트 안에서 강조 색은 1개, 보조 색은 2개 이내로 제한한다.
- grid, axis, legend는 과도하게 진하지 않게 유지한다.
- 요약 숫자 카드는 차트보다 먼저 읽히도록 배치한다.

## 12. 지도와 공간 정보 화면

- 지도는 화면의 주인공이지만, 컨트롤 패널이 기능을 방해하면 안 된다.
- 필터 박스, 요약 카드, floating action은 동일한 radius와 shadow 체계를 공유한다.
- 지도 위 오버레이는 텍스트 대비를 충분히 확보한다.

## 13. 모션

- 모션은 의미가 있을 때만 사용한다.
- 기본 duration은 `180ms` 또는 `240ms`
- 페이지 등장, 카드 reveal, hover lift 정도만 허용한다.
- 무한 애니메이션은 주목도 높은 hero 구간 외에는 제한한다.

## 14. 접근성

- 텍스트 대비는 WCAG AA 이상을 목표로 한다.
- hover만으로 정보가 드러나는 인터랙션은 피한다.
- 버튼, 링크, 입력은 키보드 포커스 스타일을 가진다.
- 아이콘 버튼에는 `aria-label`을 명시한다.

## 15. 구현 규칙

- 새 화면은 반드시 공통 토큰 파일에서 색상, spacing, radius를 가져다 쓴다.
- 디자인 예외가 필요하면 해당 화면 안에서 임시 상수를 만들지 말고 토큰에 추가할지 먼저 검토한다.
- 공통 컴포넌트 후보는 화면 파일에 중복 정의하지 않고 `src/components`로 올린다.

## 16. 피해야 할 것

- 화면마다 다른 블루 색상
- 화면마다 다른 border-radius
- 과한 blur, glass, neon 효과
- 섹션마다 다른 그림자 스타일
- 모바일에서 지나치게 작은 탭/버튼 터치 영역
- 레거시 톤과 무관한 새 브랜드 재해석
