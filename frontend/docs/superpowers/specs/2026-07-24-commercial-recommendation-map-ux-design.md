# 상권 추천 지도 UX 마이그레이션 설계

## 배경

기존 NowDoBoss의 상권 추천은 왼쪽 조건 패널과 전체 Kakao Map을 결합하고,
줌 레벨에 따라 자치구·행정동·상권 폴리곤을 전환했다. 이 방식은 위치 맥락을
직관적으로 보여주지만, 지도 줌이 선택 단계와 추천 범위까지 암묵적으로 바꿔
사용자가 현재 기준을 예측하기 어려웠다.

BossPickSeoul의 현재 `/recommend`는 레거시 `/recommendation/...` 계약을
호출하며 지도 없이 카드 중심으로 구성되어 있다. dev Swagger에는 지역·지도
좌표와 업종별 추천 API가 별도 계약으로 제공되므로, 백엔드를 변경하지 않고
새 계약에 맞춘 지도형 추천 화면으로 마이그레이션한다.

## 결정 사항

- 추천 범위는 사용자가 선택한 **한 행정동 안으로 고정**한다.
- 지도 이동과 확대·축소는 추천 결과를 다시 계산하지 않는다.
- 지도 이동이 끝나면 현재 화면 bounds로 해당 depth의 폴리곤만 다시 조회한다.
- 왼쪽의 단일 패널이 `조건 선택`에서 `Top 5 결과`로 전환된다.
- 지도는 선택 범위와 추천 결과를 설명하고 비교하는 보조 인터페이스다.
- 데스크톱은 왼쪽 패널과 전체 지도, 모바일은 전체 지도와 바텀시트를 사용한다.
- 추천 페이지에서는 데스크톱과 모바일 모두 사이트 푸터를 표시하지 않는다.
- 추천 조건은 자치구·행정동·업종으로 유지하고 상권 셀렉트박스는 추가하지
  않는다.
- 레거시의 줌 레벨 기반 depth 전환은 이식하지 않는다.

## 목표

- 자치구 → 행정동 → 업종 → 행정동 내 상권 Top 5 흐름을 제공한다.
- 패널 선택과 지도 폴리곤 선택을 같은 상태로 연결한다.
- 추천 점수와 이유를 목록 및 지도에서 빠르게 비교할 수 있게 한다.
- 비로그인 사용자도 추천 결과를 조회할 수 있게 한다.
- 지도 SDK나 개별 좌표 요청이 실패해도 조건 선택과 결과 목록은 사용할 수
  있게 한다.
- `/status`에서 검증한 선택 강조, 모션, 모바일 바텀시트 언어를 재사용한다.

## 범위 밖

- 백엔드 API, 응답 모델 또는 데이터 적재 변경
- 현재 지도 뷰포트를 기준으로 추천 결과를 자동 갱신하는 탐색 모드
- 추천 프리셋이나 지표 가중치를 사용자가 직접 조정하는 기능
- 두 상권 비교, AI 리포트 생성, 창업 시뮬레이션 자동 연결
- Kakao Map 이외의 지도 SDK 도입
- 지도·React 관련 신규 패키지 설치

## 정보 구조

### 조건 모드

왼쪽 패널은 다음 세 단계를 순서대로 보여준다.

1. 자치구
2. 행정동
3. 업종

자치구는 서울 25개 정적 메타데이터를 사용한다. 자치구가 선택되면 해당
행정동을 조회하고, 행정동이 선택되면 후보 상권 목록을 조회한다. 업종은 기존
`simulationCatalog`의 이름과 `serviceCode`를 사용한다.

세 조건과 후보 상권이 모두 준비되면 `상권 추천받기` 버튼을 활성화한다.
조건이 빠졌거나 지역 데이터가 비어 있으면 버튼을 비활성화하고 해당 단계
안에서 이유를 설명한다.

### 결과 모드

추천 성공 후 같은 패널을 다음 구성으로 전환한다.

- 헤더: 업종명과 `추천 Top 5`
- 조건 요약: 자치구·행정동·업종
- `조건 수정` 버튼
- API `rank` 순서의 추천 카드 최대 5개
- 선택 카드의 점수, 선정 이유, 기회도·위험도, 이유 태그
- 선택 카드에서 펼칠 수 있는 세부 지표
- 로그인 사용자를 위한 상권 북마크 보조 액션

첫 결과를 기본 선택한다. 결과가 5개보다 적으면 반환된 항목만 표시하고
빈 순위를 만들지 않는다. 카드 선택은 추천 순서를 바꾸지 않는다.

`조건 수정`을 누르면 조건 모드로 돌아간다. 이전 결과는 React Query 캐시에
남기되 화면과 지도에서는 제거하여 수정 중인 조건과 기존 결과가 섞이지 않게
한다. 업종은 지역과 독립적인 값이므로 유지하고, 자치구 변경은 행정동과 후보
상권을 초기화한다. 행정동 변경은 후보 상권과 결과를 초기화한다. 변경한
조건은 `상권 추천받기`를 다시 눌러야 결과에 반영된다.

## 데스크톱 레이아웃

사이트 헤더 아래의 가용 높이를 지도 스테이지가 사용한다. 지도는 전체 폭을
채우고, 왼쪽 패널을 지도 위에 배치한다.

- 패널 너비: 370~400px
- 지도 여백: 데스크톱 16~24px
- 패널: 기존 `--radius-card`, `--shadow-level-1` 또는 `--shadow-level-2`
- 추천 결과 목록: 패널 내부 세로 스크롤
- 지도 기본 조작: 이동, 확대·축소
- 지도 보조 조작: `선택 범위로 이동`
- 상태 배지: `추천 범위 고정`

패널의 조건·결과 전환은 opacity와 짧은 수평 이동을 적용하되 패널 자체의
크기는 유지한다. 지도가 다시 레이아웃되지 않으므로 전환 중 Kakao Map의
중심점이 튀지 않는다.

## 모바일 레이아웃

1024px 미만에서는 왼쪽 패널을 지도 하단 바텀시트로 전환한다. `/status`의
드래그 경계 계산과 reduced-motion 정책을 재사용하되 추천 전용 콘텐츠를
제공하는 별도 컴포넌트로 구현한다.

### 바텀시트 상태

- `expanded`: 조건 입력 또는 Top 5 결과 본문을 표시한다.
- `collapsed`: 약 44px 높이의 `－` 핸들만 표시하고 본문은 숨긴다.

첫 진입과 조건 수정, 추천 응답 직후에는 펼친 상태로 시작한다. 조건 입력과
결과 화면 모두 최소화할 수 있다. 지도 배경을 누르면 현재 선택과 입력값을
유지한 채 최소화한다. 최소화 상태에서 핸들 영역을 누르거나 위로 드래그하면
다시 펼친다. 펼친 상태에서 핸들을 누르거나 아래로 드래그하면 최소화한다.
폴리곤·순위 마커 클릭은 지도 배경 클릭으로 전파하지 않아 시트를 임의로
최소화하지 않는다.

드래그 중에는 시트 높이가 포인터 이동을 그대로 따라오고, 허용 범위 밖으로
넘어가지 않게 clamp한다. 포인터를 놓을 때 최근 수직 속도가 0.45px/ms 이상이면
방향에 맞는 snap으로 이동하고, 그보다 느리면 현재 높이가 expanded와
collapsed 높이의 중간점을 넘었는지로 snap을 결정한다. 드래그 직후 발생하는
click은 억제해 상태가 두 번 전환되지 않게 한다. 본문 스크롤과 시트 드래그가
충돌하지 않도록 드래그 시작 영역은 핸들로 제한하고, 최소화 상태에서는 보이는
전체 영역이 핸들 버튼이 된다.

최소화 시 본문은 `inert`와 `aria-hidden`으로 상호작용에서 제외한다. 본문에
포커스가 있던 상태에서 최소화하면 핸들로 포커스를 복원한다. safe area와
`prefers-reduced-motion`을 유지한다.

## 지도 depth와 상호작용

지도 레이어는 줌 레벨이 아니라 현재 명시적 단계로 결정한다.

### 자치구 단계

- 서울 자치구 폴리곤을 중립색으로 표시한다.
- 패널 또는 폴리곤에서 자치구를 선택할 수 있다.
- 선택 자치구를 Primary 테두리와 옅은 채움으로 강조한다.
- 선택 후 해당 자치구 bounds에 맞추고 행정동 단계로 이동한다.

### 행정동 단계

- 선택 자치구에 속한 행정동 폴리곤만 선택 가능 상태로 표시한다.
- 패널 또는 폴리곤에서 행정동을 선택할 수 있다.
- 선택 행정동 bounds에 지도를 맞추고 경계를 고정한다.
- 사용자가 지도를 움직여도 선택 행정동과 추천 후보는 바뀌지 않는다.

### 상권 탐색 단계

- 행정동을 선택하면 현재 지도 bounds의 상권 폴리곤을 조회한다.
- 지역 API에서 받은 선택 행정동의 `commercialCode` 집합으로 지도 응답을
  필터링해 다른 행정동 상권이 섞이지 않게 한다.
- 상권 폴리곤 클릭은 지도 강조와 미리보기에만 사용하고 추천 조건을 변경하지
  않는다.
- 상권 셀렉트박스는 두지 않는다. 추천 요청에는 선택 행정동의 모든
  `commercialCode`를 전달한다.
- 지도 이동과 확대·축소로 보이는 상권 폴리곤은 바뀔 수 있지만, 선택한
  자치구·행정동·업종과 추천 후보 집합은 유지한다.

### 결과 단계

- 선택 행정동 경계는 Primary 600의 2px 선과 8~12% 채움으로 유지한다.
- Top 5 상권 폴리곤을 행정동 경계 위에 렌더링한다.
- Top 5는 모두 Primary 계열을 사용하며 `compositeScore`가 높을수록 채움
  농도를 높인다.
- 점수가 없거나 유효하지 않으면 API rank에 따른 고정 농도를 사용하고
  점수 텍스트는 `집계 중`으로 표시한다.
- 선택 상권은 3px 테두리와 가장 높은 레이어를 사용한다.
- 각 상권 중심에는 1~5 순위 마커를 항상 노출한다.
- 카드 hover/focus와 폴리곤·마커 hover를 연결하고, 선택은 클릭 또는
  키보드 활성화로만 변경한다.

색상만으로 상태를 전달하지 않는다. 순위 숫자, 상권명, 점수 또는 점수 상태를
함께 표시한다. 폴리곤 자체는 시각 보조이며, 접근 가능한 기본 선택 수단은
패널의 컨트롤과 결과 카드다. 지도 순위 마커는 Kakao CustomOverlay 안의
버튼으로 렌더링하고 `aria-label`과 `aria-pressed`를 제공한다.

## 데이터 계약과 호출 흐름

브라우저는 기존과 동일하게 `/api/bff`를 호출한다. BFF가 게이트웨이 요청에
`/api/v1`을 추가하고 세션이 있으면 Bearer 토큰을 주입한다.

### 1. 자치구 지도

페이지 진입 시 서울 전체 기본 bounds로 다음 API를 호출한다.

`GET /api/bff/map/districts?lngSW&latSW&lngNE&latNE`

초기 bounds는 프런트 상수
`{ lngSW: 126.70, latSW: 37.40, lngNE: 127.30, latNE: 37.75 }`로
시작한다. Kakao Map의 `idle` 이벤트에서 현재 남서·북동 좌표를 읽고 300ms
디바운스한 뒤, 의미 있게 달라진 bounds로 해당 depth의 지도 좌표를 다시
조회한다. 소수점 정규화와 동일 key 비교로 미세한 좌표 차이로 인한 중복
요청을 막는다. bounds는 추천 범위가 아니라 현재 화면의 geometry를 가져오기
위한 조회 범위다.

응답 `areas[]`의 `areaCode`, `areaName`, `centerLng`, `centerLat`,
`boundaryCoords`를 사용한다. 좌표 튜플은 `[lng, lat]`이므로 Kakao
`LatLng` 생성 시 `lat, lng` 순서로 변환한다.

### 2. 자치구 선택

다음 두 데이터를 병렬로 준비한다.

1. `GET /api/bff/regions/districts/{districtCode}/administrations`
2. 현재 지도 bounds로
   `GET /api/bff/map/administrations?lngSW&latSW&lngNE&latNE`

지도 응답에는 부모 자치구 코드가 없으므로, 첫 번째 응답의
`administrationCode` 집합으로 두 번째 응답을 필터링한다. 코드 비교는
문자열로 정규화한다.

### 3. 행정동 선택

`GET /api/bff/regions/districts/{districtCode}/administrations/{administrationCode}/commercials`

응답의 모든 `commercialCode`가 추천 후보 범위다. 중심 좌표는 이후 상권
프로필 좌표가 없을 때 마커 fallback으로 사용한다.

현재 지도 bounds로 다음 API도 호출한다.

`GET /api/bff/map/commercials?lngSW&latSW&lngNE&latNE`

지도 응답은 선택 행정동의 `commercialCode` 집합으로 필터링한다. 화면에
보이는 폴리곤은 bounds에 따라 바뀌지만 추천 요청에는 지역 API가 반환한 선택
행정동의 전체 상권 코드 집합을 사용한다. 상권 폴리곤 클릭은 조건 폼에 새
필드를 만들거나 후보 집합을 축소하지 않는다.

### 4. 추천 요청

`GET /api/bff/commercials/recommendations/by-service`

- `serviceCode`: 선택 업종 코드
- `commercialCodes`: 선택 행정동의 모든 후보 코드
- `periodCode`: `20233`
- `topN`: `5`

`commercialCodes`는
`commercialCodes=A&commercialCodes=B` 형식의 반복 query key로
직렬화한다. `commercialCodes[]=A` 형태는 사용하지 않는다.

응답의 `rank`, `commercialCode`, `commercialName`, `compositeScore`,
`grade`, `summaryLabel`, `selectionReason`, `opportunityLabel`,
`riskLabel`, `metricBreakdown`, `reasonTags`를 결과 카드에 사용한다.
순서는 클라이언트에서 재계산하지 않고 API `rank`를 신뢰한다.

응답의 `periodCode`를 화면 보조 정보에 표시한다. 현재 계약 기본값인
`20233`은 `2023년 3분기 기준`으로 포맷하여 최신 데이터로 오해하지 않게
한다.

### 5. Top 5 지도 좌표

추천 항목별로 다음 프로필을 최대 5건 병렬 조회한다.

`GET /api/bff/map/commercials/{commercialCode}/profile?serviceCode&periodCode`

프로필의 `boundaryCoords`와 중심 좌표를 지도에 사용한다. 개별 프로필 실패는
추천 목록 전체 실패로 처리하지 않는다. 프로필 경계가 비어 있으면 행정동
상권 목록의 중심 좌표로 순위 마커만 표시한다. `keyMetrics`가 `null`이면
추천 응답의 `metricBreakdown`만 표시한다.

### 6. 북마크

추천 조회는 인증과 무관하게 허용한다. 북마크는 로그인 사용자에게만 제공한다.

- 목록: `GET /api/bff/members/me/bookmarks`
- 추가: `POST /api/bff/members/me/bookmarks`
- 삭제: `DELETE /api/bff/members/me/bookmarks/{bookmarkId}`

추가 body는 다음과 같다.

```json
{
  "targetType": "COMMERCIAL",
  "targetCode": "3110008",
  "targetName": "강남역 상권"
}
```

삭제에는 상권 코드가 아니라 목록 또는 추가 응답의 `bookmarkId`를 사용한다.
목록은 커서 페이지네이션을 따라 필요한 페이지를 조회하고
`targetType === "COMMERCIAL"` 항목만 추천 북마크로 해석한다. 비로그인
사용자가 북마크를 누르면 현재 `/recommend` 복귀 경로를 포함해 로그인으로
이동한다.

기존 `/profile/bookmarks/recommend`도 레거시 추천 저장 API 대신 같은 공통
목록에서 `COMMERCIAL` 항목을 표시한다. 새 계약에 없는 자치구·행정동 정보는
추정하지 않고 상권명, 상권 코드, 저장일만 표시한다. 이번 범위에서는 저장
항목만으로 추천 조건을 자동 복원하지 않는다.

## 상태와 캐시

페이지 컴포넌트는 사용자 선택과 화면 모드를 관리하고, 서버 상태는 React
Query로 관리한다. 기존 `LocationSelector`와 숫자 기반 레거시 타입은 새
계약과 필드명이 달라 추천 화면에서 재사용하지 않는다.

권장 query key는 다음과 같다.

- `['recommend', 'map', 'districts', viewportBounds]`
- `['recommend', 'regions', 'administrations', districtCode]`
- `['recommend', 'map', 'administrations', districtCode, viewportBounds]`
- `['recommend', 'regions', 'commercials', districtCode, administrationCode]`
- `['recommend', 'map', 'commercials', administrationCode, viewportBounds]`
- `['recommend', 'results', districtCode, administrationCode, serviceCode, periodCode, commercialCodesKey]`
- `['recommend', 'profile', commercialCode, serviceCode, periodCode]`
- `['member', 'bookmarks']`

조건 선택값과 결과에 적용된 조건 snapshot을 분리한다. 결과 query는
`상권 추천받기`를 누를 때 snapshot을 만든 뒤에만 활성화한다. 따라서 select
변경이나 지도 이동만으로 네트워크 추천 요청이 발생하지 않는다. 지도 이동은
해당 depth의 폴리곤 좌표 query만 갱신한다.
`commercialCodesKey`는 후보 코드를 중복 제거하고 정렬한 뒤 결합한 안정적인
문자열로 만들어, 같은 조건의 응답 순서 차이가 불필요한 재요청을 만들지 않게
한다.

코드는 API 경계에서 모두 문자열로 정규화한다. 지도 geometry와 도메인
데이터의 결합 key는 각각 `areaCode`, `administrationCode`,
`commercialCode`의 문자열 값이다.

## 컴포넌트 경계

- `RecommendPage`: query 조합, 조건 snapshot, 결과 선택과 반응형 상태를
  조정한다.
- `RecommendMap`: Kakao Map 생명주기, bounds 이동, polygon·marker
  렌더링, 정규화된 viewport bounds 전달과 지도 이벤트만 담당한다.
- `RecommendPanel`: 조건 모드와 결과 모드 전환을 담당한다.
- `RecommendConditionForm`: 자치구·행정동·업종 선택과 단계별 피드백을
  담당한다.
- `RecommendResultList`: Top 5와 선택 카드의 요약·세부 지표를 담당한다.
- `RecommendMobileSheet`: 추천 전용 expanded/collapsed 상태와 드래그를
  담당한다.
- 순수 추천 상태·좌표 변환·query 직렬화 함수는 `lib/recommend` 아래에
  두어 브라우저 SDK 없이 단위 테스트할 수 있게 한다.

Kakao Maps는 기존 `NEXT_PUBLIC_KAKAOMAP_API_KEY`와 네이티브 JavaScript
SDK를 사용한다. 공유 SDK용 기존 `lib/kakao.ts`와 충돌하지 않도록 지도
전용 loader와 최소 타입 선언을 분리한다. `react-kakao-maps-sdk`를 추가하지
않는다.

## 로딩·오류·빈 상태

### 지도

- SDK key 누락 또는 script 로드 실패: 지도 영역에 오류와 재시도 버튼을
  표시하되 패널은 계속 사용할 수 있게 한다.
- 지도 좌표 API 실패: 해당 depth 폴리곤을 숨기고 목록 선택은 유지한다.
- 잘못된 좌표 튜플: 해당 geometry만 제외하고 나머지를 렌더링한다.
- 개별 Top 5 프로필 실패: 해당 항목은 중심 마커 fallback을 사용한다.

### 지역

- 행정동 로딩: 행정동 컨트롤에 skeleton과 disabled 상태를 표시한다.
- 행정동 오류: 같은 단계에 오류와 재시도를 표시한다.
- 행정동 빈 배열: `현재 자치구의 행정동 데이터가 준비되지 않았습니다.`
- 상권 후보 빈 배열: 업종을 선택해도 추천 버튼을 비활성화하고
  `현재 행정동의 추천 대상 상권이 없습니다.`

### 추천

- 추천 로딩: 조건 snapshot을 유지하고 패널에 Top 5 skeleton을 표시한다.
- transport 오류 또는 `dataHeader.success === false`: 패널 안에서 오류와
  재시도 버튼을 표시한다.
- 성공한 빈 `items`: `현재 조건으로 추천 가능한 상권이 없습니다.`와
  `조건 수정`을 표시한다.
- null 점수: API rank는 유지하고 점수 대신 `집계 중`을 표시한다.
- 중복 상권 코드: 최초 rank 항목만 사용하고 개발 환경에서 확인 가능한
  진단 로그를 남긴다.

2026-07-24 dev 환경은 지역·지도 API가 성공 응답과 함께 빈 배열을 반환한다.
프런트 구현과 빈 상태 검증은 가능하지만, 실데이터 Top 5와 폴리곤 결합의 E2E
완료 판정은 데이터 적재 후 수행한다.

## 접근성

- 모든 입력에는 label, 설명, 오류 연결을 제공한다.
- 추천 카드와 지도 순위 마커에는 선택 상태를 `aria-pressed`로 제공한다.
- 지도 없이도 패널만으로 전체 추천 플로우를 완료할 수 있게 한다.
- 결과 로딩 완료와 오류는 적절한 live region으로 알린다.
- 결과 성공 후 결과 제목으로 포커스를 이동하되 포인터 사용자에게 불필요한
  스크롤 이동을 만들지 않는다.
- 터치 대상은 최소 44×44px을 확보한다.
- hover에서만 나타나는 핵심 정보는 두지 않는다.
- `prefers-reduced-motion: reduce`에서는 패널 전환과 바텀시트 애니메이션을
  제거한다.

## 테스트와 검증

### 단위 테스트

- 자치구 변경이 행정동·후보·결과를 초기화하고 업종은 유지하는지
- 행정동 변경이 후보·결과만 초기화하는지
- 추천 요청 전에는 조건 변경으로 추천 query가 활성화되지 않는지
- 상권 코드 배열이 반복 query key로 직렬화되는지
- `[lng, lat]`가 Kakao의 `(lat, lng)`로 변환되는지
- geometry bounds 계산이 잘못된 좌표를 제외하는지
- 지도 응답을 지역 API 코드 집합으로 정확히 필터링하는지
- Top 5 프로필 실패 시 중심 마커 fallback을 선택하는지
- null 점수와 1~5개 결과를 안전하게 표시하는지
- 모바일 expanded/collapsed 전환, 드래그 중 실시간 높이와 snap 경계
- 조건 입력 중에도 지도 배경 클릭이 값을 유지한 채 collapsed로 변경하는지
- collapsed 본문이 inert이고 최소 핸들 탭·위 드래그로 펼쳐지는지
- 지도 idle bounds가 디바운스·정규화되고 동일 bounds를 중복 전달하지 않는지
- depth별 지도 query만 viewport bounds 변경에 반응하는지
- 상권 지도 응답을 선택 행정동 상권 코드 집합으로 필터링하는지
- 북마크 추가 응답의 `bookmarkId`로 삭제하는지

### 통합 테스트

- 패널 자치구 선택과 지도 자치구 선택이 같은 행정동 query를 만드는지
- 지도 행정동 선택이 폼의 행정동 값까지 갱신하는지
- 상권 폴리곤 클릭이 추천 조건이나 후보 상권 코드 집합을 변경하지 않는지
- 추천 버튼을 한 번 누를 때 확정 조건으로만 Top 5를 요청하는지
- 결과 카드 선택과 지도 마커 선택이 같은 상권을 강조하는지
- 개별 프로필 실패가 결과 목록을 오류 상태로 바꾸지 않는지
- 비로그인 추천 조회와 로그인 북마크 분기가 올바른지
- API 실패·빈 배열·재시도가 패널의 현재 단계 안에서 처리되는지

### 수동 검증

- 데스크톱에서 패널 370~400px과 지도 조작 영역이 겹치지 않는지
- 조건 → 결과 전환 중 지도 중심과 크기가 튀지 않는지
- 지도 이동·줌 후 추천 결과와 선택 행정동이 유지되는지
- `선택 범위로 이동`이 현재 행정동 또는 선택 상권으로 복귀하는지
- 모바일에서 입력, 결과 목록, collapsed 상태가 키보드와 safe area를 침범하지
  않는지
- 모바일에서 드래그 중 시트가 손가락을 따라오고 놓은 뒤 자연스럽게 snap되는지
- 지도 배경을 누르면 조건·결과 선택을 유지한 채 핸들만 남는지
- 최소 핸들을 누르거나 위로 드래그하면 다시 펼쳐지는지
- 추천 페이지에서 데스크톱·모바일 모두 푸터가 렌더 영역을 차지하지 않는지
- 폴리곤의 기본·hover·선택 농도와 순위 마커가 명확한지
- 키보드 탐색, 화면 확대 200%, reduced-motion, 콘솔 오류를 확인한다.
- 실데이터 적재 후 자치구 1곳 이상에서 행정동 → 후보 → Top 5 → 프로필
  경계가 동일 코드로 결합되는지 확인한다.

## 완료 조건

- 사용자가 자치구·행정동·업종을 선택해 해당 행정동 내부 Top 5를 요청할 수
  있다.
- 지도 이동과 줌은 결과를 다시 계산하거나 선택 범위를 변경하지 않는다.
- 지도 bounds 변경은 폴리곤 query만 갱신하고 추천 조건과 결과는 유지한다.
- 자치구·행정동 폴리곤 클릭이 해당 조건 셀렉트와 동기화된다.
- 상권 셀렉트박스 없이 선택 행정동의 전체 상권 코드를 추천 요청에 사용한다.
- 패널 카드와 지도 마커가 하나의 선택 상태를 공유한다.
- 데스크톱 패널 전환과 모바일 expanded/collapsed 흐름이 승인된 디자인대로
  동작한다.
- 추천 페이지에서 모든 해상도의 사이트 푸터를 제외한다.
- 지도 또는 개별 프로필 실패가 추천 목록 사용을 막지 않는다.
- 비로그인 추천과 로그인 북마크가 새 Swagger 계약으로 동작한다.
- 로딩·오류·빈 결과·null 점수 상태가 명시적으로 표시된다.
- 백엔드, 패키지 버전, lockfile, 빌드·배포 설정을 변경하지 않는다.
- 자동 검사와 수동 검증 결과를 기록한다.
