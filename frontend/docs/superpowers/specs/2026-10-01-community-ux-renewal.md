## 0. 한 줄 진단과 방향

**지금 커뮤니티는 「게시판 관리 화면」처럼 생겼다.** 큰 소개 카드와 3단 드롭다운 필터가
첫 화면을 차지하고, 글은 그 아래에서 시작한다. 모바일 390px 에서는 **첫 화면에 글이 한 건도
안 보인다.** 상세는 모든 액션이 같은 모양의 버튼으로 나열돼 무엇을 눌러야 할지 모르고,
글쓰기는 설정 폼처럼 「지역 → 제목 → 내용」을 위에서부터 채우게 한다.

개편 방향은 세 가지다.

1. **글이 먼저 보인다** — 필터는 칩 하나로 접고, 소개 카드는 한 줄 헤더로 줄인다.
2. **우리 동네 게시판처럼 느껴진다** — 지역은 「필터 값」이 아니라 **들어가 있는 게시판**이다.
   지역을 고르면 그 지역 이름이 화면 제목이 된다.
3. **쓰고 반응하기 쉽다** — 모바일은 하단 고정 바(좋아요·댓글·공유), 글쓰기는 전체 화면
   에디터, 덜 쓰는 액션(신고·수정·삭제)은 더보기(⋯) 메뉴로 숨긴다.

## 3. 반응형 골격

### 3.1 브레이크포인트

DESIGN.md §8 의 `<480 / 480–768 / >768` 을 따르되, 3단을 펼칠 지점 하나를 더한다(§9 Q2).

| 이름    | 폭         | 골격                                                       |
| ------- | ---------- | ---------------------------------------------------------- |
| Mobile  | `<480`     | 1단. 하단 고정 바 · FAB · 바텀시트                         |
| Tablet  | `480–1079` | 1단 피드(`--w-read` 중앙) + 상단 칩 툴바. 시트 → 팝오버    |
| Desktop | `≥1080`    | **3단** — 좌 내비 240 · 피드 `--w-read`(720) · 우 레일 300 |

3단 합계 = 240 + 24 + 720 + 24 + 300 = **1308px** → `centeredColumn('var(--w-wide)')`(1400) 안에 들어간다.
새 폭 토큰이 필요 없다. 1080–1307 구간은 좌 내비를 빼고 2단(피드 + 레일)으로 둔다.

## 4. 화면별 개편안

### 4.1 목록

**A. 헤더 — 소개 카드를 한 줄로**

- 테두리 카드형 히어로를 없애고 페이지 제목 줄로 바꾼다.
  - 기본: `사장님 이야기` (22/700) + 보조 한 줄 `운영 경험과 동네 소식을 나눠요` (14/400 grey600)
  - **지역 선택 시 제목이 지역명으로 바뀐다**: `성수동 이야기` + `성동구 · 행정동 게시판` + 「전체로」 링크.
    목록 응답의 `board`(`targetName`)를 그대로 쓴다 — BE 변경 없음.
- 데스크톱·태블릿은 제목 줄 오른쪽에 `글쓰기` 버튼(primary). 모바일은 FAB.

**B. 툴바 — 검색 + 지역 칩, 스크롤 시 고정**

- 한 줄: `[🔍 제목이나 내용으로 검색      ]  [📍 서울 전체 ▾]`
  - 검색: 돋보기 아이콘이 든 입력칸 하나. Enter 로 제출, 값이 있으면 ✕ 지우기. 「검색」 버튼 제거.
  - 지역 칩: 현재 범위를 말한다(`서울 전체` → `성수동`). 누르면 **지역 선택 시트**(§5.1).
    선택돼 있으면 칩 안에 ✕ 가 붙어 한 번에 해제.
- 툴바 바로 아래 **밑줄 탭** `최신 | 인기` — 보기 전환임이 분명한 모양으로 바꾼다.
  - `좋아요한 글` 은 성격이 「내 활동」이라 분리한다(§9 Q3):
    모바일·태블릿은 탭 오른쪽 끝 `♥ 좋아요한 글` 텍스트 링크, 데스크톱은 좌 내비 `내 활동` 그룹.
    URL 계약(`view=liked`)과 「필터 함께 해제」(CM-005)는 그대로다.
- 모바일은 툴바+탭이 스크롤하면 위로 붙는다(sticky, 상단 헤더 아래). 아래로 내리면 헤더는 숨고
  툴바만 남는 「숨는 헤더」는 2차(P2).

**C. 글 행 — 카드에서 리스트 행으로**

카드 박스를 걷어내고 디바이더로 나눈 행으로 바꾼다. 한 화면 글 수: 데스크톱 4 → **7**, 모바일 0 → **3~4**.

```
┌────────────────────────────────────────────────┬────────┐
│ [성수역 상권]  ·  3시간 전                      │        │
│ 성수역 여름 POP-UP 협업 제안          (16/600)  │ 썸네일  │
│ 여름 시즌에 함께 작은 팝업을 열 식음료 브랜드…  │ 72×72  │
│ 사장님을 찾고 있습니다.         (14/400, 2줄)   │ (r 8)  │
│ (역) 역삼동 김사장        ♡ 9   💬 1           │        │
└────────────────────────────────────────────────┴────────┘
```

- 위에서 아래로 **어디(지역)·언제 → 무엇(제목) → 내용 → 누가·반응** 순서. 지역 칩을 맨 위에 두는 이유:
  커뮤니티의 차별점이 「지역에 붙은 글」이라 훑을 때 첫 신호가 지역이어야 한다.
- 썸네일: `thumbnailUrl` 있을 때만 우측 72px(태블릿·데스크톱 96px). 없으면 텍스트가 폭을 다 쓴다.
- 시간: 7일 이내는 상대 시간(`3시간 전`, `어제`), 그보다 오래되면 `7월 27일`, 해가 다르면 `2025. 7. 27.`
- 인기 보기에서는 상위 3건 좌측에 순위 숫자(1·2·3, tabular, 700). 정보이자 재미 요소.
- 행 전체가 링크(최소 높이 52px — DESIGN.md §8 Touch Targets), hover 는 grey50 배경.
- 지역 칩을 누르면 그 지역 게시판으로 필터된다(행 링크와 별도 타깃 — 이벤트 전파 막기).

**D. 다음 쪽 · 상태**

- IntersectionObserver 로 **자동 무한 스크롤**, 실패하면 그 자리에 「다시 불러오기」 버튼(fallback).
  끝에 닿으면 `여기까지 다 봤어요` + `글쓰기` 링크.
- 로딩: 행 모양 스켈레톤 5줄(DESIGN.md S-COM-1).
- 빈 상태는 이유별로 한 줄 + 행동 하나:
  - 지역 첫 글 없음: `성수동에는 아직 글이 없어요. 첫 이야기를 남겨 보세요.` → `글쓰기`(지역 프리필)
  - 검색 결과 없음: `「팝업」 이 들어간 글이 없어요.` → `검색어 지우기`
  - 좋아요한 글 없음: `마음에 드는 글에 좋아요를 눌러 모아 보세요.` → `인기 글 보기`
- 상세에 갔다 돌아오면 **스크롤 위치·불러온 쪽 수 복원**(React Query 캐시 + `scrollRestoration`).

**E. 글쓰기 진입**

- 모바일·태블릿: 우하단 FAB `✎ 글쓰기`(확장형). 아래로 스크롤하면 아이콘만 남게 줄고, 위로 올리면 펼친다.
  목록 하단에 FAB 높이 + 16px 여백을 둬 마지막 행을 가리지 않는다(L9).
- 지역 게시판 안에서 누르면 **그 지역이 프리필**된 글쓰기로 간다.

**F. 데스크톱 좌우 레일 (≥1080)**

- 좌 내비(240, sticky): `보기`(최신·인기) · `내 활동`(좋아요한 글) · `지역 게시판`(최근 본 지역 최대 5개 —
  localStorage, 없으면 숨김).
- 우 레일(300, sticky):
  1. **이번 주 인기 글 TOP 5** — 같은 목록 API 를 `sortType=POPULAR`, 소량으로 한 번 더 부른다. BE 변경 없음.
     (「이번 주」 기간 필터는 BE 가 없어 실제로는 「인기 글」이다 — 문구를 `인기 글` 로 둔다.)
  2. **글쓰기 유도 카드** — `성수동 사장님들께 물어보세요` + `글쓰기`(지역 선택 중일 때 지역명 치환).
  3. (분석 연결) `이 지역 상권 분석 보기` — 지역 선택 중일 때만, `/analysis` 로 연결.

### 4.2 상세

**A. 레이아웃 고침 (D1)**

- 그리드를 `minmax(0, var(--w-read)) 300px` + `justify-content: center` 로 바꿔 본문과 레일을 붙인다.
  레일이 오른쪽 끝에 떨어지지 않는다. 1080 미만은 1단(레일 내용은 본문 아래로).
- 본문을 카드 박스에서 꺼내 페이지 흰 바탕에 바로 둔다(읽기 화면은 테두리가 소음이다). 댓글과는
  8px grey50 구분 띠로 나눈다.

**B. 글 머리**

```
← 목록                                              ⋯
[성수역 상권 ›]
성수역 여름 POP-UP 협업 제안                    (22/700)
(아바타 36) 역삼동 김사장
            3시간 전 · 조회 297            (13/400 grey600)
```

- 지역 칩은 링크(`성수역 상권 ›`) — 누르면 그 지역 게시판.
- 날짜는 한 번만. 수정된 글이면 `3시간 전 · 수정됨`(D5). 댓글도 같은 규칙.
- `⋯` 더보기: 내 글이면 `수정` · `삭제`, 남의 글이면 `신고`. 모바일은 바텀시트 액션 리스트,
  데스크톱은 팝오버 메뉴. 삭제는 확인 다이얼로그 후 실행(되돌릴 수 없음을 한 줄로).

**C. 본문**

- 본문 16/400, 줄 높이 1.7, `--w-read` 상한. 링크 자동 감지는 2차.
- 이미지: 본문 폭 가득(최대 720), radius 12. 탭/클릭하면 **라이트박스**(좌우 스와이프, 닫기, n/전체).
  여러 장이면 모바일은 가로 스와이프 캐러셀 + 점 인디케이터, 데스크톱은 세로 나열.
- 분석 첨부(비교 초안 글)는 본문 위에 **분석 카드**로 — `강남역 vs 성수역 상권 비교 · 2023 4분기` +
  `비교 결과 보기 ›`. 「글 → 근거 데이터」로 돌아가는 다리가 이 서비스만의 강점이다.

**D. 반응 바**

- 본문 끝 한 줄: `[♡ 좋아요 9]  [💬 댓글 1]  [↗ 공유]` — 아이콘 + 라벨 + 수, 높이 40.
  - 좋아요: 누르면 즉시 채움(낙관적 업데이트) + 짧은 scale 모션(DESIGN.md §15), 실패 시 되돌리고 토스트.
  - 댓글: 댓글 입력으로 스크롤 + 포커스(지금 동작 유지).
  - **공유(신규, D3)**: 모바일은 Web Share API(`navigator.share`), 미지원이면 링크 복사 + 토스트
    `링크를 복사했어요`. FE 만으로 된다.
- **모바일 하단 고정 바(D6)**: 본문 반응 바가 화면 밖으로 나가면 하단에 고정 바가 뜬다.
  `[♡ 9]  [ 댓글을 남겨 보세요…      ]  [↗]` — 가운데 가짜 입력칸을 누르면 댓글 입력 시트가 올라온다.
  safe-area inset 포함(DESIGN.md §8 Collapsing Strategy).

**E. 댓글 (D4 · D7)**

- 순서를 **목록 → 입력**으로 바꾼다. 데스크톱·태블릿은 댓글 목록 아래 입력칸(한 줄로 접혀 있다가
  포커스하면 3줄로 펼치고 `등록` 버튼 노출). 모바일은 하단 고정 바가 입력을 맡는다.
- 댓글 행:

```
(아바타 32) 뚝섬 디저트랩  [글쓴이]   · 2시간 전        ⋯
            디저트 브랜드도 참여할 수 있을까요?
            ♡ 1   답글 달기
     └ (28) 역삼동 김사장 [글쓴이] · 1시간 전           ⋯
            네, 환영해요!
```

- 글 작성자의 댓글에 `글쓴이` 배지(blue50/blue700) — `memberId` 비교, BE 변경 없음.
- `♡ 1` · `답글 달기` 는 아이콘+텍스트, 터치 영역 최소 36×36(패딩으로 확보).
- 신고·삭제는 댓글 `⋯` 로.
- 답글은 depth 1 유지. 답글이 3개 넘으면 `답글 5개 더 보기`로 접는다.
- 비로그인: 입력칸 자리에 `로그인하고 댓글 남기기`(지금 동작 유지 — 돌아올 자리 보존, CM-002).

**F. 이어 보기**

- 본문·댓글 아래(1080 미만) 또는 우 레일(≥1080, sticky):
  1. 이전 글 / 다음 글 — 제목 한 줄씩(지금 `AdjacentNavigation` 재사용).
  2. 같은 지역 최신 글 3건. **비었으면** 회색 박스 대신
     `성수역 상권의 다음 이야기를 남겨 보세요` + `글쓰기`(지역 프리필)(D8).

### 4.3 글쓰기 · 수정

**A. 순서를 「쓰고 싶은 말」 먼저로 (W1)**

모바일은 전체 화면 에디터로 바꾼다.

```
┌──────────────────────────────────────┐
│ ✕          새 글             [등록]  │ ← 상단 앱바(sticky). 등록은 필수값 채워지면 활성
├──────────────────────────────────────┤
│ [📍 어느 지역 이야기인가요? ▾]        │ ← 지역 칩 하나. 누르면 지역 선택 시트(§5.1)
│                                      │
│ 제목을 입력해 주세요         (20/600) │ ← 테두리 없는 큰 입력
│ ──────────────────────────────────── │
│ 운영하면서 겪은 일, 궁금한 점을       │ ← 자동 높이 textarea
│ 편하게 적어 주세요.                   │
│                                      │
│ [사진][사진][+]                       │ ← 첨부 썸네일 가로 줄. 첫 장에 「대표」 배지
├──────────────────────────────────────┤
│ [📷 사진 0/5]          본문 0/5,000   │ ← 하단 툴바(키보드 위에 붙음)
└──────────────────────────────────────┘
```

- 태블릿·데스크톱: `--w-form` 중앙에 같은 순서. 앱바 대신 페이지 제목 `새 글` + 하단 고정 액션 바
  `[취소] [등록하기]`(W4). 데스크톱 ≥1080 은 우측에 **작성 팁** 카드(좋은 글 예시 3줄).
- 지역 칩은 **목록·상세에서 넘어온 지역이 있으면 프리필**. 비교 초안은 지금처럼 행정동 고정 프리필.
  수정 모드에서는 칩이 읽기 전용(지금 규칙 유지).
- 안내 문구는 칩 placeholder 한 곳(`어느 지역 이야기인가요?`)으로 줄인다(W2). 지역 없이 등록을 누르면
  칩이 흔들리며 시트가 열린다 — 막는 이유를 행동으로 보여 준다(CM-008 유지).
- 글자 수는 한도의 90% 를 넘을 때부터 강조(red700). 평소엔 grey600.

**B. 잃지 않게 (W3)**

- 쓰는 중 **localStorage 자동 임시 저장**(입력 멈춘 뒤 1초). 다시 들어오면
  `작성하던 글이 있어요. 이어서 쓸까요?` [새로 쓰기] [이어 쓰기].
  키는 `community-draft:new` / `community-draft:edit:{postId}` 로 분리, 등록 성공 시 삭제.
- 내용이 있는 채로 ✕·뒤로 가기·새로고침: `작성 중인 글은 임시 저장돼요. 나갈까요?` 확인.
  (`beforeunload` + App Router 내비게이션 가드.)

**C. 사진**

- 툴바 `📷` 와 썸네일 줄 끝 `[+]` 두 입구. 썸네일 72px, 우상단 ✕, 업로드 중엔 진행 스피너.
- 첫 장이 목록 썸네일이 된다는 걸 `대표` 배지로 알린다. 순서 바꾸기(드래그)는 2차.

**D. 작성 도움 칩 (선택, §9 Q4)**

- 본문 비어 있을 때만 본문 위에 칩 3개: `질문해요` · `경험 나눠요` · `같이 해요`.
  누르면 본문에 짧은 틀을 넣는다(예: 질문 → `상황:\n궁금한 점:\n`). 말머리 대체가 아니라 **빈 칸 공포를
  덜어 주는 장치**다. 저장 데이터는 그냥 본문이라 BE 변경 없음.

### 4.4 신고 다이얼로그

- 지금: 자유 입력 textarea 하나. 무엇을 써야 할지 몰라 대충 쓰거나 포기한다.

### 5.1 지역 선택 시트

3단 select 를 **한 단계씩 들어가는 리스트 + 검색**으로 바꾼다. 같은 컴포넌트가 목록 필터와 글쓰기에 쓰인다.

```
┌────────────────────────────────┐
│ 지역 선택                   ✕  │
│ [🔍 동네·상권 이름으로 찾기   ] │ ← 자치구·행정동·상권 통합 검색(클라이언트 필터)
│ 서울 전체 › 성동구              │ ← 브레드크럼. 누르면 그 단계로 돌아감
├────────────────────────────────┤
│ ✓ 성동구 전체                   │ ← 「이 단계로 선택」이 첫 행
│   성수1가1동                 ›  │
│   성수1가2동                 ›  │
│   왕십리도선동               ›  │
│   …                            │
└────────────────────────────────┘
```

- 각 단계 첫 행이 「○○ 전체」 — 자치구만으로도 고를 수 있다는 걸 설명 없이 보여 준다(지금 도움말 문구 대체).
- 검색은 지금 select 가 이미 받아 오는 목록을 클라이언트에서 거른다. 새 API 없음.
  (상권 목록을 자치구 선택 전에 못 받는 구조면 검색 범위를 「자치구·행정동」으로 한정 — 구현 시 확인.)
- 목록 필터에서는 고르는 즉시 닫고 반영. 글쓰기에서는 고른 뒤 닫고 칩에 표시.
- 모바일 바텀시트(최대 높이 85vh) / 태블릿·데스크톱 칩 아래 팝오버(폭 360, 최대 높이 480).
