## 1. 요약

**이슈의 전제 세 개가 낡았다.** 네 번 미뤄지는 동안 그중 하나는 이미 해결됐고, 나머지
둘은 실측으로 성립하지 않았다.

| 이슈가 적은 것                      | 실측 결과                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 04단계가 494px 중 153px(31%)만 찬다 | **PR #228 이 이미 고쳤다.** `CostBreakdownBar` → `BreakEvenChart` 로 **60%**. 이슈가 지목한 `cost-breakdown-bar.tsx` 는 **삭제된 파일**이다 |
| 01(87%)과 04(31%)가 3배 차이 난다   | 정상 상태는 **92 / 85 / 68 / 60%** — **1.5배**다                                                                                            |
| 여백과 폭 개방은 한 덩어리다        | **무관하다.** 셸 전폭으로 열어도 참 비율이 한 자리도 안 바뀐다                                                                              |

그래서 이 작업은 이슈가 상정한 「2배 크기의 한 덩어리」가 아니라 **서로 독립인 두 개의
작은 결정**이 된다.

## 2. 실측

측정 조건: `pnpm build && pnpm start`, 헤드리스 브라우저, develop `3b17b9a4`.
추천 연쇄는 로컬 스텁(상권 40곳 → 추천 5곳)으로 정상 상태를 만들었다.

### 2.1 단계별 데모가 패널을 채우는 비율 (1920×1080)

| 단계          | 데모                 | 콘텐츠 / `DemoArea` | 참      |
| ------------- | -------------------- | ------------------- | ------- |
| 01 현황 확인  | `MetricRankingBoard` | 456 / 494           | **92%** |
| 02 상권 분석  | `AnalysisMiniDemo`   | 459 / 542           | **85%** |
| 03 후보 추천  | `RecommendPreview`   | 338 / 494           | **68%** |
| 04 시뮬레이션 | `BreakEvenChart`     | 296 / 494           | **60%** |

> 03 은 추천 연쇄가 실패하면 도넛이 빠져 **126px(26%)** 로 떨어진다. 그 상태는 01·02 도
> 함께 열화된 상태라 이 작업의 대상이 아니지만, 03 의 「정상 68% / 실패 26%」 격차는
> 기록해 둔다.

### 2.2 폭을 열면 어떻게 되는가

`Sticky` 를 `--w-wide`(1400) 에서 셸 전폭으로 바꿔 측정했다.

| 뷰포트         | `DemoArea` 폭  | 참 비율                           |
| -------------- | -------------- | --------------------------------- |
| 1920 (셸 1865) | 958 → **1423** | 92 / 85 / 68 / 60 — **변화 없음** |
| 2560 (셸 2505) | 958 → **2063** | 92 / 85 / 68 / 60 — **변화 없음** |

**데모가 전부 폭 가변·높이 고정이라 넓혀도 세로 여백이 그대로다.** 이슈가 주장한
「데모 내부를 재설계하지 않으면 어느 쪽도 못 푼다」는 인과가 성립하지 않는다.

### 2.3 헤더와의 어긋남

| 뷰포트    | 헤더 안쪽 | 스토리 컬럼 | 한쪽 어긋남 |
| --------- | --------- | ----------- | ----------- |
| 1440×900  | 1385      | 1385        | **0**       |
| 1600×900  | 1545      | 1400        | 73px        |
| 1920×1080 | 1865      | 1400        | **233px**   |
| 2560×1440 | 2505      | 1400        | **553px**   |

**1440 에서는 이미 셸 전폭이다.** 어긋남은 뷰포트 **1455px 초과**에서만 생긴다.

1920 홈 전체를 재면 스토리만 튄다: 히어로 1865 · 도구 보드 1865 · 앵커 문장 980(읽기
컬럼) · **스토리 1400** · 벤토 1865. 홈에서 **유일하게 셸도 읽기 컬럼도 아닌 섹션**이다.

## 3. 결정

### 3.1 스토리 폭 — 열지 않는다. 대신 전폭 배경 밴드를 깐다

폭을 여는 두 방법을 모두 시도했고 **둘 다 더 나빴다.**

| 시도                           | 결과                                                                                                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 그냥 연다                      | 01 의 가로 막대가 **1300px** 로 늘어난다 — 폭 체계 **§6 이 직접 정한 「가로 막대 → 560px 상한」을 스스로 어긴다.** 03 의 도넛(300px)은 1423px 한가운데 뜬다 |
| 열고 `DemoArea` 에 1000px 상한 | 1920 까지는 깔끔하지만 2560 에서 카드가 2105px 인데 안의 데모가 1000px 이라 **좌우 550px 씩 빈다.** 카드 밖 어긋남을 카드 안 공백으로 옮겼을 뿐이다         |

**그래서 폭 체계 설계 §5 가 중앙 그룹에 대해 이미 써 둔 처방을 스토리에 적용한다.**

> 중앙 그룹의 잔여 어긋남은 **페이지 상단 전폭 배경 밴드**로 처리한다. 좁은 카드가 넓은
> 판 위에 놓인 것으로 읽혀 **어긋남이 아니게 된다.**

`Container` 에 `--color-background-muted` 를 깔면 1400 이 **결함이 아니라 선택**으로
읽히고, 흰 `Panel` 카드가 배경에서 떠올라 대비도 함께 얻는다. 2560 에서도 무너지지 않는다.

**`--w-wide` 1400 과 `centeredColumn` 은 그대로 둔다.**

#### 함께 고쳐야 하는 충돌

`StepButton` 의 hover 배경이 **밴드와 같은 토큰**(`--color-background-muted`)이다.
밴드를 깔면 **hover 가 보이지 않게 된다.** `--color-surface-muted` 로 한 단계 내린다.
활성 상태(`--color-primary-100`)는 그대로 둔다.

`Container` 는 스티키·스택 두 분기를 모두 감싸므로 **모바일 스택 모드에도 같은 밴드가
깔린다.**

### 3.2 `StoryRow` 의 `flex: 0 1 600px` — 유지한다

늘어나게 두면 **모든 단계가 나빠진다**(1920 실측).

| 단계 | 유지 | `flex: 1 1 600px` 로 바꾸면 |
| ---- | ---- | --------------------------- |
| 01   | 92%  | **61%**                     |
| 04   | 60%  | **40%**                     |

문서(D9-3·D9-4)에 적힌 근거가 정확했다. **이 결정은 뒤집지 않는다.**

### 3.3 04단계 세로 여백 — 차트 높이만 200 → 260px

D8-11·D9-5 가 가리킨 문제는 **#228 이 이미 해소했다**(31% → 60%). 남은 것은 04 만
유일하게 60% 라는 것이고, 원인이 명확하다 — `LineChart height={200}` 이 494px 영역 안에
있다.

| 뷰포트    | 200px | 260px   | 넘침                      |
| --------- | ----- | ------- | ------------------------- |
| 1920×1080 | 60%   | **74%** | 0                         |
| 1440×900  | 60%   | **74%** | 0                         |
| 1100×800  | —     | **78%** | 0                         |
| 1280×620  | —     | 128%    | **패널 20px 내부 스크롤** |

1280×620 은 이미 스텝 목록이 101px 스크롤하는 「열화로 버티는」 구간이므로(D9-3),
패널이 함께 스크롤하는 것은 그 규약과 일치한다.

**03(68%)은 손대지 않는다.** 정상 상태에서 04 와 나란해지므로 남는 격차가 없다.

## 4. 감수하는 것

- **1455px 초과에서 스토리 컬럼은 여전히 헤더보다 좁다.** 밴드가 그것을 「어긋남」이
  아니라 「판 위의 컬럼」으로 읽히게 할 뿐, 폭 자체는 그대로다
- **1280×620 에서 04 패널이 20px 내부 스크롤한다** — 열화 구간의 기존 규약과 같은 처리다
- **03 의 실패 상태(26%)는 그대로 남는다** — 추천 연쇄가 죽었을 때만 나타나며, 그때는
  01·02 도 함께 열화돼 있다
