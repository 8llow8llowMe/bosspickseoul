# 과업 흐름 감사 (2026-09-01)

「이 화면이 규격에 맞나」가 아니라 **「사용자가 목적을 달성하나」** 를 렌즈로,
과업 3개를 끝까지 걸었다. 아래는 전부 `origin/develop` `26befcb7` 에서 실측한 것이고,
가설과 확인된 결함을 구분해 적었다.

## 결론 한 줄

**제품의 두 핵심 도구(`/analysis` · `/recommend`)가 서로 완전히 단절되어 있고,
「후보 여러 곳 중 고르기」라는 창업자의 실제 과업을 지원하는 화면이 없다.**

---

## 과업 1 — 「강남에서 카페 하려는데 어디가 좋을까」

가장 흔한 진입 의도. **완주 실패.** 이탈 지점 5개.

### J1-1 (High) 홈 본문이 추천·시뮬레이션으로 가는 길을 주지 않는다

홈의 링크 분포 실측 (헤더/푸터 제외한 본문 기준):

| 대상              | 본문 링크 수                         |
| ----------------- | ------------------------------------ |
| `/analysis`       | **4** (히어로 CTA·스텝 CTA·최종 CTA) |
| `/status`         | 1                                    |
| `/register`       | 1                                    |
| **`/recommend`**  | **0**                                |
| **`/simulation`** | **0**                                |

홈에는 「네 단계로 좁힙니다」 스크롤리텔링이 있고 그 안에 **「후보 추천」·「창업 시뮬레이션」
섹션이 실제로 존재**한다. 그런데 4개 스텝 중 **3개(현황 확인·후보 추천·창업 시뮬레이션)에
CTA 가 하나도 없다.** CTA 가 있는 스텝은 「상권 분석」 하나뿐(`이 조건으로 실제 분석하기`).

게다가 그 스크롤리텔링은 `y≈2966` 에서 시작한다 — 히어로에서 **3.7 화면분을 스크롤해야**
네 도구의 관계를 처음 알게 된다. 히어로 CTA 2개는 `/analysis` 와 `/status` 다.

→ **「어디가 좋을지 모르는」 사람이 그것을 위해 만든 도구(`/recommend`)에 닿지 못한다.**

### J1-2 (High) `/analysis` 안에 빠져나갈 길이 없다

`/analysis` 본문의 내부 링크 **0개**(헤더 제외. 유일한 `<a>` 는 카카오 지도 저작권 링크).
4단계 선택을 요구하면서, 「어느 상권인지 모르겠다」는 사용자를 추천으로 보내주지 않는다.

### J1-3 (High) 상권만 바꾸면 이미 고른 업종이 말없이 사라진다

후보 비교를 하려면 3단계로 돌아가 상권만 바꾸게 된다. 그때:

- URL 에서 `serviceCode=CS100010` **소실**
- 4단계 칩이 `4단계 업종` 으로 **리셋**
- `분석 결과 보기` **다시 비활성**
- **아무 경고도 없다**

재현: `/analysis` → 강남구 → 역삼1동 → 역삼역 4번 → 커피-음료 → 결과 → 닫기 →
3단계 칩 → 국기원 선택. URL 이
`...commercialCode=3110954&c=...` 로 바뀌며 `serviceCode` 가 빠진다.

→ 후보 3곳을 같은 업종으로 비교하려면 **업종을 매번 다시 고른다.**

### J1-4 (High) 「비교」 탭은 상권끼리 비교하지 않는다

`/analysis/result` 의 `비교` 탭 본문:

> 역삼역 4번의 매출과 소비력 지표를 **자치구 및 행정동 평균**과 비교한 결과입니다.

상권 ↔ 상권 비교가 아니다. 탭 이름이 기대를 만들고 그 기대를 배신한다.
**후보 간 비교 수단이 상권분석에 전혀 없다.**

대조적으로 시뮬레이션에는 `/analysis/simulation/compare?a.<params>` 라는
A/B 비교 라우트가 **이미 있다**. 비교 프리미티브는 제품에 존재하는데,
정작 핵심 판단이 일어나는 자리에는 없다.

### J1-5 (High) 추천 결과에서 분석으로 가는 링크가 0개

`/recommend` 를 어렵게 찾아가 「커피-음료 추천 Top 5」를 받아도,
결과 카드에서 `/analysis` 로 가는 링크가 **0개**다. 카드의 액션은 `북마크 추가` 뿐.
1위 상권을 자세히 보려면 `/analysis` 로 가서 4단계를 **손으로 다시** 밟아야 한다.

### 이 이탈의 실제 대가 (실측)

히어로 CTA 를 그대로 따라가면 `/analysis` 에서 역삼역 4번을 고르게 된다.
같은 조건으로 `/recommend` 를 돌리면 **역삼역 4번은 커피-음료 5위/5위, 기회도 낮음(21점)**
— 5개 후보 중 꼴찌다. 1위는 「역삼역」(84점, 기회도 높음).

**상권분석은 이 사실을 끝까지 알려주지 않는다.** 비교 탭이 자치구 평균만 보여주기 때문이다.

## 과업 2 — 「역삼역 앞 한식집, 되는 장사인가」

특정 후보 검증. **완주 성공** — 이 과업은 제품이 잘 지원한다.
결과 다이얼로그는 7탭(요약·유동인구·매출·점포·생활권·트렌드·비교)으로 충실하고,
이어가기 액션(`공유`·`화면 보관`·`상권 저장`·`시뮬레이션`)도 갖췄다.

> 인계 문서의 가설 4 「화면 간에 다음에 뭘 하지가 이어지는지 미확인」은
> **이 지점에서 반증된다.** 분석 결과에서 다음 단계로 가는 길은 잘 놓여 있다.

다만 진입 조건에 문제가 둘 있다.

### J2-1 (High) `/recommend` 는 행정동이 필수다 — 「강남구에서」에 답하지 못한다

`/recommend` 의 문구는 「어디에 어떤 가게를 열까요?」이고 스텝은 자치구 · 행정동 · 업종이다.
행정동을 **건너뛸 수 있어 보이지만 아니다.**

- 강남구 + 커피-음료 선택 → `상권 추천받기` **비활성 유지**
- 역삼1동 추가 선택 → **활성화**

즉 이 도구는 「강남구 안에서 어디」가 아니라 **「역삼1동 안에서 어디」** 만 답한다.
**자치구 단위 순위는 제품에 없다.** 그런데 창업자는 보통 동 단위로 좁혀오지 않는다.

### J2-2 (High) 비활성 CTA 가 무엇이 빠졌는지 말하지 않는다 — 3화면 중 `/recommend` 만

| 화면             | 비활성 CTA       | 안내 문구                                                                                               |
| ---------------- | ---------------- | ------------------------------------------------------------------------------------------------------- |
| `/analysis`      | `분석 결과 보기` | 「상권과 업종을 선택해 주세요」 ✅                                                                      |
| `/simulation`    | `계산하기`       | 「프랜차이즈 창업인지 먼저 선택해 주세요」 → 「매장 크기와 층 구분을 선택해 주세요」 ✅ (단계별로 갱신) |
| **`/recommend`** | `상권 추천받기`  | **없음** ❌                                                                                             |

`/recommend` 의 CTA 는 `disabled=true` 이면서 `aria-disabled`·`title`·`aria-describedby`
**전부 없고**, 섹션 안에 안내 텍스트도 없다. 섹션 전체 텍스트는
「어디에 어떤 가게를 열까요? 강남구 행정동 선택 커피-음료 상권 추천받기」가 전부다.

접근성 문제이기도 하다 — `disabled` 버튼은 탭 순서에서 빠지고 이유를 읽어주지 않는다.
`/simulation` 의 단계별 안내가 그대로 모범 답안이다.

## 과업 3 — 「얼마 드는지 보고 저장해두기」

**대체로 잘 된다.** 이 여정이 제품에서 가장 잘 만들어진 구간이다.

### 잘 되는 것 (유지할 것)

- **컨텍스트 인계**: `/analysis/result` 의 `시뮬레이션` → `/analysis/simulation?...` 에
  **자치구·업종이 미리 선택된 채** 도착. 남는 건 창업 형태와 매장 조건뿐.
- **단계별 안내**: 창업 형태를 고르면 안내가 「매장 크기와 층 구분을 선택해 주세요」로 갱신.
- **게이트 명시**: 리포트의 저장 버튼 라벨이 아예 **「저장하려면 로그인」** 이고,
  `href` 가 `/login?redirect=<리포트 전체 URL>` 로 **상태를 전부 보존**한다.
- 계산 결과(예: 개인창업·강남구·커피-음료·61㎡·1층 → **7,833만원**)와 근거 요약이 함께 나온다.

### J3-1 (Medium) 북마크는 사전 안내 없이 로그인으로 튕긴다

`/recommend` 결과의 `북마크 추가` 를 누르면 토스트도 다이얼로그도 없이 즉시
`/login?redirect=...` 로 이동한다. `redirect` 로 상태가 보존되는 건 좋지만,
같은 제품 안에서 리포트는 **「저장하려면 로그인」** 이라고 미리 말해준다. **규약이 갈린다.**

### J3-2 (Medium) `/login` 에 앱으로 돌아갈 길이 없다

`/login` 은 **헤더가 없고**, 페이지 전체의 링크가 **`/register` 하나뿐**이다.
로고도, 홈 링크도, 「취소」도 없다. 실수로 북마크를 누른 사용자에게 남은 건
로그인·회원가입·브라우저 뒤로가기뿐이다.

### J3-3 (Low) 계산 결과가 제목 아웃라인에서 사라진다

계산 **전**: 「예상 총 창업 비용」이 `<h2>`.
계산 **후**: 같은 문구가 `<p class="simulation-result-preview__Caption">` 로 강등.
페이지에서 제일 중요한 출력이 heading 이 아니게 되어, 제목 단위로 훑는 사용자는 답을 건너뛴다.

### J3-4 (Low) 추천 결과 `aria-label` 의 조사·중복 오류

> 「공격형 기준으로 기회도 높음**를** 우선 반영했고, **기회도는 기회도 높음**이며
> **위험도는 위험도 높음**입니다」

`높음을` 이 맞고, 「기회도는 기회도」·「위험도는 위험도」가 중복된다.
라벨 문자열을 조사 처리 없이 이어붙이는 템플릿 문제. 스크린리더에만 노출된다.

## 확인하지 못한 것 (결함으로 올리지 않음)

- **콜드 로드 딥링크 공백**: `/analysis/result?...` 에 URL 로 직접 진입하면 화면이 비었다.
  그러나 **대조군 `/analysis` 콜드 로드도 똑같이 실패**했다. 숨겨진 브라우저 pane 에서
  `useSearchParams` Suspense 경계의 스트리밍 reveal 이 멈추는 **환경 아티팩트**다.
  클릭(클라이언트 내비게이션)으로는 전부 정상 동작한다.
  → **`공유` 버튼이 만드는 링크가 실제로 열리는지는 보이는 창에서 사람이 재검증해야 한다.**
- **`/analysis` 4단계에 업종 검색창이 없다** (1~3단계엔 있고, `/recommend` 에도 있다).
  다만 dev 데이터에서 해당 상권의 업종이 5개뿐이라 검색이 불필요해 숨긴 것일 수 있다.
  업종이 많은 상권에서 재확인 필요.
- **로그인 이후 경로 전체**(저장 → `/profile/bookmarks` → 다시 찾기)는 계정이 없어 못 걸었다.
