## S1. 기능 개요

사용자는 **지역에 붙은 글**을 목록에서 보고(최신·인기·좋아요한 글), 검색하고, 하나를 열어
읽고 댓글·답글·좋아요로 참여한다. 글을 쓸 때는 대상 지역을 고르고, `/recommend/compare` 에서
넘어온 경우 백엔드가 만든 **비교 초안**이 제목·본문을 미리 채운다.

```
목록(커서 페이지네이션) → 상세 → 댓글·좋아요
글쓰기: 대상 지역 선택 → 작성 → POST /community/posts
비교 초안: /recommend/compare → POST …/drafts/commercial-comparisons → 글쓰기 화면 프리필
```

## S4. 세부 명세

세부 명세는 아직 없다. 아래는 공통 명세가 짊어지고 있는 계약·규약이다.

### 백엔드 계약 (실측)

| 동작                | 호출                                                  | 인증             |
| ------------------- | ----------------------------------------------------- | ---------------- |
| 목록                | `GET /community/posts`                                | —                |
| 검색                | `GET /community/posts/search`                         | —                |
| 좋아요한 글         | `GET /community/posts/liked`                          | 필요             |
| 상세                | `GET /community/posts/{id}`                           | —                |
| 작성 · 수정 · 삭제  | `POST` · `PATCH` · `DELETE /community/posts[/{id}]`   | 필요             |
| 글 좋아요 토글      | `POST /community/posts/{id}/likes`                    | 필요             |
| 댓글 목록·작성·삭제 | `…/{id}/comments[/{commentId}]`                       | 작성·삭제만 필요 |
| 댓글 좋아요 토글    | `…/comments/{commentId}/likes`                        | 필요             |
| 신고                | `POST /community/reports`                             | 필요             |
| 이미지 업로드       | `POST /community/posts/images`                        | 필요             |
| 비교 초안           | `POST /community/posts/drafts/commercial-comparisons` | **불필요**       |

**초안만 인증이 없다.** 비교 결과를 읽은 사람이 로그인 전에도 글감을 받아 볼 수 있고,
저장 시점에만 로그인을 요구한다.

### 대상(target) 규약

```
targetType: 'DISTRICT' | 'ADMINISTRATION' | 'COMMERCIAL'
```

**비교 초안의 대상은 행정동으로 고정한다**(`community-drafts.ts`). 비교는 두 상권에 관한
글이라 한쪽 상권에 붙이면 임의적이고, 그 행정동 피드에서 발견되지도 않는다. 요청 본문
조립을 API 모듈 한 곳에 둔 이유가 이것이다 — 화면이 각자 정하면 **글이 어떤 대상에 붙는지가
화면마다 갈린다.**

`periodCode` 도 비교 화면이 표를 그릴 때 쓴 상수를 그대로 쓴다. 초안이 다른 분기를 말하면
사용자가 방금 읽은 숫자와 글이 어긋난다.

### 정렬과 커서

| 보기        | `sortType`  | 커서 키                        |
| ----------- | ----------- | ------------------------------ |
| 최신        | `LATEST`    | `lastPostId`                   |
| 인기        | `POPULAR`   | `lastPostId` + `lastLikeCount` |
| 좋아요한 글 | (전용 경로) | `lastPostId`                   |

인기 정렬이 좋아요 수를 함께 실어야 하는 이유는 같은 좋아요 수의 글이 여러 개일 때 id 만으로
다음 쪽을 가릴 수 없기 때문이다.

### 인증 게이트 — 막지 않고 보낸다

```ts
const requireAuth = (action: () => void) => {
  if (!authReady) return // 판정 전에는 아무것도 하지 않는다
  if (!viewer.authenticated) {
    onRequireLogin()
    return
  }
  action()
}
```

**`authReady` 를 먼저 보는 것이 요점**이다. 회원 정보가 도착하기 전에는 「비로그인」이
아니라 「아직 모름」이라, 그 사이 누른 사람을 로그인으로 보내면 **이미 로그인한 사용자를
쫓아내는** 것이 된다.

### 작성자 표시 — 받은 대로 적는다

목록·검색·좋아요한 글·상세·댓글·답글 응답에 `writerNickname` · `writerProfileImageUrl` 이
실린다(BE #271, auth-service 실조회). **둘 다 null 가능**이다.

| 응답 값              | 뜻                              | 화면                                      |
| -------------------- | ------------------------------- | ----------------------------------------- |
| 닉네임 문자열        | 현재 닉네임(스냅샷 아님)        | 그대로 적는다                             |
| `"탈퇴회원"`         | 탈퇴 회원. 백엔드가 값으로 준다 | **그대로 적는다** — FE 가 판정하지 않는다 |
| `null`               | 회원 서비스 장애 · 미존재 회원  | 「사장님」(`COMMUNITY_WRITER_FALLBACK`)   |
| 프로필 이미지 `null` | 업로드본·소셜 사진 모두 없음    | 닉네임 첫 글자 이니셜 아바타              |

한 컴포넌트(`CommunityWriter`)가 세 화면을 다 맡는다. 화면마다 따로 적으면 null 처리가
한 곳에서 빠진다. 작성자 본인 판정은 여전히 `memberId` 다(S2 #6) — 닉네임은 중복될 수 있다.

### 화면 구성 — 개편 1단계 (2026-10-01)

근거와 전체 로드맵(2~4단계)은 [커뮤니티 UI/UX 개편 제안서](../../superpowers/specs/2026-10-01-community-ux-renewal.md)다.
여기에는 **확정돼 구현하는 동작만** 적는다. 1단계 목표는 두 가지다 — 모바일 첫 화면에 글이 보이게 하고,
상세 데스크톱 레이아웃 깨짐을 고친다.

**브레이크포인트**: `<480` 모바일 · `480–1079` 태블릿 · `≥1080` 데스크톱(DESIGN.md §8). 커뮤니티 화면은
레거시 640·760·768 을 쓰지 않는다. 1단계에서 목록은 모든 폭에서 `--w-read` 1단이다(3단 레일은 4단계).

#### 목록

| 영역       | 동작                                                                                                                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 헤더       | 소개 카드 대신 제목 한 줄. 기본 `사장님 이야기`, **대상이 있으면 `{board.targetName} 이야기`** + `전체 글 보기` 링크. 검색 중이면 `「{keyword}」 검색 결과`. `≥480` 은 오른쪽에 `글쓰기` 버튼                              |
| 툴바       | 검색 입력칸(돋보기 아이콘, Enter 제출, 값이 있으면 지우기 버튼) + **지역 칩**. 스크롤하면 사이트 헤더 아래에 붙는다(sticky). 「검색」 버튼은 없다                                                                          |
| 지역 칩    | 현재 범위를 적는다(`서울 전체` · `성수동`). 누르면 지역 선택 시트. 대상이 있으면 칩 옆 해제(✕) 버튼. **검색 중·좋아요한 글 보기에서는 비활성** — 검색은 서울 전체에서 하고(S4 계약) 좋아요한 글은 필터를 함께 푼다(CM-005) |
| 보기 전환  | 밑줄 탭 `최신` · `인기`. `좋아요한 글` 은 탭 줄 오른쪽 끝의 별도 토글 — 「보기」가 아니라 「내 활동」이라서다. URL(`view=liked`)과 필터 해제 규칙은 그대로                                                                 |
| 글 행      | 카드 대신 구분선으로 나눈 행. 위에서부터 `지역 · 시간` → 제목(16/600) → 미리보기 2줄(14/400) → `작성자 · ♡ · 💬`. `thumbnailUrl` 이 있으면 오른쪽 썸네일(`<480` 72px, 그 이상 96px). 인기 보기 상위 3건은 왼쪽에 순위 숫자 |
| 행 안 지역 | **글자 라벨이다, 링크가 아니다.** 행 전체가 링크라 안에 링크를 또 두면 중첩 인터랙티브가 된다                                                                                                                              |
| 다음 쪽    | 2단계에서 자동 무한 스크롤로 바뀌었다(아래 「목록 — 끊기지 않는 피드」)                                                                                                                                                    |
| 글쓰기     | `<480` 은 우하단 FAB. 목록 아래에 FAB 높이만큼 여백을 둬 마지막 행을 가리지 않는다                                                                                                                                         |

#### 지역 선택 시트

자치구 → 행정동 → 상권으로 **한 단계씩 들어가는 리스트**다. 3단 select 를 대체한다(목록만. 글쓰기는 3단계).

- 각 단계 첫 행이 `{상위 이름} 전체`(최상위는 `서울 전체`)다. 누르면 그 단계로 확정하고 닫는다.
  하위 단계로 들어가는 행은 `›` 를 단다. 상권 단계의 행은 바로 확정한다.
- 위쪽 경로(`서울 전체 › 성동구 › 성수1가1동`)를 누르면 그 단계로 돌아간다.
- 검색 입력은 **지금 보이는 단계의 목록을 클라이언트에서 거른다**. 하위 목록은 상위를 골라야 받아지므로
  단계를 건너뛰는 통합 검색은 하지 않는다(새 API 없음).
- 행정동·상권 목록은 지금 선택기와 같은 API·목 데이터를 쓴다. 불러오는 중 / 실패(`다시 시도`) 상태가 단계마다 있다.
- 시트를 닫으면(✕ · Esc · 바깥 누름) 아무것도 바꾸지 않는다. **고른 순간에만 URL 이 바뀐다** — 지금 선택기는
  select 를 바꿀 때마다 목록을 다시 불렀다.
- `<480` 바텀시트(위쪽 radius 16, 최대 높이 85dvh), `≥480` 가운데 다이얼로그(폭 420). 포커스를 가두고
  닫으면 칩으로 돌려준다.

| 반응 바    | 본문 끝 한 줄: `♡ 좋아요 N` · `💬 댓글 N` · `↗ 공유`. 아이콘 + 라벨 + 수, 높이 40. 좋아요한 상태는 하트를 채운다                                                                                                                                               |
| 공유       | `navigator.share` 가 있으면 그것을 쓰고(사용자가 취소하면 아무것도 하지 않는다), 없으면 주소를 클립보드에 복사하고 토스트 `링크를 복사했어요`. 복사가 실패하면 `링크를 복사하지 못했어요`. 로그인 불필요                                                       |
| 더보기(⋯)  | 내 글: `수정` · `삭제`(지금처럼 확인 후 삭제). 남의 글: `신고`(인증 게이트). `<480` 바텀시트 액션 목록, `≥480` 버튼 아래 팝오버. Esc · 바깥 누름으로 닫힌다                                                                                                    |
| 이 지역 글 | 레일 제목 `{지역} 최신 글`. 「현재 지역」 블록은 지역 칩과 겹쳐 뺀다. 비었으면 `{지역}의 다음 이야기를 남겨 보세요` + `글쓰기` 링크. **대상이 없는 글은 레일을 그리지 않는다** — 관련 글을 조회하지 않으니(`relatedParams=null`) 「비었다」고 말할 근거가 없다 |

분석 첨부 메모는 **링크 없이** 둔다 — `analysisRefCode` 형식이 계약으로 보장되지 않는다는 기존 판단을 유지한다.
댓글 영역 개편(목록 → 입력 순서, 하단 고정 바)은 2단계다.

#### 전역 내비

사이트 헤더에 `커뮤니티`(`/community/list`)를 다시 노출한다(채팅은 계속 숨김). 숨긴 채로는 개편 효과를 잴 수 없다.

### 화면 구성 — 개편 2단계 「참여」 (2026-10-01)

목표는 **읽은 자리에서 바로 반응하게** 하는 것이다 — 좋아요·댓글까지의 거리를 줄이고, 목록은 끊기지 않게 이어진다.
제안서 §4.1-D·E, §4.2-D·E 중 백엔드 없이 되는 것만 한다.

#### 댓글

| 영역        | 동작                                                                                                                                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 순서        | `댓글 N` → **목록** → **입력칸**. 읽고 나서 쓴다. 설명 문구(「운영 경험과 질문을 나누고…」)는 뺀다                                                                                                                                        |
| 빈 상태     | 목록 자리에 한 줄 `아직 댓글이 없어요. 첫 댓글을 남겨 보세요.` — 별도 카드를 띄우지 않는다                                                                                                                                                |
| 입력칸      | 평소 한 줄(높이 48)로 접혀 있다가 포커스하거나 내용이 있으면 3줄로 펼치고 글자 수 · `등록` 을 보인다. 비로그인은 그 자리에 `로그인하고 댓글 남기기`(돌아올 자리 보존, CM-002). `data-community-comment-entry` 는 이 두 요소에 그대로 둔다 |
| 댓글 행     | 카드 대신 구분선 행. `아바타 · 닉네임 · [글쓴이] · 시간(· 수정됨)` → 본문 → `♡ N · 답글 달기`. 시간은 **한 번만**(절대 날짜는 `title`), 수정됨 판정은 글과 같은 함수                                                                      |
| 글쓴이 배지 | 댓글 작성자가 글 작성자와 같으면(`memberId`) `글쓴이` 배지(blue50 바탕 · `text-primary-on-light`)                                                                                                                                         |
| 신고·삭제   | 행 오른쪽 더보기(⋯)로. 내 댓글은 `삭제`, 남의 댓글은 `신고`. 글 더보기와 같은 메뉴(`<480` 시트 · `≥480` 팝오버)                                                                                                                           |
| 좋아요      | 하트 아이콘 + 수, 좋아요한 상태는 채움. 처리 중엔 「처리 중」 글자 대신 `aria-busy` + 비활성. 터치 영역 36 이상                                                                                                                           |
| 답글        | depth 1 유지. 들여쓰기 + 작은 아바타. **답글이 4개 이상이면 앞 3개만 보이고 `답글 N개 더 보기`** 로 나머지를 펼친다                                                                                                                       |

#### 모바일 하단 고정 바 (`<480`)

- 본문 끝 반응 바가 화면에 보이지 않으면 하단에 고정 바가 뜬다: `[♡ N]  [댓글을 남겨 보세요…]  [↗]`.
  **위·아래 모두**다 — 긴 글을 읽는 중(반응 바가 아직 아래)에도 뜬다. 고치려던 문제가 「좋아요하려면 본문 끝까지 스크롤」이었다.
  댓글 입력칸이 화면 안에 보이면 숨긴다(입력칸과 겹치지 않게).
- 가운데 칸은 **진짜 입력칸이 아니라 버튼**이다. 누르면 댓글 입력칸으로 스크롤하고 포커스한다(비로그인이면 로그인 CTA 로).
  별도 입력 시트를 두지 않는 이유: 입력 상태가 두 곳으로 갈리고, iOS 에서 시트 안 입력칸 포커스가 키보드와 자주 어긋난다.
- 좋아요·공유는 본문 반응 바와 **같은 핸들러**를 쓴다(인증 게이트 · 공유 연타 가드 그대로).
- 높이 56 + `safe-area-inset-bottom`. 바가 있는 동안 **body 끝에** 같은 높이의 여백을 둔다 — 셸에서 푸터가 main 뒤에 오므로
  main 안에 여백을 두면 맨 아래 푸터가 가려진다.

#### 목록 — 끊기지 않는 피드

| 영역         | 동작                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 다음 쪽      | 목록 끝 감시 요소(IntersectionObserver, 여유 400px)가 보이면 자동으로 다음 쪽을 부른다. 다음 쪽 실패면 그 자리에 `다시 불러오기`. 「게시글 더 보기」 버튼은 없앤다                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 로딩         | 첫 로딩은 글 행 모양 스켈레톤 5줄, 다음 쪽 로딩은 2줄. 피드에는 `aria-live` 를 두지 않는다 — 자동 다음 쪽마다 20건을 통째로 읽게 된다. 알림은 스켈레톤(status)·실패(alert)·끝(status)이 각자 맡는다                                                                                                                                                                                                                                                                                                                                                                                                       |
| 끝           | `hasNext=false` 이고 글이 있으면 `여기까지 다 봤어요` + `글쓰기` 링크                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 뒤로 가기    | 상세에서 **브라우저 뒤로/앞으로**(popstate)로 돌아오면 누른 행을 같은 화면 높이에 다시 둔다. 헤더 링크 등 새 진입은 맨 위에서 시작한다. 불러온 쪽은 쿼리 캐시가 들고 있는 동안만 다시 그려진다 — 수명은 staleTime 이 아니라 gcTime(기본 5분)이라 자리(`sessionStorage`)도 5분 뒤 버린다. 캐시가 사라져 누른 행이 다시 그려지지 않으면 복원하지 않는다(맨 위). 기본 스크롤 복원은 목록이 다시 그려지기 전에 걸려 잘린다. 뒤로 가기 여부는 **마운트 다음 프레임**에 판정한다 — 라우터가 popstate 리스너 안에서 목록을 동기로 다시 그려, 마운트 순간에는 목록의 popstate 구독이 아직 불리지 않았다(e2e 실측) |
| FAB (`<480`) | 아래로 스크롤하면 아이콘만 남은 원형(56)으로 줄고, 위로 올리거나 맨 위면 다시 `글쓰기` 를 펼친다. `aria-label` 은 늘 `글쓰기`. `prefers-reduced-motion` 이면 모양 전환 애니메이션을 끈다. 펼친 높이도 56 으로 맞춰 접을 때 높이가 튀지 않는다                                                                                                                                                                                                                                                                                                                                                             |

### 화면 구성 — 개편 3단계 「글쓰기」 (2026-10-01)

목표는 **쓰고 싶은 말부터 쓰게** 하고, **쓴 글을 잃지 않게** 하는 것이다. 제안서 §4.3·§4.4.

#### 글쓰기 · 수정 (`/community/register`)

| 영역           | 동작                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 머리           | 안내 세 줄(아이브로·제목·설명)을 제목 한 줄 `새 글` / `글 수정` 으로 줄인다. `<480` 은 사이트 헤더 아래에 붙는 편집 바 `[✕] 새 글 [등록]` 가 머리를 대신한다                                                                                      |
| 순서           | **지역 칩 → 제목 → 본문 → 사진.** 지역 select 3단을 1단계의 지역 선택 시트(칩)로 바꾼다. 칩이 비어 있으면 `어느 지역 이야기인가요?`                                                                                                               |
| 지역 프리필    | 목록·상세에서 들어오면 그 지역이 채워진다: `?targetType=&targetCode=&targetName=`(목록 대상, 상세 글의 대상). 형식이 틀린 값은 버린다. 비교 초안(`draftSource=comparison`)이 있으면 초안의 행정동이 이긴다. 수정 모드의 칩은 읽기 전용(지금 규칙) |
| 시트           | 글쓰기 시트에는 최상위 `서울 전체` 확정 행이 없다 — 글은 대상이 필수라 고르면 다시 빈 값이 된다. 키보드 위 툴바는 두지 않는다(사진 줄 `+` 와 글자 수로 충분하고, `visualViewport` 추적이 따로 필요하다)                                           |
| 지역 없이 등록 | 등록을 누르면 칩으로 포커스를 옮기고 시트를 연다. 안내 문구는 칩 아래 한 줄 `지역을 골라 주세요`(CM-008 유지)                                                                                                                                     |
| 제목           | 테두리 없는 큰 입력(20/600), 120자                                                                                                                                                                                                                |
| 본문           | 내용에 맞춰 늘어나는 입력칸(최소 8줄), 5,000자. 글자 수는 한도 90% 를 넘으면 `--color-negative-text`                                                                                                                                              |
| 작성 도움 칩   | 본문이 비어 있을 때만 본문 위에 `질문해요` · `경험 나눠요` · `같이 해요`. 누르면 본문에 짧은 틀을 넣고 커서를 첫 빈 줄로 옮긴다. 저장되는 것은 그냥 본문이다(말머리 아님, BE 변경 없음)                                                           |
| 사진           | 썸네일 가로 줄(72) + 끝에 `+` 타일. 첫 장에 `대표` 배지(목록 썸네일이 된다). 업로드 중 타일은 진행 표시. 기존 규칙(5장·5MB·형식, 수정 모드는 기존 이미지를 들고 시작)은 그대로                                                                    |
| 등록 버튼      | `<480` 은 편집 바의 `등록`, 그 이상은 하단에 붙는 액션 바 `[취소] [등록하기]`. 필수값(지역·제목·본문)이 비면 비활성이 아니라 **눌렀을 때 무엇이 비었는지 알려 준다**(비활성 버튼은 이유를 말하지 않는다)                                          |
| 업로드 중 등록 | 사진을 올리는 중에 누르면 보내지 않고 사진 줄 아래에 `사진을 올리는 중이에요. 끝나면 다시 눌러 주세요.`(비활성 대신 안내). 업로드가 끝나면 안내가 걷힌다. 그대로 보내면 올리던 사진이 빠진 채 저장된다                                            |
| 중복 등록      | 저장 중, 그리고 **성공한 뒤 상세로 이동이 끝나기 전까지** 두 등록 버튼을 끄고 제출을 무시한다 — 그 사이 다시 누르면 같은 글이 또 생긴다                                                                                                           |
| 제목 Enter     | 제목 칸의 Enter 는 제출이 아니라 본문으로 포커스를 옮긴다. 한글 조합 중 Enter(`isComposing` · keyCode 229)와 조합 키를 낀 Enter 는 건드리지 않는다                                                                                                |
| 작성 팁        | `≥1080` 에서 폼 오른쪽에 작성 팁 카드(좋은 글 예시 3줄). 그 아래 폭에서는 없다                                                                                                                                                                    |

#### 잃지 않게 — 임시 저장 · 이탈 확인

- 입력이 멈추고 1초 뒤 `localStorage` 에 **제목·본문·지역**을 저장한다. 키: 새 글 `community-draft:{memberId}:new`, 수정
  `community-draft:{memberId}:edit:{postId}`(목 모드는 목 회원 id). 등록·수정 성공 시 지운다. 저장 실패(용량·사생활 모드)는
  조용히 넘긴다.
- **키에 회원 id 를 넣고, 로그아웃하면 `community-draft:` 로 시작하는 키를 모두 지운다**(사이트 헤더 로그아웃). 공용 기기에서
  다음 계정이 앞 사람의 쓰던 글을 「이어 쓰기」로 보면 안 된다. 회원 id 를 모르면(로그인 판정 전·비로그인) 저장도 복원도 하지
  않는다. 401 로 로그인에 보내질 때는 지우지 않는다 — 같은 계정으로 돌아와 이어 쓴다.
- **두 탭이 같은 키를 쓰면 마지막 저장이 이긴다.** 한쪽이 등록에 성공하면 저장본이 지워진다 — 다른 탭에 열린 글은 그 탭의
  `beforeunload` 확인이 지키고, 그 탭에서 다시 치면 다시 저장된다. 탭 사이 잠금은 두지 않는다.
- **사진은 저장하지 않는다.** 올린 사진 키는 저장 전까지 어떤 글에도 연결되지 않아 백엔드 회수 배치가 지울 수 있다 —
  되살린 초안에 깨진 사진이 남는 것보다 다시 고르게 하는 편이 낫다.
- 다시 들어왔을 때 저장본이 있으면 **폼을 띄우기 전에** 고르게 한다: `작성하던 글이 있어요` + `[새로 쓰기]` `[이어 쓰기]`.
  폼은 마운트 시점 값만 읽으므로(`initialValue`) 뒤늦게 덮어쓰면 그 사이 친 글자가 사라진다. 비교 초안으로 들어온
  경우에는 묻지 않는다(초안이 이긴다).
- **비교 초안으로 들어오면 임시 저장을 끈다**(실패·깨진 초안 링크 포함). 초안 글을 새 글 키(`…:new`)에 쓰면 따로 쓰던
  저장본을 덮는다. 그래서 이때의 이탈 확인은 `작성 중인 글이 저장되지 않아요. 나갈까요?` 다 — 「임시 저장돼요」는 거짓이 된다.
- 「바뀌었는지」의 기준은 **원래 값**(빈 폼 · 수정 원본)이다. 이어 쓰기 직후도 바뀐 상태다. 기준을 저장본으로 두면 이어 쓰기
  직후 autosave 가 「바뀐 것 없음」으로 보고 저장본을 지운다.
- 입력이 1초를 채우기 전에 나가면(언마운트 · `pagehide`) 그 자리에서 저장한다. 등록을 눌러 **저장 중**이 될 때도 잡힌
  저장을 버리지 않고 곧바로 쓴다(401 로 로그인에 보내지며 폼이 사라져도 남게). 버리는 것은 **성공한 뒤**뿐이다.
- 이어 쓰기로 시작해 원래 값(빈 글 · 수정 원본)으로 되돌리면 저장본을 지운다 — 아직 한 번도 새로 쓰지 않았어도 그 키에는
  이어 쓴 저장본이 있다.
- 내용이 바뀐 채로 `✕` · `취소` 를 누르면 `작성 중인 글은 임시 저장돼요. 나갈까요?` 확인. 새로고침·탭 닫기는
  `beforeunload`. 헤더 링크 같은 앱 안 이동은 막지 않는다 — 임시 저장이 대신 지킨다.

### 화면 구성 — 개편 4단계 「넓은 화면」 (2026-10-01)

목표는 **넓은 화면이 주는 자리를 탐색에 쓰는 것**, 그리고 사진을 제대로 보여 주는 것이다. 제안서 §4.1-F, §4.2-C·F.

#### 목록 3단

| 폭          | 골격                                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<1080`     | 지금 그대로(1단)                                                                                                                                                                     |
| `1080–1359` | 피드(`--w-read`) + 우 레일 300. 탭은 피드 위에 그대로                                                                                                                                |
| `≥1360`     | 좌 내비 240 · 피드 `--w-read` · 우 레일 300(간격 24, 합계 1308 — `--w-wide` 안). **탭 줄은 숨기고 좌 내비가 대신한다** — 같은 조작이 두 곳에 있으면 어느 쪽이 지금 상태인지 헷갈린다 |

1360 은 3단 1308 + 셸 거터 40 이 들어가는 첫 폭을 올림한 값이다.

- **좌 내비**(sticky): `보기` — 최신 · 인기 / `내 활동` — 좋아요한 글 / `최근 본 지역` — 지역 게시판을 열 때마다 `localStorage` 에
  최대 5개(최근 순, 중복 제거) 기록하고 링크로 보여 준다. 없으면 그 묶음을 그리지 않는다. 지금 상태 항목은 `aria-current` —
  `page` 는 연 지역 게시판(최근 본 지역 항목) 하나에만, 보기·내 활동은 `true`(주소 하나가 둘을 함께 정해 `page` 가 둘이면
  「현재 페이지」를 두 번 읽는다. 서울 전체면 `page` 항목이 없다). URL 계약(`view`·대상)과 CM-005 는 그대로.
  최근 본 지역은 회원이 아니라 **브라우저 단위**다(비로그인 열람도 남긴다). **로그아웃하면 지운다** — 3단계 임시 저장과 같은
  이유로 공용 기기의 다음 사람에게 앞 사람이 본 동네를 보여 주지 않는다.
- **우 레일**(sticky):
  1. `인기 글` — 같은 목록 API 를 `sortType=POPULAR`, 5건으로 한 번 더 부른다. 대상을 고른 중이면 그 대상으로(`{지역} 인기 글`).
     검색 중·좋아요한 글 보기에서는 서울 전체 인기 글. 순위 숫자 + 제목 한 줄 + ♡ 수. 비면 묶음을 숨긴다. 실패하면 조용히 숨긴다
     (레일은 보조라 오류 카드를 띄우지 않는다).
  2. 글쓰기 유도 카드 — `{지역}에 대해 물어보세요` / 대상 없으면 `사장님들께 물어보세요` + `글쓰기`(프리필 링크).
  3. 분석 연결 — 대상이 **자치구**면 `{구} 상권 분석 보기`(`/analysis?districtCode=`). 행정동·상권은 상위 코드를 계약으로
     알 수 없어 `상권 분석에서 찾아보기`(`/analysis`)로 둔다.
- 1단에서는 레일 내용을 그리지 않는다(모바일 첫 화면 글 수를 지킨다). 폭은 matchMedia 로 판정해 **렌더와 인기 글 쿼리를 함께**
  막는다 — CSS 로만 숨기면 모바일에서도 요청이 나간다. 그리드 트랙은 판정 전(서버 렌더)부터 잡혀 있어 레일이 늦게 와도 피드가 밀리지 않는다.
- 인기 글 쿼리 키는 목록 키와 따로 둔다(`['community','popular',…]`). 상세에서 좋아요·댓글을 하면 목록 키와 함께 무효화한다.
  레일 글 링크는 지금 보던 목록의 맥락 키를 실어 상세의 `← 목록` 이 그 목록으로 돌아온다. 공개 목록 401 복구(세션 정리 뒤
  익명 재조회)가 끝나면 인기 글 키도 무효화한다 — 같은 401 로 숨어 있던 묶음이 돌아온다.
- 레일 글을 눌러 상세에 갔다가 뒤로 와도 보던 자리에 선다(CM-030). 누른 링크는 피드 행이 아니라 **화면 안 첫 피드 행**을
  기준 행으로 남긴다(위가 헤더 밑으로 잘린 행 포함 — 같은 화면 높이에 되돌리니 보던 화면이 그대로다). 화면에 피드 행이 없으면
  (목록이 비었거나 실패) 옛 자리를 지운다 — 예전에 누른 글 자리로 돌아가면 엉뚱한 곳에 떨어진다.
- 탭 줄은 `≥1360` 이라도 **좌 내비가 실제로 그려졌을 때만** 숨긴다. 서버 렌더 중에 탭까지 숨기면 잠깐 조작할 곳이 없다.

#### 상세 레일 보강 (`≥1080`)

- 레일에 `이전 글 · 다음 글`(인접 글이 있을 때)을 `{지역} 최신 글` 위에 둔다. `≥1080` 에서는 본문 아래 인접 글 묶음을
  그리지 않는다(CSS 로 숨긴 한쪽은 접근성 트리에서도 빠진다). 대상 없는 글도 인접 글이 있으면 레일을 그린다.
- sticky 레일 칸은 높이를 화면에 묶는다(`max-height: calc(100dvh - 88px - 24px)`, 칸 안 스크롤, overscroll 막음) — 낮은
  화면에서 인접 글 + 지역 글 5건이 화면보다 길면 아래가 잘려 닿을 수 없다. 링크·버튼은 카드 안쪽 여백 안이라 포커스 링이 잘리지 않는다.

#### 사진 보기

- **라이트박스**: 본문 사진을 누르면 전체 화면 보기. 어두운 바탕(`--color-overlay` 계열) · 가운데 사진(비율 유지) ·
  `n / 전체` · 이전/다음 버튼 · 닫기. 키보드 ←/→/Esc, 터치 좌우 스와이프(40px 이상). 포커스를 가두고 닫으면 누른 사진으로
  돌려준다. 열려 있는 동안 스크롤 잠금. 사진 하나면 이전/다음을 그리지 않는다.
  핀치로 확대한 동안(`visualViewport.scale > 1`)은 스와이프로 넘기지 않고 사진 칸의 `touch-action` 을 `auto` 로 돌려
  확대한 사진을 가로로도 둘러보게 한다(평소는 `pan-y pinch-zoom`). `visualViewport` 가 없는 브라우저는 지금처럼 넘긴다.
- **모바일 사진 줄**(`<480`, 사진 2장 이상): 세로 나열 대신 가로 스와이프(scroll-snap) + 점 표시(지금 장).
  `≥480` 은 세로 나열 그대로. 어느 쪽이든 누르면 라이트박스.
- 사진 `alt` 는 지금 규칙(`첨부 이미지 n`) 유지.
- 라이트박스 바탕은 `--color-overlay`(0.5)를 세 겹 쌓아 0.875 로 만든다(DESIGN.md Overlay Scrim 범위 안) — 한 겹이면 뒤 글자가 비친다.
  끝 장의 이전/다음은 `disabled` 대신 `aria-disabled` 다(누른 버튼이 비활성이 되면 포커스가 body 로 빠져 가두기가 깨진다).
  키보드는 document 에서 받는다. **바탕을 눌러도 닫지 않는다** — 스와이프 직후 click 이 닫기로 오인된다. 모바일 줄의 `n / 전체` 는
  live 가 아니다(넘길 때마다 읽으면 시끄럽다).

#### 숨는 헤더 (목록, `<480`)

- 목록을 아래로 스크롤하면 사이트 헤더가 위로 숨고 검색·지역 툴바만 맨 위에 붙는다. 위로 올리거나 맨 위면 헤더가 돌아온다.
  방향 판정은 FAB 축소와 같은 규칙(누적 8px · 80 미만은 펼침)을 쓴다. 헤더의 메뉴 패널이 열려 있으면 숨기지 않는다.
- 목록 화면만 켠다(다른 화면 헤더는 그대로). `prefers-reduced-motion` 이면 전환 없이 바뀐다.
- 목록은 `<html data-community-header-hidden>` 만 켜고 끈다(언마운트 때 지운다). 헤더와 툴바는 같은 선택자를 읽고, 헤더 메뉴가
  열려 있거나 헤더 안에 **키보드 포커스**가 있으면(`:has([data-site-header] :focus-visible)`) 둘 다 원래 자리다. `:focus-within`
  으로 넓히지 않는다 — Android 는 탭한 버튼에 포커스가 남아 숨는 헤더가 사실상 꺼진다. `:has` 를 모르는 브라우저는 헤더가 숨지 않을 뿐 툴바와 어긋나지 않는다.
  스크롤 구독은 FAB 축소와 하나로 쓴다.
