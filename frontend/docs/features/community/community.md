| 연관 기능 / 의존성 | `/recommend/compare` 가 **비교 초안**으로 글쓰기를 연다 · 프로필이 좋아요한 글을 쓴다 · 회원 정보(작성자 판정) |

**이 문서는 사후 작성이다.** 화면은 이미 구현·머지됐고 설계 기록은 저장소 루트

(`frontend/docs/` 가 아니라 **저장소 루트 `docs/`** 아래라 찾기 어렵다).

> ⚠️ **기획 문서 없이 코드에서 역으로 적었다.** 「무엇을 만들기로 했는가」가 아니라
> **「무엇이 만들어져 있는가」**를 기록한다. 의도와 갈리는 부분이 있으면 원래 의도가 맞다.

### ⚠️ 실데이터 확인이 막혀 있다

**dev 백엔드에 `commercial_region_mapping` 테이블이 없어 글쓰기가 404 다**(BE 이슈 #190).

이유로 「dev 에 글 0건」인 채 끝났다.

## S1. 기능 개요

사용자는 **지역에 붙은 글**을 목록에서 보고(최신·인기·좋아요한 글), 검색하고, 하나를 열어
읽고 댓글·답글·좋아요로 참여한다. 글을 쓸 때는 대상 지역을 고르고, `/recommend/compare` 에서
넘어온 경우 백엔드가 만든 **비교 초안**이 제목·본문을 미리 채운다.

```
목록(커서 페이지네이션) → 상세 → 댓글·좋아요
글쓰기: 대상 지역 선택 → 작성 → POST /community/posts
비교 초안: /recommend/compare → POST …/drafts/commercial-comparisons → 글쓰기 화면 프리필
```

## S2. 공통 요구사항

| #   | 요구사항                                                                                                    | 상세 참조                        |
| --- | ----------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 1   | **읽기는 로그인 없이** 된다. 쓰기(글·댓글·좋아요·신고)만 로그인이 필요하다                                  | S4 인증 게이트                   |
| 2   | 로그인이 필요한 동작을 누르면 **막지 말고 로그인으로 보낸다**. 돌아올 자리를 잃지 않는다                    | `requireAuth` → `onRequireLogin` |
| 3   | 목록은 **커서 페이지네이션**이다. 정렬에 따라 커서 키가 다르다(`lastPostId` · `lastLikeCount`)              | S4 계약                          |
| 4   | 목록의 보기·검색어·대상은 **URL 에 실린다** — 공유·뒤로가기가 같은 목록을 낸다                              | S3 #1                            |
| 5   | 글은 반드시 **대상(`targetType` + `targetCode`)에 붙는다.** 대상 없는 글은 만들지 않는다                    | S3 #4                            |
| 6   | 작성자 본인에게만 수정·삭제를 보인다. 판정은 회원 정보의 `memberId` 로 한다                                 | `viewer.memberId`                |
| 7   | 이미지 첨부는 **전용 업로드 API** 를 쓴다(`POST /community/posts/images`, PR #198). 「준비 중」 안내는 없다 | S4 계약                          |

## S4. 세부 명세

세부 명세는 아직 없다. 아래는 공통 명세가 짊어지고 있는 계약·규약이다.

### 백엔드 계약 (실측)

| 동작                | 호출                                                  | 인증             |
| ------------------- | ----------------------------------------------------- | ---------------- |
| 목록                | `GET /community/posts`                                | —                |
| 검색                | `GET /community/posts/search`                         | —                |
| 좋아요한 글         | `GET /community/posts/liked`                          | 필요             |
| 상세                | `GET /community/posts/{id}`                           | —                |
| 작성 · 수정 · 삭제  | `POST` · `PATCH` · `DELETE /community/posts[/{id}]`   | 필요             |
| 글 좋아요 토글      | `POST /community/posts/{id}/likes`                    | 필요             |
| 댓글 목록·작성·삭제 | `…/{id}/comments[/{commentId}]`                       | 작성·삭제만 필요 |
| 댓글 좋아요 토글    | `…/comments/{commentId}/likes`                        | 필요             |
| 신고                | `POST /community/reports`                             | 필요             |
| 이미지 업로드       | `POST /community/posts/images`                        | 필요             |
| 비교 초안           | `POST /community/posts/drafts/commercial-comparisons` | **불필요**       |

**초안만 인증이 없다.** 비교 결과를 읽은 사람이 로그인 전에도 글감을 받아 볼 수 있고,
저장 시점에만 로그인을 요구한다.

### 대상(target) 규약

```
targetType: 'DISTRICT' | 'ADMINISTRATION' | 'COMMERCIAL'
```

**비교 초안의 대상은 행정동으로 고정한다**(`community-drafts.ts`). 비교는 두 상권에 관한
글이라 한쪽 상권에 붙이면 임의적이고, 그 행정동 피드에서 발견되지도 않는다. 요청 본문
조립을 API 모듈 한 곳에 둔 이유가 이것이다 — 화면이 각자 정하면 **글이 어떤 대상에 붙는지가
화면마다 갈린다.**

`periodCode` 도 비교 화면이 표를 그릴 때 쓴 상수를 그대로 쓴다. 초안이 다른 분기를 말하면
사용자가 방금 읽은 숫자와 글이 어긋난다.

### 정렬과 커서

| 보기        | `sortType`  | 커서 키                        |
| ----------- | ----------- | ------------------------------ |
| 최신        | `LATEST`    | `lastPostId`                   |
| 인기        | `POPULAR`   | `lastPostId` + `lastLikeCount` |
| 좋아요한 글 | (전용 경로) | `lastPostId`                   |

인기 정렬이 좋아요 수를 함께 실어야 하는 이유는 같은 좋아요 수의 글이 여러 개일 때 id 만으로
다음 쪽을 가릴 수 없기 때문이다.

### 인증 게이트 — 막지 않고 보낸다

```ts
const requireAuth = (action: () => void) => {
  if (!authReady) return // 판정 전에는 아무것도 하지 않는다
  if (!viewer.authenticated) {
    onRequireLogin()
    return
  }
  action()
}
```

**`authReady` 를 먼저 보는 것이 요점**이다. 회원 정보가 도착하기 전에는 「비로그인」이
아니라 「아직 모름」이라, 그 사이 누른 사람을 로그인으로 보내면 **이미 로그인한 사용자를
쫓아내는** 것이 된다.

### `?mock=1` — dev 데이터가 없어서 있는 길

목록·상세는 `?mock=1` 로 **목 데이터 소스**로 갈아 끼울 수 있다(`community-mock.ts`).
dev 백엔드에 글이 0건이라(BE #190) 레이아웃·상호작용을 볼 방법이 달리 없었다.

> ⚠️ **목 모드는 검증 보조 수단이지 기능이 아니다.** BE #190 이 풀리면 이 경로가 계속 필요한지
> 다시 판단한다 — 남겨 두면 「목으로는 되는데 실데이터로는 안 되는」 차이를 못 보게 된다.

## S5. 테스트케이스

| TC     | 검증 내용                             | 기대 결과                                               |
| ------ | ------------------------------------- | ------------------------------------------------------- |
| CM-001 | 비로그인으로 목록·상세 진입           | 읽을 수 있다. 로그인 요구 없음                          |
| CM-002 | 비로그인으로 좋아요·댓글 시도         | 로그인으로 보내고, 돌아올 자리를 잃지 않는다            |

| CM-005 | 좋아요한 글 보기로 전환               | 검색어·대상 필터가 **함께 해제**된다                    |

| CM-008 | 글 작성 — 대상 지역 미선택            | 저장되지 않는다                                         |
| CM-009 | `/recommend/compare` 에서 글쓰기 진입 | 제목·본문이 초안으로 채워지고 대상은 **행정동**이다     |
| CM-010 | 비로그인으로 비교 초안 진입           | 초안은 받아지고, 저장 시점에 로그인을 요구한다          |
| CM-011 | 작성자 본인 / 타인으로 상세 열람      | 수정·삭제가 본인에게만 보인다                           |
| CM-012 | 신고 사유 500자 초과 · 공백만         | 각각 안내 문구가 뜨고 전송되지 않는다                   |
| CM-013 | 이미지 첨부 후 저장                   | 전용 업로드 API 를 거쳐 본문에 실린다                   |
| CM-014 | 모바일·데스크톱 목록·상세             | 가로 스크롤 없음                                        |
