## S1. 기능 개요

사용자는 **지역에 붙은 글**을 목록에서 보고(최신·인기·좋아요한 글), 검색하고, 하나를 열어
읽고 댓글·답글·좋아요로 참여한다. 글을 쓸 때는 대상 지역을 고르고, `/recommend/compare` 에서
넘어온 경우 백엔드가 만든 **비교 초안**이 제목·본문을 미리 채운다.

```
목록(커서 페이지네이션) → 상세 → 댓글·좋아요
글쓰기: 대상 지역 선택 → 작성 → POST /community/posts
비교 초안: /recommend/compare → POST …/drafts/commercial-comparisons → 글쓰기 화면 프리필
```

## S4. 세부 명세

세부 명세는 아직 없다. 아래는 공통 명세가 짊어지고 있는 계약·규약이다.

### 백엔드 계약 (실측)

| 동작                | 호출                                                  | 인증             |
| ------------------- | ----------------------------------------------------- | ---------------- |
| 목록                | `GET /community/posts`                                | 선택(#471)       |
| 검색                | `GET /community/posts/search`                         | 선택(#471)       |
| 좋아요한 글         | `GET /community/posts/liked`                          | 필요             |
| 상세                | `GET /community/posts/{id}`                           | 선택(#471)       |
| 작성 · 수정 · 삭제  | `POST` · `PATCH` · `DELETE /community/posts[/{id}]`   | 필요             |
| 글 좋아요 토글      | `POST /community/posts/{id}/likes`                    | 필요             |
| 댓글 목록·작성·삭제 | `…/{id}/comments[/{commentId}]`                       | 작성·삭제만 필요 |
| 댓글 좋아요 토글    | `…/comments/{commentId}/likes`                        | 필요             |
| 신고                | `POST /community/reports`                             | 필요             |
| 이미지 업로드       | `POST /community/posts/images`                        | 필요             |
| 비교 초안           | `POST /community/posts/drafts/commercial-comparisons` | **불필요**       |

**초안만 인증이 없다.** 비교 결과를 읽은 사람이 로그인 전에도 글감을 받아 볼 수 있고,
저장 시점에만 로그인을 요구한다.

**조회수·내 좋아요(#471, BE #539).** 목록·검색·좋아요한 글 항목과 상세 응답에 `viewCount` 와
`liked` 가 있다. 목록·검색·상세는 **선택 인증**이다 — 로그인이면 `liked` 가 `true`/`false`, 비로그인이면
`null` 이고 **`null` 은 「안 누름」이 아니라 「모름」**이라 좋아요 상태를 그리지 않는다. 좋아요한 글의
`liked` 는 늘 `true` 다. FE 가 따로 할 일은 없다 — BFF 가 세션이 있을 때만 `Authorization` 을 붙이고,
재발급에 실패하면 세션을 지운 뒤 익명으로 보낸다. BFF 의 백엔드 호출은 `cache: 'no-store'` 를 명시한다
(조회자별 응답이라 Next data cache 에 넣지 않는다).

- **쿼리 키에 조회자를 넣는다.** 목록·레일 인기 글·상세·관련 글 키 끝에 `memberId`(비로그인 `'anonymous'`,
  목 모드는 목 회원 id)를 붙인다. 기본 `staleTime` 이 5분이라 그러지 않으면 로그아웃·다른 계정 로그인 뒤에도
  앞사람의 `liked` 가 캐시에서 나온다. 좋아요한 글 보기에만 붙이던 `'member'` 세그먼트는 이 자리로 합쳤다.
- **로그인 확인(`/api/auth/me`) 뒤에 공개 쿼리를 시작한다.** 확인 전에는 키가 `'anonymous'` 라, 그때 부르면
  회원 응답이 익명 키에 들어가고 확인 뒤 같은 목록을 또 받는다(상세면 조회수가 두 번 오른다). 그동안은 첫 로딩
  상태(스켈레톤)다. 목 모드는 기다리지 않는다. 확인 요청에는 타임아웃이 없어, 목록·상세는 **2.5초**
  (`COMMUNITY_VIEWER_WAIT_LIMIT_MS`)까지만 기다리고 그 뒤에는 익명으로 시작한다 — 나중에 확인이 끝나 회원으로
  바뀌면 회원 키로 한 번 더 받는다. 좋아요·로그인 유도는 상한과 상관없이 확인이 끝나야 켜진다.
- **공개 쿼리 401 복구.** 회원 키에서 401 이 나면 실패한 키(목록, 상세·관련 글)를 지우고 세션만 지운다 —
  조회자 세그먼트가 `'anonymous'` 로 바뀌어 새 키가 익명으로 받는다. 옛 키를 다시 부르지 않는 것은 중복 요청·
  조회수 이중 증가를 막고, 401 을 품은 키가 남아 같은 회원이 다시 로그인했을 때 복구가 또 돌지 않게 하려는 것이다.
  조회자가 없는 댓글 키와 익명 키는 예전처럼 같은 키를 다시 부른다. 범위당 한 번만 시도하는 규칙은 그대로다.

**말머리(#470, BE #539).** 작성·수정 요청에 선택 필드 `category`(`QUESTION` · `EXPERIENCE` · `TOGETHER` · `NEWS`,
대문자로 보낸다), 목록·검색·좋아요한 글 항목과 상세 응답에 `category: {code, name, description} | null`(말머리 없는 글 —
기존 글 전부 — 은 `null`), 피드(`GET /posts`)에만 쿼리 `category` 가 있다. 표시명은 `질문` · `경험 공유` · `같이 해요` ·
`동네 소식` 이고 FE 표(`lib/community/post-category.ts`)가 BE `name` 과 글자까지 같다.

- **작성**: 말머리를 고르지 않았으면 `category` 키를 뺀다(말머리 없음).
- **수정은 전체 교체다 — `category` 를 빼면 말머리가 지워진다**(`imageKeys` 와 같은 함정). 수정 화면은 상세 응답의
  `category.code` 로 칩을 채우고 **건드리지 않았어도 같은 code 를 다시 싣는다.** 키를 빼는 것은 사용자가 해제했을 때뿐이다.
  FE 가 모르는 code 의 글은 보낼 값이 없어 말머리 없음으로 시작한다 — 그 글을 수정하면 말머리가 지워진다(알려진 값만 보낼 수 있다).
- **응답 code 는 `string` 으로 받는다.** BE 가 값을 더해도 화면이 죽지 않게 — 분기·필터는 알려진 네 값만 쓰고, 배지는 `category.name`
  을 그대로 적는다(모르는 말머리도 이름은 보인다). 옛 BE 응답에 필드가 없어도 렌더가 깨지지 않게 `category?.name` 으로 읽는다.
- 잘못된 값은 `400 COMMUNITY_017`(작성·수정·목록 공통). 화면은 알려진 값만 보내므로 사실상 일어나지 않고, 일어나면 지금의
  서버 문구 그대로 경로로 보인다. URL 의 모르는 `category` 는 서버에 보내기 전에 「전체」로 읽는다.

**신고 사유 코드(#473, BE #539).** 신고 요청은 `{ targetKind, targetId, reasonCode, detail? }` 다. `reasonCode` 는
`SPAM` · `ABUSE` · `PRIVACY` · `FALSE_INFO` · `ETC`, `detail` 은 선택이고 500자 이하(`400 COMMUNITY_124`), `ETC` 만 필수
(`400 COMMUNITY_123`)다. **레거시 `reason` 은 보내지 않는다**(BE 에 호환용으로 남아 있고, `reasonCode` 가 있으면 서버가 무시한다).
상세는 걷어 내서 비면 키째 뺀다. 사유 code 가 없으면 `400 COMMUNITY_110`, 모르는 code 는 `400 COMMUNITY_018`.

- **배포 순서: BE 먼저.** #539 이전 BE 는 `reason` 이 필수라 이 요청을 `COMMUNITY_110` 으로 막는다.
- **안내 자리는 `resultCode` 로 정한다** — `api-error.ts` 의 「코드로 UI 분기하지 않는다」의 명시적 예외다. 110·123 은 요청 모양
  검증이라 `errors[].field` 가 입력칸 이름이 아니라 `reasonPresent`·`etcDetailPresent` 로 온다. 110·018 → 사유 선택, 123·124 →
  상세 입력칸, 그 밖(중복 신고 `409 COMMUNITY_009` 등) → 일반 오류 자리(`lib/community/report-reason.ts` 의
  `getCommunityReportErrorField`). 200 + `success: false` 경로도 같은 코드를 읽도록 `CommunityDetailQueryError` 가 `resultCode` 를 싣는다.

### 대상(target) 규약

```
targetType: 'DISTRICT' | 'ADMINISTRATION' | 'COMMERCIAL'
```

**비교 초안의 대상은 행정동으로 고정한다**(`community-drafts.ts`). 비교는 두 상권에 관한
글이라 한쪽 상권에 붙이면 임의적이고, 그 행정동 피드에서 발견되지도 않는다. 요청 본문
조립을 API 모듈 한 곳에 둔 이유가 이것이다 — 화면이 각자 정하면 **글이 어떤 대상에 붙는지가
화면마다 갈린다.**

`periodCode` 도 비교 화면이 표를 그릴 때 쓴 상수를 그대로 쓴다. 초안이 다른 분기를 말하면
사용자가 방금 읽은 숫자와 글이 어긋난다.

### 정렬과 커서

| 보기        | `sortType`  | 커서 키                        |
| ----------- | ----------- | ------------------------------ |
| 최신        | `LATEST`    | `lastPostId`                   |
| 인기        | `POPULAR`   | `lastPostId` + `lastLikeCount` |
| 좋아요한 글 | (전용 경로) | `lastPostId`                   |

인기 정렬이 좋아요 수를 함께 실어야 하는 이유는 같은 좋아요 수의 글이 여러 개일 때 id 만으로
다음 쪽을 가릴 수 없기 때문이다.

**인기 기간(#531, BE #472).** 인기순(`sortType=POPULAR`)에는 `period` 를 함께 보낸다 — `WEEK`(최근 7일) ·
`MONTH`(최근 30일) · `ALL`(전체 기간). 작성 시각 기준 롤링 기간이고, **생략하면 전체 기간이 아니라 `WEEK`** 다.
최신순에는 싣지 않는다(서버도 무시한다). 검색 인기순도 계약상 `period` 를 받지만 검색 화면에는 기간 칩이 없어
늘 `WEEK` 를 보낸다.

- URL 은 `view=popular&period=MONTH` 처럼 쓰고 **기본값 `WEEK` 는 생략**한다 — 예전 `view=popular` 주소·공유
  링크가 그대로 이번 주를 뜻한다. 값은 대문자 정확 일치만 받고 그 밖(`YEAR`·`month`)은 `WEEK` 로 읽는다
  (서버는 잘못된 값을 `400 COMMUNITY_117` 로 막는다). 인기 보기가 아니거나 검색어가 있으면 늘 `WEEK` 다.
- 기간을 바꾸면 커서를 처음(`0`)부터 다시 받는다. 따로 리셋 코드는 없다 — 기간이 목록 상태의 일부라 목록 쿼리 키가
  바뀌고, 새 무한 쿼리가 첫 커서로 시작한다. 다른 기간의 커서를 이어 쓰지 않는다(계약).
- 목록 맥락 키(스크롤 복원·이웃 글·상세 `← 목록`)에는 기간이 **기본값이 아닐 때만** 들어간다 — 이미 저장된 키가
  예전 모양 그대로 맞는다. 상세의 `← 목록` 은 보던 기간으로 돌아간다.
- 지역을 바꿔도 기간은 남는다(대상 필터와 함께 쓸 수 있다). 검색하거나 다른 보기로 가면 `WEEK` 로 돌아간다.

**말머리 필터(#529, BE #470).** 피드 요청(`mode: 'list'`)에만 `category` 를 싣는다 — 검색·좋아요한 글에는 계약상 말머리 필터가
없어 싣지 않는다. 대상 필터·정렬·기간과 함께 쓴다. 우 레일 인기 글에는 걸지 않는다.

- URL 은 `category=QUESTION` 처럼 쓰고 **「전체」는 생략**한다. 대문자 정확 일치만 받고 그 밖(`question`·`BOGUS`)은 「전체」로
  읽는다. 검색어가 있거나 좋아요한 글 보기면 늘 「전체」다.
- 말머리를 바꾸면 커서를 처음(`0`)부터 다시 받는다. 기간과 같이 따로 리셋 코드는 없다 — 말머리가 목록 상태의 일부라 목록 쿼리
  키가 바뀐다.
- 목록 맥락 키에는 말머리가 **있을 때만** 들어간다 — 이미 저장된 키가 예전 모양 그대로 맞는다. 상세의 `← 목록` 은 보던 말머리로
  돌아간다.
- 지역·보기(최신↔인기)·기간을 바꿔도 말머리는 남는다. 검색하거나 좋아요한 글로 가면 풀린다.

### 인증 게이트 — 막지 않고 보낸다

```ts
const requireAuth = (action: () => void) => {
  if (!authReady) return // 판정 전에는 아무것도 하지 않는다
  if (!viewer.authenticated) {
    onRequireLogin()
    return
  }
  action()
}
```

**`authReady` 를 먼저 보는 것이 요점**이다. 회원 정보가 도착하기 전에는 「비로그인」이
아니라 「아직 모름」이라, 그 사이 누른 사람을 로그인으로 보내면 **이미 로그인한 사용자를
쫓아내는** 것이 된다.

### 작성자 표시 — 받은 대로 적는다

목록·검색·좋아요한 글·상세·댓글·답글 응답에 `writerNickname` · `writerProfileImageUrl` 이
실린다(BE #271, auth-service 실조회). **둘 다 null 가능**이다.

| 응답 값              | 뜻                              | 화면                                      |
| -------------------- | ------------------------------- | ----------------------------------------- |
| 닉네임 문자열        | 현재 닉네임(스냅샷 아님)        | 그대로 적는다                             |
| `"탈퇴회원"`         | 탈퇴 회원. 백엔드가 값으로 준다 | **그대로 적는다** — FE 가 판정하지 않는다 |
| `null`               | 회원 서비스 장애 · 미존재 회원  | 「사장님」(`COMMUNITY_WRITER_FALLBACK`)   |
| 프로필 이미지 `null` | 업로드본·소셜 사진 모두 없음    | 닉네임 첫 글자 이니셜 아바타              |

한 컴포넌트(`CommunityWriter`)가 세 화면을 다 맡는다. 화면마다 따로 적으면 null 처리가
한 곳에서 빠진다. 작성자 본인 판정은 여전히 `memberId` 다(S2 #6) — 닉네임은 중복될 수 있다.

### 화면 구성 — 개편 1단계 (2026-10-01)

근거와 전체 로드맵(2~4단계)은 [커뮤니티 UI/UX 개편 제안서](../../superpowers/specs/2026-10-01-community-ux-renewal.md)다.
여기에는 **확정돼 구현하는 동작만** 적는다. 1단계 목표는 두 가지다 — 모바일 첫 화면에 글이 보이게 하고,
상세 데스크톱 레이아웃 깨짐을 고친다.

**브레이크포인트**: `<480` 모바일 · `480–1079` 태블릿 · `≥1080` 데스크톱(DESIGN.md §8). 커뮤니티 화면은
레거시 640·760·768 을 쓰지 않는다. 1단계에서 목록은 모든 폭에서 `--w-read` 1단이다(3단 레일은 4단계).

**행 메타 — 조회수 · 내 좋아요(#530).** 조회수는 `♡ · 💬` 다음에 상세 메타와 같은 `조회 N`(축약 표기)으로 붙고, 응답에 없으면(옛 BE)
그리지 않는다. 내 좋아요는 `liked === true` 일 때만 하트를 채우고 상세의 눌린 하트 색
(`--color-text-primary-on-light`)을 쓴다. 스크린리더는 `좋아요 N, 내가 좋아요한 글`. `false`·`null`(비로그인)은
지금 모양이다. **표시만 한다** — 행 전체가 상세 링크라 토글 버튼을 넣으면 중첩 인터랙티브가 된다. 우 레일 행은 바꾸지 않는다.

**인기 기간 칩(#531).** `role="group"` · `aria-label="인기 기간"` 의 `aria-pressed` 버튼 묶음이다. 모양은 작성 도움 칩
(알약 · `--color-border-200` 테두리 · 44 높이), 눌림은 선택 칩 관용구(`--color-primary-600` 테두리 · `--color-primary-100` 바탕 ·
`--color-primary-700` 글자)를 그대로 쓴다 — 새 토큰이 없다. 말머리 칩과 같은 컴포넌트(`community-choice-chips.tsx`)다. 좁은 폭에서는 줄을 바꾼다. `≥1360` 에서 좌 내비가 탭 줄을 대신해도
기간은 내비에 없으므로 이 행은 남는다. 누르면 주소만 바꾸고(`router.replace`), 인기 순위 숫자(1·2·3)는 그대로다.
인기 피드가 비면 제목이 기간을 말한다 — `이번 주 인기 글이 아직 없어요` · `이번 달 …` · 전체 기간은 `인기 글이 아직 없어요`.
지역·검색으로 빈 경우는 그 원인 문구가 먼저다.

**말머리 필터 칩(#529).** 기간 칩과 같은 컴포넌트·같은 모양이고 `aria-label="말머리"` 다. 맨 앞 `전체` 가 필터 없음이다.
**탭 줄 → 말머리 → 기간** 순이라 최신↔인기를 오가도 말머리 줄이 제자리에 있다. 다섯 칩이라 좁은 폭에서 두 줄이 되지 않게
**가로로 민다** — 스크롤바를 숨기므로 가려진 쪽 끝을 흐리고(DESIGN.md 「스크롤바를 숨긴 가로 스크롤 탭」), 눌린 칩이 가려져
있으면 가로로만 밀어 가운데로 맞춘다. 포커스 링이 잘리지 않게 묶음 안쪽에 4px 를 두고 바깥으로 되돌린다. `≥1360` 에서도 남는다.
말머리로 피드가 비면 `이 말머리의 글이 아직 없어요` + `말머리 필터 해제`(누르면 「전체」). 지역·기간보다 먼저 말한다 — 지역 게시판에
글이 있어도 그 말머리 글이 없을 수 있다.

**모바일 필터 — 버튼 + 시트(CM-059~061).** `<480` 에서는 말머리·기간 칩 행을 그리지 않는다 — 두 줄(최대 ~120px)이 375×812
첫 화면 글 행을 셋 밑으로 밀었다(CM-015). 대신 탭 줄 오른쪽(`좋아요한 글` 다음)에 **필터 버튼** 하나를 두고, 누르면 커뮤니티
공용 시트(`community-sheet.tsx`, 제목 `필터`)에서 `말머리` 묶음과 인기 보기면 `기간` 묶음을 고른다. 칩은 같은 컴포넌트를 줄바꿈 배치로
쓴다. 분기는 CSS 미디어쿼리라(버튼은 `≥480` 에서, 칩 행은 `<480` 에서 `display: none`) SSR 첫 페인트부터 맞는 쪽만 보인다.

- **보이는 곳**: 말머리 필터가 있는 곳(최신·인기 보기, 검색어 없음)만. 좋아요한 글·검색에서는 없다.
- **라벨**: 아무것도 안 골랐으면 아이콘 + `필터`. 고른 값만 `·` 로 잇는다 — `질문` · `질문 · 이번 달` · (인기에서 기간만) `이번 달`.
  기본값(`전체`·`이번 주`)은 쓰지 않는다. 걸려 있으면 아이콘을 빼고 선택 칩 토큰(`--color-primary-600` 테두리 ·
  `--color-primary-100` 바탕 · `--color-primary-700` 글자)으로 그리고, 읽는 이름은 `필터: {라벨}` 이다. 넘치면 말줄임.
- **고르면 바로 적용**한다(지역 시트와 같은 관례 — `적용` 버튼이 없다). 칩 행과 같은 URL 액션이다. 시트는 닫지 않는다 — 인기
  보기는 두 묶음이라 하나 고를 때마다 닫으면 둘 다 바꾸려면 두 번 열어야 한다. ✕·Esc·바깥 누름으로 닫으면 버튼으로 포커스가
  돌아온다(CM-016 과 같은 규칙).
- **탭 줄 한 줄 유지**: 버튼 터치 영역은 44, 칩 모양은 그 안에 32 높이로 그린다. 버튼이 있을 때 `<480` 의 `좋아요한 글` 토글은
  `좋아요` 만 보이고 `한 글` 은 눈에서만 숨긴다(읽는 이름은 그대로) — 375 에서 가장 긴 라벨 `경험 공유 · 전체 기간` 이 말줄임 없이
  들어간다.

**말머리 배지(#529).** 행 메타 줄 맨 앞(지역 앞)과 상세 머리의 지역 칩 옆에 `category.name` 을 공통 Badge **grey** 톤으로 단다
(`community-category-badge.tsx`). 파란 쪽은 지역과 `글쓴이` 배지가 쓰고 있어 「어디 이야기」와 「무슨 이야기」를 색으로 가른다.
`null`·필드 없음이면 아무것도 없다. 좋아요한 글·검색 결과도 같은 행이라 같이 보인다. 우 레일 행에는 넣지 않는다(좁은 레일).

#### 지역 선택 시트

자치구 → 행정동 → 상권으로 **한 단계씩 들어가는 리스트**다. 3단 select 를 대체한다(목록만. 글쓰기는 3단계).

- 각 단계 첫 행이 `{상위 이름} 전체`(최상위는 `서울 전체`)다. 누르면 그 단계로 확정하고 닫는다.
  하위 단계로 들어가는 행은 `›` 를 단다. 상권 단계의 행은 바로 확정한다.
- 위쪽 경로(`서울 전체 › 성동구 › 성수1가1동`)를 누르면 그 단계로 돌아간다.
- 검색 입력은 **지금 보이는 단계의 목록을 클라이언트에서 거른다**. 하위 목록은 상위를 골라야 받아지므로
  단계를 건너뛰는 통합 검색은 하지 않는다(새 API 없음).
- 행정동·상권 목록은 지금 선택기와 같은 API·목 데이터를 쓴다. 불러오는 중 / 실패(`다시 시도`) 상태가 단계마다 있다.
- 시트를 닫으면(✕ · Esc · 바깥 누름) 아무것도 바꾸지 않는다. **고른 순간에만 URL 이 바뀐다** — 지금 선택기는
  select 를 바꿀 때마다 목록을 다시 불렀다.
- `<480` 바텀시트(위쪽 radius 16, 최대 높이 85dvh), `≥480` 가운데 다이얼로그(폭 420). 포커스를 가두고
  닫으면 칩으로 돌려준다.
- **시트 높이는 최대 높이로 고정한다**(`<480` 85dvh, `≥480` `min(640px, 100dvh - 48px)`, 목록은 시트 안에서 스크롤, #518).
  높이가 내용을 따르면 가운데·바닥 정렬 때문에 하위 목록이 도착하는 순간 위쪽 행이 밀려, 그때 누른 손가락이 다른 지역을
  고른다(dev 실측: 「성동구 전체」를 눌렀는데 「금호4가동」이 골라짐). 더보기 메뉴 시트는 내용 높이를 따른다(`CommunitySheet` 의 `fixedHeight`).

#### 좋아요 — 누르면 바로 바뀐다 (#580)

서버 API 는 **토글**이다(`POST …/likes` 가 누를 때마다 뒤집고 `{ liked, likeCount }` 를 준다). set 이 아니라서 연타를 그대로
보내면 응답이 엇갈려 마지막 화면과 서버가 갈린다. 그래서(`lib/community/like-toggle-queue.ts`):

- **낙관적 갱신** — React Query `onMutate` 가 관련 쿼리(상세 · 관련 글 / 댓글)를 `cancelQueries` 한 뒤 `setQueryData` 로
  하트와 수를 먼저 뒤집는다. 수는 0 아래로 내려가지 않는다.
- **직렬화** — 글 하나 · 댓글 하나마다 요청은 한 번에 하나다. 진행 중에 또 누르면 「마지막 의도」만 적어 둔다. 응답이 오면
  서버 상태와 마지막 의도를 비교해 다르면 토글을 한 번 더 보낸다(짝수 번 연타 → 원래대로, 홀수 번 → 뒤집힘). 같은 실행에 묶인
  클릭은 모두 같은 결과로 끝나고, 캐시 쓰기·요약 무효화는 마지막 클릭 하나만 한다.
- **롤백** — 실패하면 서버가 마지막으로 확인해 준 상태로 되돌리고 기존 오류 문구 자리에 이유를 적는다.
- 버튼은 `disabled` 로 잠그지 않는다(인증 확인 전만 잠근다). 글 좋아요는 요청 중 `aria-busy` 만 단다.
- **댓글 좋아요의 첫 상태**는 BE #594(열림)가 응답에 `liked` 를 실어야 안다. 그 전에는 「모름」(`null`)이라 빈 하트로
  그리고, 누르면 「채움」이 의도다 — 첫 토글 결과가 의도와 다르면(이미 눌렀던 댓글) 한 번 더 보내 의도에 맞춘다.
  응답에 `liked` 가 생기면 타입(`CommunityComment.liked?`)이 이미 받으므로 그대로 첫 상태가 된다.
- **댓글 캐시 키에는 조회자가 없다**(`communityKeys.comments` = `['community','comments', postId, mock]`). 그래서 토글 결과의
  `liked` 를 댓글 캐시에 쓰지 않고 수만 쓴다 — 같은 탭에서 로그아웃 · 다른 계정 로그인 뒤 앞사람의 하트가 비치면 안 된다. 하트는
  스레드 로컬 상태가 든다. **BE #594 착수 때 댓글 키에 조회자(`viewerKey`)를 넣는다** — 상세 키처럼. 지금 넣지 않은 이유: 댓글 키는
  401 복구에서 「조회자 없는 키(다시 부름)」로 따로 다뤄지고(`recoverCommunityPublicQueries`), 조회자 확인 전에도 댓글을 부르므로
  키를 바꾸면 복구 분기 · 조회 시작 조건까지 함께 바꿔야 한다. 응답에 `liked` 가 없는 지금은 얻는 것이 없다.

`window.confirm` 을 쓰지 않는다 — 카카오톡·네이버 인앱 브라우저는 도메인이 붙은 대화상자를 띄우고, 위험 동작의 색 구분이 없고,
「…하시겠습니까?」로 결과를 말하지 못한다. 공용 `components/ui/confirm-sheet.tsx`(채팅도 쓴다)로 묻는다.

- 모양은 커뮤니티 공용 시트와 같다: `<480` 바텀시트, `≥480` 가운데 420. `role="alertdialog"` 에 제목 · 결과 한 줄을 잇는다.
- 버튼 두 개(같은 폭): ghost 취소 + danger 확인(48, `size="large"`). 되돌릴 수 있는 동작(임시 저장되는 글쓰기 이탈)은 primary.

  돌려준다. 확인 요청 중에는 Esc · 취소 · 바깥 누름이 듣지 않는다.
- 소스 스캔 가드(`components/ui/no-window-confirm.test.ts`)가 `src` 에서 `window.confirm` 호출을 막는다(주석은 제외).

#### 댓글 삭제 되돌리기 (#581)

댓글은 확인 창 대신 **낙관적 숨김 + 지연 삭제 + 되돌리기**다(`lib/community/comment-delete.ts`, 지연 실행 큐는 프로필과 같이 쓰는 `lib/ui/deferred-commit.ts`). BE 에 지운 댓글을 되살리는
API 가 없어(다시 쓰면 id · 작성 시각 · 답글 연결이 바뀐다) 즉시 삭제 뒤 되돌리기는 할 수 없다.

- 누르면 그 행을 화면에서만 숨기고(루트면 딸린 답글까지) 토스트 `댓글을 삭제했어요.` + `되돌리기` 를 띄운다. 행이 사라지므로
  포커스는 `댓글 N` 제목으로 옮긴다.
- **두 `댓글 N` 은 세는 것이 다르다.** 반응 바(상세 응답 `commentCount`)는 **숨긴 댓글 하나당 1** 을 뺀다 — 루트에 답글이 달려
  있어도 1. BE 는 루트를 지울 때 답글을 남기고 `commentCount` 를 1 만 줄이므로(`CommunityCommandProcessor.deleteComment`) 같은
  수를 빼야 지연 삭제가 끝나 응답이 올 때 수가 튀지 않는다. 스레드 제목은 화면에 그린 행 수(루트 + 답글)라 숨긴 루트의 답글까지
  빠진다 — 다시 받은 목록도 그 행들을 그리지 않으므로 제목도 튀지 않는다.
- **BE 확인 필요**: 루트를 지워도 답글이 `ACTIVE` 로 남아 `commentCount` 와 실제로 보이는 댓글 수가 어긋난다(답글 달린 루트를
  지우면 반응 바 수가 스레드 행 수보다 답글 수만큼 크다). 답글을 함께 지울지, 「삭제된 댓글입니다」 자리로 남길지 BE 결정이
  필요하다. FE 는 BE 와 같은 수를 따른다.
- 되돌리기 기간은 액션 토스트 수명과 같은 10초(`TOAST_ACTION_DURATION_MS`). 그 안에 `되돌리기` 를 누르면 숨김만 푼다 —
  서버에는 아무것도 가지 않았다. 기간이 지나면 `DELETE` 를 보낸다.
- 성공하면 댓글을 다시 받은 뒤 숨김을 푼다(먼저 풀면 지운 댓글이 한 번 비친다). 실패하면 숨김을 풀어 댓글을 되살리고
  `댓글을 삭제하지 못해 다시 보여 드려요.` 를 적는다.
- **페이지를 떠나면**(앱 안 이동 = 언마운트) 기다리던 삭제를 바로 보낸다 — 사용자는 이미 지웠다고 봤다. 탭 닫기 · 새로고침
  (`pagehide`)도 같은 일을 시도하지만 브라우저가 요청을 끊을 수 있다. 끊기면 댓글이 남는다(안전한 쪽 실패 — 지우지 않은 것을
  지웠다고 하지는 않는다).
- 보낸 댓글의 되돌리기 토스트는 **함께 닫는다**(토스트 `dismissToast(dedupeKey)`). 토스트는 앱 전역이라 상세를 떠나도 남는데,
  누르면 되돌릴 것이 없다. 그래도 이미 보낸 뒤에 `되돌리기` 가 눌리면 `댓글이 이미 삭제됐어요.` 로 알린다 — 아무 일 없이
  성공처럼 닫히지 않는다.
- **한계 — 10초 안에 4개 이상 지우면** 토스트 상한(3, `TOAST_LIMIT`) 때문에 가장 오래된 토스트가 밀려나 그 댓글은 되돌리기
  수단이 사라진다(삭제는 예정대로 나간다). 여러 건을 하나로 묶는 토스트는 두지 않는다 — 연달아 여러 댓글을 지우는 일이 드물다.

#### 모바일 하단 고정 바 (`<480`)

- 본문 끝 반응 바가 화면에 보이지 않으면 하단에 고정 바가 뜬다: `[♡ N]  [댓글을 남겨 보세요…]  [↗]`.
  **위·아래 모두**다 — 긴 글을 읽는 중(반응 바가 아직 아래)에도 뜬다. 고치려던 문제가 「좋아요하려면 본문 끝까지 스크롤」이었다.
  댓글 입력칸이 화면 안에 보이면 숨긴다(입력칸과 겹치지 않게).
- 가운데 칸은 **진짜 입력칸이 아니라 버튼**이다. 누르면 댓글 입력칸으로 스크롤하고 포커스한다(비로그인이면 로그인 CTA 로).
  별도 입력 시트를 두지 않는 이유: 입력 상태가 두 곳으로 갈리고, iOS 에서 시트 안 입력칸 포커스가 키보드와 자주 어긋난다.
- 좋아요·공유는 본문 반응 바와 **같은 핸들러**를 쓴다(인증 게이트 · 공유 연타 가드 그대로).
- 높이 56 + `safe-area-inset-bottom`. 바가 있는 동안 **body 끝에** 같은 높이의 여백을 둔다 — 셸에서 푸터가 main 뒤에 오므로
  main 안에 여백을 두면 맨 아래 푸터가 가려진다.

#### 목록 — 끊기지 않는 피드

| 영역         | 동작                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 다음 쪽      | 목록 끝 감시 요소(IntersectionObserver, 여유 400px)가 보이면 자동으로 다음 쪽을 부른다. 다음 쪽 실패면 그 자리에 `다시 불러오기`. 「게시글 더 보기」 버튼은 없앤다                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 로딩         | 첫 로딩은 글 행 모양 스켈레톤 5줄, 다음 쪽 로딩은 2줄. 피드에는 `aria-live` 를 두지 않는다 — 자동 다음 쪽마다 20건을 통째로 읽게 된다. 알림은 스켈레톤(status)·실패(alert)·끝(status)이 각자 맡는다                                                                                                                                                                                                                                                                                                                                                                                                       |
| 끝           | `hasNext=false` 이고 글이 있으면 `여기까지 다 봤어요` + `글쓰기` 링크                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 뒤로 가기    | 상세에서 **브라우저 뒤로/앞으로**(popstate)로 돌아오면 누른 행을 같은 화면 높이에 다시 둔다. 헤더 링크 등 새 진입은 맨 위에서 시작한다. 불러온 쪽은 쿼리 캐시가 들고 있는 동안만 다시 그려진다 — 수명은 staleTime 이 아니라 gcTime(기본 5분)이라 자리(`sessionStorage`)도 5분 뒤 버린다. 캐시가 사라져 누른 행이 다시 그려지지 않으면 복원하지 않는다(맨 위). 기본 스크롤 복원은 목록이 다시 그려지기 전에 걸려 잘린다. 뒤로 가기 여부는 **마운트 다음 프레임**에 판정한다 — 라우터가 popstate 리스너 안에서 목록을 동기로 다시 그려, 마운트 순간에는 목록의 popstate 구독이 아직 불리지 않았다(e2e 실측) |
| FAB (`<480`) | 아래로 스크롤하면 아이콘만 남은 원형(56)으로 줄고, 위로 올리거나 맨 위면 다시 `글쓰기` 를 펼친다. `aria-label` 은 늘 `글쓰기`. `prefers-reduced-motion` 이면 모양 전환 애니메이션을 끈다. 펼친 높이도 56 으로 맞춰 접을 때 높이가 튀지 않는다                                                                                                                                                                                                                                                                                                                                                             |

### 화면 구성 — 개편 3단계 「글쓰기」 (2026-10-01)

목표는 **쓰고 싶은 말부터 쓰게** 하고, **쓴 글을 잃지 않게** 하는 것이다. 제안서 §4.3·§4.4.

#### 글쓰기 · 수정 (`/community/register`)

| 영역           | 동작                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 머리           | 안내 세 줄(아이브로·제목·설명)을 제목 한 줄 `새 글` / `글 수정` 으로 줄인다. `<480` 은 사이트 헤더 아래에 붙는 편집 바 `[✕] 새 글 [등록]` 가 머리를 대신한다                                                                                                                                                                                                                                           |
| 순서           | **지역 칩 → 말머리 → 제목 → 본문 → 사진.** 지역 select 3단을 1단계의 지역 선택 시트(칩)로 바꾼다. 칩이 비어 있으면 `어느 지역 이야기인가요?`                                                                                                                                                                                                                                                           |

| 시트           | 글쓰기 시트에는 최상위 `서울 전체` 확정 행이 없다 — 글은 대상이 필수라 고르면 다시 빈 값이 된다. 키보드 위 툴바는 두지 않는다(사진 줄 `+` 와 글자 수로 충분하고, `visualViewport` 추적이 따로 필요하다)                                                                                                                                                                                                |
| 지역 없이 등록 | 등록을 누르면 칩으로 포커스를 옮기고 시트를 연다. 안내 문구는 칩 아래 한 줄 `지역을 골라 주세요`(CM-008 유지)                                                                                                                                                                                                                                                                                          |
| 말머리         | `말머리 선택` 아래 칩 행 `질문` · `경험 공유` · `같이 해요` · `동네 소식`(#529). 단일 선택이고 **다시 누르면 풀린다**(말머리 없음 — 목록 필터와 달리 `전체` 칩은 없다). `aria-label="말머리"` 의 `aria-pressed` 묶음, 목록 칩과 같은 컴포넌트. 선택 사항이라 등록 검증·작성 체크에 넣지 않는다. **수정 화면에서도 바꿀 수 있다**(지금 말머리가 눌린 채 시작)                                           |
| 제목           | 테두리 없는 큰 입력(20/600), 120자                                                                                                                                                                                                                                                                                                                                                                     |
| 본문           | 내용에 맞춰 늘어나는 입력칸(최소 8줄), 5,000자. 글자 수는 한도 90% 를 넘으면 `--color-negative-text`                                                                                                                                                                                                                                                                                                   |
| 작성 도움 칩   | 본문이 비어 있을 때만 본문 위에 `질문해요` · `경험 나눠요` · `같이 해요`. 누르면 본문에 짧은 틀을 넣고 커서를 첫 빈 줄로 옮긴다. **말머리가 비어 있을 때만** 대응 말머리(`질문해요`→`QUESTION` · `경험 나눠요`→`EXPERIENCE` · `같이 해요`→`TOGETHER`)를 같이 골라 준다 — 이미 고른 말머리는 덮지 않는다. 칩만으로는 말머리를 고를 수 없다(본문이 비었을 때만 보인다) — 그래서 말머리 칩 행이 따로 있다 |
| 사진           | 썸네일 가로 줄(72) + 끝에 `+` 타일. 첫 장에 `대표` 배지(목록 썸네일이 된다). 업로드 중 타일은 진행 표시. 기존 규칙(5장·5MB·형식, 수정 모드는 기존 이미지를 들고 시작)은 그대로                                                                                                                                                                                                                         |
| 등록 버튼      | `<480` 은 편집 바의 `등록`, 그 이상은 하단에 붙는 액션 바 `[취소] [등록하기]`. 필수값(지역·제목·본문)이 비면 비활성이 아니라 **눌렀을 때 무엇이 비었는지 알려 준다**(비활성 버튼은 이유를 말하지 않는다)                                                                                                                                                                                               |

#### 잃지 않게 — 임시 저장 · 이탈 확인

- 입력이 멈추고 1초 뒤 `localStorage` 에 **제목·본문·지역·말머리**를 저장한다. 키: 새 글 `community-draft:{memberId}:new`, 수정
  `community-draft:{memberId}:edit:{postId}`(목 모드는 목 회원 id). 등록·수정 성공 시 지운다. 저장 실패(용량·사생활 모드)는
  조용히 넘긴다.
- **키에 회원 id 를 넣고, 로그아웃하면 `community-draft:` 로 시작하는 키를 모두 지운다**(사이트 헤더 로그아웃). 공용 기기에서
  다음 계정이 앞 사람의 쓰던 글을 「이어 쓰기」로 보면 안 된다. 회원 id 를 모르면(로그인 판정 전·비로그인) 저장도 복원도 하지
  않는다. 401 로 로그인에 보내질 때는 지우지 않는다 — 같은 계정으로 돌아와 이어 쓴다.
- **두 탭이 같은 키를 쓰면 마지막 저장이 이긴다.** 한쪽이 등록에 성공하면 저장본이 지워진다 — 다른 탭에 열린 글은 그 탭의
  `beforeunload` 확인이 지키고, 그 탭에서 다시 치면 다시 저장된다. 탭 사이 잠금은 두지 않는다.
- **말머리(#529)** 는 늘 적는다(없으면 `null`). 필드가 없는 저장본은 말머리 이전의 옛 저장본이라 「모름」으로 읽고 처음 값을
  지킨다 — 수정 이어 쓰기에서 `null`(없음)로 읽으면 원본 말머리가 풀린 채 저장돼 서버가 지운다. 수정의 이어 쓰기는
  제목·본문·말머리가 저장본이고 지역·사진은 원본이다. 말머리만 바꿔도 「바뀐 것」이다.
- **사진은 저장하지 않는다.** 올린 사진 키는 저장 전까지 어떤 글에도 연결되지 않아 백엔드 회수 배치가 지울 수 있다 —
  되살린 초안에 깨진 사진이 남는 것보다 다시 고르게 하는 편이 낫다.
- 다시 들어왔을 때 저장본이 있으면 **폼을 띄우기 전에** 고르게 한다: `작성하던 글이 있어요` + `[새로 쓰기]` `[이어 쓰기]`.
  폼은 마운트 시점 값만 읽으므로(`initialValue`) 뒤늦게 덮어쓰면 그 사이 친 글자가 사라진다. 비교 초안으로 들어온
  경우에는 묻지 않는다(초안이 이긴다).
- **비교 초안으로 들어오면 임시 저장을 끈다**(실패·깨진 초안 링크 포함). 초안 글을 새 글 키(`…:new`)에 쓰면 따로 쓰던
  저장본을 덮는다. 그래서 이때의 이탈 확인은 `쓰던 내용은 저장되지 않고 사라져요.` 다 — 「임시 저장돼요」는 거짓이 된다.
  이탈 확인은 확인 시트로 묻는다(위 「확인 시트」, #581).
- 「바뀌었는지」의 기준은 **원래 값**(빈 폼 · 수정 원본)이다. 이어 쓰기 직후도 바뀐 상태다. 기준을 저장본으로 두면 이어 쓰기
  직후 autosave 가 「바뀐 것 없음」으로 보고 저장본을 지운다.
- 입력이 1초를 채우기 전에 나가면(언마운트 · `pagehide`) 그 자리에서 저장한다. 등록을 눌러 **저장 중**이 될 때도 잡힌
  저장을 버리지 않고 곧바로 쓴다(401 로 로그인에 보내지며 폼이 사라져도 남게). 버리는 것은 **성공한 뒤**뿐이다.
- 이어 쓰기로 시작해 원래 값(빈 글 · 수정 원본)으로 되돌리면 저장본을 지운다 — 아직 한 번도 새로 쓰지 않았어도 그 키에는
  이어 쓴 저장본이 있다.
- 내용이 바뀐 채로 `✕` · `취소` 를 누르면 `작성 중인 글은 임시 저장돼요. 나갈까요?` 확인. 새로고침·탭 닫기는
  `beforeunload`. 헤더 링크 같은 앱 안 이동은 막지 않는다 — 임시 저장이 대신 지킨다.

#### 신고 다이얼로그

- 사유를 **고른 뒤** 필요하면 덧붙인다: `스팸·홍보` · `욕설·비방` · `개인정보 노출` · `거짓 정보` · `기타`(라디오).
  `기타` 만 상세 입력이 필수다.
- 보내는 값은 사유 code 와 상세를 **나눠** 싣는다(#532): `{ reasonCode: 'SPAM', detail: '…' }`, 상세가 없으면 `detail` 키가 없다.
  라디오 값은 code, 보이는 글자는 라벨이다(라벨은 BE 표시명과 글자까지 같다). 예전의 `[사유] 상세` 조립·접두 몫을 뺀 한도는
  없어졌다 — 상세 입력칸 `maxLength` 와 카운터는 사유와 무관하게 **상세 자체 500자**다(CM-012).
- 서버 검증 오류는 `resultCode` 로 자리를 정해 클라이언트 검증과 **같은 자리·같은 포커스**로 보인다: 사유(110·018)는 사유 묶음
  아래 + 고른 라디오(없으면 첫 라디오) 포커스, 상세(123·124)는 입력칸 아래 + 입력칸 포커스, 그 밖은 버튼 위 일반 자리(CM-058). 그 입력을 고치면 걷힌다.
  문구는 서버 문구 그대로다.
- `<480` 바텀시트 / 그 이상 다이얼로그는 유지. 레거시 640 분기와 글로우 포커스를 1단계 규칙으로 맞춘다.

### 화면 구성 — 개편 4단계 「넓은 화면」 (2026-10-01)

목표는 **넓은 화면이 주는 자리를 탐색에 쓰는 것**, 그리고 사진을 제대로 보여 주는 것이다. 제안서 §4.1-F, §4.2-C·F.

| `1080–1359` | 피드(`--w-read`) + 우 레일 300. 탭은 피드 위에 그대로                                                                                                                                |

1360 은 3단 1308 + 셸 거터 40 이 들어가는 첫 폭을 올림한 값이다.

- **좌 내비**(sticky): `보기` — 최신 · 인기 / `내 활동` — 좋아요한 글 / `최근 본 지역` — 지역 게시판을 열 때마다 `localStorage` 에
  최대 5개(최근 순, 중복 제거) 기록하고 링크로 보여 준다. 없으면 그 묶음을 그리지 않는다. 지금 상태 항목은 `aria-current` —
  `page` 는 연 지역 게시판(최근 본 지역 항목) 하나에만, 보기·내 활동은 `true`(주소 하나가 둘을 함께 정해 `page` 가 둘이면
  「현재 페이지」를 두 번 읽는다. 서울 전체면 `page` 항목이 없다). URL 계약(`view`·대상)과 CM-005 는 그대로.
  최근 본 지역은 회원이 아니라 **브라우저 단위**다(비로그인 열람도 남긴다). **로그아웃하면 지운다** — 3단계 임시 저장과 같은
  이유로 공용 기기의 다음 사람에게 앞 사람이 본 동네를 보여 주지 않는다.
- **우 레일**(sticky):
  1. `이번 주 인기 글` — 같은 목록 API 를 `sortType=POPULAR&period=WEEK`, 5건으로 한 번 더 부른다(#531 — 피드 기간 칩과 상관없이
     **이번 주 고정**이라 인기 글 키에 기간을 넣지 않는다. 생략해도 서버 기본값이 `WEEK` 지만 계약대로 명시한다). 대상을 고른 중이면
     그 대상으로(`{지역} 이번 주 인기 글`).
     검색 중·좋아요한 글 보기에서는 서울 전체 인기 글. 순위 숫자 + 제목 한 줄 + ♡ 수. 비면 묶음을 숨긴다. 실패하면 조용히 숨긴다
     (레일은 보조라 오류 카드를 띄우지 않는다).
     **반응 없는 인기 글 대체(#590)**: 받은 글이 **모두** 반응(좋아요 + 댓글)이 임계값(`COMMUNITY_POPULAR_MIN_REACTIONS = 1`) 미만이면
     같은 응답을 `이번 주 새 글`(`{지역} 이번 주 새 글`)로 바꿔 부른다 — 순위와 ♡ 0 을 빼고 상대 시각을 적는다. 인기순은 좋아요 수가
     같으면 글 id 내림차순이라(BE `likeCount desc, id desc`) 모두 0 이면 곧 이번 주 최신 글 순서다. 요청을 더 보내지 않는다.
     `최근 댓글이 달린 글` 은 그 정렬을 주는 API 가 없어 쓰지 않는다. 반응 있는 글이 하나라도 있으면 지금처럼 인기 글이다.
  2. 질문 유도 카드 — `{지역}에 대해 물어보세요` / 대상 없으면 `사장님들께 물어보세요` + **`질문하기`**(#590). 링크는 목록 글쓰기 링크와
     같은 프리필(대상 · 로그인 감싸기)에 **말머리 `질문`(`category=QUESTION`)을 골라 둔** 글쓰기다. 목록 머리의 `글쓰기` 와 같은 행동이
     두 곳에 있지 않게 레일은 질문 템플릿으로 가른다. 글쓰기 화면은 새 글일 때만 `category` 쿼리를 읽고, 아는 말머리 값(대문자 정확
     일치)만 받는다(`parseCommunityEditorCategoryPrefill`). 고른 말머리가 기준값이라 그것만으로는 「바뀌었다」(이탈 확인)가 아니다.
  3. 분석 연결 — 대상이 **자치구**면 `{구} 상권 분석 보기`(`/analysis?districtCode=`). 행정동·상권은 상위 코드를 계약으로
     알 수 없어 `상권 분석에서 찾아보기`(`/analysis`)로 둔다.
- 1단에서는 레일 내용을 그리지 않는다(모바일 첫 화면 글 수를 지킨다). 폭은 matchMedia 로 판정해 **렌더와 인기 글 쿼리를 함께**
  막는다 — CSS 로만 숨기면 모바일에서도 요청이 나간다. 그리드 트랙은 판정 전(서버 렌더)부터 잡혀 있어 레일이 늦게 와도 피드가 밀리지 않는다.
- 인기 글 쿼리 키는 목록 키와 따로 둔다(`['community','popular',…]`). 상세에서 좋아요·댓글을 하면 목록 키와 함께 무효화한다.
  레일 글 링크는 지금 보던 목록의 맥락 키를 실어 상세의 `← 목록` 이 그 목록으로 돌아온다. 공개 목록 401 복구(세션 정리 뒤
  익명 재조회)가 끝나면 인기 글 키도 무효화한다 — 같은 401 로 숨어 있던 묶음이 돌아온다.
- 레일 글을 눌러 상세에 갔다가 뒤로 와도 보던 자리에 선다(CM-030). 누른 링크는 피드 행이 아니라 **화면 안 첫 피드 행**을
  기준 행으로 남긴다(위가 헤더 밑으로 잘린 행 포함 — 같은 화면 높이에 되돌리니 보던 화면이 그대로다). 화면에 피드 행이 없으면
  (목록이 비었거나 실패) 옛 자리를 지운다 — 예전에 누른 글 자리로 돌아가면 엉뚱한 곳에 떨어진다.
- 탭 줄은 `≥1360` 이라도 **좌 내비가 실제로 그려졌을 때만** 숨긴다. 서버 렌더 중에 탭까지 숨기면 잠깐 조작할 곳이 없다.

#### 상세 레일 보강 (`≥1080`)

- 레일에 `이전 글 · 다음 글`(인접 글이 있을 때)을 `{지역} 최신 글` 위에 둔다. `≥1080` 에서는 본문 아래 인접 글 묶음을
  그리지 않는다(CSS 로 숨긴 한쪽은 접근성 트리에서도 빠진다). 대상 없는 글도 인접 글이 있으면 레일을 그린다.
- sticky 레일 칸은 높이를 화면에 묶는다(`max-height: calc(100dvh - 88px - 24px)`, 칸 안 스크롤, overscroll 막음) — 낮은
  화면에서 인접 글 + 지역 글 5건이 화면보다 길면 아래가 잘려 닿을 수 없다. 링크·버튼은 카드 안쪽 여백 안이라 포커스 링이 잘리지 않는다.

#### 사진 보기

- **라이트박스**: 본문 사진을 누르면 전체 화면 보기. 어두운 바탕(`--color-overlay` 계열) · 가운데 사진(비율 유지) ·
  `n / 전체` · 이전/다음 버튼 · 닫기. 키보드 ←/→/Esc, 터치 좌우 스와이프(40px 이상). 포커스를 가두고 닫으면 누른 사진으로
  돌려준다. 열려 있는 동안 스크롤 잠금. 사진 하나면 이전/다음을 그리지 않는다.
  핀치로 확대한 동안(`visualViewport.scale > 1`)은 스와이프로 넘기지 않고 사진 칸의 `touch-action` 을 `auto` 로 돌려
  확대한 사진을 가로로도 둘러보게 한다(평소는 `pan-y pinch-zoom`). `visualViewport` 가 없는 브라우저는 지금처럼 넘긴다.
- **모바일 사진 줄**(`<480`, 사진 2장 이상): 세로 나열 대신 가로 스와이프(scroll-snap) + 점 표시(지금 장).
  `≥480` 은 세로 나열 그대로. 어느 쪽이든 누르면 라이트박스.
- 사진 `alt` 는 지금 규칙(`첨부 이미지 n`) 유지.
- 라이트박스 바탕은 `--color-overlay`(0.5)를 세 겹 쌓아 0.875 로 만든다(DESIGN.md Overlay Scrim 범위 안) — 한 겹이면 뒤 글자가 비친다.
  끝 장의 이전/다음은 `disabled` 대신 `aria-disabled` 다(누른 버튼이 비활성이 되면 포커스가 body 로 빠져 가두기가 깨진다).
  키보드는 document 에서 받는다. **바탕을 눌러도 닫지 않는다** — 스와이프 직후 click 이 닫기로 오인된다. 모바일 줄의 `n / 전체` 는
  live 가 아니다(넘길 때마다 읽으면 시끄럽다).

#### 숨는 헤더 (목록, `<480`)

- 목록을 아래로 스크롤하면 사이트 헤더가 위로 숨고 검색·지역 툴바만 맨 위에 붙는다. 위로 올리거나 맨 위면 헤더가 돌아온다.
  방향 판정은 FAB 축소와 같은 규칙(누적 8px · 80 미만은 펼침)을 쓴다. 헤더의 메뉴 패널이 열려 있으면 숨기지 않는다.
- 목록 화면만 켠다(다른 화면 헤더는 그대로). `prefers-reduced-motion` 이면 전환 없이 바뀐다.
- 목록은 `<html data-community-header-hidden>` 만 켜고 끈다(언마운트 때 지운다). 헤더와 툴바는 같은 선택자를 읽고, 헤더 메뉴가
  열려 있거나 헤더 안에 **키보드 포커스**가 있으면(`:has([data-site-header] :focus-visible)`) 둘 다 원래 자리다. `:focus-within`
  으로 넓히지 않는다 — Android 는 탭한 버튼에 포커스가 남아 숨는 헤더가 사실상 꺼진다. `:has` 를 모르는 브라우저는 헤더가 숨지 않을 뿐 툴바와 어긋나지 않는다.
  스크롤 구독은 FAB 축소와 하나로 쓴다.
