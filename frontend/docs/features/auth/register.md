> **작성일**: 2026-07-21
> **공통 명세**: [인증 공통 명세](./auth.md)
> **대상**: 웹 (Next.js App Router)
> **작성자**: FE
> **상태**: 초안

이 문서는 [인증 공통 명세](./auth.md)의 **회원가입 화면 및 플로우**를 상세화한다. 백엔드는 **단일 단계 signup**만 제공하므로 그 계약에 맞춘다. legacy의 2단계·이메일 인증은 미결(D8).

## D1. 기능 개요

이메일·비밀번호·이름·닉네임을 입력받아 가입을 요청하고, 성공 시 로그인으로 유도한다.

```
입력 → 클라이언트 유효성(백엔드 제약과 동일) → POST /api/bff/members/signup → 성공 시 로그인 유도
```

> **Figma 디자인**: (링크 미정 — DESIGN.md 기준 신규 디자인 허용)

## D3. 아키텍처 / 시스템 설계

가입 화면은 client component. 제출은 BFF 프록시 경유 `POST /api/bff/members/signup`. 인증 불필요 엔드포인트이므로 세션 없이 호출 가능(프록시는 Bearer 없이 포워드).

| 모듈                           | 책임                      |
| ------------------------------ | ------------------------- |
| `app/(auth)/register/page.tsx` | 가입 화면(폼·유효성·제출) |
| `src/components/auth/*`        | 입력 컴포넌트             |

## D4. 상세 동작 정의

### D4-1. 가입 제출

| 사용 엔드포인트                                                | 용도     | 요청                                | 비고                       |
| -------------------------------------------------------------- | -------- | ----------------------------------- | -------------------------- |
| `POST /api/bff/members/signup` → `POST /api/v1/members/signup` | 회원가입 | `{email, password, name, nickname}` | 응답 `Response<Void>` 성공 |

**클라이언트 유효성 (백엔드 제약과 동일):**
| 필드 | 제약 |
|---|---|
| email | 이메일 형식 필수 |
| password | 공백 없이 영문자+숫자+특수문자 포함 8~20자 (`^(?=.*[A-Za-z])(?=.*\d)(?=.*[특수문자])\S{8,20}$`) |
| name | 필수, 최대 10자 |
| nickname | 필수, 최대 10자 |
