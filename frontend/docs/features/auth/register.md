# 인증(auth) — 회원가입 세부 명세서

> **작성일**: 2026-07-21
> **공통 명세**: [인증 공통 명세](./auth.md)
> **대상**: 웹 (Next.js App Router)
> **작성자**: FE
> **상태**: 개정(v3.0 — 가입 동의·만 14세 이상 확인 반영, #495)

이 문서는 [인증 공통 명세](./auth.md)의 **회원가입 화면 및 플로우**를 상세화한다. 백엔드가 **이메일 인증(코드 발송·검증)을 회원가입 선행 조건**으로 요구하므로(`MEMBER_006`), send-code → verify-code → signup 순서를 FE에서 오케스트레이션한다.

## D0. 배경 / 기획 의도

| 항목              | 내용                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| 충족 요구사항     | 공통 명세 S3-3                                                                                                  |
| 해결하려는 문제   | 신규 회원 가입 진입점 + 이메일 소유 검증                                                                        |

| 목표 동작 (to-be) | 인증코드 발송 → 코드 검증 → 가입의 3단계를 단일 페이지에서 progressive disclosure로 처리. 인증 완료 후에만 가입 |

| 연관 세부 기능    | [login](./login.md), [social-login](./social-login.md)                                                          |

## D1. 기능 개요

이메일 인증을 완료한 뒤 비밀번호·이름·닉네임을 입력받아 가입을 요청하고, 성공 시 로그인으로 유도한다.

```
이메일 입력 → send-code(발송) → 코드 입력 → verify-code(검증)
  → 검증 성공 → 나머지 필드 활성화
  → 필수 동의 3개(이용약관·개인정보 처리방침·만 14세 이상) 체크 — 단계와 무관하게 늘 보인다
  → signup(가입, 동의 boolean 3개 포함) → 성공 시 /login?signup=1(&redirect=원래 화면) 로 유도
```

> **동의(#495)**: 정본 계약은 `backend/docs/auth-account-frontend-guide.md` §0-1. 같은 동의를 화면 맨 위 「카카오 로그인」(가입 모드, #577)도 쓴다 — [social-login](./social-login.md) D4-3.

> **인증 상태 보관**: `verify-code` 응답은 `Response<Void>`로 별도 인증 토큰을 주지 않는다. 백엔드가 서버측에서 "인증 완료된 이메일"을 기억하므로(추정: Redis TTL), FE는 **동일 이메일**로 send → verify → signup을 순서대로 호출하면 된다. signup 요청 바디에 인증 토큰/플래그는 포함하지 않는다. (dev API 실측으로 검증 — D8-1)

## D3. 아키텍처 / 시스템 설계

가입 화면은 client component. 세 호출 모두 인증 불필요 공개 엔드포인트로, 기존 **범용 BFF 프록시**(`/api/bff/...`)를 그대로 경유한다(세션 없이 Bearer 없이 포워드). **새 BFF 라우트 불필요.**

| 모듈                                              | 책임                                                       |
| ------------------------------------------------- | ---------------------------------------------------------- |
| `app/(auth)/register/page.tsx`                    | 라우트 진입(메타데이터)                                    |
| `src/components/auth/register-form.tsx`           | 가입 화면(단계 상태·유효성·제출)                           |
| `src/lib/api/*` (선택)                            | send-code/verify-code/signup 호출 유틸(선택)               |
| `src/components/auth/signup-consent-fieldset.tsx` | 동의 체크박스 묶음(전체 동의·[필수] 3개·오류 연결)         |
| `src/lib/auth/signup-consent.ts`                  | 동의 판정·전체 동의·누락 목록·authorize 쿼리·오류코드 매핑 |

**단계 상태(step state)**: `email-entry` → `code-sent` → `verified` → (제출) 의 로컬 상태 머신으로 관리.

## D4. 상세 동작 정의

### D4-1. 인증코드 발송

| 엔드포인트                                                                 | 요청      | 응답             |
| -------------------------------------------------------------------------- | --------- | ---------------- |
| `POST /api/bff/auth/email/send-code` → `POST /api/v1/auth/email/send-code` | `{email}` | `Response<Void>` |

- 유효 이메일 형식 확인 후 발송. 성공 시 코드 입력 UI 노출 + 재전송 쿨다운 시작.

### D4-2. 인증코드 검증

| 엔드포인트                                                                     | 요청            | 응답             |
| ------------------------------------------------------------------------------ | --------------- | ---------------- |
| `POST /api/bff/auth/email/verify-code` → `POST /api/v1/auth/email/verify-code` | `{email, code}` | `Response<Void>` |

- 성공 시 이메일/코드 잠금 + 나머지 필드 활성화. 실패 시 코드 오류 메시지.

### D4-3. 가입 제출

| 엔드포인트                                                     | 요청                                                                                | 응답             |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ---------------- |
| `POST /api/bff/members/signup` → `POST /api/v1/members/signup` | `{email, password, name, nickname, termsAgreed, privacyAgreed, ageOver14Confirmed}` | `Response<Void>` |

**클라이언트 유효성 (백엔드 제약과 동일):**

| 필드               | 제약                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| email              | 이메일 형식 필수(인증 완료된 이메일과 동일)                                                     |
| password           | 공백 없이 영문자+숫자+특수문자 포함 8~20자 (`^(?=.*[A-Za-z])(?=.*\d)(?=.*[특수문자])\S{8,20}$`) |
| name               | 필수, 최대 10자                                                                                 |
| nickname           | 필수, 최대 10자                                                                                 |
| termsAgreed        | boolean, `true` 여야 함 — 「[필수] 이용약관에 동의합니다」(`/terms` 새 탭)                      |
| privacyAgreed      | boolean, `true` 여야 함 — 「[필수] 개인정보 처리방침에 동의합니다」(`/privacy` 새 탭)           |
| ageOver14Confirmed | boolean, `true` 여야 함 — 「[필수] 만 14세 이상입니다」                                         |

- 「전체 동의」는 화면 편의다. 서버에는 세 필드를 **각각** 보낸다. 빼고 보내면 서버가 `false` 로 본다.
- 동의 fieldset 은 이름·닉네임 아래, 「회원가입」 버튼 위에 두고 단계와 무관하게 늘 보인다.

## D5. 비즈니스 로직

| 조건                        | 결과                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 이메일 형식 오류            | 발송 버튼은 켜 둔다. 누르거나 칸을 떠날 때(blur, 빈 칸 제외) 「올바른 이메일 형식을 입력해주세요.」를 이메일 칸에 `aria-describedby` 로 붙이고 보내지 않는다(#578)                                                                                                                                                                                                                                                                                                                               |
| 코드 발송 성공              | 코드 입력 UI 노출, 쿨다운 시작                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 코드 검증 성공              | `verified` 상태 전환, 이메일/코드 잠금, 나머지 필드 활성화                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 이메일 변경(발송 후)        | `email-entry` 로 되돌린다. 입력한 코드·재전송 대기·코드 오류를 버린다 — 옛 주소의 코드로 새 주소를 확인하지 않게 한다(#578)                                                                                                                                                                                                                                                                                                                                                                      |
| 이메일 변경(검증 후)        | 인증 상태 리셋 → 재발송·재검증 필요(이메일 칸은 인증 뒤 `readOnly` 라 방어용)                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 미인증 상태 가입 시도       | 가입 버튼이 인증 뒤에만 나타난다(방어). 강제 호출 시 백엔드 `MEMBER_006` 표시                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 유효성 실패                 | 가입 버튼은 켜 둔다. 누르면 보내지 않고 막힌 칸(비밀번호·이름·닉네임)마다 `FieldError` + `aria-invalid` + `aria-describedby`, 빠진 동의는 체크박스 강조. 오류가 커밋된 **뒤** 첫 칸으로 포커스(#578)                                                                                                                                                                                                                                                                                             |
| 칸을 떠날 때(blur)          | 적은 값이 있으면 그 칸만 판정해 오류를 붙이거나 걷는다. 빈 칸은 지나가도 탓하지 않는다. 오류가 붙은 칸은 고치는 동안 다시 판정해 맞는 순간 걷는다. 단 비밀번호는 blur 로 오류를 새로 붙이지 않는다 — 체크리스트가 실시간으로 말하고, 오류 줄이 끼어들면 바로 아래 「회원가입」 클릭이 밀려 빗나간다(375px 실측, e2e `signup-to-login.spec.ts`)                                                                                                                                                   |
| 비밀번호 규칙               | 항목별 체크리스트(영문자·숫자·특수문자·공백 없이 8~20자)를 `<ul id="register-password-rules">` 로 보이고 입력칸이 `aria-describedby` 로 읽는다. 항목마다 아이콘·색(지킴 `--color-green-700`)·숨은 문구(「충족」/「미충족」). 판정 정본은 `PASSWORD_PATTERN` 이고 `PASSWORD_RULES` 를 모두 지킨 것과 같다(테스트로 묶음). 둘 다 `@/lib/auth/password-rules` 에 있고 `register-machine` 은 다시 내보내기만 한다. 오류 문구는 정본 `PASSWORD_RULE_TEXT` 한 문장(재설정·프로필 비밀번호 변경과 같다) |
| 가입 성공                   | `/login?signup=1` 로 보낸다(복귀 경로가 홈이 아니면 `&redirect=`). 로그인 화면이 「가입을 마쳤어요. 방금 만든 비밀번호로 로그인해 주세요.」(success)를 띄우고, 가입한 이메일을 미리 채운 뒤 비밀번호 칸으로 포커스한다. 이메일은 URL 이 아니라 `sessionStorage`(`bps:signup-email`)로 넘기고 로그인 화면이 한 번 읽고 지운다(#576). 백엔드 signup 토큰 미발급 — BE #595 반영 시 자동 로그인으로 바꾼다                                                                                           |
| 가입 실패(중복 이메일 등)   | 백엔드 메시지 표시                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 필수 동의 미완료            | 보내지 않는다(`canSubmit(state, form, consent)` false). 빠진 체크박스를 강조하고, 막힌 입력칸이 없으면 첫 체크박스로 포커스                                                                                                                                                                                                                                                                                                                                                                      |
| `MEMBER_114`                | 이용약관 체크박스 강조(`aria-invalid` + 「이용약관에 동의해 주세요.」) + 포커스 이동                                                                                                                                                                                                                                                                                                                                                                                                             |
| `MEMBER_010`                | 약관·처리방침 공용(CONSENT_REQUIRED) — 둘 중 지금 꺼진 것만 강조, 둘 다 켜져 있으면 둘 다 강조                                                                                                                                                                                                                                                                                                                                                                                                   |
| `MEMBER_115`                | 처리방침 체크박스 강조(「개인정보 처리방침에 동의해 주세요.」) + 포커스 이동                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `MEMBER_116` / `MEMBER_011` | 만 14세 체크박스 강조(「만 14세 이상만 가입할 수 있어요.」) + 포커스 이동                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 동의 오류가 여러 개         | `resultMessage.errors[]` 의 필드를 모두 강조(필드별 첫 오류), 첫 항목으로 포커스                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 동의로 거절됨               | 이메일 인증 상태는 **그대로** 둔다 — 인증은 소비되지 않는다(계약 §0-1). 체크 후 다시 제출                                                                                                                                                                                                                                                                                                                                                                                                        |
| 포커스 시점                 | 강조(`aria-invalid`·오류 문구)가 커밋된 **뒤** 포커스한다(`useSignupConsentFocus`). 거절·카카오 미동의 Notice(error)는 `role="alert"`                                                                                                                                                                                                                                                                                                                                                            |
| 문체                        | 체크박스 라벨 「…동의합니다」는 법적 고지라 합니다체, 오류·안내는 해요체(DESIGN.md §10). 계약 §0-1 의 「…있습니다」를 「만 14세 이상만 가입할 수 있어요.」로 옮겼다                                                                                                                                                                                                                                                                                                                              |

| 비밀번호 정규식 | 백엔드 정규식과 **정확히 동일**하게 유지                                                                                                                                   |

| 가입 후 상태    | 백엔드 signup은 토큰 미발급 → 가입 직후 로그인 별도 필요                                                                                                                   |
| 중복확인        | 실시간 이메일 중복확인 엔드포인트 없음 → 제출 시 서버 응답으로만 판별                                                                                                      |
| 에러 코드 매핑  | `MEMBER_006`(미인증), 코드 만료/불일치 등 resultCode → 사용자 문구 매핑(공통명세 S2 #7 보존)                                                                               |
| 문서 판         | **판(version)은 보내지 않는다.** 서버 설정(`legal.terms-version`/`legal.privacy-version`)이 정한다(계약 §0)                                                                |
| 「보기」 링크   | `LEGAL_HREF` + `target="_blank" rel="noopener noreferrer"` — 인증까지 마친 입력 흐름을 잃지 않게 한다                                                                      |
| 복귀 경로       | `?redirect=` 는 **항상 `safeReturnPath` 를 거친다**(`auth-flow.ts`). 외부 주소·`//`·백슬래시·제어문자·인증 화면이면 버리고 쿼리 없이 보낸다 — 오픈 리다이렉트 방지         |
| 세션 확인 대기  | `page.tsx` 가 세션 쿠키(`bps_session`) 유무만 보고, 없으면 `GuestOnly assumeGuest` 로 `/api/auth/me` 응답 전에도 폼을 그린다(#579). 쿠키가 있으면 예전처럼 확인을 기다린다 |
