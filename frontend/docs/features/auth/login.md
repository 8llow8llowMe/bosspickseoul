## D1. 기능 개요

이메일/비밀번호를 입력받아 BFF 로그인을 호출하고, 성공 시 인증 상태로 전환·리다이렉트한다.

```
email/pw 입력 → 클라이언트 유효성 → POST /api/auth/login → 성공 시 auth-store 갱신 + redirect(원경로 또는 홈)
```

## D3. 아키텍처 / 시스템 설계

로그인 화면은 client component. 제출은 [session-bff](./session-bff.md) D4-1의 `/api/auth/login`을 호출한다. 토큰·세션 처리는 서버측(session-bff)이 전담하므로 이 화면은 토큰을 다루지 않는다.

| 모듈                        | 책임                                           |
| --------------------------- | ---------------------------------------------- |
| `app/(auth)/login/page.tsx` | 로그인 화면(폼, 유효성, 제출)                  |
| `src/components/auth/*`     | 입력 컴포넌트(legacy `components/User/*` 대응) |

## D4. 상세 동작 정의

### D4-1. 로그인 제출

| 사용 엔드포인트              | 용도        | 응답 → 내부 모델          | 비고                                                      |
| ---------------------------- | ----------- | ------------------------- | --------------------------------------------------------- |
| `POST /api/auth/login` (BFF) | 로그인 대행 | `{memberId}` → auth-store | 실제 백엔드 `/auth/login` 및 세션 봉인은 session-bff D4-1 |

동작: 폼 제출 → 클라이언트 유효성(이메일 형식, 비밀번호 비어있지 않음) → `POST /api/auth/login` → 성공 시 auth-store `isAuthenticated=true`, `memberId` 설정 → `redirect` 쿼리 경로(없으면 홈)로 이동. 실패 시 에러 표시.

## D5. 비즈니스 로직

| 조건                   | 결과                                                                                                                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 유효성 실패            | 제출 차단, 필드 에러 표시                                                                                                                                                                                                                                            |
| 로그인 성공            | auth-store 갱신 + 리다이렉트                                                                                                                                                                                                                                         |
| 로그인 실패(자격 오류) | 에러 메시지 표시, 비밀번호 필드 초기화(선택), 이메일 보존                                                                                                                                                                                                            |
| 네트워크/5xx           | 일반 에러 표시(금지 문구 회피, DESIGN.md 카피 규칙)                                                                                                                                                                                                                  |
| `?signup=1`            | Notice(success) 「가입을 마쳤어요. 방금 만든 비밀번호로 로그인해 주세요.」. `sessionStorage` 의 `bps:signup-email` 을 **한 번** 꺼내 지우고 이메일 칸에 채운 뒤 비밀번호 칸 포커스. 없거나 형식이 아니면 안내만. 이메일은 URL 에 싣지 않는다(방문 기록·로그·Referer) |
| `?reset=1`             | Notice(success) 「비밀번호를 재설정했어요. 새 비밀번호로 로그인해 주세요.」                                                                                                                                                                                          |

## D6. 주의사항

| 항목           | 내용                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 토큰 미취급    | 이 화면은 토큰을 받지도 저장하지도 않는다(서버 세션 전담)                                                                                                                                                                                                                                                                                                                                      |
| redirect 검증  | `redirect` 쿼리는 오픈 리다이렉트 방지를 위해 내부 경로만 허용. `safeRedirect`는 `/`로 시작 + `//`로 시작하지 않음 + 백슬래시(`\`) 미포함을 모두 만족해야 통과(Next URL 정규화로 `/\evil.com`→외부도메인 되는 우회 차단). 불충족 시 `/`로 대체                                                                                                                                                 |
| 이미 로그인    | 인증 상태로 `/login` 진입 시 `redirect`(안전할 때) 또는 홈으로 리다이렉트. 로그인 성공 직후 폼의 `router.replace(returnTo)` 와 `GuestOnly` 의 이동이 **같은 곳**을 가리켜야 한다 — 다르면 늦게 도는 GuestOnly effect 가 이겨 홈으로 떨어졌다(`login-form-return.interaction.test.ts`, e2e `signup-to-login.spec.ts`)                                                                           |
| 세션 확인 대기 | `page.tsx`(서버)가 세션 쿠키 `bps_session` 이 **있는지만** 본다. 없으면 `GuestOnly assumeGuest` 로 확인 전에도 폼을 그린다. 쿠키가 있으면(만료일 수 있음) 확인을 기다린다. 확인 결과가 로그인이면 어느 쪽이든 `GuestOnly redirectTo={returnTo}` 로 보낸다(#579). 세션 확인은 5초(`AUTH_HYDRATE_TIMEOUT_MS`)를 넘기면 끊고 비로그인으로 확정한다. 이 때문에 `/login`·`/register` 는 동적 렌더다 |
| 복귀 경로 전달 | 「회원가입」 링크·`error=social_signup` 의 「회원가입하기」 링크는 `buildRegisterHref(returnTo)` — `safeReturnPath` 를 통과한 값만 `?redirect=` 로 싣는다(#576)                                                                                                                                                                                                                                |
