# profile — 공통 개발 명세서

> **작성일**: 2026-07-28
> **대상**: 웹 (Next.js App Router)
> **상태**: V2 계약 정합화 진행

## S0. 배경 / 계약 점검

프로필 화면은 레거시 V1 회원·상권분석·시뮬레이션 API를 일부 호출하고 있어
현재 V2 백엔드 계약과 불일치한다. 백엔드는 변경하지 않고, 존재하는 V2 계약만
사용하며 미제공 기능은 실패하는 폼 대신 명시적인 대기 상태를 제공한다.

| 화면 / 기능          | 기존 프런트 호출                                | V2 백엔드 계약 | 처리                                  |
| -------------------- | ----------------------------------------------- | -------------- | ------------------------------------- |
| 내 정보 조회         | `GET /members/me`                               | 제공           | 유지                                  |
| 회원 정보 수정       | `PATCH /member/update`, `POST /firebase/upload` | 미제공         | 읽기 전용 정보와 대기 안내            |
| 비밀번호 변경        | `PATCH /member/password/change`                 | 미제공         | 대기 안내                             |
| 회원 탈퇴            | `DELETE /member/delete`                         | 미제공         | 대기 안내                             |
| 회원 북마크          | `GET /members/me/bookmarks`                     | 제공           | 자치구·행정동·상권을 V2 목록으로 표시 |
| 상권분석 저장 목록   | `GET /commercial/analysis-list`                 | 미제공         | V2 회원 북마크로 대체                 |
| 시뮬레이션 저장 목록 | `GET /simulation`                               | 미제공         | 대기 안내                             |

V2 회원 북마크는 저장한 기능의 출처가 아니라 대상 타입
(`DISTRICT`, `ADMINISTRATION`, `COMMERCIAL`)만 제공한다. 따라서 화면도
“상권분석/상권추천”이라는 출처 기반 표현 대신 “자치구·행정동/상권”으로
표현한다.

## S1. 기능 개요

로그인 사용자는 프로필에서 최신 회원 정보를 확인하고, V2 북마크 API에 저장된
자치구·행정동·상권을 대상 타입별로 확인한다. 수정 계약이 없는 계정 관리 기능과
시뮬레이션 저장 목록에는 실행 가능한 것처럼 보이는 입력·버튼을 노출하지 않는다.

## S2. 공통 요구사항

1. 프로필 전체는 인증 사용자만 접근한다.
2. 회원 정보는 `GET /api/v1/members/me`의 응답을 기준으로 표시한다.
3. 북마크는 `GET /api/v1/members/me/bookmarks`의 커서 페이지네이션을 끝까지
   수집하고 중복을 제거한다.
4. 북마크 로딩·빈 데이터·오류 상태를 구분해 표시한다.
5. 백엔드 계약이 없는 쓰기 기능은 네트워크 요청을 보내지 않는다.
6. 모바일과 데스크톱에서 가로 스크롤 없이 사용할 수 있어야 한다.

### S4-1. 북마크·설정 사용성 정리 (2026-10-10, #574 · #575 · #606 · #583)

UI/UX 진단(2026-10-09) C1·C2·C4·C5·C10·C13 후속. 화면 규격 정본은 `DESIGN.md` §5.6.

| 항목                     | 결정                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 북마크 카드 열기         | 카드 전체가 분석 탐색 화면 딥링크(`lib/profile/bookmark-links.ts`). 자치구·행정동은 정적 주소, 상권은 누를 때 그 카드만 역조회                                                                                                                                                                                                                                                                                                                                                                      |
| 내부 코드 표기           | 「지역 코드 11440660」 대신 상위 지역 이름(`서울특별시 마포구`). 상권은 응답에 상위 이름이 없어 적지 않는다(BE 응답 확장 시 추가)                                                                                                                                                                                                                                                                                                                                                                   |
| 해제·삭제                | 「숨기고 → 10초 되돌리기 토스트 → 그 뒤 DELETE」(`use-undoable-removal.ts`). 지역·상권 북마크 해제, 화면 보관 삭제, 시뮬레이션 기록 삭제, 로그인 기기 해제에 같은 규칙. 404 는 성공. 성공 뒤에는 숨김을 풀지 않는다(재조회 실패에도 다시 비치지 않게). 화면 이탈(페이지 이동·pagehide·**안쪽 탭 전환**)이면 대기 삭제를 바로 보내고, 그 뒤 실패는 「…하지 못했어요」로만 알린다. 한 페이지 마지막 항목을 숨기면 되돌리기 시간 동안 빈 페이지 문구가 보인다(시뮬레이션은 실제 DELETE 뒤 앞 페이지로) |
| 지역·화면 안쪽 탭        | 알약형 세그먼트, 선택은 `?tab=archive`(replaceState)                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 모바일 프로필 머리       | ≤1024px 에서 48px 아바타 + 닉네임 한 줄, 메뉴 가로 세그먼트, 약관 카드 숨김                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 회원 탈퇴 위치(결정 D-6) | 설정 탭에서 빼고 회원 정보 맨 아래 회색 링크. 탈퇴 확정 버튼은 danger 48px                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 비밀번호 폼              | 공용 `TextField` password 모드(표시 토글). 규칙 문구 유지 + 칸별 오류(`aria-invalid`·`aria-describedby`). 강도 미터는 두지 않는다(규칙이 이진이라 단계가 서버 판정과 어긋난다)                                                                                                                                                                                                                                                                                                                      |

**가입 폼 이관(B15, 2026-10-10)**: 가입 폼(`register-form.tsx`)은 `TextField revealable` 로 **옮기지 않고 같은 동작으로 맞췄다**. 이 폼은 `AuthShell` 의 입력칸(`TextInput`·`FieldLabel`)으로 로그인·재설정과 모양을 맞추고 있고, 비밀번호 칸 바로 아래에 규칙 체크리스트(`<ul>`, #578)를 둔다. `TextField` 의 `helperText` 는 `<p>` 안에 그려져 목록을 담을 수 없고, 칸 모양도 달라져 같은 화면의 다른 칸과 어긋난다. 대신 토글을 공용과 같게 했다 — 이름 `PASSWORD_REVEAL_LABEL`(「비밀번호 표시」) + `aria-pressed`, 모바일 히트 영역 44px(`touchHitArea`), 누를 때 포커스를 입력칸에 남김(`pointerdown`·`mousedown` `preventDefault`). 로그인 폼(`login-form.tsx`)도 같은 이유(AuthShell 칸)로 자체 토글을 두고 같은 동작으로 맞췄다. `register-form-password-toggle.interaction.test.ts`·`login-form-password-toggle.interaction.test.ts` 가 고정한다.
