## S0. 배경 / 기획 의도

| 항목               | 내용                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청 배경          | 가입 화면·푸터·마이페이지 어디에도 약관·처리방침이 없었다. 회원 정보(이메일·이름·닉네임)와 게시물·저장 이력을 받는 서비스라 개인정보 보호법 제30조의 처리방침 공개가 필요하다.                            |
| 참고본             | hondigagae 의 `/terms` · `/privacy`(조·항 트리 데이터 + 렌더러 + 구조 테스트). **구조만 가져오고 본문은 이 서비스의 실제 동작으로 다시 썼다** — 반려견 여행 서비스의 조항(위치정보·반려견 프로필)은 제외. |
| 구현 제외 범위     | 문의 페이지                                                                                                                                                                                               |
| 연관 기능 / 의존성 | [auth](../auth/auth.md), [layout](../layout), `src/components/layout/site-footer.tsx`                                                                                                                     |

## S1. 화면

| 라우트     | 파일                           | 비고                                                                                                          |
| ---------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `/terms`   | `app/(shell)/terms/page.tsx`   | 로그인 없이 열린다. sitemap `index`                                                                           |
| `/privacy` | `app/(shell)/privacy/page.tsx` | 로그인 없이 열린다. sitemap `index`                                                                           |
| 푸터       | `site-footer.tsx`              | 두 문서 링크. 푸터를 숨기는 지도 화면에서는 보이지 않는다                                                     |
| 마이페이지 | `profile-legal-links.tsx`      | 프로필 사이드바 맨 아래 「약관 및 정책」 카드. 푸터와 같은 `LEGAL_LINKS` 를 쓴다. ≤1024 에서는 한 줄로 접는다 |

- **구조**: 목차(`≥1080` 왼쪽 sticky 240) + 본문(`--w-read` 720) 중앙 묶음. 좁으면 제목 → 목차(2열) → 본문. 본문은 카드 한 장, 조문 사이 구분선, 개정 이력은 별도 카드.
- **데이터**: `src/lib/legal/{terms-of-service,privacy-policy}.ts` — 마크다운이 아니라 조·항 트리(`types.ts`). 본문은 합니다체, 화면 라벨(`copy.ts`)은 해요체.
- **구조 테스트**: `legal.test.ts` — 조 번호 연속, 표 행 길이, 처리방침 법정 12개 절 제목·순서, 보호책임자 값.
- **개정**: `version` · `effectiveDate` · `history` 를 함께 고친다. **처리방침·약관의 `version` 은 BE `legal.{privacy,terms}-version`(auth-service local·dev·prod yml)과 같은 PR 에서 함께 바꾼다** — 가입 동의 기록에 남는 판이 이 값이다. 약관 제3조가 사전 공지 7일(불리한 변경 30일)을 규정하므로 시행일을 미래로 두고 먼저 배포할 수 있다.

## S3. 확인이 필요한 값 (사람이 정해야 한다)

코드에서 확인되지 않아 **초안 값이거나 문구를 일부러 좁힌 곳**이다. 운영값이 정해지면 고친다.

| 항목                                | 현재 문서의 상태                                                                                                                                                        | 필요한 결정                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 개인정보 보호책임자·문의 이메일     | `contact.ts` — 최성호 · `privacy@bosspickseoul.com`(**메일함 존재 미확인**)                                                                                             | 실제 책임자와 열려 있는 주소. 테스트가 `@bosspickseoul.com` 도메인을 강제        |
| 운영 주체 표기                      | 「BossPickSeoul 운영팀」 (저장소에 사업자·대표·주소 없음)                                                                                                               | 사업자 등록 여부에 따라 사업자명·주소 표기                                       |
| 시행일                              | 이용약관 1.0 2026-10-02 · 처리방침 1.2 2026-10-14(1.1 은 2026-10-09)                                                                                                    | 1.2 는 공지 후 7일로 잡았다. 배포가 2026-10-07 보다 늦어지면 시행일을 뒤로 민다  |
| 접속 로그 보관 기간                 | 「관계 법령에서 정한 기간」                                                                                                                                             | 게이트웨이 로그(IP·UA·URI) 실제 보관 기간                                        |
| 탈퇴 이메일 보관 기간               | 「탈퇴 후에도 보관」(기간 미명시)                                                                                                                                       | **보관 기간 명시가 필요하다** — 무기한 보관은 파기 의무와 충돌할 수 있다         |
| 탈퇴 후 이력·북마크 보존            | 「탈퇴 후에도 보존」으로 사실대로 적음                                                                                                                                  | 탈퇴 시 삭제로 바꿀지(백엔드 변경). 처리방침상 가장 약한 부분                    |
| 이메일 발송 사업자                  | Google LLC(Gmail SMTP, 국외 이전)                                                                                                                                       | 운영 SMTP 가 Gmail 이 아니면 제5조 수정                                          |

| 「그 밖에 위탁 없음」·「요금 없음」 | 그렇게 적었다                                                                                                                                                           | 호스팅 사업자(클라우드)가 있으면 위탁·국외 이전 표 갱신, 유료 도입 시 약관 제7조 |
