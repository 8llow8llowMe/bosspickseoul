## 0. 결론

9/11 감사가 **"잘 만든 화면인가"** 를 봤다면, 이 문서는 **"보자마자 써 보고 싶어지는가"** 를 본다.

홈은 제품을 정직하고 정확하게 설명한다. 그런데 **방문자가 직접 해 보는 순간이 늦고, 해 본 것이 다음 화면으로 이어지지 않는다.**
고칠 것은 세 가지다.

1. **첫 5초에 "내 얘기"가 없다.** 히어로는 "상권부터 확인하세요"라는 지시이고, 실제 제품(지도)은 흐린 회색 배경으로 카드 뒤에 깔려 있다. 지도가 눌린다는 신호가 없다.
2. **해 본 것이 끊긴다.** 02단계에서 강남구·카페를 골라도 「이 조건으로 AI 리포트 받기」는 **빈 `/analysis`** 로 간다. 마지막 CTA도 "시작하기"로 리셋된다.
3. **페이스가 늘어진다.** 데스크톱에서 한 화면짜리 섹션 넷 중 셋이 **47\~60% 비어 있고**, 자치구 Top5 순위가 같은 모양으로 **두 번** 나온다.

좋은 소식은 **새 백엔드 API 없이** 다 고칠 수 있다는 점이다. `/analysis` 는 이미 `districtCode`·`serviceCode` 딥링크를 읽고(`src/lib/analysis/selection.ts:144`), 히어로 툴팁은 이미 `GET /districts/{code}` 실데이터를 쓴다. 분석·추천·시뮬레이션은 비로그인 공개 라우트라(`middleware.ts:14`) **가입 전에 가치를 보여 주는 구조**가 이미 깔려 있다. 남은 일은 그 길을 랜딩에서 이어 주는 것이다.

## 2. 지금 잘하는 것 — 유지

1. **가입 벽이 없다.** 분석·추천·시뮬레이션 모두 공개 라우트다. 토스가 "신용점수 무료 조회"로 가입 전에 가치를 먼저 준 것과 같은 구조다. 이게 이 서비스의 가장 큰 무기다.
2. **판단 흐름 4탭이 제품 데모 그 자체다.** 01 실데이터 순위, 02 지역·업종 칩 미니데모, 03 실추천 API, 04 손익분기 곡선. "설명" 대신 "보여 주기"를 한다.
3. **정직하다.** 예시 데이터에는 전부 「예시」 라벨이 있고, 지어낸 수치·과장 문구가 없다. 데이터 출처 섹션이 공식 원문 링크를 단다. 이건 절대 깨면 안 되는 자산이다 — 아래 제안도 전부 이 원칙 안에서 만든다.

## 4. 수정 제안

규모: **S** = 반나절, **M** = 1\~2일, **L** = 3일+. 모든 항목은 **새 백엔드 API·계약 변경 없음**, DESIGN.md 토큰 안에서 한다.

### P0 — 전환에 직접 영향

#### P0-1. 「이 조건으로 AI 리포트 받기」가 조건을 버린다 — 딥링크 연결 `S`

- **문제**: `story-steps.ts:61` 의 CTA `href` 가 고정 `'/analysis'` 다. 사용자가 02단계에서 강남구·카페를 골랐어도 분석 화면은 빈 지도에서 시작한다. 버튼 문구가 약속한 것을 지키지 않는다 — 신뢰를 가장 크게 깎는 종류의 결함이다.
- **제안**: `product-story.tsx` 가 이미 들고 있는 `selection` 으로 `href` 를 만든다. `/analysis` 는 `districtCode → administrationCode → commercialCode → serviceCode` 순서로 읽으므로(`selection.ts:199` `getActiveAnalysisStep`) 02→03 연쇄가 풀어 둔 행정동·상권 코드까지 실으면 **분석 결과 화면으로 바로 착지**한다. 연쇄가 아직 안 풀렸으면 `districtCode` 만 실어 "행정동 고르기" 단계부터 시작.
- 03 「상권 추천받기」, 히어로 지도 클릭(`seoul-districts-map.tsx:184`, 이미 `districtCode` 를 싣는다 — 좋음)도 같은 원칙으로 점검한다.
- **지표**: 02 CTA 클릭 → 분석 결과 도달 단계 수 (현재 4단계 선택 필요 → 0\~1).

#### P0-2. 히어로에 "내 경우" 입력 칸 — 가치 먼저 보여 주기 `M`

- **문제**: 히어로 카드는 읽을거리 + 버튼이다. 방문자가 아무것도 넣지 않고 다음 페이지로 가야 "나한테 해당되는지"를 안다.
- **제안**: 카드 안 CTA 위에 **질문형 2칸 피커**를 둔다.

  ```
  어디에 차리실 건가요?   [ 마포구 ▾ ]   [ 카페 ▾ ]   [ 바로 보기 → ]
  ```

  - 자치구를 고르는 즉시 카드 아래에 **실데이터 미리보기 한 줄**이 펼쳐진다: 「마포구 · 월 매출 ○○억 · 일 유동인구 ○○만 명」. 데이터는 히어로 툴팁이 이미 부르는 `GET /districts/{code}` 를 재사용한다(새 호출 없음, 같은 캐시).
  - 동시에 지도에서 그 자치구가 파랗게 채워진다 — **25칸 중 하나를 고르는 "Pick"** 이 로고 은유 그대로 화면에서 일어난다(9/11 감사 P 「Pick 이 카피에 없다」의 해법).
  - 「바로 보기」는 `/analysis?districtCode=…&serviceCode=…` 딥링크(P0-1 과 같은 빌더).
  - 업종은 고르지 않아도 된다(선택 사항). 자치구 1개만 골라도 다음 화면이 의미 있다.

- **왜 이게 핵심인가**: 랜딩 전환에서 가장 큰 레버는 "첫 입력을 얼마나 일찍 받느냐"다. 입력한 사람은 결과를 보러 간다(매몰 효과). 토스의 "내 신용점수 바로 보기", 직방의 "어느 동네 찾으세요?" 와 같은 패턴이다.
- **지켜야 할 것**: 미리보기 수치는 실데이터만. API 실패 시 미리보기 줄만 숨기고 버튼은 살린다(홈의 "조용한 실패" 원칙).
- **지표**: 히어로 피커 사용률, 히어로 → `/analysis` 진입률.

#### P0-3. 모바일 첫 화면에 h1·CTA — 기존 초안 구현 `M`

- **문제**: 375×812 첫 화면에 지도와 두 줄만 있다. 지도 위 공백 약 200px. 모바일 방문자는 서비스가 뭔지 모른 채 지도를 탭해 바로 이탈하거나, 스크롤을 포기한다.
- **제안**: [mobile-hero-first-screen](./mobile-hero-first-screen.md) 초안(카드 → 지도 순서, 지도 탭 → 하단 시트)을 그대로 구현하되, **P0-2 피커를 카드에 포함**한다. 하단 시트의 CTA 도 딥링크.
- **완료 기준**: 375×812 첫 화면에 h1·피커·주 CTA 가 모두 보인다.

#### P0-4. 이벤트 계측 붙이기 `S`

- **문제**: 계측 도구가 없다. 아래 어떤 제안도 효과를 잴 수 없다.
- **제안**: 최소 이벤트 8개만 먼저 — `hero_cta_click`, `hero_picker_select`, `hero_map_hover`, `hero_map_click`, `story_tab_change`, `story_demo_chip`, `story_cta_click(step)`, `final_cta_click`. 도구 선택(GA4 / Amplitude / 자체 수집)은 **사용자 결정**. 개인정보 처리방침 갱신이 따라올 수 있다.

### P1 — "해 보고 싶다"를 만드는 인터랙션

#### P1-1. 지도가 눌린다는 걸 보여 주기 — 자동 시연 + 범례 `S`

- **문제**: 데스크톱 히어로 지도는 호버하면 실데이터 툴팁(시간대별·요일별 막대)이 뜨는 **이 홈 최고의 인터랙션**인데, 아무 신호가 없어 대부분 발견하지 못한다. 지도 채도도 낮아(회색 위 연회색) 배경 장식으로 읽힌다. 파랗게 펄스하는 자치구 3곳의 의미도 화면에 없다.
- **제안**:
  1. **자동 시연**: 로드 2초 후, 사용자가 아직 지도와 상호작용하지 않았으면 강조 자치구 하나에 툴팁을 **한 번** 띄웠다가 4초 뒤 닫는다. 마우스가 지도에 들어오면 즉시 중단, 다시 하지 않는다. `prefers-reduced-motion` 이면 끈다.
  2. **어포던스 캡션**: 지도 하단에 한 줄 — 「자치구에 마우스를 올리면 시간대별 유동인구가 보여요」(모바일: 「눌러서 보기」).
  3. **범례**: 펄스 3곳의 실제 기준을 캡션으로(9/11 감사 K). 펄스는 3회 후 정지.
- **지표**: `hero_map_hover` 비율.

#### P1-2. 04 손익분기 — "내 숫자로 해 보기" 슬라이더 `M`

- **문제**: 04단계는 고정 예시(초기 투자 1억 2천, 월 순이익 1,600만 → 8개월)다. 문구도 「이 단계는 고른 조건과 상관없는 예시예요」. 방문자가 가장 궁금한 질문("내 돈으로 몇 달이면 회수?")에 답할 수 있는 자리인데 구경만 하게 한다.
- **제안**: 곡선 위에 슬라이더 2개 — **초기 투자**, **월 순이익**. 드래그하면 곡선 기울기·0 교차점·「N개월째 손익분기」 라벨·왼쪽 큰 숫자가 실시간으로 바뀐다. 계산은 `누적 = −투자 + 월 순이익 × 개월` 로 **클라이언트에서만** 한다 — 방문자당 `POST /simulations/reports` 를 피한 기존 결정(story-and-rankings)을 지킨다. 매출·비용 비율 같은 가정을 지어내지 않으려고 입력을 "순이익"으로 받는다.
- CTA 는 「이 숫자로 정밀 시뮬레이션 →」로 바꾸고, 시뮬레이션 마법사가 쿼리를 받게 되면 값을 넘긴다(지금은 받지 않음 — 별도 검토).
- **왜**: 슬라이더는 "만지면 결과가 바뀌는" 가장 원초적인 후킹이다. 사용자가 직접 0선을 넘기는 순간 제품의 가치가 체감된다.
- **지표**: 슬라이더 조작률, 04 CTA 클릭률.

#### P1-3. 02 AI 요약을 "생성되는 것처럼" + 숫자 카운트업 `S`

- **문제**: 차별점인 AI 리포트가 한 줄 회색 문장으로만 나온다. 판단 흐름 왼쪽 큰 숫자(25곳 · +5.3% · 9→5 · 8개월)는 탭이 바뀌어도 그냥 바뀐다.
- **제안**:
  - 02탭이 활성화되거나 칩을 바꾸면 AI 요약 문장이 **글자 단위로 타이핑**(약 600ms)된다. 「AI 리포트 요약 · 예시」 라벨은 그대로 먼저 보인다(정직성 유지).
  - 큰 숫자는 탭 활성화 시 0 → 값으로 **카운트업**(`--motion-slow` 400ms, `--ease-standard`).
  - 둘 다 `prefers-reduced-motion` 에서 즉시 표시. `aria-live` 는 최종 문장 한 번만 읽힌다.

#### P1-4. 같은 Top5 두 번 → 두 번째는 "요즘 뜨는 곳"으로 `S`

- **문제**: 판단 흐름 01탭의 「자치구 순위 · 상위 5곳」과 바로 아래 「자치구 지표 순위」 섹션이 **같은 데이터·같은 막대·같은 토글**이다(조회수 데이터가 n<3 이라 지표만 렌더되는 상태 — `ranking-minimum-sample` 이 의도한 동작). 결과적으로 방문자는 같은 표를 두 번 본다.
- **제안** (택 1, 사용자 결정):
  - **A. 관점 바꾸기** — 지표만 렌더되는 모드에서 정렬 기준을 "전월 대비 변화율"로 바꾸고 제목을 「상위 10곳 중 지난달보다 가장 많이 늘어난 자치구」로. 같은 `GET /districts/top-ten` 응답이라 새 호출이 없고, "요즘 뜨는 곳"은 뉴스성이 있어 재방문 이유가 된다. 범위(상위 10곳 안)를 제목에 명시해 오해를 막는다.
  - **B. 빼기** — 지표만 렌더되는 모드에서는 섹션을 숨긴다. 문서 0.9 화면 단축.
- 순위 행은 이미 링크다 — 행 끝에 「분석 →」 힌트를 hover 시 노출해 클릭 가능성을 드러낸다.

#### P1-5. 빈 화면을 채우거나 줄이기 `S`

- **문제**: 2026-09-30 「섹션 최소 한 화면」 결정 이후 짧은 섹션 셋이 **47\~60% 비어 있다**(§1-1). 스크롤하다 400px 넘는 흰 화면을 만나면 사용자는 "끝났다"거나 "로딩 중"으로 읽는다. 특히 순위 → 데이터 출처 사이에서 흐름이 끊긴다.
- **제안**: 이전 결정이 사용자 요청이었으므로 **재결정을 요청**한다. 두 갈래다.
  - **A. 채우기** — 한 화면 규칙은 유지하고 콘텐츠를 키운다: 섹션 제목 26→30px, 카드 패딩 확대, 데이터 출처 카드에 데이터 규모(「자치구 25 · 행정동 425 · 상권 1,650」, 이미 카드 안에 있는 실값)를 큰 숫자 배너로 끌어올린다.
  - **B. 풀기** — 판단 흐름(고정 스크롤)만 한 화면을 유지하고 나머지는 `min-height` 를 풀어 섹션 상하 여백 토큰으로 간다. 문서 약 1.5 화면 단축.
  - PM 추천은 **A** — 데이터 출처의 숫자 배너는 그 자체로 신뢰 후킹이다.

#### P1-6. 마지막 CTA를 "이어서 하기"로 `S`

- **문제**: 「지금 내 상권을 분석해 보세요. / 시작하기」 — 페이지 내내 한 행동(지역·업종 선택, 순위 클릭)과 무관하게 리셋된다. "시작하기"는 무엇이 시작되는지 말하지 않는다(카피 규칙: 목적어 생략 금지).
- **제안**:
  - 방문자가 히어로 피커나 02탭에서 조건을 골랐으면: 「**마포구 · 카페**로 이어서 분석할까요?」 + 주 버튼 「이 조건으로 분석하기」(딥링크) + 보조 「회원가입하고 결과 저장하기」.
  - 고른 게 없으면: 「계약하기 전에, 그 자리부터 확인해 보세요.」 + 「내 상권 분석하기」 + 보조 「회원가입」.
  - 가입 버튼에는 가입하면 얻는 것을 한 줄로 — 「분석 화면 저장 · 시뮬레이션 비교」(실제 기능만, 벤토 카드에 이미 있는 것).
  - 선택 상태는 페이지 안 상태로만 들고 간다(스토어·저장소 신설 불필요 — 히어로·스토리·CTA 가 같은 `HomePage` 아래라 컨텍스트 하나면 된다).

## 5. 하지 않는 것

- **지어낸 사회적 증거**: "1만 명이 사용 중", "오늘 ○○명 분석" 같은 수치는 실집계 API 가 생기기 전엔 넣지 않는다. 「지금 많이 본 지역」의 n≥3 규칙도 유지.
- **긴급성 조작**: 카운트다운, "지금만" 문구, 진입 팝업·이탈 모달.
- **결과 보장 문구**: "성공하는 자리", "망하지 않는" 류.
- **랜딩 방문자당 쓰기 API**: 시뮬레이션 `POST` 등. 04 슬라이더는 클라이언트 계산만.

이 서비스의 브랜드 자산은 "정직한 데이터"다. 후킹은 **만져 보게 하는 것**으로 만들고, **부풀리는 것**으로 만들지 않는다.
