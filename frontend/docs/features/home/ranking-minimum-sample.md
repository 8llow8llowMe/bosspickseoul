### D0-1. 실측 근거

**dev 백엔드 실응답** (2026-09-11, `GET https://api-dev.bosspickseoul.com/api/v1/analysis-rankings?areaType=DISTRICT&size=8`):

```json
{
  "dataHeader": { "success": true, "resultCode": null, "resultMessage": null },
  "dataBody": {
    "areaType": {
      "code": "DISTRICT",
      "name": "자치구",
      "description": "자치구 분석"
    },
    "windowHours": 24,
    "rankings": [
      { "rank": 1, "areaCode": "11680", "areaName": "강남구", "viewCount": 1 }
    ]
  }
}
```

| 대상                               | 실측                                                                 | 문제                                                 |
| ---------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 조회 순위 항목 수                  | **1** (강남구 1회)                                                   | 「순위」라고 부를 표본이 아니다                      |
| 좌측 열 콘텐츠 높이                | **65px** / 열 높이 **330px**                                         | 콘텐츠가 열 안에 떠 있다                             |
| 렌더된 인사이트                    | 「유동인구 2위 관악구는 지금 많이 본 **1곳**에 들지 않았습니다.」    | n=1 에서 비교 문장이 공허하다                        |
| 섹션 제목                          | 「다른 사람들이 보는 곳과, 숫자가 좋은 곳은 다릅니다.」              | 근거를 잃는다. 종결형도 합니다체라 S2 #3-1 위반      |
| 스크롤 트랙                        | **300dvh 켜짐** (`dual` 판정 통과 — 좌측 1행 + 우측 지표)            | 1행짜리 열을 위해 3화면을 쓴다                       |

## D1. 기능 개요

조회 순위 응답의 **유효 항목 수 n** 으로 이 섹션의 표현 강도를 정한다. n≥3 이면 지금까지의 듀얼 랭킹 그대로, n<3 이면 좌측 열을 접고 지표 순위만 남기며 제목·아이브로를 그 상태의 문구로 바꾼다.

```
analysis-rankings 응답 → 유효 항목 n 산출 → 최소 표본 판정(n≥3) → 상태 결정(제거 / 지표만 / 조회만 / dual) → 문구·인사이트·트랙 결정
```

```
                    ┌─ n≥3 & 지표 있음 ──→ [dual]    두 열 + 인사이트 + (트랙)
응답 도착 ─ 판정 ───┼─ n≥3 & 지표 없음 ──→ [조회만]  좌측 1단, 인사이트 없음
                    ├─ n<3  & 지표 있음 ──→ [지표만]  우측 1단, 인사이트 없음
                    └─ n<3  & 지표 없음 ──→ [제거]    섹션 자체를 렌더하지 않음
```

:::mermaid
stateDiagram-v2
[_] --> 스켈레톤: 두 쿼리 중 하나라도 pending
스켈레톤 --> dual: n≥3 그리고 지표 1종 이상 데이터
스켈레톤 --> 지표만: n<3(실패·빈 목록·표본 부족) 그리고 지표 데이터 있음
스켈레톤 --> 조회만: n≥3 그리고 지표 전부 결손
스켈레톤 --> 제거: 좌우 모두 부재
dual --> [_]
지표만 --> [_]
조회만 --> [_]
제거 --> [*]
:::

| 상태       | 진입 조건(두 쿼리 모두 결론난 뒤)                                        | 렌더                                        |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------- |
| **dual**   | 유효 조회 항목 `n ≥ 3` **그리고** 3지표 중 1종 이상에 데이터             | 좌·우 2단 + 인사이트 슬롯 + (트랙은 D5-3)   |
| **지표만** | `n < 3` (집계 실패 / 빈 목록 / 표본 부족 셋 모두) **그리고** 지표 데이터 | 우측 1단. 인사이트 슬롯 **없음**            |
| **조회만** | `n ≥ 3` **그리고** 3지표 전부 결손 — `story-and-rankings` D5-4 승계      | 좌측 1단. 인사이트 슬롯 **없음**            |
| **제거**   | 좌측도 우측도 없음                                                       | `return null` — 오류 카드·재시도 버튼 없음  |
| 스켈레톤   | 두 쿼리 중 하나라도 `isPending`                                          | 기존 스켈레톤(8칸) + **지표만 상태의 문구** |

> 「조회만」은 이 문서가 새로 만드는 상태가 아니라 `story-and-rankings` D5-4 의 「좌측 단독 1단」이다. 최소 표본 게이트가 그 진입 조건을 `n ≥ 3` 으로 좁힐 뿐이므로 여기 함께 적는다.

| -------------------------------------------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |

| 뷰모델이 `PopularDistrictsView` 에 판정 결과 필드를 추가 | ✗    | 뷰모델은 `/analysis` 1단계와 표기 규칙을 공유한다. 홈에서만 쓰는 임계값을 공유 뷰모델의 필드로 올리면 다른 소비자가 그 값을 의미 없이 들고 다닌다          |
| **lib 에 상수 + 순수 판정 함수, 적용은 컴포넌트**        | ✓    | 임계값과 판정식이 한 곳에 있어 인사이트와 컴포넌트가 같은 기준을 쓴다. 「원본 항목 수」는 그대로 남아 원인 구분이 가능하다. 순수 함수라 단위 테스트가 쉽다 |

| ---------------------- | ----------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| (상수)                 | `MIN_VIEW_SAMPLE_SIZE`                          | `number` = `3`                            | 좌측 열·인사이트가 성립하는 최소 유효 항목 수. `src/lib/home/popular-districts.ts` 가 소유하고 export      |
| (판정)                 | `hasEnoughViewSample(view)`                     | `(view: PopularDistrictsView) => boolean` | `view.items.length >= MIN_VIEW_SAMPLE_SIZE`. 순수 함수                                                     |
| `PopularDistrictsView` | `items` / `windowLabel`                         | `PopularDistrict[]` / `string \| null`    | **변경 없음.** 표본 부족이어도 `items` 는 원본 그대로 유지한다                                             |
| `PopularDistrict`      | `rank` `districtCode` `name` `viewCount` `href` | 현행                                      | 변경 없음                                                                                                  |
| (컴포넌트 지역 상태)   | `view`                                          | `PopularDistrictsView \| null`            | `rawView && rawView.items.length > 0 && hasEnoughViewSample(rawView) ? rawView : null`                     |
| (컴포넌트 지역 상태)   | `dual`                                          | `boolean`                                 | `viewWillExist && metricWillExist` — 계산식 자체는 현행 유지(D5-4-2). `view` 정의가 바뀌면서 결과가 바뀐다 |

```ts
// src/lib/home/popular-districts.ts (추가분)

/**
 * 좌측(조회수) 열과 인사이트 문장이 성립하는 최소 표본.
 *
 * 1~2곳짜리 「순위」는 비교 대상이 되지 못한다 — 사회적 증거는 표본이 작을수록
 * 역효과다. 이 값은 인사이트 가드와 공유한다(두 곳의 임계값이 갈리면 좌측 열은
 * 있는데 문장만 없거나 그 반대가 된다).
 */
export const MIN_VIEW_SAMPLE_SIZE = 3

export const hasEnoughViewSample = (view: PopularDistrictsView): boolean =>
  view.items.length >= MIN_VIEW_SAMPLE_SIZE
```

## D4. 상세 동작 정의

### D4-1. 최소 표본 판정

> **API 문서**: [commercial-service OpenAPI](https://api-dev.bosspickseoul.com/commercial-service/v3/api-docs) — `분석 인기 순위` 태그 (2026-09-11 실물 확인)

| 사용 엔드포인트                                   | 용도                               | 응답 → 내부 모델 매핑                                                                                                           | 비고                               |
| ------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `GET /analysis-rankings?areaType=DISTRICT&size=8` | 조회 상위 자치구(현행 호출 그대로) | `dataBody.rankings[]` → `PopularDistrict[]` / `dataBody.windowHours`(int32) → `windowLabel` / **`areaCode` 유효 항목 수** → `n` | BFF 가 `/api/v1` 프리픽스를 붙인다 |

응답 스키마 실물(Swagger `AnalysisRankingResponse` / `AnalysisRankingItem`):

| 필드                   | 타입                        | 필수/nullable                                | 이 문서가 쓰는 방식                                 |
| ---------------------- | --------------------------- | -------------------------------------------- | --------------------------------------------------- |
| `areaType`             | 객체(code/name/description) | `DISTRICT \| COMMERCIAL \| ADMINISTRATION`   | 쓰지 않음                                           |
| `windowHours`          | integer(int32)              | 예시 `24`                                    | 「최근 N시간」 표기(현행 규칙 유지)                 |
| `rankings[]`           | 배열(조회 수 내림차순)      | 스키마상 required 표기 없음 — 부재 대비 필요 | **길이가 판정의 유일한 입력**                       |
| `rankings[].rank`      | integer(int32)              | 1부터                                        | 표시·인사이트 문장                                  |
| `rankings[].areaCode`  | string                      | 예시 `"3110008"`                             | 공백이면 항목을 버린다(현행) → 버린 뒤의 길이가 `n` |
| `rankings[].areaName`  | string                      | **수집되지 않았으면 null**                   | 정적 표로 폴백(현행)                                |
| `rankings[].viewCount` | integer(int64)              | 윈도우 내 조회 수                            | 표시만. **판정에 쓰지 않는다**(D5-2)                |

> **응답에 총 조회수·총 항목 수·전체 모수 필드는 없다.** `windowHours` 와 `rankings[]` 가 전부다. 「총 조회 N회 미만이면 표본 부족」 같은 판정을 서버 값으로 세울 수 없고, FE 가 더할 수 있는 것은 `size=8` 로 잘린 상위 8개의 합뿐이다(D5-2).

판정 순서:

1. `isApiSuccess` 통과 + `toPopularDistrictsView` 로 뷰모델 생성 → 실패면 `view = null`.
2. `areaCode` 가 빈 항목은 기존 규칙대로 버린다(누를 곳이 없는 행은 남기지 않는다).
3. 남은 길이가 `n`. `n === 0` → `view = null`(빈 목록, 현행).
4. `n < MIN_VIEW_SAMPLE_SIZE` → `view = null`(**표본 부족, 신규**).
5. `n ≥ 3` → `view` 유지.

**`rank` 값은 판정에 쓰지 않는다.** 서버가 주는 `rank` 는 1부터의 순위이지 목록 길이가 아니고, 중간 항목이 `areaCode` 결손으로 버려지면 `rank` 최댓값과 실제 행 수가 어긋난다.

### D4-2. 상태별 문구

**모든 문구는 해요체로 확정한다.** 현재 제목이 합니다체(S2 #3-1 위반)이므로 이 작업에서 함께 바꾼다. 과장·결과 보장 표현(「최적의」·「성공적인」)은 쓰지 않는다.

| 자리             | dual (n≥3 + 지표)                                   | 지표만 (n<3)                                 | 조회만 (n≥3, 지표 결손)                  |
| ---------------- | --------------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| 아이브로         | `지금 많이 본 지역`                                 | `자치구 지표 순위`                           | `지금 많이 본 지역`                      |
| 제목(h2)         | `다른 사람들이 보는 곳과, 숫자가 좋은 곳은 달라요.` | `유동인구·매출·개업 수로 자치구를 비교해요.` | `지금은 이 자치구들을 많이 보고 있어요.` |
| 좌측 열 제목(h3) | `지금 많이 본 지역` + `· {windowLabel}`             | (없음)                                       | `지금 많이 본 지역` + `· {windowLabel}`  |
| 우측 열 제목(h3) | `{지표라벨} 상위 자치구`                            | `{지표라벨} 상위 자치구`                     | (없음)                                   |
| 지표 결손 안내   | `이 지표는 아직 집계가 없어요.`                     | `이 지표는 아직 집계가 없어요.`              | (없음)                                   |
| 인사이트 슬롯    | 마운트(문장은 규칙 A·B, D4-3)                       | **없음**                                     | **없음**                                 |

문구 확정 근거:

- **dual 제목**은 뜻을 바꾸지 않고 종결형만 해요체로 옮겼다(「다릅니다」 → 「달라요」). 이 섹션의 논지는 그대로다.
- **지표만 아이브로**를 `지금 많이 본 지역` 으로 두면 좌측 열이 없는데 「많이 본」을 약속하게 된다. `자치구 지표 순위` 는 화면에 실제로 있는 것만 말한다.
- **지표만 제목**은 세 토글(유동인구·매출·개업)이 화면에 그대로 있으므로 참이다. 「비교해요」는 사용자가 토글로 실제 하는 행동이다.
  - 기각안 ①: `유동인구·매출·개업 수로 본 자치구 상위 5곳이에요.` — 지표가 5행 미만으로 올 수 있어(D5-4-1) 숫자가 거짓이 될 수 있다.
  - 기각안 ②: `숫자가 좋은 자치구를 골라 드려요.` — 결과 보장·추천으로 읽힌다(S2 #3-2 위반). 이 순위는 추천이 아니다.
- **조회만 제목**은 집합 소속만 진술한다. 「많이 보고 있어요」는 응답이 실제로 말해 주는 사실이다.
- **지표 결손 안내**는 합니다체(`이 지표는 집계가 없습니다.`)에서 해요체로 옮기며 「아직」을 넣었다 — 영구 부재가 아니라 집계 대기 상태임을 말한다.

**문구 교체가 레이아웃을 밀지 않게 한다.** 스켈레톤(1줄) → 최종 상태(데스크톱 1줄 / 모바일 2줄)로 제목 줄 수가 바뀔 수 있다. `Title` 에 **2줄분 `min-height`** 를 둔다(R2 인사이트 슬롯 74px 예약과 같은 근거).

| 브레이크포인트 | `font-size` / `line-height` | `min-height`(2줄) |
| -------------- | --------------------------- | ----------------- |
| 기본           | 26px / 36px                 | **72px**          |
| ≤640px         | 22px / 30px                 | **60px**          |
| ≤480px         | 20px / 28px                 | **56px**          |

### D4-3. 인사이트 최소 표본 조건

`buildRankingInsight` 의 맨 앞 가드를 바꾼다.

```ts
// 현행
if (views.length === 0 || metric.items.length === 0) return null

// 개정
if (views.length < MIN_VIEW_SAMPLE_SIZE || metric.items.length === 0)
  return null
```

문장 자체의 형태는 유지하고 종결형만 해요체로 바꾼다.

| 규칙 | 조건(현행 유지)                                          | 확정 문구                                                              |
| ---- | -------------------------------------------------------- | ---------------------------------------------------------------------- |
| A    | 지표 Top3 중 조회수 목록에 **없는** 첫 항목 `x`          | `{지표라벨} {x.rank}위 {x.name}는 지금 많이 본 {N}곳에 들지 않았어요.` |
| B    | 조회수 Top3 중 지표 목록에 **없는** 첫 항목 `y`          | `조회수 {y.rank}위 {y.name}는 {지표라벨} Top {M} 밖이에요.`            |
| —    | 둘 다 해당 없음 / `views.length < 3` / 지표 목록 빈 배열 | `null` — 슬롯은 자리만 예약한 채 비운다(R2)                            |

`N` = `views.length`(3~8), `M` = `metric.items.length`(랭킹 우측은 Top5 고정).

**「지금 많이 본 N곳」 표현을 유지하는 근거.** `N` 은 **좌측 열에 실제로 보이는 행 수와 항상 같다** — 사용자는 문장 옆의 목록을 세어 검증할 수 있다. 최소 표본이 3으로 올라가면 문제가 됐던 `1곳`·`2곳` 은 사라지고, 남는 최솟값 `3곳`(「…지금 많이 본 3곳에 들지 않았어요.」)은 목록 3행과 정확히 대응해 읽힌다. `size=8` 상한에 걸린 경우에도 「많이 본 8곳」은 화면의 8행을 가리키므로 거짓이 아니다.

- 기각안: `지금 많이 본 목록에 없어요.` — N 을 지워 표본 크기를 감추게 된다. 표본을 드러내는 편이 정직하고, 최소 표본 가드가 이미 하한을 보장한다.

### D4-4. 로딩 스켈레톤이 가정하는 상태

스켈레톤은 두 쿼리 중 하나라도 `isPending` 이고 아직 그릴 것이 없을 때 나온다. 이때는 최종 상태를 알 수 없다.

| 후보                       | 채택 | 이유                                                                                                                                                              |
| -------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| dual 문구를 쓴다(현행)     | ✗    | dev 실데이터의 기본값이 「지표만」이므로 **정상 로드마다** 제목이 dual → 지표만으로 바뀐다. 없는 비교를 먼저 약속하는 셈이다                                      |
| 중립 문구를 새로 만든다    | ✗    | 어느 상태에서도 쓰이지 않는 네 번째 문구가 늘어난다. 카피가 하나 더 생기면 종결형·톤 검사 대상도 하나 더 생긴다                                                   |
| 제목을 비우고 높이만 예약  | ✗    | 랜딩에서 제목 자리가 비어 보이는 구간이 생긴다                                                                                                                    |
| **「지표만」 문구를 쓴다** | ✓    | `유동인구·매출·개업 수로 자치구를 비교해요.` 는 **dual 에서도 참**이다(dual 은 지표 열을 반드시 포함한다). 최종 상태가 dual·지표만 어디로 가든 거짓이 되지 않는다 |

- 스켈레톤 아이브로도 같은 이유로 `자치구 지표 순위` 를 쓴다.
- 유일하게 문구가 거짓이 되는 조합은 **「조회만」**(지표 3종 전부 결손)이다. 이 경로는 `top-ten` 이 통째로 죽었을 때만 발생하고, 그때는 제목이 한 번 교체된다. `Title` 의 `min-height` 예약(D4-2)이 그 교체로 인한 밀림을 막는다.
- 스켈레톤의 8칸 그리드·`aria-busy="true"`·링크 없음은 **현행 그대로** 둔다.

### D5-1. 조건표 — 조회 항목 수 × 지표 유무

`n` = `areaCode` 유효 항목 수. 「지표 있음」 = 3지표 중 **1종 이상**에 데이터(`hasMetricData`, D5-4-1 승계).

| n                | 지표     | 상태       | 좌측 열 | 우측 열 | 인사이트 슬롯 | 아이브로·제목 | `dual` | 스크롤 트랙 |
| ---------------- | -------- | ---------- | ------- | ------- | ------------- | ------------- | ------ | ----------- |
| 0 (빈 목록·실패) | 없음     | 제거       | ✗       | ✗       | ✗             | —             | —      | ✗           |
| 0                | 있음     | 지표만     | ✗       | ✓       | ✗             | 지표만 문구   | false  | ✗           |
| 1                | 없음     | 제거       | ✗       | ✗       | ✗             | —             | —      | ✗           |
| **1**            | **있음** | **지표만** | ✗       | ✓       | ✗             | 지표만 문구   | false  | ✗           |
| 2                | 없음     | 제거       | ✗       | ✗       | ✗             | —             | —      | ✗           |
| **2**            | **있음** | **지표만** | ✗       | ✓       | ✗             | 지표만 문구   | false  | ✗           |
| 3+               | 없음     | 조회만     | ✓       | ✗       | ✗             | 조회만 문구   | false  | ✗           |
| **3+**           | **있음** | **dual**   | ✓       | ✓       | ✓             | dual 문구     | true   | ✓(D5-3)     |

굵게 표시한 네 행이 이 문서가 바꾸는 동작이다. 나머지는 `story-and-rankings` D5-4 의 현행 유지다.

**pending 축은 그대로다**(D5-4-2 승계). 표본 부족은 **결론이 난 뒤에만** 판정할 수 있으므로 계산식을 바꾸지 않아도 자동으로 맞는다.

| 조회(`analysis-rankings`) | 지표(`top-ten`) | `viewWillExist` | `dual` | 결과                                            |
| ------------------------- | --------------- | --------------- | ------ | ----------------------------------------------- |
| pending                   | pending         | true            | true   | 스켈레톤(지표만 문구)                           |
| pending                   | 결론(존재)      | true            | true   | 스켈레톤 유지 — 아직 「없다」로 단정하지 않는다 |
| 결론 n=1                  | pending         | **false**       | false  | 지표가 올 때까지 스켈레톤, 이후 지표만          |
| 결론 n=1                  | 결론(존재)      | **false**       | false  | 지표만                                          |
| 결론 n=5                  | 결론(존재)      | true            | true   | dual                                            |

> `viewWillExist = rankingQuery.isPending || view !== null` 의 `view` 에 표본 게이트가 이미 들어 있으므로 식 자체는 손대지 않는다.

### D5-2. 왜 항목 수 하나만 쓰는가

「총 조회수가 작으면(예: 10회 미만) 표본 부족」이라는 두 번째 기준을 **두지 않는다.**

| 근거                       | 내용                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 서버가 총량을 주지 않는다  | Swagger 실물에 총 조회수·모수 필드가 없다(D4-1). FE 가 더할 수 있는 건 `size=8` 로 **잘린 상위 8개의 합**이라 「전체 조회수」가 아니다 |
| 기준이 파라미터에 종속된다 | 잘린 합을 임계값과 비교하면 `size` 를 8→10 으로 바꾸는 순간 같은 트래픽에서 판정이 달라진다. 표시 개수와 표현 강도가 몰래 묶인다       |
| 화면과 대응하지 않는다     | 인사이트 문장이 실제로 말하는 단위는 「N곳」이라는 **항목 수**다. 조회수 합계는 화면 어디에도 없어 사용자가 검증할 수 없다             |
| 설명 가능성                | 규칙이 둘이면 「왜 이 섹션이 접혔는가」에 대한 답이 두 갈래가 된다. 하나면 「조회된 자치구가 3곳이 안 됩니다」로 끝난다                |

**따라서 판정은 `n ≥ 3` 하나뿐이다.** 「n≥3 이지만 전 항목이 1~2회」인 저활동 구간은 관찰 대상으로 D8-3 에 남긴다.

### D5-3. `dual` 과 트랙의 관계

- `dual` 의 정의·계산식은 바꾸지 않는다. 바뀌는 것은 `view` 가 `null` 이 되는 조건뿐이다.
- **`dual` 이 아니면 스크롤 트랙(`ScrollTrack`, `calc(100dvh * 3)`)을 만들지 않는다** — `interaction-polish` R1 의 기존 불변식이다. 따라서 `n < 3` 에서는 트랙이 자동으로 꺼진다.
- **트랙 자체의 존폐는 이 문서가 정하지 않는다.** 감사 §3 P0-D(스크롤 예산)가 트랙 제거를 제안했고, 그 결정은 `scroll-budget.md`(작성 예정)가 소유한다. 트랙이 제거되면 이 문서의 「트랙」 열은 전부 ✗ 가 되고, 나머지 판정·문구는 **그대로 유효**하다.
- 솔로(1단) 분기에서 `min-height: 100dvh` 를 다시 켜지 않는다(`story-and-rankings` D4-3 「여백으로 채우지 않는다」).

### 판정 의사코드

```
n = rankings.filter(r => r.areaCode?.trim()).length

view        = (응답 성공 && n >= 3) ? 뷰모델 : null
hasMetric   = 지표 3종 중 하나라도 items.length > 0
dual        = (조회 pending || view) && (지표 pending || hasMetric)

if (!view && !hasMetric)            → pending 이면 스켈레톤, 아니면 섹션 제거
if (view && hasMetric)              → dual   : 2단 + 인사이트 슬롯 + dual 문구
if (!view && hasMetric)             → 지표만 : 1단 + 지표만 문구
if (view && !hasMetric)             → 조회만 : 1단 + 조회만 문구

insight = dual ? buildRankingInsight(view.items, activeMetric) : null
```
