### D0-1. 「한 화면」의 정의

`min-height: calc(100dvh - 헤더)` 다. 헤더가 sticky(65px)라 실제로 보이는 칸은 그만큼 작다 —
`100dvh` 를 그대로 쓰면 섹션 윗단이 헤더 밑에 붙었을 때 아래 65px 가 화면 밖으로 나가 「한 화면」이 안
된다. 히어로·판단 흐름 고정 칸이 이미 같은 식을 쓴다.

### D0-2. 채택하지 않은 안

- **툴팁 분기 추이 꺾은선**: 4점뿐이고 변동폭이 ±3% 라 min-max 로 늘리면 과장, 0 기준이면 평평하다.
- **분기 추이 + 하루 리듬 + 요일 전부**: 툴팁이 지도를 너무 가린다.
- **25개 구 상세를 미리 받기**: 첫 페인트 호출 예산(≤3)을 깬다. hover 한 구만 받는다.

## D4. 상세 동작 정의

### D4-1. 한 화면 섹션

- 공용 조각 `HOME_FULL_SCREEN_SECTION`(`layout-constants.ts`) — `min-height` + `display:flex; flex-direction:column; justify-content:center`.
- 판단 흐름은 고정 모드에서 트랙이 이미 한 화면보다 길어 변화가 없다. 클릭 모드(1099px 이하·낮은 화면·모션 감소)에서 효과가 난다.
- 데이터 출처는 예전 `padding-bottom: 0`(바로 뒤 섹션과 붙이기)을 버리고 다른 섹션과 같은 96/72/56 을 쓴다.

### D4-2. 판단 흐름 제목 고정

- 머리말(`Lead`)을 `PinSticky` 안, 탭 위로 옮긴다. 클릭 모드에서는 예전과 같은 자리·간격이다.
- 고정 모드에서는 제목 `max-width` 를 풀어 한 줄로 두고 간격을 16px 로 줄인다: 헤더 65 + 머리말 62 + 16 + 탭 52 + 16 + 패널 570 = **781**.
- `STORY_PIN_QUERY` 최소 높이 760 → **800**. 760~799px 화면은 클릭 모드로 떨어진다(제목이 가려지는 것보다 낫다).

### D4-3. 순서

`home-page.tsx`: `Hero → ProductStory → PopularDistricts → DataSources → FeatureBento`. 많이 본 지역이
실패로 빠지면 데이터 출처가 판단 흐름 바로 뒤에 온다 — 원래 자리라 어색하지 않다. 데이터 출처 카드의
단계 배지(01~04)는 그대로 둔다.

### D4-4. 요청

- `useDistrictDetail(code)` — 쿼리 키 `['home','districtDetail',code]`, `fetchStatusDetail`, `staleTime` 5분, 4xx 는 재시도 안 함.
- hover 가 120ms 머물러야 코드를 넘긴다(지도를 가로지를 때 지나간 구마다 요청하지 않는다).
- 모바일(≤640)은 hover 가 없어 요청도 없다.

### D4-5. 툴팁

크기 212 × 188(viewBox 단위, 800 × 620 지도 좌표). 색은 파랑 한 색(순차) — 값의 크기만 말하므로 범주색을 쓰지 않는다.

| 줄        | 내용                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 머리      | 구 이름(14/700) · 오른쪽 알약 `changeIndicatorName`(예: 다이나믹, 11/600, 회색 — 상태색 아님)                                                                                    |
| 지표      | `formatSinoUnit(최근 분기, '명')`(13/700) + 전분기 대비 `formatStatusChange`, 색은 `STATUS_CHANGE_TONE_COLOR`(글자용 AA 토큰). 아래 캡션 「2026년 1분기 유동인구 · 전분기 대비」 |
| 하루 리듬 | 라벨 「시간대별 · 시간당」 + 최다 구간 「14~17시 최다」. 막대: 여섯 구간 합을 **구간 시간 수로 나눠** 시간당으로 바꾸고, 폭은 구간 시간 수에 비례(24시간 한 줄), 높이는 0 기준   |
| 요일      | 라벨 「요일별」 + 「주말 ±N%」(주말 하루 평균 vs 평일 하루 평균). 막대 7개, **0 기준**, 가장 많은 요일만 진한 파랑                                                               |

- **왜 시간당인가**: 백엔드 구간은 00~~06(6시간)·06~~11(5)·11~~14(3)·14~~17(3)·17~~21(4)·21~~24(3)이라 합계를 그대로 그리면 긴 구간이 늘 이긴다. 응답의 `dominantTimeSlotType` 도 합계 기준이라 쓰지 않는다(예: 강남구는 합계로 「06~~11시」가 최다지만 시간당으로는 14~~17시다).
- **막대는 모두 0 기준**이다 — 잘라 그리면 차이가 과장된다. 차이가 작은 구(강동 요일 ±4%)는 평평하게 보이는 것이 사실이고, 그 차이는 「평일 대비 주말 ±N%」 글자가 말한다.
- 부드러운 곡선을 쓰지 않은 이유: 여섯 구간 평균뿐인 자료에 곡선을 그리면 없는 시간 해상도를 있는 것처럼 보인다.
- 로딩: 이름 + 회색 막대 자리표시(같은 크기). 실패: 이름 + 「지금은 데이터를 불러오지 못했어요」.
