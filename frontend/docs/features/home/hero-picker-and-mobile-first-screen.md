### D0-3. 업종을 싣지 않는 이유

`/analysis` 는 행정동을 고르는 순간 업종을 지운다(`selectAnalysisValue` 의 `administration` 분기 —
[measurement-and-deep-link](./measurement-and-deep-link.md) D3-1). 히어로에서 업종을 받아 `serviceCode` 로 실어도
다음 화면의 첫 클릭에 사라진다. 「고른 게 버려진다」는 제안서 P0-1 의 결함을 히어로에 새로 만드는 셈이라 받지
않는다. 분석 화면의 그 동작을 바꾸는 것은 이 문서 밖이다(D8-1).

### D0-4. 미리보기에 「월 매출」이 없는 이유

`GET /districts/{code}` 응답의 `sales` 는 `topSalesServices`(업종별 상위)·`topSalesAdministrations`(행정동별 상위)뿐이고
**자치구 전체 매출 합계가 없다**(`src/types/status.ts` `DistrictSalesDetail`). 합계를 상위 항목으로 더해 만들면 틀린
숫자가 된다. 미리보기는 응답에 실제로 있는 유동인구(분기 합계·전분기 대비·시간대 최다)만 말한다 — 툴팁과 같은 말이다.

## D1. 기능 개요

```
[공통] 히어로 카드
  h1 「서울 어디에 차려야 할까요?」
  본문
  [ 자치구 고르기 ▾ ] [ 🔍 내 상권 분석하기 ]        ← 고르면 「마포구 분석하기」, href 에 districtCode
  미리보기 줄 (aria-live)                            ← 고르기 전: 안내 / 불러오는 중 / 실데이터 / 실패 시 숨김
  [ 구별현황 보기 ]   어디가 좋을지 모르겠다면 상권 추천받기

[데스크톱 >640] 지도 위 떠 있는 카드(변경 없음) + 고른 구 채움 + 캡션 + 자동 시연 1회
[모바일 ≤640]  카드 → 지도(빈 띠 0) → 캡션.  지도 탭 = 피커에서 고르기
```

## D3. 아키텍처

### D3-1. 상태 소유 — `HeroSection`

| 안                                 | 판단                                                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **A. `HeroSection` 이 소유(채택)** | 피커(카드)와 지도가 모두 `HeroSection` 의 자식이다. 순서 3(마지막 CTA·고정 바)이 이 값을 필요로 할 때 `HomePage` 로 한 단계 끌어올린다 |
| B. `HomePage` 컨텍스트 지금 신설   | 쓰는 곳이 생기기 전에 짓는 구조다(YAGNI)                                                                                               |
| C. URL 쿼리                        | 랜딩에서 새로고침 복원 이득이 작고 히스토리를 더럽힌다                                                                                 |

판단 흐름 02 의 `DemoSelection`(4구 × 4업종 예시)과는 **잇지 않는다.** 선택지 집합이 다르다 — 25구 중 21곳이 데모에 없다.

```
HeroSection
  state: pickedCode: string | null
  ├─ HeroWindow  props: pickedCode, onPick(code, 'select'), pickerRef
  │    └─ usePickPreview(pickedCode) → useDistrictDetail(pickedCode, pickedCode != null) → toDistrictRhythm
  └─ SeoulDistrictsMap props:
       selectedCode = pickedCode
       onDistrictActivate = code => onPick(code, 'map')        ← v1.2 부터 모든 폭(hero-split-layout D4-7). 전엔 모바일만
       tooltipEnabled = !isMobileViewport
       onHoverChange  = isMobileViewport ? undefined : setHoveredCode
       autoDemo       = dragEnabled && !hasPicked              ← dragEnabled = 데스크톱·정밀 포인터·모션 허용(기존 값)
       demoAvoidRight = () => 카드 right                        ← 시연 툴팁이 카드 뒤로 숨지 않게(D5-3)
```

- `isMobileViewport`·`dragEnabled` 는 effect 로 정해져 **SSR·첫 렌더에서 `false`** 다. 하이드레이션 전 탭은 기존처럼
  링크 동작이 없다(핸들러 미부착). 자동 시연도 effect 뒤에만 켜진다.
- 미리보기와 툴팁은 **같은 쿼리 키**(`homeDistrictDetailQueryKey`)를 쓴다. 피커로 고른 구를 지도에서 다시 호버하면
  요청 없이 캐시로 뜬다.

### D3-2. 순수 함수 — `hero-picker.ts`

vitest 가 node 환경이라(jsdom 없음) 화면 규칙을 순수 함수로 빼서 잠근다.

| 함수                                  | 반환                                                                  |
| ------------------------------------- | --------------------------------------------------------------------- |
| `HERO_PICKER_OPTIONS`                 | `{ code, name }[]` — `districts` 25구, `localeCompare('ko')` 가나다순 |
| `resolveHeroPrimaryCta(code \| null)` | `{ href, label, carried }`                                            |
| `describePickPreview(rhythm)`         | `string[]` — 미리보기 조각(빈 칸 제외). 조각이 0개면 빈 배열          |

`resolveHeroPrimaryCta` 의 `href` 는 `createAnalysisExplorerHref({ ...createEmptyAnalysisSelection(), districtCode })` 로
만든다 — 판단 흐름 02 CTA(`resolveStoryCta`)와 **같은 빌더**다.

## D4. 상세 동작

### D4-1. 피커

- `<select>` + 시각적으로 숨긴 `<label>` 「창업할 자치구」. 첫 `<option value="">` 는 「자치구 고르기」.
- 첫 항목을 다시 고르면 선택 해제(`null`) — 주 버튼·미리보기·지도 채움이 고르기 전으로 돌아간다.
- 스타일은 `analysis-period-select.tsx` 를 따른다: `--radius-field` · 높이 48px(주 버튼과 같은 줄 높이) · **글자 16px**
  (iOS 포커스 확대 방지, `DESIGN.md` 시뮬레이션 편집기 규칙과 같다) · 포커스 링은 전역 `:focus-visible`.
- 카드는 `user-select: none` 이지만 `<select>` 조작에는 영향이 없다.
- 배치: >640 은 [피커 flex 1, 최소 140px][주 버튼] 한 줄. ≤640 은 두 줄(피커 전폭 → 주 버튼 전폭).

  분석하기」(가장 긴 경우)로 확인한다(D7 B3).
- `/analysis` 는 `districtCode` 만 받아도 자치구 단위 AI 리포트 카드를 보여 준다(`resolveAiReportLevel`).

### D5-3. 시연 대상과 툴팁 배치 — 카드 오른쪽 밖

카드가 지도 **가운데 위**에 떠 있어 가운데 구(중구·용산구 등)의 툴팁은 유리 카드 뒤로 숨는다. 툴팁은 카드 위·아래로는 들어갈
자리가 없다(viewBox 높이 620 에서 툴팁 204 + 카드 높이). 남는 곳은 **카드 오른쪽**뿐이라 동쪽 끝 **강동구**를 대상으로 둔다.
순위·추천을 암시하지도 않는다.

**작성 시 추정이 틀렸다.** 「1024 폭은 지도가 폭 기준이라 툴팁(viewBox x 588~)이 카드 밖」이라고 적었으나, 실제로는 지도가
**높이 기준**(배율 1.056, 왼쪽 86px)이라 툴팁 왼쪽 32px(구 이름 자리)이 카드 뒤로 들어갔다. 그래서 고정 좌표 대신
**카드 오른쪽 끝 + 16px 에 놓는다**(`tooltip-geometry.ts` `placeBesideRect`).

```
minX = (카드 right + 16 − ctm.e) / ctm.a          ctm = svg.getScreenCTM()  (x_px = e + x·a)
x    = max(기본 자리 588, minX)                    svg 는 overflow: visible — viewBox 오른쪽 여백까지 쓴다
x 로 놓은 툴팁 오른쪽 끝 > svg 요소 오른쪽 끝  →  시연하지 않는다(반쯤 가린 툴팁은 신호가 아니다)
```

| 1440×900 | 947        | 963 ~ 1232      | 표시             |

## D6. 주의사항

- **데스크톱 클릭과 모바일 탭이 다르게 동작한다**(이동 vs 고르기). 의도된 차이다 — 데스크톱은 호버가 미리보기라 클릭이
  곧 결정이고, 모바일은 호버가 없어 탭이 첫 정보 요청이다. 캡션 문장이 각 동작을 그대로 말한다(D4-5).
- 641px 이상 터치 기기(태블릿)는 데스크톱 동작이다. 탭 시 `mouseenter` 로 툴팁이 뜨고 `click` 으로 이동한다 — 지금과 같다.
- 피커와 지도 채움이 같은 상태를 보므로, 데스크톱에서 피커로 고른 구 위에 마우스를 올리면 호버 색과 채움 색이 같아
  변화가 없다. 툴팁이 뜨므로 문제 삼지 않는다.
- `scrollIntoView` 는 sticky 헤더(65px)를 모른다. `block: 'nearest'` 로 위쪽에 붙을 때 헤더에 가릴 수 있어 피커 덩어리에
  `scroll-margin-top: calc(65px + 16px)` 을 준다.
- 폴리곤 터치 타깃은 44px 규칙의 예외다(초안 D6 근거 그대로 — 지도 형상이 크기를 정한다). 피커·버튼은 48px.
