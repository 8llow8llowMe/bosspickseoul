## D1. 기능 개요

히어로 아래를 세 섹션으로 줄인다. 네 도구 보드와 앵커 문장을 없애고, 보드가 하던 일(히어로 바로 뒤에서 네 도구를 한 줄로 보여 주기)은 판단 흐름의 **탭 4장**이 이어받는다. 판단 흐름과 랭킹의 스크롤 트랙을 없애고 클릭 전환으로 바꾼다.

```
히어로 → 판단 흐름 [탭 01·02·03·04 → 패널(설명 · 손에 남는 것 · CTA | 데모)] → 지금 많이 본 지역 [토글] → 더 많은 기능 + CTA
```

## D4. 상세 동작 정의

### D4-1. 탭 (`StepTabs`)

- 구조: `<div role="tablist" aria-label="판단 흐름 네 단계">` 안에 `<button role="tab">` 4개.
  - `id="story-tab-{step}"` · `aria-selected` · `aria-controls="story-panel"` · 활성만 `tabIndex=0`, 나머지 `-1`
  - 탭 내용: 아이콘 배지(장식, `aria-hidden`) · 번호(`01`) · 단계명 · 수치(`stepFigure`)
- 배치: `grid-template-columns: repeat(4, minmax(0, 1fr))`, **≤768px 에서 `repeat(2, …)`**(2×2). 한 줄 가로 스크롤을 쓰지 않는다 — 숨는 탭이 생긴다.
- 활성 표시: 테두리 `--color-primary-600` + 배경 `--color-primary-100`. 비활성 hover 는 테두리만 `--color-border-300`. 포커스 링은 `--shadow-focus-primary`.
- 터치 영역: 탭 높이 ≥ 52px(DESIGN.md §8 리스트 행).
- 키보드: `onKeyDown` 에서 `nextTabIndex` 가 숫자를 주면 `preventDefault` → 선택 변경 → 그 탭에 `focus()`. **자동 활성화**를 고른 이유: 패널 전환 비용이 없다(데모는 캐시된 쿼리를 다시 그릴 뿐이다).
- 자동 순환(autoplay)은 두지 않는다 — WCAG 2.2.2, 그리고 사용자가 읽는 중에 패널이 바뀐다.

### D4-2. 패널 (`StepPanel`)

- `<div role="tabpanel" id="story-panel" aria-labelledby="story-tab-{활성 step}" tabIndex={0}>`
- 데스크톱(>768px): 2열 `minmax(0, 5fr) minmax(0, 7fr)` · gap 40px
  - 왼쪽: 단계명(h3) · `body` · 「손에 남는 것」 라벨 + `outcome` · `note`(있으면) · CTA(있으면, 규격은 기존 `Cta`)
  - 오른쪽: `DemoPanel`(기존 4종). 세로 가운데는 `margin-block: auto`(PR #424 의 넘침 안전 규칙 승계)
  - **높이 예약**: 패널 `min-height: 560px` — 데모 최댓값 519(D0-1) + 패널 패딩 40. 탭을 바꿔도 아래 랭킹 섹션이 밀리지 않는다
- 모바일(≤768px): 1열 — 설명 묶음 위, 데모 아래. 높이 예약 없음(아래 섹션이 밀려도 보고 있는 패널의 위치는 그대로다)
- 패널 CTA: 01 `구별 현황 보기` · 03 `상권 추천받기` · 04 `창업 시뮬레이션 해보기`(기존 라벨). 02 는 없다(미니데모 CTA)

### D4-3. 마운트와 요청

- 활성 탭의 `DemoPanel` 하나만 렌더한다. 비활성 패널을 `hidden` 으로 DOM 에 두지 않는다 — 두면 04 차트·03 추천이 첫 페인트에 마운트된다.
- 03 탭 수치(「상권 9곳 중 추천 5곳」)를 위해 `useRecommendPreview` 는 **섹션 수준**에서 부른다. `enabled` 는 섹션 루트가 뷰포트에 들어온 뒤 `true` 가 되고 다시 끄지 않는다(기존 `storyInView` 게이트를 섹션 루트로 옮긴다). 스택 모드 예외(`stacked || storyInView`)는 스택이 없어지므로 사라진다.
- 결과: 첫 페인트 BFF 요청 2개(e2e `bffRequests`)가 유지된다. 이것은 D7 에서 실측으로 확인한다.

### D4-4. 지금 많이 본 지역

1. **트랙 제거**: `ScrollTrack`·`ScrollSticky`·`useScrollProgress`·`scrollToPinnedStep` 을 걷어낸다. 지표 정본은 로컬 state(`pickedMetric`) 하나다. `useScrollTrack`·`scrollIndex` 분기를 지운다.
2. `dual` 판정은 이제 **레이아웃(두 열이냐 한 열이냐)** 만 정한다. pending 을 「있을 것」으로 보는 규칙은 두 열 → 한 열 깜빡임을 막는 데 계속 쓴다.
3. **`ranking-minimum-sample.md` 를 그대로 구현한다**: 유효 항목 n 판정(n≥3), 상태 4종(dual / 지표만 / 조회만 / 제거), 상태별 아이브로·제목·열 제목(그 문서 D4-2 표), 인사이트 n≥3, 해요체, `Title` 2줄 `min-height`, 스켈레톤 문구. 그 문서가 「트랙 존폐는 scroll-budget 소관」이라 비켜 둔 부분은 이 문서가 **「트랙 없음」**으로 닫는다.

### D5-1. 키보드 판정 (`nextTabIndex`)

| key          | 결과                                                                        |

## D6. 주의사항

- **CTA 노출의 대가.** `/recommend`·`/simulation` CTA 는 해당 탭을 눌러야 보인다. 헤더 메뉴(네 도구)와 히어로 보조 링크(「어디가 좋을지 모르겠다면 상권 추천받기」)는 항상 보이므로 도달 경로는 남는다. 공통 명세 TC-004 · TC-005 를 이에 맞춰 고친다(D7-3).
- **패널 높이 예약은 실측값에 묶여 있다.** 데모가 커지면(예: 02 에 행이 추가) 560px 를 다시 잰다. 테스트는 값 자체가 아니라 「예약이 있다」를 잠근다.
- **탭 id 는 페이지에 하나뿐이라는 전제**다(홈에 판단 흐름은 한 번). 재사용이 생기면 `useId` 로 바꾼다.
- **e2e 기준선은 나아진 만큼만 내린다**(`home-metrics.spec.ts` 규칙). 나빠진 지표가 있으면 기준선을 올리지 말고 원인을 고친다.
- `interaction-polish.md` D8-10(자동화 브라우저가 숨으면 rAF·scroll 이 멈춰 검증 불가)의 제약이 사라진다 — 이제 클릭만으로 모든 상태에 닿는다.
