# home — 4단계 스토리 · 듀얼 랭킹 · AI 리포트 승격 세부 명세서

> **작성일**: 2026-09-03
> **공통 명세**: [home 공통 명세](./home.md)
> **선행 명세**: [below-hero-scrollytelling](./below-hero-scrollytelling.md) — 이 문서는 그 명세의 ②·③부를 **개정**한다(대체하지 않는다. 3부 구조와 앵커·스티키 트랙은 그대로 유지).
> **대상**: 웹 (Next.js App Router)
> **작성자**: Claude Code
> **상태**: 구현 완료

히어로 하위 3부(앵커 → 스토리 → 벤토)와 그 사이의 「지금 많이 본 지역」 섹션이
**보여주기로 한 것을 실제로 보여주지 못하고 있다.** 네 가지를 고친다.

1. 스토리 CTA 가 선언(48px)의 2.5배(120px)로 렌더된다 — 그리드 행 stretch 버그.
2. 스토리 01단계가 히어로와 **같은 지도 컴포넌트를 재렌더**한다.
3. 랭킹 섹션이 422px 로 꺼지고, 순위인데 1위와 8위가 시각적으로 동등하다.
4. AI 리포트가 **분석의 산출물인데 「분석 이후의 기능」 칸**에 놓여 정보구조가 한 칸 밀렸다.

## D4. 상세 동작 정의

### D4-1. CTA 높이 복구

`product-story.tsx` 의 `PanelWithCta` 에 행 정의를 준다.

```
PanelWithCta {
  display: grid;
  grid-template-rows: minmax(0, 1fr) auto;   /* ← 추가 */
  gap: 16px;
}
```

**왜 이 값인가.** 부모 `StoryRow` 가 `height: 600px` + `align-items: stretch` 라
`PanelWithCta` 는 600px 로 늘어난다. 행이 `auto auto` 면 남는 216px 가 두 행에 분배되고
CTA 가 행 높이(120px)만큼 늘어난다. `minmax(0,1fr) auto` 는 남는 공간을 **패널이 전부**
가져가게 하고 CTA 는 자기 높이만 쓴다.

`align-self: start` 로도 높이는 잡히지만 그때는 패널이 늘어나지 않아 카드가 위로 붙는다.
`minmax(0, ...)` 의 0 은 필수다 — `1fr` 만 쓰면 최소 콘텐츠 크기가 하한이 되어 좁은 폭에서
패널이 넘친다.

> 이미 있는 `> a { justify-self: start }` 는 **지우지 않는다.** 그것은 가로축 담당이고,
> 없애면 주석에 기록된 「343px → 121px 찌그러짐」 사고가 되돌아온다.

### D4-3. 랭킹 섹션 — 듀얼 랭킹

```
┌─ Section (min-height: 100dvh) ──────────────────────────┐
│ eyebrow: 지금 많이 본 지역                                │
│ h2:      다른 사람들이 보는 곳과, 숫자가 좋은 곳은 다릅니다. │
│ ┌── 좌: 조회수 (최근 N시간) ──┬── 우: 실제 지표 TOP 5 ──┐ │
│ │ 1 강남구  ███████ 1,284회   │ [유동인구][매출][개업]   │ │
│ │ 2 마포구  ██████  1,102회   │ 1 강남구 ███ 1,842만 +3.2%│ │
│ │ … 8행                       │ … 5행                    │ │
│ └─────────────────────────────┴──────────────────────────┘ │
│ 인사이트 문장 (D5-1) — 없으면 렌더 안 함                   │
└──────────────────────────────────────────────────────────┘
```

- 좌측 8행 × 우측 5행 + 헤더 + 인사이트로 100dvh 가 **내용으로** 찬다. 여백으로 채우지 않는다.
- 막대 폭 = `value / max(values) × 100%`. 1위는 항상 100%다.
- `≤900px`: 2단 → 1단 세로 스택. `min-height: 100dvh` 를 해제한다(모바일에서 두 목록을
  한 화면에 넣으면 글자가 읽히지 않는다).
- 좌측 항목의 링크·`aria-label`·「N회」 표기는 **현행 그대로 유지**한다. 이미 접근성이 맞춰져 있다.

### D4-6. 03단계 — 실 추천 미리보기

고정 시드로 2단계 연쇄 호출한다. **dev 백엔드에서 실제 응답을 확인한 값이다.**

```ts
const RECOMMEND_SEED = {
  districtCode: '11680', // 강남구
  administrationCode: '11680640', // 역삼1동
  serviceCode: 'CS100010', // 커피-음료
  periodCode: RECOMMENDATION_PERIOD_CODE, // '20233'
  topN: RECOMMENDATION_TOP_N, // 5
} as const
```

응답이 주는 것: `preset`(공격형), `priorityMetric`(기회도), `summary`, 그리고 `items[]` 의
`rank` · `commercialName` · `compositeScore` · `grade` · `opportunityLabel` · `riskLabel` ·
`selectionReason`.

화면은 점수 막대 5행 + **1위의 `selectionReason` 한 문장**을 렌더한다. 지금의 정적 막대와
가장 크게 달라지는 지점이 이 문장이다 — 「왜 이 상권인가」를 서비스가 직접 말한다.

시드 지역명(강남구 역삼1동 · 커피-음료)을 패널에 **명시**한다. 안 적으면 사용자가 자기
지역 결과로 오해한다.

### D4-7. 04단계 — 손익 워터폴 (예시 유지)

실 API 를 호출하지 않는다. `POST /simulations/reports` 는 쓰기 동사이고 `store-sizes` GET
이 선행돼야 해서, 랜딩 방문자마다 계산 요청이 나가게 된다. 데모 하나가 치를 값이 아니다.

표현만 바꾼다: 막대 3개(월매출/고정비/순이익) → 워터폴 5칸.

```
월매출 4,200 → 임차료 −1,050 → 인건비 −1,200 → 기타 −350 → 순이익 1,600  (만원)
```

`대표 예시 데이터` 라벨을 **유지**한다. 금액 단위는 시뮬레이션 Feature 규약대로 **만원**이다.

## D5. 비즈니스 로직

### D5-1. 인사이트 문장 생성 규칙

입력: `views`(조회수 순위, 최대 8) · `metric`(선택 지표 Top5). 둘 다 `districtCode` 기준.
**첫 번째로 걸리는 규칙만** 쓴다.

| 순위 | 조건                                                 | 문장                                                                     |
| ---- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| A    | 지표 Top3 중 조회수 목록(8곳)에 **없는** 첫 항목 `x` | `{지표라벨} {x.rank}위 {x.name}는 지금 많이 본 {N}곳에 들지 않았습니다.` |
| B    | 조회수 Top3 중 지표 Top5 에 **없는** 첫 항목 `y`     | `조회수 {y.rank}위 {y.name}는 {지표라벨} Top 5 밖입니다.`                |
| —    | 둘 다 해당 없음                                      | **문장을 렌더하지 않는다** (`null`)                                      |

A 가 B 보다 앞선다. 「아무도 안 보는데 지표가 상위인 곳」이 창업 후보를 찾는 사람에게
더 값진 정보이기 때문이다.

**문장은 집합 소속만 진술한다.** 「좋다/나쁘다/유망하다」로 해석하지 않는다 — 지표 상위가
곧 좋은 상권이라는 근거가 우리에게 없다. `highlightCode` 로 양쪽 목록의 해당 행을 함께
강조해 문장과 목록이 같은 것을 가리키게 한다.

### D5-2. 변화율 배지를 어디에 붙이는가

| 목록                          | 변화율   | 이유                                                                 |
| ----------------------------- | -------- | -------------------------------------------------------------------- |
| 조회수 (`/analysis-rankings`) | **없음** | 집계에 전기가 없다. 0 으로 채우면 「변동 없음」이라는 틀린 말이 된다 |
| 지표 (`/districts/top-ten`)   | **있음** | 응답이 `changeRate` 를 준다. `formatStatusChange` 로 그대로 쓴다     |

기존 `popular-districts.tsx` 주석이 남긴 판단을 그대로 승계한다. 이번에 변화율이 생긴 것은
**다른 API 를 붙였기 때문**이지, 기존 판단이 틀렸기 때문이 아니다.

### D5-3. 폐업 지표를 홈에서 빼는 이유

`top-ten` 은 4지표를 주지만 홈은 3개만 노출한다.

폐업 Top10 은 **상위가 나쁜 것**이다. 다른 세 지표와 방향이 반대라, 같은 토글에 섞으면
① 랜딩에서 「폐업 1위 자치구」를 순위표처럼 자랑하게 되고 ② D5-1 의 인사이트 문장이
정반대 의미가 된다(「아무도 안 보는데 폐업 1위」는 기회가 아니다).

`/status` 는 4지표를 전부 유지한다. 그 화면은 현황 조회가 목적이라 방향이 섞여도 된다.

### D5-4. 실패·빈 상태 분기

| 조회수 | 지표    | 랭킹 섹션 렌더                            |
| ------ | ------- | ----------------------------------------- |
| 성공   | 성공    | 2단 + 인사이트(규칙에 걸릴 때)            |
| 성공   | 실패    | 좌측 단독 1단. 인사이트 없음. 100dvh 해제 |
| 실패   | 성공    | 우측 단독 1단. 인사이트 없음. 100dvh 해제 |
| 실패   | 실패    | **섹션 전체 제거** (`return null`)        |
| 성공   | 빈 배열 | 실패와 동일 취급                          |

**인사이트 문장은 양쪽이 다 있을 때만 만들 수 있다** — 두 목록의 차이를 말하는 문장이므로.

| 03단계 시드/추천 | 렌더                                                   |
| ---------------- | ------------------------------------------------------ |
| 성공             | 실 응답 + `selectionReason`                            |
| 실패 / 빈 items  | 기존 하드코딩 5행 + `대표 예시 데이터` 라벨로 **폴백** |

03 은 섹션을 빼지 않는다. 스토리는 4단계가 다 있어야 「네 단계로 좁힙니다」가 성립한다.
로딩 중에는 스켈레톤을 쓰지 않고 **예시 데이터를 먼저 그린 뒤 실 응답이 오면 교체**한다 —
스토리 패널은 높이가 고정(600px)이라 교체가 레이아웃을 밀지 않는다.

01단계(지표 보드)는 `top-ten` 실패 시 **단계 전체를 예시 랭킹으로 폴백**한다.
스토리에서 한 단계만 사라지면 번호(01~04)에 구멍이 난다.

### D5-5. 01단계와 랭킹이 같은 쿼리를 쓰는 법

둘 다 `useQuery({ queryKey: ['home','districtTopTen'], ... })` 를 호출한다.
React Query 가 같은 키를 dedupe 하므로 **네트워크 요청은 1회**다. 별도의 전역 상태나
props drilling 을 만들지 않는다.

`src/hooks/use-district-top-ten.ts` 로 훅을 하나 만들어 두 곳이 같은 키·`staleTime`·
`retry` 를 쓰게 고정한다. 키를 문자열로 두 번 적으면 언젠가 한쪽만 바뀐다.

## D6. 주의사항

1. **`justify-self: start` 를 지우지 말 것.** D4-1 의 수정은 세로축만 건드린다.
   가로축 규칙을 함께 지우면 기록된 찌그러짐 사고가 재발한다.
2. **`SeoulDistrictsMap` 자체는 지우지 않는다.** 히어로가 쓰고 있다. 스토리에서 참조만 뺀다.
3. **`formatStatusValue` 를 홈용으로 복사하지 말 것.** import 한다. 복사하면 같은 숫자가
   `/status` 와 홈에서 다르게 보이는 날이 온다.
4. **`RANKING_SIZE = 8` 을 유지한다.** 좌측 8행이 우측 5행 + 토글과 높이가 맞는다.
5. **로딩 스켈레톤은 랭킹 섹션에만 둔다.** 기존 코드가 이미 그렇게 하고 있고, 이유도 같다
   (뒤늦게 나타나며 아래 섹션을 밀지 않게).
6. **03 시드 코드는 상수 파일 한 곳에만** 둔다. `11680640` 이 언젠가 개편되면 폴백이
   동작하겠지만, 그때 고칠 자리가 한 곳이어야 한다.
7. `prefers-reduced-motion: reduce` 에서 막대 `width`·워터폴 `height` 트랜지션을 제거하고
   최종 상태를 즉시 그린다.
8. 새 색·radius·shadow 토큰을 만들지 않는다. 변화율의 상승/하락은 `DESIGN.md` 의
   `green500`/`red500` 시맨틱 토큰을 쓴다.
