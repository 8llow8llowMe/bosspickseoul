## D0. 배경

히어로 카드(유리 창)가 지도 **가운데 위**에 떠 있어, 자치구 중심점이 카드 밑에 깔린다.

| 뷰포트   | 카드에 가려지는 구(중심점 기준)                                               |
| -------- | ----------------------------------------------------------------------------- |
| 1440×900 | **12/25** — 종로·중구·용산·성동·동대문·성북·은평·서대문·마포·영등포·동작·강남 |
| 1024×768 | **14/25** — 위 + 광진·강북                                                    |

피커(PR #505)로 「고르기」는 되지만, 지도 **호버 툴팁**(홈 최고의 인터랙션)은 도심·강남에서 쓸 수 없다. 카드 드래그·접기·독
축소가 있지만 발견하는 사람이 드물다. 그래서 겹침 자체를 없앤다.

## D1. 기능 개요

```
≥1440   : 1400 컬럼(--w-wide) 가운데 정렬 — 지도가 더 커지지 않는다(D4-5)
1200~1439: [ 카드 460px ] [ 지도 (나머지) ]                       ← 겹침 0. 둘 다 세로 가운데
900~1199: [ 카드 460fr ] [ 지도 652fr ] — 1200 의 비율 그대로 함께 준다(D4-6)
641~899 : [ 제목·소개 ] → [ 지도 (폭 가득) ] → [ 피커 바 ] → [ 보조 링크 ]   ← 지도 중심(D4-3)
≤640    : 변경 없음(PR #505) — [ 카드 ] → [ 지도 ] → [ 캡션 ]
```

- 지도 클릭·탭·Enter 는 **모든 폭에서** 피커 선택이다(D4-7). 호버 툴팁 끄기만 **≤640px** 동작 기준으로 남는다.

## D3. 아키텍처

- 분할 기준은 `layout-constants.ts` 의 `HERO_STACKED_MEDIA = '(max-width: 899px)'` 한 곳에 둔다. 히어로(`hero-section.tsx`)와 지도
  (`seoul-districts-map.tsx` 의 지도 높이·캡션 위치)가 같은 값을 쓴다. **동작** 판정용 640px(`isMobileViewport`)과는 다른 값이다.
- `HeroStage` 는 ≥900px 에서 `display: grid; grid-template-columns: minmax(360px, 460px) minmax(0, 1fr)`. 자식은 `CardLayer` 와
  `MapScreen`(`display: contents` → `MapLayer` 가 둘째 칸). 카드 칸과 지도 칸 사이 `column-gap: 48px`.
- `CardLayer` 는 더 이상 `position: absolute` 오버레이가 아니다(모든 폭에서 흐름 배치). 오버레이를 위해 있던 `pointer-events: none`·
  `z-index` 도 필요 없다.
- `HeroWindow` 에 `chrome: boolean` prop. `false` 면 `TitleBar` 를 렌더하지 않는다 → 드래그 핸들·신호등·접기·창 확대 점이 함께
  사라지고, 닫기가 없으니 독 버튼도 나오지 않는다. `HeroSection` 은 `HERO_WINDOW_CHROME`(= `false`)을 넘기고, 드래그도
  `HERO_WINDOW_CHROME && …` 일 때만 켠다. 독·접기 상태 코드와 `use-window-drag.ts`·`window-display.ts` 는 지우지 않는다(U3).
- `placeBesideRect`·`demoAvoidRight` prop 은 남기되 넘기지 않는다 — 오버레이로 되돌릴 때 다시 넘긴다.
- **v1.2** 폭 기준은 `layout-constants.ts` 에 다섯이다: `HERO_SPLIT_MEDIA`(≥900) · `HERO_FLUID_MEDIA`(900~~1199) · `HERO_FLUID_NARROW_MEDIA`(900~~1023) ·
  `HERO_TABLET_MEDIA`(641~~899) · `HERO_STACKED_MEDIA`(≤899, 히어로 높이 해제만). 히어로 `Inner` 는 셸 대신 `HOME_COLUMN` 이다.
- **v1.2** 지도 중심 배치는 컴포넌트를 쪼개지 않는다. `CardLayer`·`WindowCard`·`WindowBody`·`WindowBodyInner` 가
  `display: contents` 로 풀리고, `Title`·`Body`·`PickerBlock`·`Actions` 가 `grid-area`(title·body·picker·actions)를 달아
  `HeroStage` 의 `grid-template-areas` 에 놓인다. 칸 이름은 hero-section.tsx 가 정하고 hero-window.tsx 가 단다.

## D4. 상세

### D4-1. ≥900px 배치

| 요소    | 규칙                                                                                                                                                                                          |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 카드 칸 | `minmax(360px, 460px)` · 세로 가운데(`align-self: center`). 카드 폭은 칸 폭(`width: 100%`)                                                                                                    |
| 지도 칸 | `minmax(0, 1fr)` · 세로 가운데. svg 는 **v1.2** 부터 `aspect-ratio: 800 / 620` · `max-height: 100dvh - 헤더 - 48 - 28px` — 상자가 폴리곤에 딱 맞는다. 상한에 걸리면 `meet` 이 가운데에 그린다 |
| 캡션    | **v1.2** 지도 바로 아래 흐름 · 가운데 정렬. 예전엔 칸 좌하단 absolute 라 1920×1080 에서 지도와 127px 떨어졌다                                                                                 |

### D4-2. 창 장식 숨김

- 렌더하지 않는 것: 제목줄(「서울 상권 데이터 분석」), 신호등 3점(닫기·접기·창 확대 링크), 제목줄 드래그.
- 결과적으로 사라지는 상태 전이: 접기(`minimized`), 닫기 → 독(`closed`), 독 → 열기 애니메이션. 상태값은 `'open'` 에서 움직이지 않는다.
- 카드 본문 위 패딩: 장식이 있을 때 16px(제목줄 아래) → 없을 때 **40px**(좌우와 같게), ≤640px 는 **24px**.
- 계측 `home_hero_cta_click { cta: 'window_max' }` 는 더 이상 나가지 않는다(창 확대 점이 없다). 이벤트 정의는 남긴다.

### D4-3. 641~899px — 지도 중심 (v1.2 에서 다시 씀)

~~≤640px 의 배치 규칙을 899px 까지 넓힌다(카드 → 지도 → 캡션).~~ 카드가 첫 화면 위를 차지해 설명서처럼 보였다(U7).

| 칸       | 규칙                                                                                                                      |
| -------- | ------------------------------------------------------------------------------------------------------------------------- |
| 스테이지 | 1열 그리드 `'title' 'body' 'map' 'picker' 'actions'` · 행 간격 12px · 위 32px. 유리 카드 배경 없음(`display: contents`)   |
| 제목     | 30/40 그대로(모바일 규칙 아님)                                                                                            |
| 지도     | 폭 가득 · `max-height: max(320px, 100dvh - 헤더 - 280px)` — 제목·피커 바까지 한 화면. 남는 폭은 `meet` 이 가운데에 그린다 |
| 캡션     | 눈에서만 치운다(visually hidden). 피커 아래 안내 줄이 같은 말을 한다. svg 의 `aria-describedby` 설명으로는 남는다         |
| 피커 바  | [선택칸 (늘어남)][주 버튼] 한 줄 + 미리보기 한 줄                                                                         |

- DOM 순서는 [제목][소개][피커][보조][지도] 그대로라 Tab 은 피커가 지도보다 먼저다. 보이는 순서와 어긋나지만 의미가 바뀌지 않는다.
- 높이 해제(`Hero`·`Inner` `height: auto`)는 `HERO_STACKED_MEDIA`(≤899) 그대로다.
- **창 장식을 다시 켜면(`HERO_WINDOW_CHROME = true`) 이 구간 규칙도 되돌린다.** `display: contents` 로 풀린 카드에서는 제목줄이
  그리드 맨 아래 암묵 행으로 밀리고, 접기(`0fr`)·닫기 transform 이 먹지 않는다(접힌 본문이 보이는데 `inert` 가 걸린다).

### D4-4. 툴팁 배율 보정 (구현 중 추가)

툴팁은 지도 viewBox 안에 그려져 **지도와 함께 줄어든다.** 오버레이 시절 지도는 높이 기준으로 크게 그려져(1440 배율 1.27)
문제가 없었으나, 오른쪽 칸으로 옮기며 좁은 폭에서 배율이 1024 **0.59** · 900 **0.43** 으로 내려가 툴팁 글자가 7px 대가 됐다.

- `tooltipScale(screenScale) = max(1, 1 / screenScale)` 배로 툴팁 그룹을 키운다 → 화면에서 설계 크기(212px) 아래로 줄지 않는다.
  지도가 크게 그려질 때는 키우지 않는다.
- `screenScale` 은 svg 의 `getScreenCTM().a` 를 `ResizeObserver` 로 갱신한다. 자리 잡기(`clampTooltipPosition`)·자동 시연 배치도
  키운 크기로 계산한다.

### D4-5. ≥1440 — 1400 컬럼 (v1.2)

히어로 `Inner` 가 `HOME_COLUMN`(= `min(--w-wide 1400, --w-shell)`)을 쓴다. 1440 에서는 셸과 같고(좌우 20), 그 위로는 양옆이 빈다.
아래 섹션(스토리·순위·출처·벤토)과 왼쪽 기준선이 같아진다.

### D4-6. 900~~1199 — 비율로 함께 축소 (v1.2)

| 요소         | 1200 이상                            | 900~~1199                                                                                        |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 칸           | `minmax(360px, 460px) 1fr` · 간격 48 | `460fr 652fr`(1200 에서 460 : 652) · 간격 40(1024~~1199) · 32(900~~1023)                         |
| 카드 안 여백 | 40                                   | 32(1024~~1199) · 24(900~~1023) — spacing 스케일 안에서 단계로                                    |
| 카드 안 간격 | 20                                   | 16                                                                                               |
| h1           | 30/40                                | Display Large 26/36 (DESIGN.md 타이포 스케일)                                                    |
| 피커 줄      | 한 줄                                | `flex-wrap` — 안 들어가면 주 버튼이 아래 줄을 다 채운다(칸 grow 999 · 버튼 grow 1). 라벨은 한 줄 |

화면 전체를 `transform: scale` 로 줄이는 안은 글자·터치 타깃까지 같이 작아져 쓰지 않았다. 여백·글자를 `vw` `clamp()` 로 연속
축소하는 안은 DESIGN.md §0 「viewport 기반 폰트 스케일링 금지」에 걸려(리뷰 지적) 단계로 바꿨다.

폭 기준은 범위 문법이다(`(640px < width < 900px)` 등) — `max-width: 640px` / `min-width: 641px` 로 맞대면 확대·OS 배율의
640.8px 같은 소수 폭이 어느 규칙에도 걸리지 않아 기본 2칸 그리드로 떨어진다.

### D4-7. 지도 클릭 = 고르기 (v1.2)

- `HeroSection` 이 `onDistrictActivate` 를 **모든 폭에서** 넘긴다 → 폴리곤은 `role="button"` · `aria-pressed`. 클릭·Enter·Space 가
  피커 값을 바꾸고 지도 칸을 채운다. 페이지는 카드의 「○○구 분석하기」로만 넘어간다.
- 계측: `home_map_click` 은 더 이상 나가지 않고 `home_hero_picker_select { source: 'map' }` 이 그 자리다. 이벤트 정의는 남긴다
  (`SeoulDistrictsMap` 의 `router.push` 폴백도 남긴다 — prop 이 없을 때의 계약).
- 문구: 데스크톱 캡션 「…누르면 그 구의 분석으로 넘어가요」 → 「…누르면 그 구가 바로 골라져요」, 툴팁 오류 상태 「눌러서 분석 화면으로
  이동해요」 → 「눌러서 이 구를 골라요」.

### D4-8. 소개 문구 (v1.2)

| 자리                     | 전                                                                                                             | 후                                                                              |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 소개(h1 아래)            | 자치구를 고르면 유동인구부터 바로 보여 주고, 분석 화면에서 매출·경쟁 강도와 AI 리포트까지 이어서 볼 수 있어요. | 가게 자리는 감보다 숫자로 고르세요. 유동인구·매출·경쟁 점포를 바로 보여 드려요. |
| 미리보기 안내(고르기 전) | 고르면 그 구의 최근 분기 유동인구부터 바로 보여 줘요.                                                          | 지도에서 구를 누르거나 목록에서 고르세요.                                       |

- 전 문구는 「화면이 어떻게 움직이는지」(유동인구부터 → 분석 화면에서 → 이어서)를 말했고, 바로 아래 안내 줄과 같은 말을 두 번 했다.
  소개는 **얻는 것**, 안내는 **하는 방법**으로 나눈다. 쉼표 없이 두 문장(사용자 요청).

### D4-9. 지도 호버 때 카드 틴트를 없앤다 (v1.2, 사용자 요청)

폴리곤에 마우스를 올리면 카드 배경에 primary 7% 틴트가 얹혔다. 좌우 분할로 카드가 지도 옆에 늘 보이게 되자 폴리곤을 훑을
때마다 카드가 깜빡여 어지러웠다. `HeroWindow` 의 `tinted` prop 과 `HeroSection` 의 `hoveredCode` 상태(틴트에만 쓰였다)를
지운다. 호버의 피드백은 폴리곤 채움과 툴팁만 남는다. `SeoulDistrictsMap` 의 `onHoverChange` prop 은 계약으로 남긴다.
