# home — 히어로 하위 섹션 재설계(스크롤리텔링) 세부 명세서

> **작성일**: 2026-08-11
> **공통 명세**: [home 공통 명세](./home.md)
> **대상**: 웹 (Next.js App Router)
> **작성자**: Claude Code
> **상태**: 초안

히어로 아래의 나열식 설명 섹션(판단 흐름 리스트·기능 카드 그리드)이 "말로만 설명(telling)"해 UI/UX 퀄리티가 떨어지는 문제를 해결한다. 히어로 아래를 **① 임팩트 앵커 → ② 제품 데모 스토리텔링(스티키) → ③ 기능 요약(벤토)+CTA** 3부로 재구성해, 제품의 실제 능력을 **보여주며(showing)** 신뢰를 만든다. 연출 톤은 `DESIGN.md`의 "절제된 신뢰"를 따르며 wow는 앵커 1곳에 집중한다(하이브리드).

## D1. 기능 개요

```
스크롤 진행 → ① 앵커 문장 텍스트 채우기(0~x%) → ② 스티키 스텝(현황→분석→추천→시뮬) 데모 패널 전환 → ③ 벤토 기능 카드 + CTA
```

히어로 직후, 기존 3개 섹션(미리체험·판단흐름·기능)을 3부 구성으로 **대체**한다. ②는 미리체험 섹션과 판단흐름 리스트를 하나의 스티키 스크롤리텔링으로 통합해 중복을 제거한다.

### D1-1. UI 진입점 / 기능 연결

> **라우트/위치**: `app/(shell)/page.tsx` → `src/components/home/home-page.tsx`. 히어로(`HeroSection`) 직후 본 3부 렌더.
> **신규 컴포넌트**: `anchor-statement.tsx`(①), `product-story.tsx`(②, 스텝 데모 컨테이너), `feature-bento.tsx`(③). 모두 `'use client'` 필요 부분만.
> **재활용**: `seoul-districts-map.tsx`, `analysis-mini-demo.tsx`, `mini-area-chart.tsx`, `reveal.tsx`.

| UI 요소            | 사용자 동작 | 결과 / UI 반영                                              |
| ------------------ | ----------- | ---------------------------------------------------------- |
| ① 앵커 문장        | 스크롤      | 진행도에 따라 글자 색이 연회색→본문색으로 채워짐          |
| ② 스텝 목록(01~04) | 스크롤      | 뷰포트 진입 스텝이 활성화, 좌측 스텝 sticky 고정          |
| ② 데모 패널        | 스크롤      | 활성 스텝에 맞춰 지도/미니데모/추천/시뮬 표현으로 교체    |
| ② 상권분석 스텝    | 클릭/키보드 | 해당 스텝 패널에 마운트된 기존 미니데모는 직접 조작 가능  |
| ③ 벤토 카드        | (표시)/호버 | AI 리포트(대)·커뮤니티·저장/알림(소). 호버 시 경계 강조   |
| ③ CTA              | 클릭        | "시작하기"→`/register`, "상권 분석"→`/analysis`           |

| 4   | ② 상권분석 스텝의 미니데모는 기존 `analysis-mini-demo`를 그대로 재활용하며 조작 가능성을 유지한다             | D3, D5    |

| 6   | 모바일(≤640px)에서 ②는 스티키를 해제하고 스텝→패널 순으로 세로 스택되며 순차 리빌한다                        | D4, D6    |
| 7   | `prefers-reduced-motion: reduce`에서 텍스트 채우기·스텝 전환·리빌을 제거하고 최종 상태를 즉시 표시한다        | D6        |
| 8   | 모션·색·radius·shadow·spacing은 `DESIGN.md` 토큰만 사용한다. 3D 아이콘·캡처 이미지·gradient/blur를 쓰지 않는다 | D6        |
| 9   | 스크롤 연동 계산은 rAF로 스로틀하며 스크롤 성능(메인스레드 블로킹)을 저해하지 않는다                          | D3, D7    |

## D3. 아키텍처 / 시스템 설계

| 모듈                        | 책임                                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `home-page.tsx`             | 3부 섹션 조립(서버 컴포넌트 유지 가능, 하위 클라이언트 컴포넌트 배치)                                        |
| `anchor-statement.tsx`      | ① 앵커. 문장을 단어 배열로 분해, 스크롤 진행도(0~1)로 채움 비율 계산·렌더                                    |
| `use-scroll-progress.ts`    | 대상 요소의 뷰포트 통과 진행도(0~1)를 rAF 스로틀로 반환하는 훅. reduced-motion이면 1 고정                     |
| `product-story.tsx`         | ② 컨테이너. 스텝 데이터·활성 인덱스 상태·sticky 레이아웃. 각 스텝 데모 패널을 매핑                           |
| `story-steps.ts`            | ② 스텝 정의(번호/제목/설명/데모 종류) 정적 데이터                                                            |
| (재활용) `seoul-districts-map` / `analysis-mini-demo` / `mini-area-chart` | ② 데모 패널 표현                                            |
| `feature-bento.tsx`         | ③ 벤토 그리드(대·소 카드) + CTA. AI 리포트 카드에 `mini-area-chart` 재활용                                  |

**클라이언트 경계**: 스크롤·IntersectionObserver·미니데모 조작이 필요한 ①②③ 본체만 `'use client'`. 카피/정적 마크업은 서버 컴포넌트로 유지.

### D3-1. ② 스티키 스텝 활성화 방식

- 각 스텝마다 sentinel 요소를 두고 `IntersectionObserver`(rootMargin 중앙 밴드)로 활성 스텝 판정. (기존 `reveal.tsx`와 동일 계열 패턴)
- 데모 패널은 우측에 sticky. 활성 스텝 변경 시 패널을 크로스페이드/슬라이드(`--motion-standard`/`--ease-standard`)로 교체.
- 스크롤-핀(pin) 방식은 쓰지 않는다 → 라이브러리 없이 크로스브라우저 안전.

### D3-2. ① 텍스트 채우기 구현 — 결정 필요(Decisions 참조)

- **원안(A)**: `gsap` + `ScrollTrigger`로 진행도 계산. 견고·요청안 부합. 단, 신규 의존성(~50KB, client-only+lazy).
- **대안(B)**: `use-scroll-progress.ts`(무의존성, 스크롤 리스너+rAF)로 진행도 계산 후 단어 채움. 번들 0 추가, `DESIGN.md` 절제 기조 부합.
- ② 스티키는 어느 안이든 IntersectionObserver로 처리하므로 GSAP는 오직 ①에만 관계됨.

## D4. 상호작용 / 상태 설계

| 상태             | 소유                | 값                                       |
| ---------------- | ------------------- | ---------------------------------------- |
| 앵커 진행도      | `anchor-statement`  | 0~1 (스크롤). reduced-motion → 1         |
| 활성 스텝 인덱스 | `product-story`     | 0~3. 초기 0(현황)                        |
| 미니데모 선택    | `analysis-mini-demo`| 기존 스펙 유지(지역·업종)                |

- 반응형 분기: 데스크톱(>640px) sticky 2열 / 모바일(≤640px) 세로 스택+순차 리빌.
- 활성 스텝 전환은 idempotent(같은 스텝 재진입 시 재애니메이션 최소화).

## D5. 데이터 / 콘텐츠

- **앵커 카피**: "감에 의존하지 마세요. AI 에이전트가 방대한 데이터를 분석해 오직 당신만을 위한 맞춤형 리포트를 완성합니다."
- **② 스텝(4)**: 01 현황 확인(지도) / 02 상권 분석(미니데모) / 03 후보 추천(추천 카드) / 04 창업 시뮬레이션(비용·매출 미니결과). 각 스텝 설명은 기존 `workflowSteps` 카피 재활용.
- **③ 벤토**: 대=AI 리포트("AI 에이전트가 상권 데이터를 분석해 맞춤형 리포트를 스트리밍으로 완성", 미니 차트) / 소1=커뮤니티 / 소2=저장·알림. 하단 CTA 밴드(시작하기/상권 분석).
- ② 데모 수치는 대표 예시(샘플)이며 그렇게 라벨링한다.

## D6. 접근성 / 비기능 요구

| 항목            | 요구                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------- |
| reduced-motion  | 채우기·전환·리빌 제거, 최종 상태 즉시 표시(D2-7)                                                   |
| 키보드          | ③ CTA·②미니데모는 키보드 조작 가능. 스크롤 연출은 비필수(콘텐츠는 스크립트 없이도 전부 읽힘)      |
| 스크린리더      | ① 앵커 문장은 완전한 문장으로 읽힘(단어 span 분해가 낭독을 깨지 않게). ② 스텝은 목록 시맨틱 유지  |
| 디자인 토큰     | 색·모션·radius·shadow·spacing 전부 `DESIGN.md` 토큰. 신규 토큰 추가 금지                          |
| 이미지/아이콘   | 3D 아이콘·스크린샷 캡처 미사용. 아이콘은 기존 `lucide-react` 라인 계열 유지                       |

## D7. 성능

- 스크롤 핸들러는 rAF 스로틀, passive 리스너. 레이아웃 스래싱 방지(읽기/쓰기 분리).
- ② 데모 패널은 활성 스텝만 렌더 부담이 크지 않게(가벼운 SVG/기존 컴포넌트).
- GSAP 채택 시(A안) client-only + `dynamic`/lazy import로 초기 번들 영향 최소화.

## D8. 테스트

- `use-scroll-progress` 진행도 계산 단위테스트(경계 0/1, reduced-motion=1).
- `product-story` 활성 스텝 판정 로직 단위테스트(스텝 경계 인덱스).
- 스텝 데이터·벤토 콘텐츠 스냅샷/구조 테스트.
- reduced-motion 분기 렌더 테스트(전환 제거·최종 상태 표시).
- 회귀: 기존 `home-page.test.ts`가 새 구조에서도 통과하도록 갱신.
