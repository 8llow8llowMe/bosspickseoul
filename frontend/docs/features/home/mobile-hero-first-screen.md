> **입력 문서**: [home-ux-audit-2026-09-11](./home-ux-audit-2026-09-11.md) — **§3 P0-A**(모바일 첫 화면에 가치 제안이 없다), §3 P2-K(지도 강조 자치구의 의미가 화면에 없다), §3 P2-P(「Pick」 이 카피에 없다)
> **대상**: 웹 (Next.js App Router)
> **작성자**: Claude Code
> **상태**: 초안 (미구현)

감사 §4 수정 계획의 **2번 항목**이다. 세 건을 한 덩어리로 다룬다 — 셋 다 같은 파일
(`hero-section.tsx` · `seoul-districts-map.tsx` · `hero-window.tsx`)을 만지고, P2-K·P2-P 는
P0-A 가 만드는 새 레이아웃에 놓일 자리가 생겨야 실행할 수 있다.

1. **P0-A** — 모바일에서 지도가 한 화면을 통째로 먹고 그 뒤에 카드가 온다. h1 이 1.24 화면, 첫 CTA 가 1.53 화면 뒤다.
2. **P2-K** — 로드 시 자치구 3곳이 깜빡이는데 그 기준이 화면 어디에도 없다.
3. **P2-P(Pick 캡션)** — 로고의 강조 칸이 뜻하는 「여러 칸 중 하나를 골랐다」가 홈 카피에 없다. 25칸 지도가 바로 그 은유를 시각화한 자리다.

**새 백엔드 호출은 없다.** 히어로 지도·툴팁·시트가 쓰는 수치는 전부
`src/data/district-metrics.ts` 의 정적 대표 예시 데이터이고, 홈 전용 API 도입은 공통
명세 S0 「구현 제외 범위」가 이미 막아 두었다. 그래서 이 문서에는 엔드포인트 표가 없다.

### D0-2. 지도 SVG 박스 635px 중 **369px 은 빈 띠다**

이 숫자가 이번 설계의 축이다. 지도 viewBox 는 `0 0 800 620`(`SEOUL_STATUS_VIEW_BOX`)이고
`preserveAspectRatio="xMidYMid meet"` 이라, 박스가 비율보다 세로로 길면 폴리곤은 **가로에
맞춰 축소되고 세로로는 가운데 정렬**된다.

```
폴리곤이 실제로 차지하는 높이 = 박스 폭 × (620 / 800)
                             = 343 × 0.775
                             = 266px

빈 띠 = 박스 높이 635 − 266 = 369px  (박스의 58%)
```

즉 **모바일에서 지도 한 화면을 쓰는 것은 지도를 크게 보여 주는 게 아니라 빈 띠를
만드는 것이다.** 감사가 「제목 아래 250px 공백」으로 잡은 것과 같은 뿌리다. 그래서
D4-2 는 지도 컨테이너 높이를 「0.6 화면」이라는 절대값이 아니라 **폴리곤이 실제로
차지하는 높이**로 정한다(산출은 D5-2).

### D0-3. `$isTop` 의 실제 기준 — 코드에서 확인한 것

`seoul-districts-map.tsx` 의 `$isTop` 은 **계산이 아니라 하드코딩된 목록**이다.

| 확인한 것     | 값                                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| 정의          | `src/data/district-metrics.ts` — `export const TOP_DISTRICT_CODES = ['11680', '11440', '11710'] as const`    |
| 주석          | 「pulse/glow로 강조할 상위 상권(강남·마포·송파)」                                                            |
| 자치구        | `11680` 강남구 · `11440` 마포구 · `11710` 송파구 (`src/data/districts.ts` 의 `gooCode`↔`gooName`)            |
| 판정          | `TOP_DISTRICT_CODES.includes(feature.districtCode)` — 지표를 읽지 않는다                                     |
| 지표와의 관계 | 세 곳은 `METRICS` 의 **월 매출 상위 3**(3.6 / 3.1 / 3.0억)이자 **일 유동 상위 3**(8.4 / 7.2 / 6.9만)이다     |
| 데이터 성격   | `METRICS` 주석 「대표 예시 수치(실데이터 아님). hover 툴팁의 "느낌" 전달용」 — 공통 명세 S0 의 「대표 예시」 |
| 기존 테스트   | `district-metrics.test.ts` 는 **개수 3 과 지도 존재 여부만** 검사한다. 상위 3 인지는 검사하지 않는다         |

**캡션은 이 사실 위에서만 쓸 수 있다.** 「유동인구 상위 3곳」이라고만 적으면 실데이터
순위처럼 읽히므로 **「대표 예시 데이터 기준」을 문장 안에 넣는다**(카피는 D4-4).
하드코딩과 캡션 문장이 갈리지 않게 **순위 일치를 테스트로 잠근다**(D4-4, D7 #7).

## D1. 기능 개요

모바일(≤640px)에서 히어로의 세로 순서를 [지도 한 화면][카드 한 화면] 에서
**[카드][지도][캡션]** 으로 뒤집고, 지도를 폴리곤이 실제로 차지하는 높이로 줄이며,
폴리곤 탭을 라우팅 대신 하단 시트로 받는다. 데스크톱은 레이아웃·클릭 동작을 유지하고
**캡션만 새로 얻는다.**

```
[모바일] 히어로 진입 → 카드(h1·본문·CTA 3개)가 첫 화면 → 지도 → 캡션(강조 기준 + Pick)
                                    └ 폴리곤 탭 → 하단 시트(이름·월 매출·일 유동·추세) → 「이 자치구 분석하기」 → /analysis?districtCode=…
[데스크톱] 변경 없음(지도 위 떠 있는 카드 + 호버 툴팁 + 폴리곤 클릭 즉시 이동) + 캡션 1개 추가
```

### D3-1. 시스템 구성

```

├ MapScreen   (JSX 순서 2번째)         ← 모바일 100dvh 고정 제거
│ ├ MobileIntro                        ← 삭제
│ ├ MapLayer → SeoulDistrictsMap       ← props 4개 추가
│ └ MobileScrollHint                   ← 삭제

├ Scrim   (portal, fixed, --color-overlay)
```

**JSX 순서를 바꾸고 CSS `order` 를 쓰지 않는다.** 데스크톱에서 `CardLayer` 는
`position: absolute; inset: 0; z-index: 10` 이라 DOM 순서가 시각 결과를 바꾸지 않는다.
그러면서 **탭 순서가 개선된다** — 지금은 폴리곤 25개를 지나야 카드 CTA 에 닿는데,
카드가 앞서면 h1·CTA 3개 → 지도 순서가 된다. `order` 로 뒤집으면 시각 순서와 탭 순서가
어긋나 접근성이 나빠진다.

| 모듈 / 컴포넌트                     | 책임 변경                                                                                                         | 비고                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `hero-section.tsx`                  | 640px 분기에서 **세로 순서·높이**를 정한다. 시트 열림 상태(`sheetDistrictCode`)를 소유하고 지도에 콜백을 내린다   | 기존 `isMobileViewport` effect 를 그대로 쓴다. 새 훅을 만들지 않는다    |

### D3-2. 데이터 흐름

```
[정적] src/data/district-metrics.ts ─ getDistrictMetric(code) ─┬─ 데스크톱 툴팁 (기존)
                                                               └─ 모바일 시트   (신규, 같은 함수)
[정적] src/data/districts.ts ─ districtNameByCode ─────────────┴─ 이름 라벨
[정적] TOP_DISTRICT_CODES ──────── $isTop ─→ 펄스·연한 파랑 채움 ─→ 캡션 문장이 설명

[상태] hero-section.isMobileViewport ─→ 지도 props(onDistrictActivate / tooltipEnabled)
[상태] hero-section.sheetDistrictCode ─→ DistrictPreviewSheet 마운트 / 폴리곤 $selected
```

**네트워크 계층이 없다.** 시트는 이미 번들에 들어 있는 배열을 읽을 뿐이라 로딩·실패
상태가 존재하지 않는다. 그래서 이 문서에는 404/5xx 분기가 없다 — 유일한 「데이터 없음」은
지도에 있는 코드가 `METRICS` 에 없는 경우인데, 기존 테스트
(`지도에 있는 모든 자치구가 매트릭을 가진다`)가 이미 이것을 막고 있다. 그래도 시트는
방어적으로 `undefined` 면 마운트하지 않는다(D6).

### D3-3. 데이터 모델

| 모델                        | 필드                                  | 타입                          | 설명                                                      |
| --------------------------- | ------------------------------------- | ----------------------------- | --------------------------------------------------------- |
| `DistrictMetric` (기존)     | `districtCode`                        | `string`                      | SIG 코드. `/analysis?districtCode=` 와 같은 값            |
|                             | `salesLabel`                          | `string`                      | 라벨+값이 붙은 문자열. 예 `'월 매출 3.6억'`               |
|                             | `footTrafficLabel`                    | `string`                      | 예 `'일 유동 8.4만'` — **「일 유동인구」가 아니다**(D8-4) |
|                             | `trend`                               | `number[]`                    | **7개 값**(테스트 하한은 6). 월 수를 카피에 적지 않는다   |
| `TOP_DISTRICT_CODES` (기존) | —                                     | `readonly string[]`(길이 3)   | `['11680','11440','11710']` = 강남·마포·송파              |
| `TooltipAreaChart` (기존)   | `linePath` / `areaPath` / `lastPoint` | `string` / `string` / `{x,y}` | `tooltipAreaChart(trend, W, H)` 반환. 시트가 그대로 쓴다  |
| 시트 상태 (신규)            | `sheetDistrictCode`                   | `string \| null`              | `hero-section` 로컬 `useState`. `null` = 닫힘             |

```ts
// src/components/home/seoul-districts-map.tsx (props 확장)
type SeoulDistrictsMapProps = {
  onHoverChange?: (districtCode: string | null) => void
  /** 주면 폴리곤 활성화(클릭·Enter·Space)가 라우팅 대신 이 콜백을 부른다. */
  onDistrictActivate?: (districtCode: string) => void
  /** 호버/포커스 툴팁을 그릴지. 모바일(≤640px)에서 false. 기본 true. */
  tooltipEnabled?: boolean
  /** 시트에서 보고 있는 자치구. 폴리곤 채움을 유지한다. */
  selectedCode?: string | null
}

// src/components/home/district-preview-sheet.tsx (신규)
type DistrictPreviewSheetProps = {
  districtCode: string
  onClose: () => void
}
```

`onDistrictActivate` 를 **optional 로 두고 기본을 라우팅으로 남기는** 이유: 지도는
히어로 말고 다른 곳에서도 쓰일 수 있고(현재 사용처는 히어로 1곳), 기본값이 「아무 일도
안 함」이면 prop 을 빠뜨렸을 때 지도가 조용히 죽는다.

| 역할                  | 요구 사항                                          | 구체 구현                                                                     |

| 하단 시트             | 포털 · 스크림 · 스크롤 잠금 · Escape · 포커스 복귀 | **새 패키지 없음.** `analysis-result-modal.tsx` 의 패턴을 그대로 따른다(D0-4) |

섞으면 641–768px 구간에서 「데스크톱 레이아웃인데 모바일 동작」이 된다.

## D4. 상세 동작 정의

### D4-1. 모바일 카드 우선 배치

`hero-section.tsx` 의 640px 미디어쿼리를 아래처럼 바꾼다. **데스크톱 규칙은 한 줄도
건드리지 않는다.**

```
MapScreen  @media (max-width: 640px) {
  height: calc(100dvh - 65px);   →  height: auto;
}

CardLayer  @media (max-width: 640px) {
  min-height: calc(100dvh - 65px);  →  min-height: auto;
  padding: 0;                       →  padding: 24px 0 0;   /* 헤더와의 간격 */
}

MapLayer (신규 모바일 규칙) {
  flex: none;
  margin-top: 24px;              /* 카드 ↔ 지도 */
}
```

- `MobileIntro` · `MobileIntroEyebrow` · `MobileIntroTitle` · `MobileScrollHint` 와 그 JSX,
  그리고 `ChevronDown` import 를 **삭제한다.**
- `MapScreen` 은 남긴다 — 데스크톱의 `display: contents` 가 `MapLayer` 를 `HeroStage` 의
  직접 자식(`flex: 1`)으로 만드는 장치라, 지우면 데스크톱 지도 높이가 무너진다.
- JSX 순서를 `<CardLayer>` → `<MapScreen>` 으로 바꾼다(근거 D3-1).

**두 요소를 되살리지 않고 없애는 이유.**

| 삭제 대상          | 지금 하는 말                                                   | 왜 없애나                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MobileIntro`      | 「서울 상권 지도」 / 「자치구를 눌러 바로 분석을 시작하세요.」 | 카드의 h1·본문이 바로 위에 오면서 **중복**이 된다. 그리고 탭이 시트를 여는 순간 「눌러 바로 분석」은 **틀린 설명**이 된다. 지도를 설명할 말은 캡션(D4-4)이 이어받는다 |
| `MobileScrollHint` | 「아래로 스크롤 ⌄」                                            | 가리키던 목적지(카드)가 이제 **위**에 있어 방향이 뒤집힌다. 대신 지도 상단 216px 이 첫 화면에 걸쳐 보여(D5-1) 「아래에 더 있다」를 콘텐츠가 직접 말한다               |

### D4-2. 모바일 지도 축소 — 빈 띠 0

`seoul-districts-map.tsx` 의 `MapSvg` 에 모바일 규칙을 더한다.

```
MapSvg  @media (max-width: 640px) {
  height: auto;
  aspect-ratio: 800 / 620;   /* SEOUL_STATUS_VIEW_BOX 와 같은 수 */
}
```

데스크톱 규칙(`height: 100%`)은 그대로다 — 거기서는 뷰포트 높이에 맞춰 축소하는 것이
의도다(파일 상단 주석).

**「0.6 화면(≈450px)」을 절대값으로 박지 않는 이유는 D5-2 에 계산으로 남긴다.** 요약하면
375px 폭에서 폴리곤은 **260px 이상 커질 수 없고**, 컨테이너에 450px 을 주면 190px 짜리
빈 띠가 생겨 이번에 없애려는 결함이 지도 안으로 옮겨 갈 뿐이다. 0.6 화면은 **상한**으로
쓰고 실제 높이는 비율이 정한다.

### D4-3. 모바일 폴리곤 탭 → 하단 시트

#### 활성화 분기

```
onClick / Enter / Space
  └ onDistrictActivate 가 있으면  → onDistrictActivate(code)        (모바일: 시트 열기)
    없으면                        → router.push('/analysis?districtCode=' + code)   (데스크톱, 기존)
```

`hero-section.tsx`:

```
onDistrictActivate = isMobileViewport ? setSheetDistrictCode : undefined
tooltipEnabled     = !isMobileViewport
selectedCode       = sheetDistrictCode
onHoverChange      = isMobileViewport ? undefined : setHoveredCode
```

`isMobileViewport` 는 effect 로 정해지므로 **SSR·첫 렌더에서는 `false`**(데스크톱 취급)다.
하이드레이션 전에는 핸들러 자체가 붙지 않아 탭이 라우팅되는 일은 없다. 기존
`deriveWindowDisplay` 도 같은 전제를 쓰고 있다.

#### 시트 내용 (위에서 아래로)

| 요소        | 내용                                                     | 출처                                       |
| ----------- | -------------------------------------------------------- | ------------------------------------------ |
| 손잡이      | 40×4px, `--color-border-300`, `aria-hidden="true"`       | `analysis-mobile-sheet.tsx` 규격           |
| 제목        | 자치구명 (예: 「강남구」) — 20px/700                     | `districtNameByCode`                       |
| 닫기 버튼   | `X` 아이콘, 44×44, `aria-label="{자치구명} 정보 닫기"`   | —                                          |
| 지표 1      | `salesLabel` 문자열 그대로 (예: 「월 매출 3.6억」)       | `getDistrictMetric(code).salesLabel`       |
| 지표 2      | `footTrafficLabel` 문자열 그대로 (예: 「일 유동 8.4만」) | `getDistrictMetric(code).footTrafficLabel` |
| 추세 차트   | 폭 100%, 높이 40px. 라벨 「최근 추세」                   | `tooltipAreaChart(trend, W, 40)`           |
| 데이터 라벨 | 「대표 예시 데이터」 (12px, `--color-text-caption`)      | 공통 명세 S0 「대표 예시로 라벨링」        |
| CTA         | 「이 자치구 분석하기」 → `/analysis?districtCode={code}` | `hero-window.tsx` 의 `PrimaryLink` 규격    |

- **지표 문자열을 쪼개지 않는다.** 데스크톱 툴팁과 **같은 필드를 같은 모양으로** 쓰는
  것이 이 시트의 설계 전제(D2 #6)다. 라벨/값을 분리하려면 데이터 구조를 바꿔야 하고
  그러면 툴팁도 같이 바뀐다 — 범위 밖이다(D8-4).
- **「6개월」 같은 기간을 카피에 쓰지 않는다.** `trend` 는 값이 7개이고 단위가 코드
  어디에도 없다. 「최근 추세」까지만 적는다.

#### 열림 / 닫힘

| 동작                      | 결과                                                                       |
| ------------------------- | -------------------------------------------------------------------------- |
| 폴리곤 탭 / Enter / Space | 시트 마운트. 배경 스크롤 잠금. 포커스를 닫기 버튼으로 이동                 |
| 스크림 탭                 | 닫힘                                                                       |
| 닫기 버튼 탭              | 닫힘                                                                       |
| `Escape`                  | 닫힘                                                                       |
| 다른 폴리곤 탭            | 시트가 열려 있으면 스크림이 덮고 있어 도달 불가 — 먼저 닫아야 한다         |
| 닫힘 공통 후처리          | 스크롤 잠금 해제 · 포커스를 **누른 폴리곤**으로 복귀 · `selectedCode` 해제 |
| CTA 탭                    | `/analysis?districtCode=…` 이동. 시트는 페이지 전환으로 자연히 사라진다    |

시트는 `role="dialog"` · `aria-modal="true"` · `aria-label="{자치구명} 요약"` 을 갖는다.
포커스 트랩은 `community-report-dialog.tsx` 의 Tab 순환 구현을 따른다(포커스 가능한
요소가 닫기·CTA 둘뿐이라 구현이 짧다).

### D4-4. 지도 캡션 — 강조 기준 + 「Pick」

`seoul-districts-map.tsx` 안에 `MapCaption` 을 둔다(설명 대상이 이 컴포넌트의 것이고
`Wrapper` 가 이미 `position: relative` 다).

```
MapCaption {                      /* 데스크톱 */
  position: absolute;
  left: 0;
  bottom: 0;
  max-width: 420px;
  pointer-events: none;           /* 아래 폴리곤의 hover 를 막지 않는다 */
  color: var(--color-text-caption);
  font-size: 13px;
  line-height: 20px;
}
@media (max-width: 640px) {       /* 모바일: 지도 아래 흐름 */
  position: static;
  max-width: none;
  margin-top: 8px;
  pointer-events: auto;
}
```

- 데스크톱에서 `DockButton` 은 스테이지 **우**하단이라 겹치지 않는다.
- 지도 `<svg>` 에 `aria-describedby={captionId}` 를 걸어, 화면 순서와 무관하게
  스크린리더가 지도 설명으로 읽게 한다.

### D4-5. 펄스 3회 정지 + 정지 후 강조 유지

```
DistrictPath {
  fill: ${p => (p.$isTop ? 'var(--color-primary-100)' : 'var(--color-surface-muted)')};
  animation: ${p => (p.$isTop ? css`${topPulse} 2.4s var(--ease-standard) 3` : 'none')};
}
```

- `infinite` → **`3`**. 7.2초 뒤 멈춘다(D5-5).
- **기본 `fill` 을 `$isTop` 에 따라 가른다.** 지금은 강조가 애니메이션에만 있어서
  멈추는 순간 세 곳이 사라지고, 캡션이 가리킬 대상이 없어진다. `topPulse` 의 `0%/100%`
  키프레임 값이 이미 `--color-primary-100` 이므로 **같은 색을 정적 기본값으로** 올리면
  애니메이션 시작·끝과 정확히 이어진다(`animation-fill-mode` 를 쓸 필요가 없다).
- 이 변경은 **`prefers-reduced-motion` 결함도 같이 고친다.** 지금은 reduced-motion 에서
  `animation: none` 이라 강조가 **아예 보이지 않는데**, 캡션은 「파랗게 칠했어요」라고
  말한다. 기본 `fill` 이 갈리면 모션 없이도 강조가 보인다.
- `:hover` · `:focus-visible` 의 `animation: none` + `fill: var(--color-primary-700)` 는
  그대로다.

`$selected` 가 참인 폴리곤은 `fill: var(--color-primary-700)` + `animation: none` 으로,
시트를 보는 동안 어디를 눌렀는지 지도에 남긴다.

### D5-2. 모바일 지도 높이 — 왜 450px 을 쓰지 않나

```
폴리곤 렌더 높이 = 컨테이너 폭 × (620 / 800)

  컨테이너 폭 335 (셸 안)  → 335 × 0.775 = 259.6 ≈ 260px
  컨테이너 폭 375 (전폭)   → 375 × 0.775 = 290.6 ≈ 291px

450px 을 주면 → 빈 띠 450 − 260 = 190px (컨테이너의 42%)
450px 을 채우려면 필요한 폭 = 450 / 0.775 = 581px  → 375px 화면에서 불가능
```

| 안                                 | 지도 높이 | 빈 띠 | 판정                                                 |
| ---------------------------------- | --------- | ----- | ---------------------------------------------------- |
| `height: 450px` (0.6 화면 그대로)  | 450       | 190   | ❌ D0-2 의 결함을 지도 안으로 옮긴다                 |
| **`aspect-ratio: 800/620`, 셸 안** | **260**   | **0** | ✅ **채택** — 0.6 화면(450) 상한 안이고 빈 띠가 없다 |
| `aspect-ratio`, 셸 밖 전폭         | 291       | 0     | 더 크지만 음수 마진이 필요하다 → **D8-2**            |

`DESIGN.md` 「폭 체계」 표가 지도를 **「넓어질수록 좋아짐」** 칸에 넣어 뒀으므로 전폭 안이
방향은 맞다. 다만 이번 변경의 완료 기준(h1·CTA 위치)과 무관하고 `Inner` 의 셸 규칙을
깨야 해서 분리한다.

### D5-5. 펄스 3회 = 7.2초

```
1주기 2.4s × 3회 = 7.2s 뒤 정지
정지 후 fill = var(--color-primary-100)  (= topPulse 의 0%/100% 값과 동일)
prefers-reduced-motion: reduce → animation: none, fill 은 그대로 primary-100
```

3회를 고른 이유: 1회는 페이지 로드 중 놓치기 쉽고, 무한은 캡션을 읽는 동안에도 계속
깜빡여 읽기를 방해한다. 감사 P2-K 의 제안(「첫 3회 후 정지」)을 그대로 쓴다.

## D6. 주의사항

| 항목                                    | 내용                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **폴리곤은 44px 타깃을 만족할 수 없다** | 335px 폭에 25개 자치구가 들어가므로 작은 구(중구·종로구)는 한 변이 20~30px 이다. 지도 기하가 정하는 값이라 CSS 로 못 고친다. **그래서 시트가 필요하다** — 오탭이 곧바로 페이지 이동으로 이어지지 않고 「강남구가 맞나?」를 되물을 수 있다. 이번 변경은 이 제약을 없애지 못하고 **덜 아프게 만든다**                                                                                                                                         |
| `prefers-reduced-motion: reduce`        | ① 펄스는 처음부터 정지하고 **강조 채움은 남는다**(D4-5 — 현재는 강조가 통째로 사라지는 결함이다) ② 시트 등장 트랜지션을 넣는다면 `@media (prefers-reduced-motion: reduce)` 에서 제거한다 ③ 기존 폴리곤 `opacity`/`transition` 규칙은 손대지 않는다                                                                                                                                                                                          |
| **포인터 `fine` 인 소형 뷰포트**        | 데스크톱 창을 640px 이하로 줄이면 마우스가 있는데도 모바일 분기가 된다. 현재 코드는 드래그만 `(min-width: 641px) and (pointer: fine)` 로 가르고 레이아웃은 폭만 본다. **이 문서는 폭 하나로 통일한다** — ≤640px 이면 포인터 종류와 무관하게 툴팁을 끄고 클릭은 시트를 연다. 근거: 한 화면에서 툴팁과 시트가 같은 정보를 두 번 말하는 편이 더 나쁘고, 판정 기준이 둘이면 「마우스로 눌렀는데 시트가 안 뜬다」 같은 재현 어려운 분기가 생긴다 |
| **시트 열린 상태에서 뒤로가기**         | 시트는 라우트가 아니다. `history.pushState` 를 **쓰지 않으므로** 안드로이드 뒤로가기·브라우저 뒤로가기는 시트를 닫지 않고 **홈 이전 페이지로 나간다.** 저장소에 히스토리 조작 선례는 `recommend-page.tsx` 의 `replaceState` 하나뿐이고, App Router 라우터 상태와 어긋날 위험이 있어 랜딩에 새로 들이지 않는다. 닫기 경로 3개(스크림·버튼·Escape)를 반드시 다 구현한다 → 선택지는 **D8-6**                                                   |
| 시트가 지도를 덮을 수 있다              | 시트(≈300px)는 화면 하단을 차지한다. 사용자가 지도를 보려고 스크롤한 위치에 따라 누른 폴리곤이 가려질 수 있다. 대응: 시트 **제목이 자치구명**을 들고 있고, 폴리곤은 `$selected` 채움을 유지한다. 자동 `scrollIntoView` 는 넣지 않는다(갑작스러운 스크롤) → **D8-7**                                                                                                                                                                         |
| 캡션이 첫 화면 밖일 수 있다             | D5-1 계산상 캡션 top ≈ 864 로 812 를 넘는다. 완료 기준(h1·주 CTA)에는 영향이 없지만 펄스는 보이는데 설명은 안 보이는 상태가 될 수 있다. 실측 후 판단한다 → **D8-1**                                                                                                                                                                                                                                                                         |
| 데이터 부재 방어                        | `getDistrictMetric(code)` 가 `undefined` 면 시트를 **마운트하지 않는다**(빈 시트를 띄우지 않는다). 현재는 테스트가 전 자치구 커버를 보장하므로 실제로 도달하지 않는 분기다. 백엔드 호출이 없으므로 404/5xx·재시도 개념 자체가 없다                                                                                                                                                                                                          |
| 하이드레이션 일치                       | `isMobileViewport` 는 effect 로만 바뀌므로 SSR 마크업과 첫 렌더가 같다. 지도 컴포넌트는 module scope 에서 `window` 를 읽지 않는다(`docs/engineering/client-boundary.md`)                                                                                                                                                                                                                                                                    |
| 토큰                                    | 새 색·radius·shadow·spacing 토큰을 만들지 않는다. 시트는 `--radius-sheet` · `--color-surface` · `--color-overlay` · `--shadow-level-4`, 캡션은 `--color-text-caption`, 강조는 `--color-primary-100` / `--color-primary-700` 만 쓴다                                                                                                                                                                                                         |
| CLS                                     | 캡션은 데스크톱에서 `position: absolute` 라 레이아웃을 밀지 않는다. 모바일 지도는 `aspect-ratio` 로 높이가 처음부터 확정된다. 현재 CLS 0 을 지킨다                                                                                                                                                                                                                                                                                          |
| 데스크톱 회귀 주의                      | JSX 순서 변경으로 `CardLayer` 가 `MapScreen` 앞에 온다. `MapScreen` 의 `display: contents` 와 `MapLayer` 의 `flex: 1` 이 살아 있어야 데스크톱 지도가 스테이지를 채운다 — **바꾸지 않는다**                                                                                                                                                                                                                                                  |
