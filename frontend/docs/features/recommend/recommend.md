## S1. 기능 개요

사용자는 자치구 → 행정동 → 업종을 고르고, 그 행정동의 상권 중 업종 기준 **상위 5곳**을 점수와 추천 이유로 받아 본다. 지도는 선택을 돕고 결과를 그려 주는 가속기이고, **목록·패널·URL 이 정본**이다. 결과에서 두 상권을 담아 비교하고, 비교 결과를 근거로 커뮤니티 글을 시작할 수 있다.

```text
조건 선택(자치구·행정동·업종) → 행정동 상권 목록 → 업종별 추천 Top 5 → 상권 프로필 → (두 곳 담기) 비교 → 비교 초안으로 글쓰기
```

| 단계        | 호출                                                                        | 인증     |
| ----------- | --------------------------------------------------------------------------- | -------- |
| 행정동 목록 | `GET /regions/districts/{districtCode}/administrations`                     | 불필요   |
| 상권 목록   | `GET /regions/districts/{d}/administrations/{a}/commercials`                | 불필요   |
| 추천        | `GET /commercials/recommendations/by-service` (`commercialCodes[]`·`topN`)  | 불필요   |
| 상권 프로필 | `GET /map/commercials/{commercialCode}/profile`                             | 불필요   |
| 지도 뱃지   | `GET /map/districts` · `/map/administrations` · `/map/commercials` (bounds) | 불필요   |
| 비교        | `GET /commercials/compare` (`leftCommercialCode`·`rightCommercialCode`)     | 불필요   |
| 북마크      | `GET/POST/DELETE /members/me/bookmarks`                                     | **필요** |

### S3-1. 추천 호출이 세 단계인 이유

추천 API 는 **후보 상권 코드 목록을 요구**한다(`commercialCodes[]`). 행정동을 넘기면 알아서 골라 주는 계약이 아니다. 그래서 화면은 행정동 상권 목록을 먼저 받아 전부를 후보로 넘기고, 응답 Top 5 각각의 프로필을 다시 받는다. 후보 목록은 `createStableCommercialCodes` 로 중복 제거·정렬해 **같은 조건이면 같은 쿼리 키**가 되게 한다 — 그렇지 않으면 순서만 다른 같은 요청이 캐시를 빗나간다.

홈 03단계 미리보기(`use-recommend-preview`)가 이 연쇄를 그대로 쓴다. 추천 규칙이 바뀌면 홈도 같이 움직여야 한다.

### S3-2. 지도 뱃지가 목록을 대체할 수 없는 이유 (실측)

지도 영역 질의는 뷰포트 기반이라 첫 진입에서 자치구 25개 중 **21개만** 뱃지가 뜬다(강동·관악·금천·도봉 누락). 그래서 뱃지는 지름길이고 선택 뷰 목록이 정본이다. 상권 경계도 `profile` 이 `centerLng: null`/`boundaryCoords: []` 를 주는 경우가 있어, 결과 폴리곤은 결과 중심점 bbox 로 뷰포트 질의해 우회한다 — 근본 해결은 백엔드가 경계를 채우는 것이다(ux-followups D8).

**상권 뷰포트 질의(`/map/commercials`)는 지도가 실제 화면 범위를 알린 뒤에만 보낸다.** 백엔드는 뷰포트 안 상권이
250개를 넘으면 `MAP_010`(400, 「지도를 확대해 주세요」)으로 거절한다(`backend/docs/map-api-frontend-guide.md`). 화면의
`viewportBounds` 초기값은 서울 전체(`SEOUL_MAP_BOUNDS`)라, 링크로 들어오면 첫 렌더에서 씨앗 행정동 때문에
`commercial` 단계가 되고 씨앗 자동 제출이 `results` 로 넘기기 전 **그 서울 전체 범위로 상권 질의가 한 번 나가 400**
이었다. 지도의 첫 `onViewportBoundsChange`(idle 300ms 디바운스) 전에는 상권 질의를 켜지 않는다. 자치구(상한 50,
서울 25)·행정동(상한 500, 서울 425) 질의는 서울 전체 범위로도 통과하므로 첫 화면을 늦추지 않도록 그대로 둔다.
카카오 지도는 생성 직후 `idle` 을 올리지 않으므로, 링크 카메라(`'url'`)로 들어와 카메라가 움직이지 않으면 범위를 영영
모른다(수정 전에는 서울 전체 bbox 400 으로 조건 링크의 상권 폴리곤이 뜨지 않았다). 그래서 지도는 생성 300ms 뒤
**범위만** 한 번 알린다 — 카메라(`c`)는 올리지 않는다(url-state §2-2 「`c` 는 카메라가 한 번 움직여야 붙는다」).

### S3-3. 지도 컨트롤 (2026-09-29)

- 자리는 **우측 상단**이다. 모바일은 바텀시트가 아래를 덮어 우측 하단이 가려진다.
  공용 부품은 `components/map/map-controls.tsx` 이고 `/analysis` 지도도 「내 위치」를 같이 쓴다.
- 「선택한 지역으로 돌아가기」는 예전 「선택 범위로 이동」 텍스트 버튼이다. 링크 복원·직접 팬으로
  카메라가 선택 영역을 떠났을 때 되돌리고 자동 맞춤을 다시 켠다(동작은 [url-state](./url-state.md) 그대로).
  문구가 무엇의 범위인지 읽히지 않아 아이콘 + 풀어 쓴 접근성 이름(툴팁 동일)으로 바꿨다.
- 「내 위치로 이동」은 **누를 때만** 위치 권한을 묻는다. 서울 밖(`SEOUL_MAP_BOUNDS`)이면 카메라를
  옮기지 않고 토스트로 이유를 말한다 — 데이터가 서울뿐이라 옮기면 빈 지도만 남는다. 권한 거부·시간
  초과도 토스트다. 성공하면 level ≤4 로 옮기고 내 위치 점(primary-600, 흰 테두리 + 맥박)을 그린다.
- 선택된 순위 마커는 먹색(`--color-grey-900`) 배경 + 흰 글자·테두리다. 예전 하늘색(primary-700)
  배경은 파란 폴리곤 채움과 겹쳐 선택이 눈에 띄지 않았다.

### S3-4. 실시간 많이 본 상권 (2026-09-29)

조건 카드는 짧아 데스크톱 좌측 아래가 비었다. 그 자리에 `GET /analysis-rankings?areaType=COMMERCIAL`
(최근 N시간 **조회 수** 순위) 상위 5개를 5초마다 한 줄씩 돌려 「살아 있는 화면」을 만든다.

- **추천 활동을 지어내지 않는다.** 「n분 전 다른 사용자가 ○○를 추천받았어요」는 백엔드에 추천 이벤트
  기록이 없어 근거가 없다. 문구는 「실시간 · 최근 24시간 많이 본 상권」이다. 추천 활동을 보여 주려면
  백엔드에 추천 이벤트 적재 + 최근 활동 API 가 먼저 필요하다(후속).
- 순위 API 만 따로 죽을 수 있다(RANKING_001 503). 실패·집계 비어 있음이면 띠를 **그리지 않는다**.
- 1분마다 다시 읽는다. 마우스·포커스가 들어오면 회전을 멈추고(WCAG 2.2.2), 동작 줄이기 설정이면
  돌리지 않는다. live region 이 아니다 — 포커스하면 현재 줄을 읽는다.
- 조건 뷰에서만 보인다. 결과·선택 뷰는 패널이 높이를 다 쓴다. 모바일 시트에는 넣지 않았다.
