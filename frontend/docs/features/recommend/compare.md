## D4. 상세 동작 정의

### D4-1. 값

```
unit 이 비지 않은 문자열이면  →  Intl.NumberFormat('ko-KR', {min=max=precision}).format(value) + unit
                                  precision = displayPrecision 이 0~4 정수면 그 값, 아니면 최대 소수 1자리(기존)
unit 이 없으면               →  기존 formatAnalysisValue(value)   (단위 없음)
value 가 유한수가 아니면      →  '—'
```

예: `293433501`·`원`·`0` → `293,433,501원` · `4410`·`명`·`0` → `4,410명` · `53.8`·`%`·`1` → `53.8%` · `12`·`개`·`0` → `12개` · `7`·`건`·`0` → `7건`.

### D4-2. 차이

- 원시 `diffValue` 를 `precision` 으로 반올림해 **표시만** 한다. 좌·우 표시값을 다시 빼지 않는다 — `53.84` 와 `52.96` 은 `53.8%`·`53.0%` 로 보이지만 차이는 `+0.9%p` 다(원시 `0.88`).
- 반올림과 부호는 `Intl.NumberFormat` 에 함께 맡긴다(`signDisplay: 'exceptZero'`). 반올림 결과가 양수면 `+`, 음수면 `-`, 0 이면 부호 없이 `0원`·`0.0%p` — `-0.04` 를 `-0.0%p` 로 적지 않는다. 기본 반올림(halfExpand)은 부호와 무관하게 대칭이다(`±2.5` → `±3`, `±0.05` → `±0.1%p`). `Math.round` 는 .5 를 +∞ 쪽으로 올려 대칭이 깨지므로 쓰지 않는다. 차이율도 같은 규칙(소수 1자리)이다.
- `differenceUnit` 이 없으면 기존 표시(`+400`, `0`)로 물러난다. `unit` 은 있는데 `differenceUnit` 이 없어도 `unit` 을 빌려 쓰지 않는다 — 비율 지표에서 `%` 를 붙이면 %p 를 %로 잘못 읽힌다.
- 열 머리는 응답과 무관하게 `차이 (왼쪽 − 오른쪽)` 이다. 구버전 응답도 `diffValue` 는 좌 − 우였다.
- 색은 중립(`--color-text-600`)이다. 부호로 좋고 나쁨을 칠하지 않는다.

### D4-3. 차이율

| 조건                                                        | 표시                                   |
| ----------------------------------------------------------- | -------------------------------------- |
| `differenceUnit` 없음(구버전)                               | 그리지 않는다 — 기존 화면에 없었다     |
| `rightValue` 가 유한수가 아님 · `diffRate` 가 유한수가 아님 | 그리지 않는다                          |
| `rightValue === 0`                                          | `차이율 비교 불가`                     |
| 그 외                                                       | `차이율 +1.7%` (소수 1자리, ×100 없음) |

`rightValue=0` 일 때 백엔드는 호환용 `diffRate=0` 을 준다. 이를 `0%` 로 적으면 「차이 없음」으로 읽혀 거짓이 된다. 좌·우가 둘 다 0 이어도 0/0 은 정의되지 않으므로 똑같이 `비교 불가` 다.

### D4-4. 기준 문구

- 표 위 중립 안내(`COMPARISON_NEUTRAL_NOTICE`) 아래에 「비교 기준」 목록으로 `periodBasis` → `serviceBasis` → `differenceBasis` → `diffRateBasis` 순서로 적는다. 빈 문자열·null 은 건너뛰고, 넷 다 없으면 목록을 그리지 않는다.
- 묶음 설명은 소제목 아래 보조 문장이다. 가로 스크롤 중에도 읽히도록 폭을 보이는 스크롤 영역에 맞춘다(`container-type: inline-size` + `100cqi`).
- 문장을 고치거나 잘라 쓰지 않는다. 0 과 결측을 구분할 수 없다는 사실(`spendingMetrics` 설명·면책 문구)은 백엔드 문장이 말한다 — 화면이 `0원` 칸을 따로 「데이터 없음」으로 바꾸지 않는다. 실제 0 인지 결측인지 화면은 알 수 없다.

### D4-5. 지표 설명 도움말

- 저장소에 공용 툴팁이 없다(`components/ui` 에 없음, DESIGN.md 에 Tooltip 은 미구현 목록). 떠 있는 툴팁은 표의 `overflow-x: auto` 컨테이너에 잘리고, 터치에서 hover 가 없다. 그래서 **인라인 펼침(disclosure)** 으로 한다 — 시뮬레이션 조건 섹션(`simulation-condition-section.tsx`)과 같은 `button[aria-expanded][aria-controls]` 관용구다.
- 버튼은 icon-only(`CircleHelp`)라 `aria-label="{묶음명} {지표명} 설명"` 을 둔다. 묶음명을 붙이는 이유는 매출·유동인구 시간대가 둘 다 `00-06` 이라 지표명만으로는 버튼 이름이 겹치기 때문이다. 시각 크기 32px, 터치 영역은 가상 요소(`inset: -8px`)로 48px 까지 넓힌다. 행 높이는 음수 여백(`-4px`)으로 유지한다. 설명 문단은 DOM 에 늘 있고 접혀 있을 때 `hidden` 이다 — `aria-controls` 가 가리키는 대상이 늘 존재한다.
- 설명 문단은 첫 열 너비를 넓히지 않는다(`width: 0; min-width: 100%`) — sticky 첫 열이 넓어지면 모바일에서 값 열이 가려진다.
- **묶음 공통 설명**: 한 묶음의 **모든 행**(2행 이상)이 같은 설명이면 행마다 도움말 버튼을 두지 않고, 그 문장을 묶음 설명 아래에 한 번만 적는다(`ComparisonGroup.sharedRowDescription`, 이때 행 `description` 은 null). 백엔드 상세 묶음은 행마다 같은 문장을 주므로(예: 시간대 6행) 그대로 두면 같은 문장에 Tab 정지가 최대 48개 생긴다. 한 행짜리 묶음(`spendingMetrics`)은 「같다」가 자명해 올리지 않고 다른 핵심 행처럼 버튼으로 둔다. 설명이 빠진 행이 하나라도 있으면 공통 설명이 아니다.

### D4-6. 핵심 / 상세 묶음 (구성 검토 결과)

| 구분 | 묶음                                                                                                                                                | 행 수              | 기본 |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | ---- |
| 핵심 | `salesMetrics` `footTrafficMetrics` `storeMetrics` `spendingMetrics` `residentPopulationMetrics` `facilityMetrics`                                  | 4+3+5+1+3+3 = 19   | 펼침 |
| 상세 | `salesTimeSlotMetrics` `salesAgeMetrics` `salesAgeGenderMetrics` `footTrafficTimeSlotMetrics` `footTrafficAgeMetrics` `footTrafficAgeGenderMetrics` | 6+6+12+6+6+12 = 48 | 접힘 |

근거:

- 상세 48행이 전체 67행의 72% 다. 다 펼치면 핵심 19행을 읽은 뒤 스크롤 대부분이 분포표다.
- 상세 묶음은 한 축(시간대·연령·성별)으로 쪼갠 분포라 「어느 쪽이 큰가」보다 「어느 때·누가 많은가」를 보는 표다. 핵심 지표를 먼저 읽은 사람만 필요하다.
- **묶음마다** 따로 접는다(전체 한 번에가 아니다). 접힌 소제목도 묶음 이름과 `n개 지표` 를 보여 무엇이 숨었는지 알 수 있다.
- 표는 **하나**로 유지한다. 묶음마다 `tbody` 는 하나이고 소제목 행과 데이터 행을 함께 담는다. 접힌 동안 데이터 `<tr>` 에만 `hidden` 을 걸고, 소제목 버튼의 `aria-controls` 는 그 `tbody`(`id`)를 가리킨다 — 대상이 늘 DOM 에 있다. 소제목과 행을 다른 `tbody` 로 나누면 `scope="rowgroup"` 머리가 데이터 행에 연결되지 않아 스크린리더가 `00-06` 이 어느 묶음 행인지 말하지 못한다. 버튼의 접근 가능한 이름은 「매출 시간대 2개 지표」다(묶음명과 개수 사이 공백). 공통 명세의 「스크롤 컨테이너는 하나뿐」 규칙 그대로 — 접힌 묶음을 따로 떼면 가로 스크롤이 갈라진다.
- 접힘은 새 필드와 무관하게 적용한다(묶음 키로만 판정). 구버전 응답도 같은 67행이다.

### D4-7. 비교 리포트 (추천 영역)

- `recommendationDisclaimer` 가 있으면 리포트 맨 아래 주의 문구 자리에 그 문장을 그대로 적는다. 없으면 기존 문구(「{좌}·{우}의 분기 데이터로 계산한 결과예요. 업종과 창업 계획에 따라 다르게 읽힐 수 있어요.」)를 쓴다. 면책 문구만 있고 판단이 하나도 없으면 리포트를 그리지 않는다 — 면책할 추천이 없다.
- 추천 이유는 `293,433,501원` 같은 단위 포함 문자열이다. 숫자를 다시 꺼내 표로 바꾸지 않는다. 대신 `tabular-nums`, 항목 간격 8px, `overflow-wrap: anywhere` 로 좁은 화면에서도 넘치지 않고 숫자 자릿수가 맞게 읽힌다.

### D4-8. 조회 조건

- 부제 기간: `formatRecommendationPeriod(body.periodCode || RECOMMENDATION_PERIOD_CODE)` (빈 문자열도 물러난다).
- 제목 업종: `body.serviceCode || state.serviceCode` 로 업종 이름을 찾는다. 요청 키·비교 초안 링크는 여전히 URL 값을 쓴다(요청을 바꾸지 않는다).
