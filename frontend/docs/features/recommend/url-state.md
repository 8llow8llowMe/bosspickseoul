## 0. 배경

| 항목              | 내용                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 해결하려는 문제   | `/recommend` 가 선택을 React 상태로만 들고 있어 **새로고침·링크 공유에서 조건이 사라진다**                                 |
| 기존 동작 (as-is) | 검색 파라미터를 **아예 읽지 않는다** — `useSearchParams` 가 코드에 없다(실측). 어떤 조건을 고르든 URL 은 항상 `/recommend` |
| 목표 동작 (to-be) | 조건·결과·선택 상권을 URL 이 나른다. 새로고침·뒤로가기·링크 공유에서 화면이 복원된다                                       |
| 딸려 오는 것      | 화면 보관함의 `COMMERCIAL_COMPARISON` **미지원 사유가 사라진다**([share D1-1](../share/share.md))                          |
| 구현 제외 범위    | 화면 보관함 payload 빌더 — 아래 §6 참고. 카메라 `c` 는 처음엔 제외였고 2026-09-11 #317 로 추가했다(§2-2)                   |

`/analysis` 는 이미 선택 전체를 URL 로 읽는다(`districtCode`·`administrationCode`·
`commercialCode`·`serviceCode`·`periodCode`). **추천은 그 규약을 그대로 따른다** — 같은 값에
다른 이름을 쓰면 딥링크(D8-2)에서 매번 변환해야 한다.

## 1. 파라미터

| 파라미터             | 값                     | 언제 붙나                                                    |
| -------------------- | ---------------------- | ------------------------------------------------------------ |
| `districtCode`       | `11680`                | 자치구를 고르면                                              |
| `administrationCode` | `11680640`             | 행정동을 고르면                                              |
| `serviceCode`        | `CS100001`             | 업종을 고르면                                                |
| `view`               | `results`              | 「상권 추천받기」를 눌러 결과 단계에 들어가면                |
| `commercialCode`     | `3110008`              | 결과에서 상권을 **사용자가 직접** 고르면                     |
| `c`                  | `37.50123,127.03456,5` | 지도가 멈출 때마다(`idle`). 뷰 상태라 **항상** 붙는다 — §1-3 |

```
조건만 골라 둔 상태 (아직 제출 안 함)
  /recommend?districtCode=11680&administrationCode=11680640&serviceCode=CS100001

결과를 본 상태
  …&view=results

결과에서 3위를 고른 상태
  …&view=results&commercialCode=3110012

지도를 옮겨 둔 상태 (카메라는 항상 맨 뒤)
  …&view=results&commercialCode=3110012&c=37.50123,127.03456,5
```

### 1-1. `view=results` 를 왜 따로 두나

조건 3개가 다 차 있는 것과 「추천받기를 눌렀다」는 **다른 상태**다. 플래그 없이 조건 코드만
쓰면 둘을 구분할 수 없어서:

- **화면 보관함이 저장한 화면을 그대로 열지 못한다.** 보관함은 결과 화면을 저장하는데,
  복원 시 조건 화면이 뜨면 저장한 것과 다른 화면이다.
- **새로고침이 누르지도 않은 추천을 실행한다.** 조건만 고르고 새로고침했을 뿐인데 API 가
  나가고 결과가 열린다.

값을 `results` 하나로 둔 것은 `picker` 를 URL 에 **넣지 않기 때문**이다 — 선택 뷰는 일시
UI 라서 링크로 복원할 가치가 없다. 그 상태로 새로고침하면 조건 화면으로 돌아간다.

### 1-2. `commercialCode` 는 「사용자가 직접 고른 것」만 쓴다

결과가 도착하면 1위가 **자동 선택**된다(목록·상세가 빈 채로 뜨지 않게). 그 자동 선택을 URL 에
쓰면 「3위를 보던 화면」을 공유해도 받는 사람은 1위를 보게 되고, 링크가 조용히 거짓말한다.

상태에 이미 [`resultSelectionSource`](./ux-followups.md)(`'auto' | 'user' | null`)가 있다.
**`'user'` 일 때만 URL 에 쓴다.**

### 1-3. `c` 는 조건이 아니라 뷰 상태다 — 형식은 `/analysis` 와 같다

`c=lat,lng,level`, 위도 우선, 소수 5자리, level 은 정수 1~14, 한국 좌표 범위 가드.
파싱·직렬화는 `lib/analysis/map-camera.ts` 의 `parseMapCamera` · `serializeMapCamera` 를
**그대로 쓴다** — 두 화면이 같은 값을 다른 형식으로 갖지 않게 한다.

`commercialCode` 와 달리 **누가 정했든 항상 쓴다.** 자동 맞춤이 정한 카메라도 사용자가
움직인 카메라도 「지금 보이는 화면」이고, 공유받은 사람은 그 화면을 봐야 한다.

파라미터 순서는 조건 → 화면 상태(`view`·`commercialCode`) → 뷰 상태(`c`) 다. `c` 는 **맨 뒤**.

분석 → 추천 딥링크(`createRecommendHrefFromCodes`)는 `c` 를 넘기지 않는다 — 추천은
결과에 맞추는 쪽이고, 분석의 카메라는 상권 하나에 붙어 있어 추천 5건을 담지 못한다.

## 2. 방향 — URL 은 씨앗이자 거울, 정본은 리듀서

`/analysis` 는 URL 을 **정본**으로 쓴다(리듀서가 없고 매 렌더 `parseAnalysisSelection`).
추천은 이미 `recommendationReducer` 가 정본이라 같은 구조를 쓸 수 없다. 둘을 억지로 맞추면
리듀서를 걷어내는 큰 수술이 된다.

**대신 두 방향을 시점으로 가른다.**

| 방향       | 언제                | 무엇                                                     |
| ---------- | ------------------- | -------------------------------------------------------- |
| URL → 상태 | **마운트 때 한 번** | `createInitialRecommendationState` 를 URL 로 씨앗 뿌리기 |
| 상태 → URL | 상태가 바뀔 때마다  | `history.replaceState` 로 거울처럼 반영                  |

마운트 때 한 번만 읽으므로 **양방향 동기화의 무한 루프가 구조적으로 불가능**하다.

히스토리를 쌓지 않는 이유는 조건을 고를 때마다 뒤로가기가 「조건 하나씩 되감기」가 되면
화면에서 빠져나갈 수 없기 때문이다. `/analysis` 도 같은 이유로 `replace` 다. 대신 **브라우저
뒤로가기로 조건을 되돌릴 수는 없다** — 이 화면에는 「조건 수정」 버튼이 이미 있다.

### 2-1. `router.replace` 가 아니라 `history.replaceState` 인 이유

`replaceState` 는 URL 이 정본이 아니라 거울인 이 화면의 설계와 맞는다 — 라우터를 흔들어
리렌더·RSC 왕복을 일으킬 이유가 없고, `useSearchParams` 는 마운트 때 한 번만 읽는다.

⚠️ **첫 인자는 반드시 `window.history.state` 다. `null` 로 바꾸지 마라.** `null` 을 넘기면
Next 의 패치가 `applyUrlFromHistoryPushReplace` → `ACTION_RESTORE` 를 디스패치하는데, Next 16
의 `restore-reducer` 는 그것을 `startPPRNavigation` + `spawnDynamicRequests` 로 처리한다 —
이름만 「복원」이지 **네비게이션 한 번**이다. 거울은 상태가 바뀔 때마다 돌므로 **조건 칩을
하나 고를 때마다 RSC 왕복이 붙는다.** `router.replace` 도 같은 이유로 비싸다.

`window.history.state` 에는 `HistoryUpdater` 가 심은 `__NA: true` 가 늘 들어 있어서, Next 의
패치가 「내부 호출」로 보고 원본 `replaceState` 로 넘긴다 — **주소창만 바뀌고 라우터는
조용하다.**

⚠️ **대가는 `canonicalUrl` 이 진입 시점에 굳는 것이다.** `appRouterState` 가 한 번이라도
커밋되면 `HistoryUpdater` 의 `useInsertionEffect` 가 주소창을 진입 URL 로 되돌린다. 지금 이
화면에는 그 트리거가 없다 — `router.refresh()` 사용처가 없고, 유일한 `router.push` 는 화면을
떠나며, 프리페치는 리듀서 상태를 바꾸지 않는다. **`router.refresh()`·서버 액션·병렬/인터셉트
라우트를 이 화면에 들이면 그때 깨진다**(dev 의 Fast Refresh 가 그 예다).

### 2-2. 카메라 `c` — 값의 정본은 지도, 모드만 리듀서 (#317)

카메라는 조건이 아니라 **뷰 상태**다. 그래서 §2 의 「정본은 리듀서」를 그대로 적용하지
않는다 — 카메라 **값**의 정본은 카카오 지도 인스턴스고, 리듀서는 「자동 맞춤이 지도를
움직여도 되는가」(**모드**)만 든다. URL 은 여기서도 씨앗이자 거울이다.

| 방향       | 언제                                       | 무엇                                                                                                  |
| ---------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| URL → 지도 | **마운트 때 한 번**                        | `c` 가 유효하면 그 카메라로 지도를 만든다. 없거나 무효면 서울 기본(기존과 같다)                       |
| 지도 → URL | 지도가 멈출 때마다(`idle`, 300ms 디바운스) | 화면이 든 최신 카메라(ref)를 갱신하고 거울을 다시 쓴다. 상태 → URL 거울도 **같은 함수**로 `c` 를 쓴다 |

마운트 때만 읽으므로 `/analysis` 의 에코 가드(`lastEmittedCameraRef`)가 필요 없다 —
마운트 뒤에는 URL 변화가 지도를 움직이는 경로가 없다.

#### 자동 맞춤과의 우선순위

문제는 「URL 이 들고 온 카메라」와 「결과에 자동으로 맞추는 카메라」([ux-followups B](./ux-followups.md))
가 서로를 덮어쓴다는 것이다. 링크로 복원하는 동안 자동 맞춤은 **여러 번** 돈다 — 자치구
fit → 행정동 fit → 결과 중심점 fit → 경계 도착 후 재fit → 링크가 지목한 상권 fit.
`cameraTargetKey` 는 데이터가 도착할 때마다 바뀌므로 그 하나하나를 골라 막을 수 없다.
그래서 **모드**로 가른다.

`cameraMode: 'url' | 'auto'` — 리듀서 필드.

| 모드     | 뜻                                       | 자동 맞춤(`applyCameraTarget`)                                                                        |
| -------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `'url'`  | 링크가 들고 온 카메라가 화면을 지배한다  | **하지 않는다.** 복원 사슬 전체(단계 fit·결과 fit·경계 재fit·지목 상권 fit)와 창 크기 변화 재적용까지 |
| `'auto'` | 카메라가 선택·결과를 따라간다(기존 동작) | 한다                                                                                                  |

전이 규칙:

| 시점                                                                                                                                                                                                                                | 모드               |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| 마운트, `c` 유효                                                                                                                                                                                                                    | `'url'`            |
| 마운트, `c` 없음·무효                                                                                                                                                                                                               | `'auto'`           |
| **사용자 의도 액션** — `districtSelected` · `administrationSelected` · `serviceSelected` · `submitted`(사용자가 「상권 추천받기」를 누름) · `resultSelected` · `editRequested` · `cameraFollowRequested`(「선택 범위로 이동」 버튼) | `'url'` → `'auto'` |
| **데이터 액션** — `resultsLoaded` · `administrationNameResolved` · `administrationRejected` · 씨앗 자동 제출(`submitted` 에 `source: 'seed'`)                                                                                       | 유지               |
| **UI 액션** — `pickerOpened` · `pickerClosed` · `sheetSnapChanged`                                                                                                                                                                  | 유지               |
| 사용자가 지도를 직접 움직임                                                                                                                                                                                                         | 유지(`c` 만 갱신)  |

`'auto'` → `'url'` 로 되돌아가는 전이는 **없다.** 사용자가 지도를 움직여도 모드는 바뀌지
않는다 — 그 뒤 다른 상권을 고르면 그쪽으로 맞춰지는 기존 동작(B-3)을 유지한다. 대신 그
움직임은 `c` 에 그대로 실린다.

정리하면 이슈 #317 이 제시한 규칙 그대로다.

- **결과가 새로 오면 자동 맞춤이 이긴다** — 새 결과는 사용자 의도 액션(`submitted`)을
  거치므로 `'auto'` 다. 맞춰진 카메라가 `idle` 로 돌아와 `c` 에 거울로 실린다.
- **사용자가 지도를 움직이면 `c` 를 갱신한다.**
- **같은 결과가 복원될 때는 `c` 가 이긴다** — 링크 진입은 `'url'` 이라 복원 사슬의 자동
  맞춤이 전부 잠긴다.

「선택 범위로 이동」 버튼은 **모드와 무관하게 즉시 맞춘다**(사용자가 원한 것이다). 그
뒤 모드는 `'auto'` 가 된다(`cameraFollowRequested`). 맞출 대상이 `keep` 이면(결과 로딩 중)
아무 일도 하지 않고 **잠금도 풀지 않는다** — 아무 일도 안 일어난 버튼이 몇 초 뒤 결과 도착과 함께
화면을 옮기면 안 된다.

#### 왜 카메라 값을 리듀서에 넣지 않나

팬 한 번마다 리듀서가 바뀌면 화면 전체가 리렌더된다. 카메라는 **ref** 로 들고 URL 만
`replaceState` 로 쓴다(§2-1 과 같은 이유로 라우터를 흔들지 않는다).

⚠️ **씨앗은 ref 의 초기값으로도 쓴다.** 마운트 직후 거울이 상태만 보고 URL 을 다시 쓰면,
지도가 첫 `idle` 을 올리기 전에 `c` 를 **지워 버린다** — §4 「복원이 끝나기 전에는 쓰지
않는다」와 같은 함정이다. 조건 없는 `/recommend?c=…` 는 거울 잠금이 없어 마운트 즉시
거울이 도니 특히 그렇다.

`c` 는 거울 잠금(§4, `seededSubmitRef`)을 그대로 따른다 — 복원 중에는 어떤 값도 쓰지 않는다.

## 3. 이름은 URL 에 넣지 않는다

상태는 `{ code, name }` 을 들고 있지만 URL 은 **코드만** 나른다. 이름을 URL 에 실으면
카탈로그가 바뀔 때 링크가 옛 이름을 들고 되살아난다.

복원 시 이름을 어디서 얻는지가 셋 다 다르다.

| 조건   | 이름 출처                                    | 동기?     |
| ------ | -------------------------------------------- | --------- |
| 자치구 | `data/districts.ts` (정적 25개)              | ✅        |
| 업종   | `data/simulation-catalog.ts` (정적)          | ✅        |
| 행정동 | `GET /regions/districts/{d}/administrations` | ❌ 비동기 |

**행정동만 마운트 시점에 이름을 모른다.** 그래서 씨앗은 이름을 빈 문자열로 두고, 목록이
도착하면 채운다.

⚠️ **`readRecommendConditionName` 이 빈 문자열을 그대로 돌려준다**(`draft[step]?.name ?? null`
— `''` 는 `??` 를 통과한다). 그대로 두면 조건 바 조각이 **글자 없이 빈 채로** 그려진다.
빈 문자열도 `null` 로 보게 고친다 → 자리표시자(「행정동 선택」)가 나온다. 그 조각은 이미
`isAdministrationsLoading` 으로 잠겨 있어 그 사이 눌리지 않는다.

## 4. 복원할 수 없는 URL 을 만났을 때

링크는 오래 산다. 코드가 유효하지 않거나 서로 맞지 않는 조합이 온다.

| 상황                                          | 처리                                                                           |
| --------------------------------------------- | ------------------------------------------------------------------------------ |
| `districtCode` 가 25개 목록에 없다            | 조건 전체를 버리고 빈 화면. **부분 복원하지 않는다**                           |
| `administrationCode` 가 그 자치구 것이 아니다 | 행정동부터 버린다(자치구는 남긴다)                                             |
| `serviceCode` 가 카탈로그에 없다              | 업종만 버린다                                                                  |
| `view=results` 인데 조건이 덜 찼다            | `view` 를 버리고 조건 화면                                                     |
| `commercialCode` 가 결과에 없다               | 선택만 버린다. 결과 목록은 그대로(1위 자동 선택)                               |
| `view` 가 `results` 가 아닌 임의 값           | 없는 것으로 본다                                                               |
| `c` 가 토큰 3개가 아니거나 한국 좌표 범위 밖  | 카메라만 버린다(서울 기본 + `'auto'`). 조건은 영향 없음. 뷰 상태라 안내도 없다 |

**복원이 끝나기 전에는 URL 을 쓰지 않는다.** 마운트 직후 `view` 는 아직 `'criteria'` 라서,
그대로 반영하면 링크가 들고 온 `view=results`·`commercialCode` 를 주소창에서 **먼저 지운다.**
그 틈에 주소를 복사하거나 새로고침하면 결과·선택이 빠진 링크가 된다 — 공유받은 링크를 다시
공유하는 흔한 경로다.

**버린 것은 URL 에서도 지운다.** 상태 → URL 거울이 다음 `replace` 에서 정리하므로 별도 처리가
필요 없다 — 주소창이 화면과 어긋난 채 남지 않는다.

`administrationCode` 는 앞 5자리가 자치구 코드다(`resolveDistrictCodeFromAdministration`
이 이미 있다). **`districtCode` 없이 `administrationCode` 만 온 링크는 자치구를 유도해서
살린다** — 딥링크(D8-2)가 행정동만 넘길 수 있어서다.

## 4-1. 결과 복원은 1위 자동 선택과 부딪힌다 (실측)

`?commercialCode=` 를 별도 이펙트로 반영했더니 **`resultsLoaded` 와 순서를 다투다 1위가
덮어썼다.** 「3위를 보던 화면」 링크를 열면 1위가 펼쳐졌다(브라우저에서 확인).

두 이펙트를 하나로 합쳤다. `createResultsLoadedAction` 이 **링크가 지목한 상권을 우선**하고,
없거나 결과에 없으면 1위로 물러난다. 그때 `resultSelectionSource` 도 `'user'` 가 되어
URL 이 그 선택을 도로 지우지 않는다.

## 4-2. 행정동 이름은 `submitted` 에도 채워야 한다 (실측)

결과 헤더는 `draft` 가 아니라 **`submitted` 를 읽는다**(`recommend-panel.tsx`). URL 로 들어오면
이름을 모르는 채 제출되므로 `draft` 만 채웠더니 **결과 헤더의 행정동 칩이 빈 채로 남았다.**
`administrationNameResolved` 가 둘 다 채운다. 코드는 그대로라 `requestKey` 가 바뀌지 않고,
따라서 재요청도 일어나지 않는다.

## 4-3. 없는 행정동은 목록이 와야 걸러낼 수 있다 (이슈 #170-3, 해결됨)

§4 의 검증은 **앞 5자리 비교뿐**이라(`resolveDistrictCodeFromAdministration`) 자치구만 맞으면
`administrationCode=11680999` 같은 **없는 동이 통과한다.** 조건 바에는 자리표시자가 뜨는데
내부 상태에는 값이 있어 `getRecommendationStage` 가 `'commercial'` 로 넘어가고, 「현재
행정동에는 추천할 상권이 없어요」로 **없는 동을 있는 것처럼** 안내하는 막다른 화면이 됐다.

**파싱 시점에는 알 수 없다** — 행정동 목록은 API 로만 오기 때문이다(§3). 그래서 검증이
두 단계다.

| 시점                                    | 무엇을 본다                | 못 거르는 것            |
| --------------------------------------- | -------------------------- | ----------------------- |
| 파싱 (`parseRecommendUrlState`)         | 앞 5자리가 자치구와 맞는가 | 자치구는 맞지만 없는 동 |
| 목록 도착 후 (`administrationRejected`) | 그 코드가 목록에 있는가    | —                       |

⚠️ **목록이 「도착한 뒤」에만 판정한다.** 로딩 중에는 목록이 빈 배열이라, `isSuccess` 가드가
없으면 **멀쩡한 링크의 행정동을 즉시 버린다.** 네트워크 오류일 때도 버리지 않는다 — 일시적인
실패로 사용자의 조건을 지울 이유가 없다.

⚠️ **버려지면 씨앗 제출 잠금도 함께 풀어야 한다.** URL 거울은 복원이 끝날 때까지 잠겨
있는데(§4), 없는 동이면 자동 제출이 영영 일어나지 않아 그 잠금이 풀리지 않는다. 그러면
**주소창에 없는 동 코드가 그대로 남는다** — 증상의 절반이 이것이었다. 그래서 씨앗 비교가
널 검사보다 **먼저** 온다.

⚠️ **주소창은 화면이 하이드레이트된 뒤에야 정리된다.** 거울이 이펙트라 당연한 일이지만,
**탭이 백그라운드(`document.hidden`)면 React 스케줄러가 throttle 되어 하이드레이션이 아예
진행되지 않는다** — 그 사이 주소창에는 잘못된 코드가 그대로 남아 있다. 탭을 보는 순간
정리된다. 이슈 #170-1 의 「재현이 엇갈린다」는 **이것을 보고 있었다**(§2-1 의 세 방식이 모두
「엇갈린」 이유이기도 하다 — 셋 다 아직 실행되지 않았을 뿐이다). 브라우저로 검증할 때는
**URL 을 읽기 전에 화면을 한 번 그리게 하라.**

⚠️ **복원은 API 사슬을 타므로 즉시 끝나지 않는다** — 행정동 → 후보 상권 → 추천 → profile 이
순서대로 걸린다. dev 서버에서는 15~20초까지 걸렸다(콜드 컴파일 포함). 화면은 그동안 조건
화면을 보여 준다. 프로덕션에서 얼마나 걸리는지는 별도 확인이 필요하다.

### 8-1. 카메라 `c` (2026-09-11, dev 5173, #317)

Browser 패널이 **숨겨진 상태**(`document.hidden === true`)에서 검증했다 — 하이드레이션·API 사슬·
프로그래매틱 이동 뒤의 `idle` 은 모두 정상 동작했지만, 드래그·휠 제스처는 완료되지 않아 **사용자
팬·줌이 `c` 에 실리는 것은 프로그래매틱 이동(`setBounds`)의 `idle` 로 대신 확인**했다.

| 경우                                   | 링크 / 동작                                                        | 결과                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **`c` 링크 진입이 자동 맞춤을 이긴다** | `…&view=results&c=37.49,127.02,4`                                  | 결과 5건 도착·1위 자동 선택까지 지도가 `c` 에 그대로(level 4). 주소창 `c` 불변             |
| 「선택 범위로 이동」                   | 위 상태에서 버튼 클릭                                              | 즉시 결과 범위로 fit, 0.5초 안에 `c=37.49594,127.02691,5` 로 갱신(`idle` → 거울 경로 확인) |
