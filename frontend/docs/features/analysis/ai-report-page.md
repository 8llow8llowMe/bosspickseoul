# analysis — AI 리포트 전용 페이지(지표+AI 결합) 세부 명세서

> **작성일**: 2026-08-12
> **공통 명세**: [analysis 공통 명세](./analysis.md) · 관련: [ai-report](./ai-report.md)
> **대상**: 웹 (Next.js App Router)
> **작성자**: Claude Code
> **상태**: 초안 (설계 확정, 구현 계획 전 — 다음 스레드에서 writing-plans로 이어감)

AI 리포트가 지금은 **텍스트 서술만** 있고(사이드바 패널), 실제 지표·차트는 별도 "전체 분석 보기" 결과 페이지에 흩어져 있다. 이 둘을 합쳐 **"AI가 실제 데이터 위에서 정리해 준 리포트"**를 보여주는 **전용 페이지**를 만든다. 데이터는 빨리 오고 AI 서술은 느린 비대칭을 **2단 속도(two-speed) 점진 렌더링**으로 해소한다. **v1은 상권(commercial) 레벨만** 지원한다.

## D1. 기능 개요

```
상권+업종 선택(level=commercial, code, serviceCode)
  ├─ 빠른 층: 상권 데이터 쿼리(fetchCommercial*) → 핵심 지표 카드 + 엄선 차트 3개 즉시 렌더
  └─ 느린 층: useAiReport(SSE job) → AI 요약/강점/주의/추천 스트리밍 채움(도착 전 스켈레톤+진행 스테퍼)
  → 하단 "전체 데이터 분석 보기"로 기존 결과 페이지 위임
```

전용 페이지는 **정독용 목적지**다. 지도 위 **사이드바 AI 패널은 빠른 요약 미리보기로 유지**하고(진입 A), 사이드바의 primary CTA로 이 페이지에 들어온다.

### D1-1. UI 진입점 / 기능 연결

> **라우트/위치(신규)**: `app/(shell)/analysis/report/page.tsx`(가칭 — ⚠️ 구현 시 라우트명 `report` vs `ai-report` 확정). searchParams: `code`(상권코드), `serviceCode`(업종). 기존 `app/(shell)/analysis/result`와 형제.
> **진입**: 사이드바 `AiReportPanel` 푸터/헤더의 CTA "AI 리포트 보기" → 이 페이지. 링크 빌더는 `createAnalysisResultHref`(`src/lib/analysis/selection.ts:163`) 옆에 `createAiReportHref` 신설.
> **깔때기**: 사이드바(훑기) → 전용 리포트(정독) → "전체 데이터 분석 보기"(원본 덤프, 기존 결과 페이지).

| UI 요소                   | 사용자 동작 | 결과 / UI 반영                                                   |
| ------------------------- | ----------- | ---------------------------------------------------------------- |
| 사이드바 "AI 리포트 보기" | 클릭        | 전용 리포트 페이지로 이동(현재 선택 상권·업종 전달)              |
| 핵심 지표 카드            | (표시)      | 데이터 도착 즉시 채움. 도착 전 개별 스켈레톤                     |
| 엄선 차트 3개             | (표시)      | 데이터 도착 즉시 렌더(recharts)                                  |

## D3. 아키텍처 / 시스템 설계

### D3-1. 두 개의 독립 데이터 소스(2단 속도의 근거)

| 층           | 소스                                                                                                                                                                                 | 특성          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------- |
| 빠른(데이터) | 상권 데이터 REST 쿼리(react-query): `fetchCommercialSalesSummary`, `fetchCommercialFootTraffic`, `fetchCommercialSales`, `fetchCommercialPopulation`, `fetchCommercialTrend`(성장률) | 즉시성 높음   |
| 느린(AI)     | `useAiReport({ level:'commercial', code, serviceCode, active, enabled })` — 제출 POST → SSE job → 폴링 폴백                                                                          | 수 초~수십 초 |

두 소스는 **서로 기다리지 않는다**. 페이지 골격은 즉시 그리고, 각 영역이 자기 소스 상태에 따라 독립적으로 채워진다.

### D3-2. 재사용 / 신규

| 구분   | 대상                                                                                                                                                                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 재사용 | 차트: `LineChart`/`BarChart`/`PopulationPyramid`(`src/components/analysis/charts/*`, `height` prop 지원). 변환: `toTrendPoints`/`toPyramidRows`(`src/lib/analysis/chart-data.ts`). 데이터 페처: `fetchCommercial*`(결과 뷰가 쓰는 것과 동일). AI: `useAiReport`·`ai-report-presentation`(뷰 변환)·`AiReportLockCard`. 인증: `useAuthStore` |
| 신규   | `app/(shell)/analysis/report/page.tsx`(라우트 셸, searchParams 파싱). `ai-report-page-view.tsx`(2단 레이아웃 오케스트레이션). 리포트 프리젠테이션 컴포넌트: 지표 카드 행, 차트 큐레이션 블록, AI 인사이트 블록(강점/주의/추천 색상 카드), 진행 스켈레톤·스테퍼. `createAiReportHref`(selection.ts).                                        |

> **매핑 참조(⚠️ 구현 시 확정)**: 각 상권 페처 응답 → 차트 데이터로의 변환은 이미 `analysis-result-view.tsx`(대략 L1289~1500: 시간대별 매출 Line, 요일별 유동인구 Bar, 연령·성별 유동인구 Pyramid)에서 수행한다. 그 매핑을 추출/공유(작은 셀렉터 함수)해 리포트와 결과 뷰가 같은 변환을 쓰게 한다 — 로직 중복 금지.

### D3-3. 클라이언트 경계

- 페이지 셸(`page.tsx`)은 서버 컴포넌트로 searchParams만 읽고, 데이터·AI·차트가 필요한 뷰 본체는 `'use client'`.
- SSR 초기엔 골격(헤더/섹션 틀 + 스켈레톤)만 렌더, 클라이언트에서 쿼리·SSE 채움.

## D4. 상호작용 / 상태 설계

| 영역        | 상태 소유                              | 로딩 표현                                                                                                  |
| ----------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 지표 카드   | 각 상권 쿼리(react-query)              | 카드별 스켈레톤 → 값                                                                                       |
| 차트 3개    | 각 상권 쿼리 + `hasLineData` 등 빈검사 | 차트별 스켈레톤/"데이터 없음"                                                                              |
| AI 인사이트 | `useAiReport` → `AiReportState`        | loading(stage/progressMessages)→스테퍼+스켈레톤; ready-commercial→요약/강점/주의/추천; error→재시도; empty |

- 부분 실패 격리: 한 쿼리 실패가 페이지 전체를 막지 않는다(D2-9).
- AI 재시도: 기존 `useAiReport` `retry()` 노출.
- 레이아웃 점프 최소화: AI 블록은 도착 전에도 최소 높이 확보(스켈레톤이 최종 형태 근사).

## D5. 데이터 / 콘텐츠 (큐레이션 확정)

**헤더**: `상권명 · 업종명` + AI 한 줄 종합(`headline.summary`, 도착 전 스켈레톤) + "데이터 준비됨" 배지.

**핵심 지표 카드(4, 빠름)**:

| 카드              | 소스                                    |
| ----------------- | --------------------------------------- |
| 월 매출           | `fetchCommercialSalesSummary`           |
| 유동인구          | `fetchCommercialFootTraffic`(요약치)    |
| 점포 수(경쟁)     | `fetchCommercialStores`/summary         |
| 매출 변화(성장률) | `fetchCommercialTrend`(sales) 방향/증감 |

**차트 큐레이션(3, 빠름)**:

| 차트               | 컴포넌트            | 의미          |
| ------------------ | ------------------- | ------------- |
| 시간대별 매출      | `LineChart`         | "언제 파나"   |
| 요일별 유동인구    | `BarChart`          | "언제 붐비나" |
| 연령·성별 유동인구 | `PopulationPyramid` | "누가 오나"   |

**AI 인사이트(느림, 스트리밍)** — `toCommercialReportView` 뷰 사용:

- 종합 요약(`headline.summary`) + 인사이트(`headline.insight`)
- **강점**(`strengths[]`, 긍정색 카드) / **주의**(`risks[]`, 경고색 카드)
- 추천 업종군 · 고객층 · 영업시간(`actions[]`, 칩)

**푸터**: "전체 데이터 분석 보기" → `/analysis/result?...`.

> 카피 톤: 예비 창업자 대상 한국어. 수치는 대표 예시가 아니라 **실데이터**(사이드바 미니데모의 "대표 예시"와 구분). `DESIGN.md` 준수.

## D6. 접근성 / 비기능 요구

## D7. 성능

- 빠른 층 쿼리는 병렬(react-query), 각자 도착 즉시 렌더. AI SSE는 기존 훅 그대로(추가 연결 없음).
- 차트는 활성 영역만. `height` prop로 리포트 맥락에 맞게 축소.
- 스켈레톤으로 CLS(레이아웃 점프) 억제.

## D8. 테스트

- 큐레이션 셀렉터(페처 응답→차트 데이터) 순수 변환 단위테스트(빈/경계).
- `createAiReportHref` 단위테스트(selection.ts 패턴).
- 페이지 뷰 SSR 렌더: 골격·섹션 제목·스켈레톤 존재.
- 2단 상태 렌더 테스트: 데이터 도착+AI loading 동시 상태에서 "차트는 있고 AI는 스켈레톤".
- 인증 분기: 비로그인 시 AI 영역 잠금 카드.
- reduced-motion 분기(전환 제거).

## 열린 결정 (구현 착수 시 확정)

1. 라우트명: `analysis/report` vs `analysis/ai-report`. (기존 `result`와 톤 맞춤 권장)
2. 비로그인 시 데이터 차트도 가릴지, AI 영역만 잠글지.
3. 지표/차트 각 페처 응답의 정확한 필드→표시 매핑: `analysis-result-view.tsx`의 기존 변환을 셀렉터로 추출해 공유(중복 방지).
4. "성장률" 지표의 계산 소스(`fetchCommercialTrend` sales 방향 or salesSummary 증감).
