# 시뮬레이션 「한 번에 한 단계」 전환 — 실측 결과

> **작성일**: 2026-09-08
> **대상**: `/simulation`, `/analysis/simulation`
> **연관 코드**: `src/lib/simulation/step-flow.ts`(`resolveOpenSection`), `src/lib/simulation/conditions.ts`(`SIMULATION_CONDITION_SECTIONS`), `src/components/simulation/simulation-builder-page.tsx`
> **연관 명세**: [simulation.md](./simulation.md) S3 #2, `simulation-report.md` D4-1-1

이 문서는 D4-1-1(「한 번에 한 단계」 전환)이 실제 화면에서 동작하는지 세 폭에서 실측한 기록이다.
측정 스크립트는 다음을 각 상태마다 `main` 기준으로 읽는다.

```js
const main = document.querySelector('main')
JSON.stringify({
  vw: window.innerWidth,
  pageH: Math.round(document.documentElement.scrollHeight),
  buttons: main.querySelectorAll('button').length,
  expanded: main.querySelectorAll('[aria-expanded="true"]').length,
})
```

측정은 dev 서버(`rm -rf .next && PORT=5173 pnpm dev`, 실제 포트 5173)에서 개인 창업 흐름을 기준으로 진행했다.
프랜차이즈 흐름은 별도로 한 줄만 남긴다(아래 참고).

## 측정 방법상의 주의 — 375px 에서 `scrollHeight`가 신뢰할 수 없었다

375×812 에서는 페이지 이동 직후 `document.documentElement.scrollHeight`가 실제 콘텐츠 높이보다
훨씬 작은 값(뷰포트 높이와 같은 812)을 돌려주는 경우가 반복 관찰됐다. 같은 순간
`offsetHeight`를 함께 재거나 몇 차례 폴링하면 실제 값(예: 1228)으로 수렴했다 — 하이드레이션이
완전히 끝나기 전에 읽으면 생기는 값으로 보인다(`CLAUDE.md`가 경고하는 "숨겨진 pane 에서는
하이드레이션이 안 돈다"와 같은 계열의 함정). 아래 375 표의 `pageH`는 이 폴링으로 안정화된 값만
신뢰값으로 적었고, 안정화에 실패한 항목은 **미검증**으로 남겼다.

세션 후반에는 브라우저 pane 자체가 클릭 입력을 받지 않는 상태(`computer` 액션이 30초 타임아웃)로
빠졌다. 이 때문에 375 폭에서는 시나리오 2·3·4(클릭으로 조건을 바꾸는 시나리오)를 라이브로
재현하지 못했다. 아래 표와 시나리오 절에 그 사실을 명시했다.

| 단계                                          | pageH                                           | buttons | expanded |
| --------------------------------------------- | ----------------------------------------------- | ------- | -------- |
| 빈 상태                                       | 1228 (폴링으로 안정화 확인)                     | 7       | 1        |

| 개인 창업 선택 이후 전체 흐름(시나리오 2·3·4) | 미검증 — 클릭 입력 불가로 세션 후반 재현 못함   | —       | —        |

375에서 확인한 두 상태 모두 `expanded`는 1을 넘지 않았다. 나머지 단계의 수치는 **미검증**이다 —
클릭 상호작용이 막힌 뒤로는 화면을 전이시킬 수 없었다. 다만 `resolveOpenSection`은 순수 함수이고
`step-flow.test.ts`가 이 전이 규칙(빈 상태 진입, 앞이 채워진 상태에서 프리필, 재편집 중 사용자 의사
우선, 무효화 연쇄로 인한 재오픈)을 전부 단위 테스트로 고정해 뒀다. 레이아웃은 폭마다 CSS만
다르고 이 로직은 폭과 무관하게 호출되므로, 1440·1024에서 동일하게 재현된 시나리오가 375에서만
다르게 동작할 구조적 이유는 없다 — 그러나 이는 정황 근거이지 375 자체의 실측은 아니다.

## 다섯 시나리오

기준: 개인 창업, 강남구 → 강동구, 한식음식점 → 편의점.

| #   | 시나리오                                                                         | 1440                                                          | 1024                                                                           | 375                                                     |
| --- | -------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------- |
| 1   | 빈 상태 → 1단계(창업 형태)가 열려 있다                                           | 확인                                                          | 확인                                                                           | 확인                                                    |
| 2   | 끝까지 고른다 → 전부 접히고 금액이 뜬다                                          | 확인(3,738만원 렌더)                                          | 확인(전부 접힘, `계산하기` 활성화까지 확인 — 클릭 결과 화면은 1440에서만 확인) | 미검증                                                  |
| 3   | 「자치구」 줄을 눌러 다른 구를 고른다 → 나머지 세 단계가 완료 상태를 유지한다    | 확인(업종·매장 조건 값 유지, 완료 배지 유지)                  | 확인                                                                           | 미검증                                                  |

| 5   | `/analysis/simulation`에서 진입 → 채워진 단계는 접혀 있고 첫 빈 단계가 열려 있다 | 확인(자치구·업종 프리필 + 컨텍스트 배너, 창업 형태 열림)      | 확인                                                                           | 확인(스크린샷으로 시각 확인, 수치는 buttons/expanded만) |

추가로 다음도 1440에서 확인했다(완료 기준 항목):

- 잠긴 매장 조건 단계는 업종 선택 전에는 `<h2>`가 `<section>` 안에 있을 뿐 `<button>`이 아니다(DOM 조사로 확인, 폭 무관).
- 자치구·업종 검색창에 문자를 입력해 목록을 좁힌 뒤, 그 단계를 벗어났다가 다시 열면 검색어가 비어 있고 전체 목록이 다시 보인다(1440에서 확인). 1024·375에서는 별도로 재확인하지 않았다 — **미검증**.
- `SIMULATION_CONDITION_SECTIONS`는 여전히 `franchise/district/service/store` 4개의 `as const` 배열이다(코드 확인, 가변 아님).

### 프랜차이즈 흐름 (별도 기록)

프랜차이즈 흐름은 이번 세션에서 클릭으로 재현하지 못했다(위 도구 문제로 개인 창업 흐름을 진행한
뒤 클릭이 막혔다). 코드(`conditions.ts`)로 확인한 구조만 남긴다: 프랜차이즈를 선택하면 업종 섹션의
완료 조건에 브랜드 선택(`franchiseeId`)이 추가되고, 업종 섹션 안에 브랜드 검색 UI가 나타나며,
업종을 바꾸면 브랜드 선택도 함께 초기화된다 — 별도 섹션이 아니라 업종 섹션에 종속된 흐름이다.
**라이브 클릭 검증은 미검증.**
