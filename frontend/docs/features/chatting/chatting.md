# chatting — 공통 개발 명세서

> **작성일**: 2026-07-28
> **대상**: 웹 (Next.js App Router)
> **상태**: 안전 대기 구현 · V2 백엔드 계약 대기

## S0. 배경 / 계약 점검

레거시 프런트에는 채팅방 REST 호출, STOMP 실시간 메시지, Firebase Cloud
Messaging 연동 코드가 이관되어 있지만 현재 V2 백엔드에는 chat-service와 관련
Controller가 없다. Gateway, Swagger, WebSocket destination 계약도 확인되지
않는다.

| 영역                  | 기존 프런트 추정 계약                           | V2 계약 | 처리                    |
| --------------------- | ----------------------------------------------- | ------- | ----------------------- |
| 채팅방 목록·상세      | `/chat-rooms/**`                                | 미제공  | 네트워크 호출 차단      |
| 채팅방 생성·입장·퇴장 | `/chat-rooms/**`                                | 미제공  | 실행 UI 차단            |
| 과거 메시지           | `/chat-rooms/{id}/messages`                     | 미제공  | 네트워크 호출 차단      |
| 실시간 메시지         | `/topic/public/rooms/{id}`, `/app/message/{id}` | 미제공  | STOMP 연결 차단         |
| 푸시 알림             | `/firebase/message/**`                          | 미제공  | FCM 토큰·구독·전송 차단 |

## S1. 목표 동작

채팅 라우트의 인증 정책과 유효한 동적 라우트 검증은 유지한다. 로그인 사용자가
접근하면 현재 기능이 V2 계약 준비 중임을 확인하고 커뮤니티나 홈으로 이동할 수
있다. 백엔드 계약이 없는 동안 REST, WebSocket, FCM 요청은 보내지 않는다.

## S2. 공통 요구사항

1. `/chatting/list`, `/chatting/[roomId]`는 기존 보호 경로 정책을 유지한다.
2. 숫자가 아닌 roomId 또는 0 이하 roomId는 404로 처리한다.
3. 두 라우트에서 레거시 채팅 컴포넌트를 import하지 않는다.
4. 대기 화면은 채팅방·메시지·실시간 연결·알림 계약이 선행 조건임을 안내한다.
5. `/community/list`와 `/` 이동 링크를 제공한다.
6. 모바일과 데스크톱에서 가로 스크롤 없이 표시한다.

## S3. 제외 범위 / 백엔드 선행 조건

- 채팅방 목록, 검색, 인기 채팅방
- 채팅방 생성, 입장, 퇴장, 인원 제한
- 메시지 히스토리와 커서 페이지네이션
- STOMP 인증, 구독, 발행, 재연결, 중복 메시지 처리
- FCM 토큰 저장, topic 구독·해제, 푸시 수신
- 메시지 신고·차단·관리 정책

위 기능은 REST Swagger, STOMP destination/payload/auth, FCM 보안 책임과
Gateway 라우팅이 확정된 뒤 별도 PR로 구현한다.
