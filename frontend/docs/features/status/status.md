## S1. 기능 개요

서울 25개 자치구를 **유동인구·매출·개업·폐업** 네 지표로 각각 Top 10 순위와 지도로 보여
주고, 자치구 하나를 고르면 그 자치구의 상세 현황(유동인구 분포·점포·매출)을 같은 화면에서
펼친다. 사용자는 「어디를 볼지 아직 모르는」 상태에서 출발해 자치구 하나로 좁힌 뒤,
상세 안의 업종·행정동 항목을 눌러 `/analysis` 로 넘어간다.

```
GET /districts/top-ten → 지표별 Top10 정규화 → 탭·지도·목록 렌더
  → 자치구 선택(URL ?district=) → GET /districts/{code} → 상세 렌더
    → 상세의 업종·행정동 항목 → /analysis 로 이동
```

## S4. 세부 명세

**세부 명세**

- [district-detail-links](./district-detail-links.md) — 통합 상세 응답이 이미 주는데 화면이
  안 쓰던 필드 6개(개업률·폐업률·매출증감률 + 행정동·업종 코드)를 **새 호출 0회로** 연결한다

### 백엔드 계약 (실측)

| 호출                     | 언제           | 응답                                           |
| ------------------------ | -------------- | ---------------------------------------------- |
| `GET /districts/top-ten` | 진입 시 1회    | 네 지표의 Top10 배열 (`DistrictTopTenSummary`) |
| `GET /districts/{code}`  | 자치구 선택 시 | 그 자치구의 **통합 상세**                      |

> **인벤토리의 「B3 자치구 상세 지표 5종 미연동」은 오류였다.** `/status` 는 통합 상세를
> 이미 쓰고 있고, 5종은 그 분할 변형이다. 엔드포인트 단위로 세면 이렇게 통합 쪽을 쓰는
> 화면이 분할 쪽을 「미연동」으로 만든다(엔드포인트 인벤토리 정정 이력 2026-09-03).

### 어댑터 — 홈과 공유하는 정본

`lib/status/status-adapter.ts` 의 `normalizeStatusTopTen` 은 응답을 `StatusRankedItem[]`
네 벌로 정규화한다. **이 화면만 쓰는 것이 아니다** — 홈의 「지금 많이 본 지역」과 지표
랭킹 보드가 같은 함수를 쓴다. 그래서 여기 한 곳의 방어가 두 화면을 함께 지킨다:

```ts
footTraffic: toRankedItems(source.footTrafficTopTenItems ?? [], ...)
//                                                          ^^^^^
// 백엔드가 200 을 주면서 배열을 통째로 누락시킬 수 있다. `?? []` 가 없으면
// `.slice()` 가 렌더 중 TypeError 로 죽는다.
```

**홈에 새 포맷팅 계층을 만들지 않는다**는 결정이 여기서 나온다(`home.md` 참조).

### 지도는 Kakao 가 아니다

`/analysis` 와 달리 이 화면의 지도는 **정적 인라인 SVG**다(`@/data/seoul-status-map` 의
`SEOUL_STATUS_FEATURES` + `viewBox`). 자치구 경계는 변하지 않고 상호작용도 선택뿐이라
지도 SDK 를 띄울 이유가 없다 — 그 덕에 이 화면은 지도 스크립트 로딩·API 키에 의존하지
않는다. **검증 시 `/analysis` 계열과 같은 함정(표시된 pane 필요)을 겪지 않는 이유**다.

### 모바일 시트의 높이 규칙

```
접힘   = 52px (STATUS_SHEET_COLLAPSED_HEIGHT)
펼침   = min(뷰포트 * 0.6, 뷰포트 - 290)   ← 290 = 지도 최소 몫
```

지도를 **상단 정렬**로 두고 시트를 기본 「펼침」으로 연다. 남는 빈 공간이 지도 위가 아니라
시트가 올라오는 하단에 모이게 하려는 배치다.

## S5. 테스트케이스

| TC     | 검증 내용                                    | 기대 결과                                                      |
| ------ | -------------------------------------------- | -------------------------------------------------------------- |
| ST-001 | `/status` 진입                               | 유동인구 탭이 기본 선택, Top10·지도가 함께 뜬다                |
| ST-002 | 지표 탭 전환                                 | 목록·지도가 그 지표로 바뀌고 **선택된 자치구는 해제**된다      |
| ST-003 | 탭에서 좌우·Home·End 키                      | 포커스가 순환 이동하고 그 탭이 선택된다                        |
| ST-004 | 자치구 선택                                  | `?district=` 가 붙고 상세가 뜬다                               |
| ST-005 | `?district=` 가 붙은 URL 로 직접 진입        | 그 자치구가 선택된 화면이 재현된다                             |
| ST-006 | 현재 지표 Top10 에 없는 `?district=` 로 진입 | 조용히 정규화돼 선택 없음 상태가 된다(오류 화면을 내지 않는다) |
| ST-007 | Top10 응답의 배열 일부가 누락된 200 응답     | 그 지표만 비고 화면은 죽지 않는다                              |
| ST-008 | Top10 호출 실패 (5xx / 통신 실패)            | 오류 안내 + **재시도 버튼**                                    |
| ST-009 | Top10 호출 실패 (4xx)                        | 오류 안내, **재시도 버튼 없음**                                |
| ST-010 | 모바일(<768) 진입                            | 지도 상단 고정 + 바텀시트. 지도 몫 290px 이 확보된다           |
| ST-011 | 모바일에서 지도 배경 탭                      | 시트가 접힘/펼침으로 토글된다                                  |
| ST-012 | 상세의 업종·행정동 항목 클릭                 | **새 호출 없이** `/analysis` 로 이동한다                       |
| ST-013 | 데스크톱·태블릿·모바일 진입                  | 가로 스크롤 없음, 페이지 세로 스크롤 없음                      |

> ST-002 의 「선택 해제」는 의도한 동작이다. 지표가 바뀌면 Top10 구성이 통째로 달라져
> 선택이 유지될 근거가 없다(`handleMetricChange` 가 `district` 를 null 로 민다).
