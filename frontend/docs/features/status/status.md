## S1. 기능 개요

서울 25개 자치구를 **유동인구·매출·개업·폐업** 네 지표로 각각 Top 10 순위와 지도로 보여
주고, 자치구 하나를 고르면 그 자치구의 상세 현황(유동인구 분포·점포·매출)을 같은 화면에서
펼친다. 사용자는 「어디를 볼지 아직 모르는」 상태에서 출발해 자치구 하나로 좁힌 뒤,
상세 안의 업종·행정동 항목을 눌러 `/analysis` 로 넘어간다.

```
기준 분기(URL ?periodCode=, 기본 최신 분기)
  → GET /districts/top-ten?currentPeriodCode= → 지표별 Top10 정규화 → 탭·지도·목록 렌더
  → 자치구 선택(URL ?district=) → GET /districts/{code}?currentPeriodCode= → 상세 렌더
    → 상세의 업종·행정동 항목 → /analysis 로 이동
```

## S4. 세부 명세

**세부 명세**

- [district-detail-links](./district-detail-links.md) — 통합 상세 응답이 이미 주는데 화면이
  안 쓰던 필드 6개(개업률·폐업률·매출증감률 + 행정동·업종 코드)를 **새 호출 0회로** 연결한다

### 백엔드 계약 (실측)

| 호출                                        | 언제                  | 응답                                           |
| ------------------------------------------- | --------------------- | ---------------------------------------------- |
| `GET /districts/top-ten?currentPeriodCode=` | 진입·분기 변경 시 1회 | 네 지표의 Top10 배열 (`DistrictTopTenSummary`) |
| `GET /districts/{code}?currentPeriodCode=`  | 자치구·분기 선택 시   | 그 자치구의 **통합 상세**                      |

- 두 호출 모두 `currentPeriodCode`(YYYYQ)를 **늘 명시해서 보낸다.** 백엔드 기본값(`AnalysisPeriodDefaults.PERIOD_CODE`)에
  기대지 않는다 — 이 파라미터를 안 보내던 동안 백엔드 기본값이 `20233` 이라 화면이 2023년 3분기에 묶여 있었다(#409).
- `previousPeriodCode` 는 보내지 않는다. 생략하면 백엔드가 **직전 분기**를 비교 기준으로 쓴다(변화율의 기준).

> **인벤토리의 「B3 자치구 상세 지표 5종 미연동」은 오류였다.** `/status` 는 통합 상세를
> 이미 쓰고 있고, 5종은 그 분할 변형이다. 엔드포인트 단위로 세면 이렇게 통합 쪽을 쓰는
> 화면이 분할 쪽을 「미연동」으로 만든다(엔드포인트 인벤토리 정정 이력 2026-09-03).

### 어댑터 — 홈과 공유하는 정본

`lib/status/status-adapter.ts` 의 `normalizeStatusTopTen` 은 응답을 `StatusRankedItem[]`
네 벌로 정규화한다. **이 화면만 쓰는 것이 아니다** — 홈의 「지금 많이 본 지역」과 지표
랭킹 보드가 같은 함수를 쓴다. 그래서 여기 한 곳의 방어가 두 화면을 함께 지킨다:

```ts
footTraffic: toRankedItems(source.footTrafficTopTenItems ?? [], ...)
//                                                          ^^^^^
// 백엔드가 200 을 주면서 배열을 통째로 누락시킬 수 있다. `?? []` 가 없으면
// `.slice()` 가 렌더 중 TypeError 로 죽는다.
```

**홈에 새 포맷팅 계층을 만들지 않는다**는 결정이 여기서 나온다(`home.md` 참조).

### 지도는 Kakao 가 아니다

`/analysis` 와 달리 이 화면의 지도는 **정적 인라인 SVG**다(`@/data/seoul-status-map` 의
`SEOUL_STATUS_FEATURES` + `viewBox`). 자치구 경계는 변하지 않고 상호작용도 선택뿐이라
지도 SDK 를 띄울 이유가 없다 — 그 덕에 이 화면은 지도 스크립트 로딩·API 키에 의존하지
않는다. **검증 시 `/analysis` 계열과 같은 함정(표시된 pane 필요)을 겪지 않는 이유**다.

### 선택은 지표와 무관하다

`?district=` 는 **서울 25개 구 코드면 유효**하다(`normalizeStatusSelection`). 예전에는 현재
지표 Top10 에 든 구만 남겨서 두 가지가 불편했다 — 순위 밖 15개 구는 지도에서 눌러도 반응이
없었고, 지표 탭을 바꾸면 보던 구가 새 Top10 에 없다는 이유로 선택이 풀렸다. 상세
(`GET /districts/{code}`)는 구 단위라 지표와 상관이 없다.

- 순위 밖 구도 고를 수 있다. 상세 머리에 값 대신 「{지표} 상위 10위 밖」을 적는다. Top10
  응답만으로는 그 구의 지표 값을 알 수 없어서다(새 호출을 만들지 않는다).
- 지표를 바꿔도 선택·시트 높이를 유지한다. 상세 머리의 값·변화율·「{지표} N위」만 바뀐다.
- 선택 구의 모양은 `resolveStatusSelectedDistrict` 가 만든다(`rankedItem` 이 null 일 수 있다).

### 지도 라벨은 중심에서 움직이지 않는다

예전에는 순위 라벨이 겹치면 다른 자리로 **밀어내고** 점선으로 원래 구에 이었다. 충돌 상자를
375px 화면 기준으로 잡아 800×620 좌표에서 142×110 이나 됐고, 라벨이 이웃 구 너머로 밀려났다
(매출 탭에서 「중구 7」이 은평구 위, 「용산구 9」가 관악구 아래). 점선은 거의 보이지 않았다.

이제 라벨은 폴리곤 중심에 고정하고, 겹치면 **옮기지 않고 줄인다**(`resolveStatusMapLabelModes`).

| 모드      | 모양             | 언제                                                 |
| --------- | ---------------- | ---------------------------------------------------- |
| `full`    | ① 강남구 (한 줄) | 기본                                                 |
| `stacked` | ① 위, 이름 아래  | 더 높은 순위 라벨과 가로로 겹칠 때(강남구 옆 송파구) |
| `badge`   | ① 만             | 두 줄로도 겹칠 때. **순위 점은 절대 지우지 않는다**  |
| `hidden`  | 없음             | 순위 없는 구 이름이 순위 라벨에 깔릴 때              |

- 높은 순위부터 자리를 잡는다. 결정적이다.
- 모드는 지도 폭 두 등급(narrow ≤460px / wide)마다 따로 정하고 `@container` 로 고른다. 등급의
  **가장 좁은 폭**(narrow 343px · wide 461px)으로 판정한다. 컨테이너는 캔버스가 아니라 지도
  뷰포트다 — 캔버스가 넓어도 높이에 막혀 지도가 좁게 그려질 수 있다.
- 폴리곤 25개가 `role="button"` 이고 Tab 으로 닿는다(홈 지도와 같은 방식). 라벨 층은
  `aria-hidden` 이다 — 폴리곤의 접근성 이름에 순위·값이 이미 들어 있다.
- hover(마우스)·키보드 포커스(`:focus-visible`)에 툴팁을 띄운다. 터치 탭에는 띄우지 않는다 —
  탭 뒤에 남은 툴팁이 지도를 가린다.

### 데스크톱 상세는 목록을 덮는다

1024px 이상은 좌측 열 + 우측 지도 2단이다(1.4 전에는 768px 부터였다). 예전에는 자치구를 고르면 **지도 자리**가
상세로 바뀌어 방금 누른 폴리곤이 사라졌고, 다른 구로 옮기려면 상세를 닫고 다시 골라야 했다.
이제는 상세가 **Top10 목록 자리**를 덮고 지도는 그대로 남아 선택 구를 강조한다(모바일 시트의
Top10 → 상세, 상권추천 좌측 패널과 같은 관용구).

- 좌측 열 폭: **목록일 때와 상세일 때 같다** — `clamp(340px, 32%, 440px)`. 예전엔 선택하면 280px → 최대
  480px 로 넓어져 지도가 통째로 다시 배치됐다. 방금 누른 구를 눈으로 다시 찾아야 했다.
- 상세 차트의 2열 전환은 뷰포트가 아니라 **상세 자신의 폭**(`@container (min-width: 640px)`)으로 정한다.
  좌측 열로 옮긴 뒤로는 뷰포트 768px 기준이 맞지 않는다.
- 상세 헤더는 닫기(X) 대신 「상위 10개로 돌아가기」(←) 하나다.
- 포커스: 목록 버튼으로 상세를 열면 그 버튼이 숨겨져 포커스가 떨어진다 → 상세의 뒤로가기로 옮긴다.
  뒤로가기로 닫으면 방금 보던 자치구의 목록 버튼으로 돌려준다. **포커스를 잃은 경우에만** 옮기므로
  지도 폴리곤을 눌러 연 경우·링크로 진입한 경우에는 포커스를 건드리지 않는다.

### 화면 골격 — 좌측 패널이 조종석, 지도가 주인공 (1.3)

예전에는 머리말(eyebrow·h1·설명문, 세로 약 130px)과 페이지 폭 전체를 쓰는 지표 칩 카드가
지도·목록 위를 차지했다. 칩 4개는 카드 왼쪽에 몰려 있고 선택 상태는 옅은 테두리뿐이었다.

- **머리말을 걷어낸다.** h1 은 좌측 패널 머리의 한 줄(「구별 상권 현황」)로 옮긴다. 모바일은
  h1 을 시각적으로 숨기고(스크린리더·검색엔진용으로 남긴다) 지표 전환이 맨 위에 온다.
- **지표 전환은 세그먼트 컨트롤이다**(DESIGN.md 「Segmented control for section switching」).
  네 칸이 같은 폭으로 패널 머리를 채우고, 선택 칸은 흰 바탕 + 그림자로 떠오른다. 키보드는
  기존 탭 규칙(좌우·Home·End, roving tabindex) 그대로다.
- **지표 전환은 목록·상세 모두 위에 늘 보인다.** 상세를 보는 중에도 지표를 바꿀 수 있어야
  「선택은 지표와 무관하다」가 의미가 있다. 그래서 전환은 좌측 열의 **고정 머리**이고, 그 아래
  한 칸을 목록 ↔ 상세가 번갈아 쓴다. 좌측 열은 카드 하나다(상세가 카드 안의 카드가 되지 않게
  상세 자신의 테두리는 지운다).
- tablist 는 DOM 에 하나만 둔다(탭 id 가 겹치지 않게). 데스크톱·모바일 배치는 grid 영역으로 바꾼다.

### Top10 은 카드가 아니라 행이다 (1.3)

카드 10개를 각각 테두리로 감싸 한 화면에 6개 남짓만 보였다. 구분선 행 10개로 바꿔 한 화면에
다 들어오게 한다(토스 증권 목록과 같은 구조).

| 칸     | 내용                                |
| ------ | ----------------------------------- |
| 순위   | 숫자만(배지·색 없음)                |
| 이름   | 구 이름                             |
| 오른쪽 | 값(위) · 증감(아래, 글자색과 ▲▼ 만) |

- 1위 대비 막대는 뺀다. 크기 비교는 지도 단계 색이 맡는다.
- 행에 마우스를 올리면 지도의 그 구가 강조되고 툴팁이 뜬다. 지도에서 구를 가리키면 목록의 그
  행이 강조된다(목록 ↔ 지도 hover 연동).

### 색 하나에 뜻 하나 (1.3)

| 색          | 뜻                                                                  |
| ----------- | ------------------------------------------------------------------- |
| 파랑(단계)  | 지도에서 순위 — 진할수록 높다                                       |
| 파랑(선명)  | 선택                                                                |
| 초록 / 빨강 | 증감이 **좋은 쪽 / 나쁜 쪽**(`--color-positive`·`--color-negative`) |
| 회색        | 순위 밖, 변동 없음                                                  |

- 예전에는 초록이 「1–3위 배지」이면서 「증가」였고, 감소는 주황이었다. 1–3위 초록 배지를 없애고
  감소는 DESIGN.md 대로 빨강이다.
- **폐업은 방향을 뒤집는다.** 폐업 증가는 빨강(나쁨), 감소는 초록이다. 폐업 증가를 초록으로
  칠하면 「좋다」로 읽힌다. 상세 머리 칩·목록이 같은 규칙(`getStatusChangeTone`)을 쓴다(지도 툴팁은 색 없는 평문).

> **증감 글자 대비 — 1.5 에서 해소.** 증감은 글자색 + ▲▼ 로만 전하는데, 1.3 에서는 글자에
> green500·red500 을 그대로 써 흰 바탕 2.77:1 / 3.71:1 로 AA(4.5) 미달이었다. 이제 글자용
> `--color-positive-text`·`--color-negative-text`(green700·red700, 5.36 / 5.27:1)를 쓴다
> ([contrast-tokens](../layout/contrast-tokens.md) D3-3). 상세 머리 칩은 색을 틴트·테두리(면적)에만
> 써 면적 토큰 그대로다. 선택 중 흐려진 순위 밖 라벨(약 2.7:1)은 의도적으로 뒤로 물린 것이라 기록만 한다.

### 지도 단계 색 (1.3)

Top10 을 순위 두 칸씩 다섯 단계로 칠한다(1–2위 가장 진함 … 9–10위 가장 옅음). 순위 밖은 회색이다.
지도 왼쪽 위(서울 윤곽 밖이 가장 넓게 비는 자리)에 범례를 둔다.

- **값이 아니라 순위로 나눈다.** Top10 응답에는 10개 구의 값만 있어 25개 구를 값으로 칠할 수
  없고, 10개 안에서 값으로 나누면 1위 한 곳만 진하고 나머지가 비슷해지는 경우가 많다.
- 색은 새 토큰 없이 `color-mix(primary-600, surface)` 비율로 만든다(기존 관용구).
- 선택하면 나머지 구를 흐리게 낮춰 선택 구에 눈이 가게 한다.
- hover 는 채움을 바꾸지 않고 테두리만 강조한다 — 단계 색 위에서 채움을 바꾸면 순위를 오독한다.

### 태블릿 세로도 지도 + 시트 (1.4)

768~1023px 은 좌측 열(340px) + 지도 2단이었다. 좌측 열을 빼면 지도 폭이 약 340px 이라 세로로
긴 패널 가운데 작게 떴다. 이제 **1024px 미만은 모두 지도 + 바텀시트**다(모바일과 같은 구조).
1024px 이상에서만 2단이다. 시트는 원래 1023px 까지 그려지도록 되어 있었고 무대만 767px 에서
끊겨 있었다.

### 지도는 시트에 가리지 않는 자리에 맞춘다 (1.4)

지도는 무대 위쪽에 붙고 시트가 아래를 덮었다. 모바일은 지도 몫(290px)이 지도 자연 높이보다
커서 문제가 없었지만, 태블릿처럼 무대가 크면 시트가 지도 아래쪽(강남·서초·송파)을 덮었다.
이제 지도 층의 아래 끝이 **현재 시트 높이**를 따라가고, 지도는 남은 자리에 비율대로 맞춰
가운데 놓인다. 시트를 접으면 지도가 커진다. 시트 높이 식(`--status-sheet-*-height`)은 시트와
무대가 한 정의(`statusSheetHeightVars`)를 나눠 쓴다.

### 시트 3단 (1.4)

| 단계        | 높이                            | 용도                   |
| ----------- | ------------------------------- | ---------------------- |
| `collapsed` | 52px                            | 지도만 보기            |
| `expanded`  | `min(무대 × 0.6, 무대 − 290px)` | 지도 + 목록/상세(기본) |
| `full`      | `무대 − 12px`                   | 상세를 길게 읽기       |

- 끌어 놓은 높이에서 **가장 가까운 단계**로 붙는다. 같은 거리면 높은 단계다.
- 손잡이 탭은 `collapsed` 면 펼치고, 그 밖에는 한 단계 접는다(`full` → `expanded` → `collapsed`).
  `full` 은 끌어 올리거나, 손잡이에 포커스를 두고 ↑ 로 간다(↓ 는 한 단계 접기 — 끌기의 대안,
  WCAG 2.5.7). 지도 배경 탭도 탭 규칙과 같다.
- `full` 에서는 지도 층이 높이 0 이라 `inert` 로 뺀다 — 보이지 않는 폴리곤 25개가 Tab 순서에
  남지 않게.
- 무대가 290px 몫보다 작으면(가로로 눕힌 폰) 펼침이 접힘과 같아진다. 그때도 `full` 로는 끌 수 있다.
- 목록에서 구를 고르면 그때 단계를 유지한다(`full` 에서 고르면 `full` 그대로). 접힌 상태에서
  지도로 고르면 `expanded` 로 연다.

### 상세 섹션 바로가기와 분석 CTA (1.4)

- 상세 머리 아래에 `상권 흐름 · 유동인구 · 점포 · 매출` 바로가기 칩을 두고 위에 붙인다(sticky).
  데스크톱은 머리도 함께 붙는다. **시트는 칩만 붙는다** — 펼침 높이(약 380px)에서 머리까지
  붙이면 칩·CTA 와 함께 본문이 90px 남짓만 남는다(375px 실측).
- 칩을 누르면 스크롤과 함께 **포커스도 그 묶음으로 옮긴다**. 스크롤만 옮기면 키보드 사용자의
  다음 Tab 이 위쪽 묶음의 링크로 가 화면이 되돌아간다. 부드럽게 스크롤하는 동안에는 지나가는
  칩이 차례로 켜지지 않게 잠근다.
- 붙은 머리·칩과 CTA 가 포커스된 요소를 가리지 않게(WCAG 2.4.11) 스크롤 상자의
  `scroll-padding` 을 그 높이로 맞춘다. 칩을 누르면 그 묶음으로 스크롤하고, 스크롤하면 지금 보는 묶음 칩이 켜진다.
- 상세 맨 아래에 `{구} 상권 분석하기` 를 붙여 둔다(sticky). 이 화면의 목적이 「좁혀서 넘기기」라
  출구가 늘 보여야 한다. 목적지는 `/analysis` 의 자치구 선택 상태(`createDistrictHref`) —
  업종·행정동 링크와 같은 빌더라 새 API 호출이 없다.

### 기준 분기를 고른다 (1.6)

분기 적재가 `20261` 까지 끝났는데 이 화면은 두 호출에 분기를 싣지 않아 백엔드 기본값(당시 `20233`)으로
Top10·상세·분기별 추이를 그렸다(#409). 이제 **최신 분기를 기본으로 명시해 보내고**, 사용자가 연도·분기를
골라 과거 분기의 Top10 과 추이를 같은 화면에서 본다.

| 항목      | 규칙                                                                                                                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI        | 좌측 머리의 제목 줄 오른쪽에 **연도·분기 select 두 개**(`AnalysisPeriodSelect` 를 `StatusPeriodSelect` 가 감싼다). 모바일·태블릿은 제목이 숨으므로 select 줄이 지표 전환 위에 온다                   |
| 선택지    | `/analysis` 와 같다 — `ANALYSIS_PERIOD_FIRST_YEAR`(2021)부터 최신 분기(`ANALYSIS_PERIOD_CODE`)까지. 최신 연도는 적재된 분기까지만 연다(`analysisPeriodQuartersOf`)                                   |
| 기본값    | `ANALYSIS_PERIOD_CODE`(현재 `20261`). 다음 분기가 적재되면 그 상수만 올린다                                                                                                                          |
| URL       | `?periodCode=YYYYQ`. **기본 분기면 적지 않는다** — `/status` 는 「최신 분기 현황」을 뜻한다. 사용자가 고른 과거 분기만 URL 에 남는다                                                                 |
| 검증      | `isSupportedAnalysisPeriod`. 형식이 틀렸거나 선택지에 없는 값(`20264`·`20204`·`abc`)은 **기본 분기로 조용히 폴백**하고 URL 에서 `replace` 로 지운다(`?district=` 정규화와 같은 방식, 오류 화면 없음) |
| 이력      | 사용자가 분기를 바꾸면 `push` 다(지표·구 선택과 같다, S3 #5). 뒤로가기가 직전 분기로 돌아간다                                                                                                        |
| 선택 유지 | 분기를 바꿔도 **지표·선택 구·시트 단계를 유지한다.** 상세는 같은 구의 새 분기 값으로 다시 불러온다                                                                                                   |
| 반영      | Top10 목록·지도 단계 색(Top10 에서 파생)·상세 머리·상세 본문(분기별 추이 포함)이 모두 그 분기 응답으로 바뀐다                                                                                        |
| 표기      | 상세 머리의 순위 줄 뒤에 `· 2026년 1분기 기준`(`formatPeriodCode`). Top10 목록은 바로 위 select 가 기준을 보여 주므로 따로 적지 않는다. 분기별 추이는 점마다 분기 라벨이 이미 있다                   |

**URL 을 정본으로 둔 이유.** 이 화면은 지표·구 선택이 이미 URL 정본이다(S2 #2). 분기만 로컬 state 로 두면
과거 분기를 보다가 새로고침·공유하면 조용히 최신 분기로 돌아간다 — `/analysis/result` 가 기간을 로컬 state
로 두었다가 같은 결함을 겪고 URL 로 옮겼다. 파라미터 이름도 `/analysis` 와 같은 `periodCode` 다(백엔드 파라미터
이름 `currentPeriodCode` 는 API 쪽 이름이라 URL 에 드러내지 않는다).

**`push` 인 이유.** `/analysis/result` 는 기간 전환이 `replace` 다 — 거기서는 탭·카메라가 모두 `replace` 라
분기만 이력을 쌓으면 어긋난다. 이 화면은 반대로 사용자의 조작(지표·구)이 모두 `push` 라 같은 규칙을 따른다.

**분기를 바꾸는 동안 화면을 통째로 로딩으로 바꾸지 않는다.** Top10 쿼리 키가 분기마다 달라 새 분기의 첫 요청
동안 데이터가 비고, 그러면 페이지가 로딩 화면으로 바뀌며 select 자체가 사라진다(포커스를 잃고, 키보드로 분기를
훑던 사용자는 다음 분기로 넘어갈 수 없다). 그래서 Top10 은 **직전 분기 응답을 자리 표시로 유지**하고
(`placeholderData`), 목록·지도는 새 응답이 올 때까지 `aria-busy` + 흐리게 둔다. 상세는 자기 자리의 스켈레톤을
그대로 쓴다(상세 슬롯은 구 코드로만 key 를 잡아 분기가 바뀌어도 다시 마운트되지 않는다).

- **상세 머리의 값·증감·순위도 흐린다.** 그 줄은 Top10 응답(`rankedItem`)에서 오므로 전환 중에는 **옛 분기** 값이다.
  React Query v5 의 자리 표시는 마지막으로 데이터가 있던 쿼리라, 20261 → (404) → 20233 처럼 가면 20261 값이 붙는다.
  그대로 두면 새 분기 이름(「· 2023년 1분기 기준」) 옆에 옛 값이 또렷하게 보인다. 그래서 값 줄·순위 줄을 `aria-busy`
  로 흐리게 둔다(`isRankPending`, 데스크톱 상세·시트 상세 모두). 순위 항목을 null 로 만들지 않는다 — 「상위 10위 밖」
  으로 잘못 읽히고 머리 높이가 흔들린다.
- **로딩·오류 화면도 평소 화면과 같은 트리를 쓴다**(`Layout > SideHead > TitleRow`). 예전엔 오류 화면이 따로 된
  트리라 평소 ↔ 오류 전환 때 select 가 다시 마운트돼 포커스가 body 로 떨어졌다. 이제 배치만 한 열(제목 줄 + 안내)로
  바꾸고(`data-feedback`) select 는 같은 노드로 남는다.

**그 분기 호출이 실패하면** 오류 화면에도 분기 select 를 둔다. 오류 화면에서 다른 분기로 옮길 길이 없으면
사용자는 URL 을 고치거나 뒤로가기밖에 없다. 네 지표가 동시에 빈 분기도 같다(「빈 상태와 장애를 가른다」 —
장애 안내 + 재시도 + select).

#### 쿼리 키

| 쿼리       | 키                                                 | 비고                                        |
| ---------- | -------------------------------------------------- | ------------------------------------------- |
| 구별 Top10 | `['status', 'topTen', periodCode]`                 | `statusQueryKeys.topTen`                    |
| 구 상세    | `['status', 'detail', periodCode, districtCode]`   | `statusQueryKeys.detail`                    |
| 홈 Top10   | `['home', 'districtTopTen', ANALYSIS_PERIOD_CODE]` | `HOME_TOP_TEN_QUERY_KEY`. 홈은 늘 최신 분기 |

- 분기를 키에 넣어 분기별 캐시가 섞이지 않게 한다. 분기를 앞에 두어 「그 분기의 status 캐시」를 접두사로 묶는다.
- **홈과 status 는 같은 분기여도 키를 나누고 dedupe 하지 않는다.** 두 화면의 쿼리 옵션이 다르다 — 홈은
  `retry: 1`·`staleTime: 5분`(실패하면 예시로 채우는 섹션), status 는 `retry: 3`·기본 staleTime(이 화면의 주
  데이터). 같은 키를 쓰면 먼저 마운트된 쪽의 캐시가 다른 쪽의 신선도 판단에 끼어들고, 한 화면의 옵션을 바꿀 때
  다른 화면이 같이 바뀐다. 얻는 것은 홈 → status 이동 때 요청 1회를 아끼는 정도라 결합 비용이 더 크다.
- 후속 25개 구 전체 순위 API(BE #433)도 같은 분기 파라미터를 받는다. 분기는 `parseStatusPeriod` 가 URL 에서
  한 번 읽고 화면 전체가 그 값을 나눠 쓰므로, 새 쿼리는 같은 값을 키·요청에 싣기만 하면 된다.

### 모바일 시트의 높이 규칙

```
접힘   = 52px (STATUS_SHEET_COLLAPSED_HEIGHT)
펼침   = min(무대 * 0.6, 무대 - 290)   ← 290 = 지도 최소 몫
전체   = 무대 - 12 (STATUS_SHEET_FULL_TOP_GAP)
```

시트는 기본 「펼침」으로 연다. 1.4 부터 지도는 상단 정렬이 아니라 **시트 위에 남는 자리 안에서
가운데**다(「지도는 시트에 가리지 않는 자리에 맞춘다」). 단계 규칙은 「시트 3단」.
