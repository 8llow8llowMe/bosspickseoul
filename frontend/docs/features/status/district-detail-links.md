## D0. 배경 / 기획 의도

### 이 문서가 「B3」을 재정의한다

엔드포인트 인벤토리(`docs/superpowers/specs/2026-09-02-be-endpoint-inventory.md`)의 **B3 — 자치구 상세 지표 5종**은 사실과 다르다.

> ~~`/status` 는 `/districts/top-ten` 하나만 쓴다. BE 의 자치구 API 가 화면보다 훨씬 넓다.~~

`/status` 는 **두 개**를 쓴다 — `/districts/top-ten` 과 `/districts/{districtCode}`(통합 상세). 그리고 통합 상세 응답은 미연동으로 적힌 5개 세부 엔드포인트의 스키마를 **그대로** 담고 있다.

| 통합 응답 필드                  | 대응 세부 엔드포인트                          | 스키마                                         |
| ------------------------------- | --------------------------------------------- | ---------------------------------------------- |
| `changeIndicator`               | `/districts/{code}/change-indicators`         | `ChangeIndicatorDistrictResponse` — **동일**   |
| `footTraffic`                   | `/districts/{code}/foot-traffic`              | `FootTrafficDistrictDetailResponse` — **동일** |
| `store`                         | `/districts/{code}/stores/top-services`       | `DistrictStoreDetailResponse` — **동일**       |
| `sales`                         | `/districts/{code}/sales/top-services`        | `DistrictSalesDetailResponse` — **동일**       |
| `sales.topSalesAdministrations` | `/districts/{code}/sales/top-administrations` | 부분집합                                       |

즉 5개는 **새 데이터가 아니라 같은 데이터의 분할 조회 변형**이고, 화면은 4개 그룹을 이미 전부 그린다(상권 흐름 · 유동인구 5차트 · 점포 3차트 · 매출 2차트).

**남은 진짜 빈틈은 「받아 놓고 안 쓰는 필드」다.** 이 문서는 그것을 다룬다.

| 항목              | 내용                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 충족 요구사항     | 인벤토리 B3 재정의분. 공통명세 미작성이라 상위 S 항목 없음                                                                                                                            |
| 해결하려는 문제   | ① 개업·폐업·매출을 **건수/금액으로만** 보여줘 규모가 다른 행정동끼리 비교가 오해를 만든다 ② `status-detail.tsx` 에 **링크가 0개다** — 행정동·업종 이름이 보이는데 눌러서 갈 데가 없다 |
| 목표 동작 (to-be) | 응답에 이미 있는 비율을 함께 적고, 이미 있는 코드로 해당 지역·업종의 상권분석으로 잇는다                                                                                              |
| 구현 제외 범위    | **새 API 호출 0회.** 5개 세부 엔드포인트를 부르지 않는다. status 공통명세 작성. `/status` 의 top-10 게이트 개선(D6 참고)                                                              |
| 연관 세부 기능    | [상권분석 탐색](../analysis/explorer.md), 홈 「지금 많이 본 지역」(이슈 #200)                                                                                                         |

## D1. 기능 개요

미사용 필드는 여섯이다. 전부 `GET /districts/{districtCode}` 응답에 **이미 도착해 있다.**

| #   | 필드                                                                            | 현재   | 이 명세에서               |
| --- | ------------------------------------------------------------------------------- | ------ | ------------------------- |
| 1   | `store.topOpenedAdministrations[].openingRate`                                  | 미사용 | 개업률(%) 병기            |
| 2   | `store.topClosedAdministrations[].closureRate`                                  | 미사용 | 폐업률(%) 병기            |
| 3   | `sales.topSalesAdministrations[].salesChangeRate`                               | 미사용 | 매출 증감률(%) 병기       |
| 4   | `store.top*Administrations[].administrationCode`                                | 미사용 | 행정동 → `/analysis` 링크 |
| 5   | `sales.topSalesAdministrations[].administrationCode`                            | 미사용 | 〃                        |
| 6   | `store.topStoreServices[].serviceCode` · `sales.topSalesServices[].serviceCode` | 미사용 | 업종 → `/analysis` 링크   |

`changeIndicator.changeIndicatorCode` 도 미사용이나 **의도된 것**이다 — 화면은 `changeIndicatorName` 으로 `INDICATOR_COPY` 를 찾아 문장을 만든다. 코드는 필요 없다. **연결하지 않는다.**

```text
GET /districts/{code} (기존 호출) → 기존 차트 + 비율 병기 + 라벨을 /analysis 링크로
```

### D3-2. 데이터 흐름

```text
fetchStatusDetail(districtCode)          ← 기존 호출, 그대로
```

### D3-3. 데이터 모델

`AnalysisMetricRow` 는 `{ label, value }` 다. 이 명세는 **선택 필드 둘을 더한다**(기존 사용처는 그대로 동작해야 한다).

```ts
export type AnalysisMetricRow = {
  label: string
  value: number | null
  /** 라벨을 링크로 만들 목적지. 없으면 링크 없이 텍스트로 그린다. */
  href?: string
  /** 값 뒤에 함께 적을 보조 표기(예: 개업률 `8.5%`). 없으면 생략한다. */
  subLabel?: string
}
```

> **왜 `AnalysisMetricRow` 를 확장하나** — 이 타입은 `/analysis` 결과 차트와 시뮬레이션 리포트도 쓴다. 선택 필드로 두면 그쪽은 손대지 않아도 되고, 나중에 같은 「눌러서 잇기」가 필요할 때 재사용된다. 필수 필드로 만들면 6개 사용처를 전부 고쳐야 한다.

### D3-4. 사용 라이브러리

recharts(기존). **새 의존성 없음.**

## D4. 상세 동작 정의

### D4-1. 비율 병기

- 개업: `132개 · 개업률 8.5%`
- 폐업: `87개 · 폐업률 4.3%`
- 행정동 매출: `158억 · +7.2%` (증감률은 부호를 붙인다 — 기존 `formatStatusChange` 재사용)

비율이 `null`·비유한수면 **`·` 이후를 통째로 생략**한다. `개업률 0%` 로 적지 않는다(D2-2).

값 라벨이 길어지므로 `HorizontalBarChart` 의 오른쪽 여백(`margin.right = 52`)을 재검토한다. 넘치면 비율을 툴팁으로 옮기는 것을 대안으로 둔다(D8-1).

### D4-2. 행정동 라벨 → `/analysis`

```ts
createAnalysisExplorerHref({
  ...createEmptyAnalysisSelection(),
  districtCode, // 현재 보고 있는 자치구
  administrationCode, // 눌린 항목
})
// → /analysis?districtCode=11680&administrationCode=11680580
```

`/analysis` 는 이 URL 을 그대로 복원하고 활성 단계는 **상권**이 된다(`getActiveAnalysisStep`: 자치구·행정동이 차 있으므로). 사용자는 상권·업종만 고르면 된다.

### D4-3. 업종 라벨 → `/analysis`

```ts
createAnalysisExplorerHref({
  ...createEmptyAnalysisSelection(),
  districtCode,
  serviceCode, // 예: CS100001
})
// → /analysis?districtCode=11680&serviceCode=CS100001
```

활성 단계는 **행정동**이 되고 업종은 이미 채워져 있다. 사용자는 행정동·상권만 고른다.

## D5. 비즈니스 로직

### 링크 생성 규칙

| 조건                                          | 결과                                          |
| --------------------------------------------- | --------------------------------------------- |
| 코드가 있고 공백이 아님                       | `href` 를 만든다                              |
| 코드가 `null`·빈 문자열                       | `href` 없음 → 라벨을 **일반 텍스트**로 그린다 |
| 자치구 코드를 모름(상세가 열렸으면 항상 안다) | 링크를 만들지 않는다                          |

### 업종 코드 정합성 — **검사하지 않는다**

업종 목록은 상권별 API(`/commercials/{code}/service-categories`)로 온다. `/status` 에서 넘긴 업종이 사용자가 나중에 고를 상권에 없을 수 있다.

**이것을 `/status` 에서 막지 않는다.** 저장소가 이미 같은 상황을 의도적으로 그렇게 다루고 있다 — `selectAnalysisValue` 의 `commercial` 분기는 상권을 바꿔도 업종을 **보존**하고, 목록이 도착한 뒤 `analysis-map-shell` 의 정합성 효과가 URL 에서 지운다. 같은 규칙을 따른다.

### 비율 포맷

- 개업률·폐업률: 부호 없음. `8.5%`
- 매출 증감률: 부호 있음. `+7.2%` / `-5.6%` — 기존 `formatStatusChange` 를 그대로 쓴다

## D6. 주의사항

### D6-1. `/status?district=` 를 목적지로 쓰지 않는다

`normalizeStatusSelection` 이 「현재 지표의 top-10」에 없는 자치구 코드를 버리고, 상세도 `selectedItem !== null` 로 게이트돼 있다. 행정동은 아예 화면이 없다. **목적지는 언제나 `/analysis` 다**(이슈 #200 에서 확인한 것과 같은 제약이며, `docs/features/_index.md` share 항목의 `DISTRICT_ANALYSIS` 미지원 사유와 같은 뿌리다).

### D6-2. SVG 안의 링크는 브라우저에서 실측해야 한다

Y축 라벨은 recharts 가 SVG `<text>` 로 그린다. 링크로 만들려면 커스텀 `tick` 렌더러에서 SVG `<a>` 를 써야 한다. **다음 셋을 브라우저에서 반드시 확인한다** — 코드만 보고 통과시키지 않는다.

1. `Tab` 으로 도달되는가 (`tabIndex` 필요할 수 있다)
2. `Enter` 로 이동하는가
3. 포커스 링이 보이는가 (SVG 안에서는 `outline` 이 잘리는 경우가 있다)

셋 중 하나라도 안 되면 **D8-2 의 대안(차트 아래 칩 목록)으로 간다.** 접근 불가능한 링크를 남기지 않는다.

> **실측 결과 (2026-09-03, 구현 시)**
>
> | 항목              | 결과                                                                                          |
> | ----------------- | --------------------------------------------------------------------------------------------- |
> | Tab 도달          | ✅ `a.chart-category-link` 로 포커스가 들어온다                                               |
> | 포커스 링         | ✅ `outline: 2px solid` + 밑줄. 스크린샷으로 확인                                             |
> | 마우스 클릭 이동  | ✅ `/analysis?districtCode=…&administrationCode=…` 로 이동, 활성 단계가 **3단계 상권**이 된다 |
> | **진짜 Enter 키** | ⚠️ **검증하지 못했다**                                                                        |
>
> 자동화 도구가 keydown 을 보내면서 `event.key` 를 **빈 문자열**로 실어 보낸다(문서 리스너로
> 확인). 그래서 네이티브 SVG 앵커의 Enter 동작을 가릴 수 없었다. `key: 'Enter'` 를 제대로 담은
> 합성 이벤트로는 이동이 확인됐다 — 즉 **핸들러는 동작하고, 네이티브 동작은 미확인**이다.
>
> 그래서 `onKeyDown` 으로 Enter 를 **방어적으로 직접 이었다.** 네이티브가 이미 동작해도
> `preventDefault` 로 중복 이동이 나지 않는다. **사람이 키보드로 한 번 확인해야 하는 항목으로
> 남는다.**

### D6-3. 차트 비율 규칙을 깨지 않는다

DESIGN.md §Charts 의 폭 상한(560px)·`full` 금지는 그대로다. 값 라벨이 길어져 오른쪽이 잘리면 **폭을 늘리지 말고** D8-1 로 간다.

### D6-4. 데스크톱·모바일 두 곳

`status-detail.tsx` 는 데스크톱 패널과 모바일 바텀시트에서 각각 렌더된다(실측: 같은 차트가 DOM 에 2벌 있고 숨은 쪽은 폭 0). 한쪽만 고치지 않는다.

## D8. 미결 사항 / 데이터 검증 제약

### D8-1. 값 라벨이 길어지는 문제 — 구현 중 판단

`132개 · 개업률 8.5%` 는 기존 `132개` 보다 두 배 이상 길다. 오른쪽 여백(52px)을 넘으면 두 갈래다.

1. 비율을 툴팁으로 옮긴다 (라벨은 건수만)
2. 여백을 늘린다 — **막대 길이가 줄어 비율 규칙에 유리하므로 이쪽이 우선**

실측 후 정한다. 폭 상한(560px)은 건드리지 않는다.

### D8-2. SVG 링크가 접근성 요건을 못 채울 때의 대안

차트 아래에 같은 항목을 칩 목록으로 두고 그쪽을 링크로 만든다. 내용이 중복되므로 **차트 라벨 링크가 되면 쓰지 않는다.** 되지 않을 때만 간다.

### D8-3. 실데이터 검증 제약

dev 에서 자치구에 따라 `topOpenedAdministrations`·`topClosedAdministrations` 가 비어 오는 경우가 있다(강남구 실측: 「행정동별 개업」·「행정동별 폐업」 차트가 렌더되지 않았다). **빈 목록에서도 화면이 온전한지**를 함께 본다.

### D8-4. status 공통명세는 여전히 없다

이 문서는 세부 명세인데 걸 상위 문서가 없다. 공통명세(S0~S5) 작성은 별도 과제로 남는다.
