# layout — Pretendard 서브셋 세부 명세서

> **작성일**: 2026-09-11
> **공통 명세**: [home.md S2 #4](../home/home.md) 및 [DESIGN.md §3 Typography](../../../DESIGN.md) — `layout` feature 에는 아직 공통 명세(S0~S5) 파일이 없다. 이 문서의 상위 정본은 **DESIGN.md §3** 과 **[home-ux-audit-2026-09-11 §3 P0-B·§5](../home/home-ux-audit-2026-09-11.md)** 다(D8-1).
> **대상**: 웹 (Next.js App Router)
> **작성자**: Claude Code
> **상태**: 초안

홈 감사에서 **폰트가 전체 전송량의 88%(3,049KB / 3,481KB)** 로 드러났다. 렌더 서체(Pretendard)·무게 구성(400/500/600/700)·로딩 방식(`next/font/local`)은 그대로 두고 **파일만 서브셋으로 교체**해 폰트 전송량을 **≤500KB** 로 줄이는 작업이다.

화면에 보이는 것은 아무것도 바뀌지 않는 것이 성공 조건이다. 글자 모양·굵기·자간이 달라지면 실패다.

## D1. 기능 개요

`public/fonts/` 의 전체 글리프 Pretendard 9파일을 **KS X 1001 기반 서브셋 1파일**로 교체하고, `src/lib/fonts.ts` 의 `localFont` 호출을 4개 `src` 항목에서 가변 무게 1개 항목으로 줄인다. 글로벌 스타일·폴백 스택·`display: swap`·CSS 변수 이름은 바뀌지 않는다.

```
Pretendard 1.3.9 원본 → 문자 집합 정의(2,566자) → pyftsubset → PretendardVariable.subset.woff2(428.6KB) → next/font/local → --font-pretendard
```

### D1-1. UI 진입점 / 기능 연결

**해당 없음.** 전역 자산 교체이며 사용자가 트리거하는 UI 요소가 없다. Figma 산출물도 없다(시각 결과가 **현행과 동일해야** 하는 것이 이 작업의 정의다).

영향 범위는 「모든 화면의 모든 텍스트」이므로, 진입점 대신 **회귀 확인 대상 화면**을 적는다.

| 확인 화면          | 무엇을 본다                               | 이유                                       |
| ------------------ | ----------------------------------------- | ------------------------------------------ |
| `/` 홈             | h1·본문·숫자·`·` 구분자                   | 전송량 재측정의 기준 화면                  |
| `/status`          | 자치구 25개 이름, 순위 숫자, `+0.7%` 배지 | 한글 고유명사 + 숫자 + 기호 혼합           |
| `/analysis/result` | 행정동·상권명, `㎡`, `→`, 차트 축 라벨    | 비ASCII 기호가 가장 많은 화면              |
| `/community/list`  | 사용자 작성 제목·본문                     | 2,350자 밖 글자가 나올 수 있는 유일한 경로 |

## D4. 상세 동작 정의

### D4-1. 문자 집합 정의

#### 한글 음절 2,350자 — 생성 규칙

KS X 1001 완성형 한글 2,350자 목록을 문서에 붙여 넣지 않는다. **Python 표준 코덱으로 판정**한다.

```python
# scripts/fonts/build-charset.py 의 핵심
def in_ksx1001(ch: str) -> bool:
    try:
        ch.encode('iso2022_kr')   # euc_kr/cp949 는 UHC 확장이라 11,172자가 다 통과한다 — 쓰면 안 된다
        return True
    except UnicodeEncodeError:
        return False

syllables = [chr(c) for c in range(0xAC00, 0xD7A4) if in_ksx1001(chr(c))]
assert len(syllables) == 2350
```

| 코덱         | `U+AC00`~`U+D7A3` 통과 수 | 판정                |
| ------------ | ------------------------- | ------------------- |
| `iso2022_kr` | **2,350**                 | ✅ KS X 1001 그대로 |
| `euc_kr`     | 11,172                    | ❌ UHC 확장 포함    |
| `cp949`      | 11,172                    | ❌                  |
| `johab`      | 11,172                    | ❌                  |

`assert len(...) == 2350` 을 스크립트에 남긴다. 파이썬 버전이 바뀌어 코덱 동작이 달라지면 그 자리에서 깨진다.

#### 한글 호환 자모 51자

`U+3131`~`U+3163` 전 구간. 51자 모두 KS X 1001 안이다. 커뮤니티·채팅에서 「ㅋㅋ」「ㅠㅠ」「ㅎㅎ」가 상시 입력되고, `src/lib/option-filter.ts` 주석이 초성 검색(`ㄱㄴ` → `강남구`)을 **범위 밖 후속 과제**로 적어 두었으므로 미리 넣는다. 51자는 용량에 영향이 없다.

#### 라틴·숫자

`U+0020`~`U+007E` 95자 전체.

#### 추가 기호 — `frontend/src` · `frontend/app` 실측 수집

주석·테스트 파일을 제외하고 **렌더되는 문자열에 실제로 쓰인** 비ASCII·비한글 문자다.

| 문자   | 코드포인트 | 사용 횟수   | 대표 위치                             | KS X 1001 |
| ------ | ---------- | ----------- | ------------------------------------- | --------- |
| `·`    | `U+00B7`   | 98 (52파일) | 전 화면 구분자                        | 포함      |

확정 추가 기호 목록(70자, KS X 1001 밖 문자를 포함해 명시적으로 싣는다):

```
₩ ￦

```

- `₩`·`±`·`≈`·`−`·`≠` 는 **현재 코드에 없다.** 서비스가 금액을 「만원」 한글로 적기 때문이다. 그래도 넣는 이유는 (1) 글리프당 비용이 사실상 0이고 (2) 이 다섯 자가 나중에 한 글자만 쓰여도 폴백 서체로 새어 눈에 띄기 때문이다.
- `✕`(`U+2715`) 는 **넣지 않는다.** Pretendard 1.3.9 에 글리프가 없고(확인함), 저장소에서도 주석에만 등장한다.
- 이모지는 넣지 않는다. Pretendard 는 이모지 글리프를 갖지 않으며 폴백 스택의 `Tossface`·시스템 이모지가 담당한다(현행과 동일).

### D4-2. 서브셋 실행 절차

`scripts/fonts/subset-pretendard.sh` 가 하는 일이다. 저장소에 Python 의존성을 추가하지 않기 위해 **임시 venv** 를 쓰고 끝나면 지운다.

```bash
# 1) 도구 (임시)
python3 -m venv .fonttools-venv
.fonttools-venv/bin/pip install "fonttools[woff]" brotli

# 2) 원본 (버전 고정)
curl -sL -o /tmp/PretendardVariable.woff2 \
  https://cdn.jsdelivr.net/npm/pretendard@1.3.9/dist/web/variable/woff2/PretendardVariable.woff2

# 3) 문자 집합
.fonttools-venv/bin/python scripts/fonts/build-charset.py > public/fonts/charset.txt

# 4) 서브셋
.fonttools-venv/bin/pyftsubset /tmp/PretendardVariable.woff2 \
  --text-file=public/fonts/charset.txt \
  --layout-features='kern,liga,calt,ccmp,locl,mark,mkmk' \
  --flavor=woff2 --with-zopfli \
  --no-hinting --drop-tables+=DSIG --name-IDs='*' \
  --output-file=public/fonts/PretendardVariable.subset.woff2
```

| 옵션                  | 왜                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------------ |
| `--text-file`         | 유니코드 범위가 아니라 **문자 목록**으로 자른다. KS X 1001 2,350자는 연속 범위가 아니라서 범위로는 못 자른다 |
| `--layout-features`   | `kern`(커닝) 을 빼면 자간이 달라져 「보이는 것이 같아야 한다」는 조건이 깨진다. `mark/mkmk` 는 한글 조합용   |
| `--with-zopfli`       | woff2 재압축. 수 KB 더 줄인다                                                                                |
| `--no-hinting`        | 웹 렌더러는 힌팅을 쓰지 않는다                                                                               |
| `--name-IDs='*'`      | **name 테이블 전체 보존.** 저작권·라이선스·폰트명 문자열이 파일 안에 남아야 OFL 파생물 고지가 유지된다       |
| `--drop-tables+=DSIG` | 서브셋하면 어차피 무효가 되는 디지털 서명                                                                    |

가변 축(`fvar`)은 그대로 살아 있다(서브셋 후 `wght 45~930` 확인). `--desubroutinize` 는 CFF 전용이라 쓰지 않는다(Pretendard 는 `glyf` 기반).

### D4-3. `fonts.ts` 구조 변경

코드 대신 **구조**로 적는다. 실제 코드는 구현자가 쓴다.

| 항목                 | 현행                                               | 변경 후                                                         |
| -------------------- | -------------------------------------------------- | --------------------------------------------------------------- |
| `src` 배열           | 4개 항목 (`weight: '400' / '500' / '600' / '700'`) | **1개 항목**                                                    |
| 그 항목의 `path`     | `../../public/fonts/Pretendard-*.woff2`            | `../../public/fonts/PretendardVariable.subset.woff2`            |
| 그 항목의 `weight`   | 단일 값 문자열                                     | **범위 문자열 `'400 700'`** (가변 폰트 표기)                    |
| 그 항목의 `style`    | `'normal'`                                         | `'normal'` (무변경)                                             |
| `display`            | `'swap'`                                           | 무변경                                                          |
| `variable`           | `'--font-pretendard'`                              | 무변경                                                          |
| `fallback`           | 10개 스택                                          | 무변경                                                          |
| `preload`            | 미지정(기본 `true`)                                | **미지정 유지(`true`)**                                         |
| `adjustFontFallback` | 미지정(기본값)                                     | **미지정 유지** — 건드리면 폴백 메트릭이 바뀌어 CLS 0 이 깨진다 |

`weight` 를 `'400 700'` 으로 적는 이유: 파일의 실제 축은 `45~930` 이지만 우리가 **쓰는** 범위는 400~700 이다. CSS `font-weight` 범위를 좁게 선언하면 그 밖의 값(예: 실수로 들어온 `font-weight: 300`)이 400 으로 클램프돼 **디자인 밖 굵기가 화면에 나오지 않는다**. DESIGN.md §3 의 「4무게」 제약을 CSS 레벨에서 강제하는 효과다.

#### preload 대상 — **1파일 전부 preload(현행 기본값 유지)**

| 안                             | preload 되는 것              | 판정                                                                                                                                                                                                          |
| ------------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **가변 1파일 (확정)**          | 428.6KB × 1                  | ✅ 「400·700 만 preload」라는 질문 자체가 사라진다. 무게 구분이 파일 구분이 아니다                                                                                                                            |
| 정적 4파일, 400·700 만 preload | 336.7KB × 2 preload + 2 lazy | ❌ `localFont` 는 **호출 단위**로 preload 를 켠다. 400·700 만 preload 하려면 호출을 둘로 쪼개야 하고, 그러면 **family 가 둘로 갈려** `font-weight: 500/600` 이 첫 family 안에서 합성(synthetic bold)돼 버린다 |

가변 1파일을 고른 실질적 이유 중 하나가 이것이다. 정적 다파일에서는 「자주 쓰는 무게만 먼저」가 `next/font/local` 의 API 로는 깨끗하게 표현되지 않는다.

### 글자 폴백 규칙

서브셋에 없는 글자는 CSS 폰트 매칭 규칙에 따라 **글자 단위로** 다음 폴백으로 내려간다. 문단 전체가 폴백으로 바뀌지 않는다.

| 입력 글자         | 예        | 렌더                                                                    |
| ----------------- | --------- | ----------------------------------------------------------------------- |
| KS X 1001 안 한글 | `강남구`  | Pretendard                                                              |
| 호환 자모         | `ㅋㅋ`    | Pretendard                                                              |
| 추가 기호 목록 안 | `㎡` `—`  | Pretendard                                                              |
| KS X 1001 밖 한글 | `뾰` `얔` | `Apple SD Gothic Neo`(mac/iOS) / `Malgun Gothic`(Win) / `Noto Sans KR`  |
| 이모지            | `🔴`      | `Tossface` 또는 시스템 이모지 — **현행과 동일**                         |
| 한자·가나         | `商` `あ` | 시스템 폰트 — **현행에서도 이미 폴백**(원본 Pretendard 한자 글리프 0자) |

**폴백 전략은 「폴백 스택」으로 확정한다.** `unicode-range` 분할은 쓰지 않는다 — KS X 1001 2,350자가 `U+AC00`~`U+D7A3` 안에 흩어져 있어 겹치지 않는 범위로 자를 수 없고, 겹치는 `unicode-range` 를 같은 family·같은 weight 로 선언하면 나중 선언이 앞 선언을 통째로 덮어쓴다. 범위 분할을 제대로 하려면 Pretendard 의 dynamic-subset(범위 수백 개) 방식이어야 하는데, 그건 `next/font/local` 로 관리할 수 있는 규모가 아니다. 별도 family 로 나머지 8,822자를 다는 안은 D8-3 에 남긴다.

| **`public/` 중복 서빙**                   | `public/fonts/` 의 파일은 next/font 복사본과 별개로 `/fonts/...` 로도 정적 서빙된다. 지금은 9파일 6.7MB 가 배포 이미지에 그대로 들어간다. 교체 후 1파일 429KB 로 줄어 실질적으로 해소된다                                                                                                                                                                            |

| **name 테이블 보존**                      | `--name-IDs='*'` 를 빼면 파일 안의 저작권·라이선스 문자열이 날아간다. OFL 파생물 고지가 사라지므로 뺄 수 없다                                                                                                                                                                                                                                                        |

Reserved Font Name 제약 유무는 원문 확인 후 파일명 정책을 정한다(D8-5)                                                                                                                                                                  |

| **BE 데이터 관찰(이 명세 범위 밖)**       | 행정동 7건의 이름에 `?` 가 들어 있다: `종로1?2?3?4가동`·`종로5?6가동`·`금호2?3가동`·`상계3?4동`·`상계6?7동`·`중계2?3동`·`면목3?8동`. 원래 `·` 자리로 보이며 **폰트 문제가 아니라 응답 데이터 문제**다. 폰트 교체 후에도 `?` 로 보인다. 별건으로 백엔드에 문의한다 — **BE 후속 요청 1**                                                                               |
