### D0-1. 실측 — 감사 §3 P0-C 실패 조합 8종

감사 보고서의 표를 그대로 옮긴다. 측정은 `getComputedStyle` 로 전경·배경을 뽑아 WCAG 2.x 명도 대비를 계산한 값이다(데스크톱 1440×900).

| 전경 → 배경                         | 대비     | 어디에                                           | 개수 |
| ----------------------------------- | -------- | ------------------------------------------------ | ---- |
| `#0ea5e9` → `#e8f3ff`(blue50)       | **2.47** | 「구별현황 보기」 보조 버튼, 활성 지표 토글      | 5    |
| `#ffffff` → `#0ea5e9`(blue500)      | **2.77** | 주 버튼 3개, 헤더 회원가입                       | 4    |
| `#0ea5e9` 13px → 흰색               | **2.77** | 도구 보드 카드 하단 라벨, 단계 번호              | 8    |
| `#03b26c` 12px → 흰색               | **2.77** | 변화율 배지 `+0.7%`                              | 6    |
| `#f04452` 12px → 흰색               | 3.71     | 변화율 배지 `-1.1%`                              | 8    |
| `#6b7684` → `#f9fafb`(grey50)       | 4.42     | 스토리 단계 본문, 아이브로 「이렇게 판단합니다」 | 9    |
| `#6b7684` → `#e8f3ff`               | 4.11     | 활성 단계 본문                                   | 1    |
| `#ffffff` → `#2272eb`(blue600) 13px | 4.49     | 순위 배지 1~3                                    | 4    |

합계 **45개 요소 / 8종**. 감사가 「18종 미달」이라 적은 것 중 나머지 10종은 열거되지 않았다 — D6-5 · D7 B1 에서 확정한다.

### D0-2. 왜 화면이 아니라 팔레트인가

| 근거                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `#0ea5e9`(blue500)의 상대 명도는 흰색과 **2.77**, 흰 배경 위 글자로도 **2.77**. 어느 방향으로도 4.5 를 만들 수 없다. 「글자색만 바꾼다」는 해법이 존재하지 않는다                                                                            |
| `#2272eb`(blue600)은 흰 글자 **4.49** 로 **0.01 차이로 미달**이다. 「hover 색을 rest 로 올리면 된다」는 직관이 통하지 않는다 — 통과처럼 보이지만 통과가 아니다                                                                               |
| DESIGN.md §4 가 「개별 화면이 텍스트 색을 바꿔 이탈하지 않는다」고 이미 못 박았다. 8개 홈 파일에서 각자 색을 고르면 §7 Don't 「화면마다 다른 블루를 쓰지 않는다」를 정면으로 어긴다                                                          |
| `#0ea5e9` 를 **텍스트용으로만** 어둡게 재지정할 수는 없다. 같은 토큰(`--color-primary-700`)이 포커스 링·지도 라벨 채움·테두리에도 쓰이고, 그 규약을 `global-styles.test.ts` 「포커스 링은 primary-700 이다」가 소스 스캔으로 잠가 뒀다(D6-3) |

→ **기존 토큰의 값은 건드리지 않고, 텍스트를 다루는 역할에 쓸 토큰을 새로 추가한다.**

## D1. 기능 개요

텍스트를 싣는 채움·글자·배지·밴드 네 상황에 쓸 색 토큰을 팔레트에 추가하고, 그 토큰을 쓰는 조합을 규칙으로 고정한다. 화면 레이아웃·문구·구조는 바뀌지 않는다.

```
DESIGN.md §2·§4 갱신(선행) → global-styles.ts 프리미티브 4 + 시맨틱 6 추가 → 홈 8개 파일·헤더가 시맨틱 토큰 참조 → 재측정 AA 미달 18 → 0
```

## D3. 아키텍처 / 시스템 설계

### D3-1. 시스템 구성 — 토큰 3계층

| 계층       | 어디에                                 | 책임                                                           | 이 명세의 변경   |
| ---------- | -------------------------------------- | -------------------------------------------------------------- | ---------------- |
| 프리미티브 | `global-styles.ts` `:root` `--color-*` | 팔레트의 실제 hex. 역할을 모른다                               | **4개 추가**     |
| 시맨틱     | `global-styles.ts` `:root` (역할 이름) | 「어떤 상황에 쓰는 색인가」. 프리미티브를 `var()` 로 가리킨다  | **6개 추가**     |
| 컴포넌트   | 각 `styled-components` 선언            | 시맨틱 토큰을 **직접 참조**한다. 별도 CSS 변수를 만들지 않는다 | 참조 대상만 교체 |

> **컴포넌트 계층에 새 CSS 변수를 만들지 않는 이유.** 현행 코드의 컴포넌트 토큰은 `--button-disabled-opacity-color` 하나뿐이다(`--button-border-radius` 는 DESIGN.md 에만 있고 `:root` 에 없다 — D6-6). 여기서 `--button-primary-background` 류를 새로 도입하면 「어떤 버튼은 컴포넌트 토큰, 어떤 버튼은 시맨틱 토큰」이 섞인다. 계층은 3개로 **말하되**, 3번째 계층은 변수가 아니라 **참조 규칙**(D4)으로 고정한다.

**이름 짓기 규칙** — DESIGN.md §2 의 경고 박스(「`--color-primary-*` 별칭은 명암을 거꾸로 말한다」)를 악화시키지 않는다.

| 하지 않는다                        | 왜                                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--color-primary-800` 추가         | 현재 `primary-700`(#0ea5e9) < `primary-600`(#2272eb) 순으로 이미 역전돼 있다. 여기에 800 을 얹으면 **700 < 600 < 800** 이라는 읽을 수 없는 서열이 된다 |
| `--color-primary-700` 의 값 재지정 | 포커스 링·지도 라벨·테두리가 함께 바뀐다. `global-styles.test.ts` 의 포커스 규약 검사가 무의미해진다(D6-3)                                             |
| 한다: **역할 이름 시맨틱 토큰**    | `fill-primary-text` = 「텍스트를 싣는 primary 채움」. 숫자가 없으니 명암을 거꾸로 말할 여지가 없다                                                     |

### D3-2. 데이터 흐름

색은 런타임 데이터가 아니라 **CSS 캐스케이드**로만 흐른다. 상태 관리·SSR/CSR 경계 변경은 없다.

:::mermaid
flowchart LR
A([:root 프리미티브 hex]) --> B[시맨틱 var 별칭] --> C[styled-components 선언] --> D[(getComputedStyle)] --> E[대비 계산 · D7]
:::

- `GlobalStyles` 는 `createGlobalStyle` 이라 **HMR 로 다시 주입되지 않는다.** 토큰을 추가하고 브라우저에 안 뜨면 dev 서버를 재시작한다(파일 상단 주석의 실측 기록 그대로).
- 서버 컴포넌트/클라이언트 컴포넌트 경계는 영향이 없다. `docs/engineering/styling-rules.md` 의 기존 규칙을 그대로 따른다.

### D3-3. 데이터 모델 — 추가할 토큰

**프리미티브(신규 4)**

| 토큰                | 값        | HSL           | 기준 색과의 관계                                             |
| ------------------- | --------- | ------------- | ------------------------------------------------------------ |
| `--color-blue-700`  | `#1a5fcc` | 217, 77%, 45% | `blue600`(#2272eb, 216/83/53)에서 **색상각 유지·명도만 -8%** |
| `--color-blue-800`  | `#1757bf` | 217, 79%, 42% | `blue700` 의 hover/pressed. 같은 색상각에서 -3%              |
| `--color-green-700` | `#0b7a52` | 158, 83%, 26% | `green500`(#03b26c, 156/97/35)의 진한 단계                   |
| `--color-red-700`   | `#c8323f` | 355, 60%, 49% | `red500`(#f04452, 355/85/60)의 진한 단계. **색상각 동일**    |

**시맨틱(신규 6)**

| 토큰                              | 가리키는 값              | 역할                                                           |
| --------------------------------- | ------------------------ | -------------------------------------------------------------- |
| `--color-fill-primary-text`       | `var(--color-blue-700)`  | **텍스트를 얹는** 파란 채움(rest) — 주 버튼·헤더 CTA·순위 배지 |
| `--color-fill-primary-text-hover` | `var(--color-blue-800)`  | 위 채움의 hover/pressed                                        |
| `--color-text-primary-on-light`   | `var(--color-blue-700)`  | 흰색·blue50·grey50·grey100 위의 **파란 글자·아이콘**           |
| `--color-positive-text`           | `var(--color-green-700)` | 상승 **수치 텍스트**(면적 채움 아님)                           |
| `--color-negative-text`           | `var(--color-red-700)`   | 하락 **수치 텍스트**(면적 채움 아님)                           |
| `--color-text-caption-on-band`    | `var(--color-grey-700)`  | grey50·grey100·blue50 밴드 위의 캡션·보조 본문                 |

> `--color-fill-primary-text` 와 `--color-text-primary-on-light` 는 지금 같은 값을 가리킨다. **그래도 이름을 나눈다** — 「채움을 더 어둡게」와 「글자를 더 어둡게」는 나중에 따로 움직일 수 있는 결정이고, 한 이름으로 묶으면 한쪽을 바꿀 때 다른 쪽이 조용히 따라간다.
>
> `--color-positive` / `--color-negative`(현행, green500/red500)는 **그대로 둔다.** 차트 막대·스코어 스케일은 면적이라 3:1 기준이고 이미 통과한다. 텍스트만 `-text` 접미 토큰으로 간다.

**바꾸지 않는 것** — `--color-blue-500`, `--color-blue-600`, `--color-primary-700`, `--color-primary-600`, `--color-primary-100`, `--color-green-500`, `--color-red-500`, `--color-text-caption`, `--color-positive`, `--color-negative`, `--shadow-focus-primary*`.

### D4-4. hover 역전 방지

| 상태  | 현행                   | 흰 글자 대비 | 변경 후            | 흰 글자 대비 |
| ----- | ---------------------- | ------------ | ------------------ | ------------ |
| rest  | `#0ea5e9`(primary-700) | 2.77         | `#1a5fcc`(blue700) | **5.91**     |
| hover | `#2272eb`(primary-600) | 4.49         | `#1757bf`(blue800) | **6.66**     |

- 현행도 hover 가 rest 보다 어둡다(2.77 → 4.49). 새 쌍도 같은 방향을 지킨다(5.91 → 6.66).
- **`#1a5fcc` 채움에 기존 hover `#2272eb` 를 그대로 쓰면 안 된다.** 5.91 → 4.49 로 hover 가 **밝아지고**, 그 상태에서 흰 글자가 다시 AA 아래(4.49)로 떨어진다. 이것이 blue800 을 함께 추가하는 유일한 이유다.
- rest ↔ hover 의 상호 대비는 **1.13:1**. 이 서비스의 hover 단계(blue500→blue600) 감각과 같은 폭이다. 더 벌리려면 D8-3 을 본다.

### D6-4. 예외 — 앵커 문장 미채움 단어색 `#e5e8eb`(1.23)

`anchor-statement.tsx` 는 채워지지 않은 단어를 `--color-border-200`(`#e5e8eb`, 흰 배경 1.23)으로 그린다. **이 명세는 이 색을 바꾸지 않는다.**

| 판단 근거                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **텍스트가 아니라 진행 상태의 표현이다.** 같은 DOM 노드가 스크롤에 따라 `--color-text-900`(16.9:1)으로 **반드시** 채워진다. 최종 상태가 AA 를 넘고, 미채움은 「아직 오지 않았다」는 장식이다                                        |
| WCAG 1.4.3 은 「**비활성 컴포넌트·순수 장식**」을 대비 요건에서 제외한다. 미채움 단어는 그 사이에 있다 — 이 명세는 **장식으로 판정**하고, 그 판정을 여기 기록해 근거 없이 유지되지 않게 한다                                        |
| 감사도 이 항목을 P0-C(색)가 아니라 **P2-L(앵커 구간의 빈 화면)** 로 분류했다. 진짜 문제는 대비가 아니라 「트랙 190dvh 동안 하단 500px 이 비어 있다」는 **레이아웃**이다                                                             |
| 따라서 해결은 스크롤 예산 슬라이스(감사 §4 4번, `frontend/docs/features/home/scroll-budget.md` — **아직 미작성**)가 sticky 높이를 줄이면서 함께 판단한다. 색만 올리면 「채워짐/안 채워짐」 대비가 약해져 인터랙션의 의미가 사라진다 |

> **결정(2026-09-11, scroll-budget D4-2 와 합의)**: 미채움 색은 `--color-text-caption`(`#6b7684`, 흰 배경 4.62)으로 올린다. 이 절의 원래 판단(「장식이므로 예외」)은 철회한다 — 스크롤을 멈춘 사용자·링크로 진입한 순간·트랙 진입 전 화면에서 미채움 상태가 **정지 화면으로 남으므로** 읽히는 텍스트로 본다. 위 문단의 「3.7배 → 1.5배」는 재현되지 않는 수치라 삭제한다. WCAG 명도 대비로 계산한 채움/미채움 쌍은 `#e5e8eb` 일 때 **13.47:1**, `#6b7684` 일 때 **3.59:1** 이고(비텍스트 구분 기준 3:1 통과), `--color-grey-300`(`#d1d6db`)의 흰 배경 대비는 1.42 가 아니라 **1.46** 이다. 적용 위치·검증은 [scroll-budget D4-2](../home/scroll-budget.md) 가 정본이다.

감사는 「43종 중 18종 미달」이라 적고 8종만 표로 남겼다. 나머지 10종은 문서에 없다. **D7 B1 재측정으로 먼저 목록을 확정한 뒤** 이 문서의 규칙(D4-1~D4-6)으로 분류한다. 규칙 밖의 조합이 나오면 임의로 색을 고르지 말고 D8 에 올린다. 지금까지 grep 으로 확인된 미열거 후보:

```js
const rows = new Map()
for (const el of document.querySelectorAll('body *')) {
  const text = [...el.childNodes]
    .filter(n => n.nodeType === 3 && n.textContent.trim())
    .map(n => n.textContent.trim())
    .join('')
  if (!text) continue
  const cs = getComputedStyle(el)
  if (cs.visibility === 'hidden' || cs.display === 'none') continue
  const size = parseFloat(cs.fontSize)
  const weight = Number(cs.fontWeight) || 400
  const large = size >= 24 || (size >= 18.66 && weight >= 700)
  const need = large ? 3 : 4.5
  const fg = cs.color
  const bg = bgOf(el)
  const r = ratio(fg, bg)
  const key = `${fg}|${bg}|${size}px/${weight}`
  const row = rows.get(key) ?? {
    fg,
    bg,
    size,
    weight,
    r,
    need,
    count: 0,
    sample: text.slice(0, 20),
  }
  row.count += 1
  rows.set(key, row)
}
const all = [...rows.values()]
console.table(all.filter(x => x.r < x.need).sort((a, b) => a.r - b.r))
console.log('조합', all.length, '· 미달', all.filter(x => x.r < x.need).length)
```
