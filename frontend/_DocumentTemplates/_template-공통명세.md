## S0. 배경 / 기획 의도

이 기능을 만드는 이유와 배경을 기술합니다. 기획팀 요청을 바탕으로 작성하며, 출처를 명시합니다.
기존 기능을 개선하는 경우 as-is와 to-be를 간략히 비교합니다.

> **마이그레이션 컨텍스트**: 기존(레거시) 시스템을 웹으로 이전하는 작업인 경우 **기존 동작 (as-is)** 과 **목표 동작 (to-be)** 를 반드시 구분해 작성합니다. 단순 신규 기능이면 as-is에 "신규"로 표기합니다.

| 항목               | 내용                                                     |
| ------------------ | -------------------------------------------------------- |
| 요청자 / 요청팀    | 기획 요청의 출처 (예: 기획팀 OOO)                        |
| 요청일             | YYYY-MM-DD                                               |
| 원본 기획 문서     | 요청 근거가 된 기획서·이슈 링크                          |
| 요청 배경          | 왜 이 요청이 나왔는가                                    |
| 기존 동작 (as-is)  | 해당 없으면 "신규". legacy 시스템 동작을 구체적으로 기술 |
| 목표 동작 (to-be)  | 웹으로 이전 시 달라지는 목표 동작을 명시                 |
| 구현 제외 범위     | 이번 작업에서 다루지 않는 것을 명시                      |
| 연관 기능 / 의존성 | 이 기능과 연결된 기존 기능 또는 모듈                     |
